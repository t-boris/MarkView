# Task 12: Pre-deploy QA

## Required Skills

Перед выполнением задачи загрузи:

## Description

Финальный приёмочный QA для фичи Recursive Insight. Это последняя волна (Wave 5) после трёх параллельных аудитов (Code Audit, Security Audit, Test Audit). Задача QA — независимо подтвердить, что фича действительно работает end-to-end, а не только «прошла ревью».

Для MarkView нет тестового таргета (Decision 9 техспека: тесты отложены в follow-up), поэтому QA опирается на:
1. **Чистый билд** — `xcodebuild build` с 0 ошибок и без новых предупреждений в модифицированных файлах.
2. **Smoke-проверка SSE-эндпоинта** — повторный `curl` против Anthropic Messages API со streaming, чтобы подтвердить, что API доступен с текущим ключом и что `Tests/Fixtures/sse-anthropic-sample.txt` не дрейфовал относительно реального формата (если дрейфовал — пере-захватить fixture).
3. **Spot-check инвариантов хранилища** — убедиться, что Recursive Insight не создал новых таблиц в `SemanticDatabase` и не пишет в существующие `artifacts` / `ai_jobs` для insight-операций (Decision 3 техспека: дерево живёт только в памяти).
4. **Все 10 пользовательских acceptance criteria** из user-spec проверяются вручную через реальный flow на папке `TestFiles/`.
5. **Mandatory: Instruments → Allocations leak check на 4 сценариях** (Decision 11 §1, AC «Closing insight tab → InsightSession and all InsightNode instances are deallocated» — отмечено в техспеке как **mandatory for QA sign-off, not optional**):
   - (a) открыть insight tab, развернуть 2-3 deep-dive, закрыть tab;
   - (b) триггер error path (kill network mid-stream), нажать Retry, успешно завершить, закрыть;
   - (c) триггер 4-го retry в течение 60s, наблюдать rate-limit error, закрыть;
   - (d) сгенерировать достаточно deep-dive контента, чтобы превысить 50 MB session cap, наблюдать eviction старейших не-current узлов, закрыть.
   После каждого: force GC, проверить что 0 retained `InsightSession` и `InsightNode` instances.
6. **Tab-switch-during-stream** ручная проверка (Decision 11 §5): открыть insight, начать стрим, переключиться на другую вкладку посреди стрима, переключиться назад — буфер продолжает накапливаться, нет потери данных.

Финальный артефакт — отчёт `logs/qa/pre-deploy-qa-report.md` с pass/fail на каждый acceptance criterion (user-spec + tech-spec) и подробностями по 4 leak-check сценариям + tab-switch flow.

Проверить, что `SELECT COUNT(*) FROM artifacts WHERE ...` и `SELECT COUNT(*) FROM ai_jobs WHERE ...` не выросли для строк, относящихся к insight-операциям.

5. **User-spec acceptance criteria (10 пунктов):** ручной flow на `TestFiles/`:
   - **AC1:** В меню `AI Tools → Analysis` появился пункт `🧭 Recursive Insight`, активный когда открыта папка с хотя бы одним `.md`-файлом. Закрыть папку → пункт меню становится disabled.
   - **AC2:** При нажатии открывается новая вкладка, в которой стримится summary всей папки, токен за токеном видный пользователю.
   - **AC3:** Inline `mermaid`-блоки в summary рендерятся как SVG-диаграммы (стандартный `mermaid.render`, без `%%INTERACTIVE`).
   - **AC4:** После завершения streaming в правой панели отображается список из 3-7 кликабельных deep-dive топиков.
   - **AC5:** Клик по топику инициирует streaming нового узла со своим summary и своим списком топиков.
   - **AC6:** Breadcrumbs корректно отображают путь от root до текущего узла; клик возвращает к уже сгенерированному узлу из памяти без повторного LLM-вызова (мгновенно, без сетевой активности).
   - **AC7:** Кнопка `💾 Save as .md` открывает NSSavePanel и сохраняет markdown текущего узла (без deep-dive списка) в выбранный файл; сохранённый файл открывается в обычном editor-режиме MarkView корректно.
   - **AC8:** Кнопка `↑ Up` возвращает к родительскому узлу.
   - **AC9:** Если папка содержит >30 `.md`-файлов, для root-узла используется map-reduce из `GraphRAG.mapReduceForFolder`. Если ≤ 30 — one-shot вызов через `streamCompletion`. Проверить логированием или дебагом.
   - **AC10:** При закрытии вкладки дерево insight-узлов полностью освобождается из памяти (см. шаг 6 — Instruments leak check).

6. **Mandatory: Instruments leak check (4 сценария):**
   - Запустить MarkView через Instruments → Allocations template (или Leaks).
   - Для каждого сценария: запустить, выполнить, force GC (Cmd+E или соответствующая команда Instruments), сделать snapshot heap, найти инстансы `InsightSession` и `InsightNode`, **подтвердить count = 0**.
   - **Сценарий (a) — Happy path:** открыть insight на `TestFiles/`, дождаться root, развернуть 2-3 deep-dive (нажимая на топики в правой панели), закрыть tab. Snapshot.
   - **Сценарий (b) — Error + Retry:** открыть insight, дождаться начала стрима, выключить Wi-Fi (или через `nettop`/`tcpkill` оборвать соединение), увидеть error banner, включить Wi-Fi, нажать Retry, дождаться успешного завершения, закрыть tab. Snapshot.
   - **Сценарий (c) — Retry rate limit:** открыть insight, дождаться стрима, оборвать сеть, нажать Retry → снова оборвать → нажать Retry → снова оборвать → нажать Retry → снова оборвать. На 4-м клике в течение 60 секунд должен прийти `setInsightError(retryable: false)` и кнопка Retry должна исчезнуть. Закрыть tab. Snapshot.
   - **Сценарий (d) — Memory cap eviction:** открыть insight, рекурсивно расширять deep-dive узлы (можно повторно кликать тот же топик в разных ветках), пока суммарный `rawBuffer` не превысит 50 MB. Подтвердить через debug-print или счётчик в `InsightSession`, что произошёл eviction старейших не-current узлов (их `nodes[id]` стал nil). Закрыть tab. Snapshot.
   - В отчёте зафиксировать для каждого сценария: retained `InsightSession` count, retained `InsightNode` count, наличие любых других «зомби» из иерархии (например, `URLSession` Task'ов или `AsyncSequence` итераторов).

7. **Tab-switch-during-stream (Decision 11 §5):**
   - Открыть `TestFiles/` (~10-30 файлов). Открыть какой-нибудь существующий `.md` файл в редакторе (вкладка А).
   - Запустить Recursive Insight (вкладка Б), дождаться начала стрима.
   - Посреди стрима (когда summary ещё активно растёт) переключиться на вкладку А.
   - Подождать 5-10 секунд (стрим должен продолжать работать в фоне; для подтверждения можно посмотреть логи или счётчик символов в `streamingBuffer`).
   - Переключиться обратно на вкладку Б. Подтвердить:
     - Контент summary вырос за время отсутствия (нет «застывшего» состояния).
     - Никаких разрывов в тексте, никаких дублирований.
     - После завершения стрима deep-dive список появился корректно.

8. **Написание отчёта:**
   - Создать `work/recursive-insight/logs/qa/pre-deploy-qa-report.md`.
   - Структура отчёта:
     - **Build verification:** статус + список новых warnings (если есть).
     - **SSE smoke:** статус + примечание о fixture drift (если был).
     - **Storage spot-check:** список таблиц diff + counts из `artifacts`/`ai_jobs` до и после.
     - **User-spec AC table:** 10 строк, для каждой `pass` / `fail` / `partial` + комментарий + (опционально) скриншот.
     - **Tech-spec AC table:** все AC из секции «Acceptance Criteria» техспека (build & compatibility, SSE & streaming correctness, lifecycle & memory, resource caps, security, marker parsing) — `pass` / `fail` / `partial`. Для тех, что не проверяемы вручную (например, "no API key in NSLog") — пометить `verified by audit (Task 9/10/11)` со ссылкой на отчёт аудита.
     - **Instruments leak check:** 4 сценария + результаты heap-snapshot (counts по `InsightSession` / `InsightNode`).
     - **Tab-switch flow:** результат.
     - **Deferred / Known issues:** что не покрыто (если есть) и почему.

**Implementation hints:**
- Перед запуском Instruments — собрать **Release** билд (`xcodebuild ... -configuration Release`), чтобы оптимизатор не удерживал лишние ссылки в дебажной информации. После QA на Release дополнительно прогнать happy path в Debug на тот случай, если найдётся UB-разница.
- Force GC в Swift / ObjC через ARC — не явный API; в Instruments Allocations есть кнопка `Mark Generation` + анализ heap diff. Альтернатива: дождаться следующей autorelease pool iteration через явный `RunLoop.main.run(until: Date().addingTimeInterval(2))` в дебажном меню (если есть) или просто 2-3 секунды idle.
- Для определения новых warnings — сравнить вывод `xcodebuild build 2>&1 | grep "warning:"` до фичи (на коммите перед началом feature/recursive-insight) и сейчас. Использовать `git stash`/`git worktree` чтобы не терять изменения.
- Для проверки таблиц `SemanticDatabase`: путь к SQLite-файлу обычно `~/Library/Application Support/MarkView/<workspace-id>/semantic.sqlite` (точный путь — посмотреть в `SemanticDatabase.init`). Команда: `sqlite3 path.sqlite ".tables"`.
- Для проверки `artifacts` / `ai_jobs`: `sqlite3 path.sqlite "SELECT COUNT(*) FROM artifacts; SELECT COUNT(*) FROM ai_jobs;"` до и после insight-сессии.
- Для kill network mid-stream без выключения Wi-Fi: можно использовать macOS `pfctl` правило, блокирующее `api.anthropic.com`, или просто `sudo route add -host api.anthropic.com 127.0.0.1` на время теста (откатить после).
- Сценарий (d) — реалистично достичь 50 MB можно через множественные deep-dive с большим `max_tokens`. Если медленно — временно понизить `InsightSession` cap до, например, 5 MB (debug build only) для ускорения проверки eviction-логики. Восстановить cap после.
- Если на каком-то AC из техспека не получается дать pass/fail вручную (например, «API key never appears in NSLog» нужно проверить грепом по логам Console.app) — пометить как `verified by Task 10 (security audit) §<номер>`.
