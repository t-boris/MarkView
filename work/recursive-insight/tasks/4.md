## Description

Recursive Insight v2 переходит на двухфазную генерацию HTML-сайта вместо markdown потока v1. Эта задача переписывает тело `mapReduceForFolder` в `MarkView/Models/GraphRAG.swift` так, чтобы оно стало источником prompt-композиции для обеих фаз: **Phase 1** (skeleton) — единичный non-streaming вызов Anthropic `tool_use` через `providerClient.toolCall` (T1) с строгой JSON-схемой, возвращает `InsightSkeleton`; **Phase 2** (per-section) — N параллельных prompt-композеров, каждый из которых отдаётся `InsightSession` (T6) для вызова `streamCompletion` в пределах `withThrowingTaskGroup` с гейтированной concurrency (cap=5).

Существующие в файле артефакты — `detectCommunities`, `escapeXMLEnvelopeBreakout`, `xmlAttrSafeCharacters`, XML-обёртка `<file path="...">`, ресурсные капы (50 KB/file, 200 KB/community, 500 файлов folder cap), валидация путей с `resolvingSymlinksInPath` — переиспользуются как есть. Метод `deepResearch()` остаётся **byte-for-byte идентичным** (regression check). Метод `callLLM()` (private helper для `deepResearch`) трогать нельзя.

Задача — fundament для T6 (InsightSession) и T7 (WebViewBridge). После T4 InsightSession сможет вызвать helper'ы для skeleton + per-section prompts без знания о tool_use schema или XML-эскейпинге внутри.

**T4 PRECONDITION (см. round-3 fix tech-spec):** ПЕРЕД любой модификацией исполнитель ОБЯЗАН выполнить `grep -rn "mapReduceForFolder" MarkView/MarkView/` и подтвердить, что единственные вызывающие — `MarkView/Models/InsightSession.swift` (v1, который тоже переписывается в T6). Ожидаемые попадания: 4 строки в InsightSession.swift (комментарии + 2 вызова) + 1 строка определения в GraphRAG.swift. Если найдены сторонние callers — НЕ трогать API, эскалировать через decisions.md, остановить задачу.
