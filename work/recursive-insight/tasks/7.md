# Task 7: WebViewBridge v2 protocol + EditorView routing

## Description

This task replaces the v1 Recursive Insight bridge protocol with the v2 protocol that drives the new sandboxed-iframe insight player (T5) from the new two-phase `InsightSession` state surface (T6).

V1 used a single-document streaming model: 5 Swift→JS commands (`loadInsightView`, `appendInsightDelta`, `setInsightDeepDives`, `showInsightLoading`, `setInsightError`) and 5 JS→Swift handlers (`insightDeepDiveClicked`, `insightSaveRequested`, `insightBreadcrumbClicked`, `insightUpClicked`, `insightRetryRequested`) all keyed by `sessionId`. The EditorView Coordinator subscribed to `session.$streamingBuffer` (computing a single suffix delta against `lastForwardedLength: Int`) and `session.$currentNodeId` (full repaint via `loadInsightView`).

V2 changes the model fundamentally — see Decisions 2 (iframe sandbox), 2.5 (`insight*` prefix), 3 (frameInfo defense-in-depth), 10 (HTML escape policy), and 11 (blob URL lifecycle):

- **5 new Swift→JS commands** drive the parent JS that owns the sandboxed iframe — not the iframe directly:
  - `loadInsightSkeleton(skeleton:into:)` — JSON-encoded `InsightSkeleton`; parent builds iframe srcdoc with placeholders + lazy lib blob URLs.
  - `updateInsightSection(sectionId:htmlChunk:into:)` — per-section delta forwarded by parent JS into iframe via `iframe.contentWindow.postMessage`.
  - `setInsightError(message:retryable:into:)` — same surface as v1 minus `sessionId` (only one active session per WebView in v2 since iframe replaces the whole insight-mode view); `retryable` is a JS boolean literal `true`/`false` (NOT `1`/`0`).
  - `setInsightStatus(message:phase:into:)` — drives the bottom status bar in parent chrome ("Phase 2: 3/7 sections...").
  - `releaseInsightBlobs(into:)` — invokes parent JS `window.releaseInsightBlobs()` to revoke all blob URLs for the closing session. Called by `WorkspaceManager.closeTab` insight branch as **step 1 of 4** per Decision 11 §2 (BEFORE `await session.cancel()`).

- **5 new JS→Swift message handlers** with strict frameInfo defense (Decision 3) and parent-side payload validation (Decisions 2.5, 10). Handler names use the `insight` prefix per Decision 2.5:
  - `insightIframeReady` — payload `{nodeId: String}`. Acknowledges iframe finished loading; cancels the 10s parent-side iframe-load timeout (timer lives in T5's index.html, but the bridge handler still must accept and forward the event so WorkspaceManager / session can record readiness if needed).
  - `insightDeepDiveClicked` — payload `{sectionId: String, topicIndex: Int}`. Parent JS side validates `sectionId ∈ skeleton.sections` and `topicIndex < skeleton.sections[sectionId].deepDiveTopics.count` before posting; the Swift bridge must still bounds-validate against the live `session.skeleton` (T6) before forwarding to `WorkspaceManager.didRequestInsightDeepDive(sectionId:topicIndex:)` because the Swift state is the source of truth (skeleton may have been replaced by a navigation that hasn't propagated to the iframe yet).
  - `insightBreadcrumbClicked` — payload `{nodeId: String}`. Bridge validates the string is a UUID and is present in `session.nodes` (T6 manifest membership) before forwarding.
  - `insightRequestSave` — no payload (was `insightSaveRequested` in v1). Forwards to `WorkspaceManager.exportInsightArchive` (the T8 replacement of `saveInsightNode`).
  - `insightRequestUp` — no payload (was `insightUpClicked` in v1). Forwards to `session.up()` via WorkspaceManager.

- **EditorView.Coordinator** retargeted: drop `lastForwardedLength: Int` (v1 single-buffer state); add `lastForwardedSectionLength: [String: Int]` keyed by sectionId. Drop `session.$streamingBuffer` and `session.$currentNodeId` Combine subscriptions; add four new subscriptions:
  - `session.$skeleton` (dropFirst, receive on main) → `bridge.loadInsightSkeleton(skeleton:into: webView)`. Resets `lastForwardedSectionLength` to `[:]` BEFORE forwarding, so the next `$currentNodeSections` emission computes deltas from 0.
  - `session.$currentNodeSections` (dropFirst, receive on main) → for each `(sectionId, state)` where `state.buffer.count > lastForwardedSectionLength[sectionId, default: 0]`, compute `delta = String(state.buffer.dropFirst(lastLen))`, update `lastForwardedSectionLength[sectionId] = state.buffer.count`, forward via `bridge.updateInsightSection(sectionId:, htmlChunk: delta, into: webView)`. Reset detection per-key: if `state.buffer.count < lastLen` (retry shrunk a section's buffer), reset `lastLen = 0` and forward whole buffer.
  - `session.$lastError` (`compactMap { $0 }`, receive on main) → `bridge.setInsightError(message: errorMsg, retryable: session.lastErrorRetryable, into: webView)`.
  - `session.$statusMessage` (dropFirst, receive on main) → `bridge.setInsightStatus(message: status, phase: <derived>, into: webView)`. (`phase` may be derived from the message itself or from a separate `session.statusPhase` enum if T6 exposes one — coordinate with the T6 surface; if T6 only exposes `statusMessage`, the bridge signature can collapse to just `message` and the design-doc adjusted accordingly.)

The `lastForwardedSectionLength` dict and the four subscriptions are scoped to the currently-routed insight session — same lifecycle pattern as v1 (cleared on session switch, on switch back to a `.file` tab, and on coordinator teardown). All closures capture `[weak self, weak session, weak webView]` to preserve v1's no-retain-cycle invariant. All emissions are delivered on `DispatchQueue.main` for ordering safety against the skeleton-then-sections sequence (skeleton must reach the iframe before any section delta does).

The 5 v1 `WebViewBridgeDelegate` insight methods are replaced with 5 new methods matching the new payloads. The 5 v1 EditorView Coordinator delegate stub bodies (currently in `EditorView.swift` lines 615-642) are rewritten to call the new WorkspaceManager forwarders that T8 will add — for this task, the bodies wire to the new method names with the new payloads, even if the WorkspaceManager methods don't exist yet (T8 fills them in; build correctness for T7 alone may require `// FIXME: T8 wires up` stub calls that compile against agreed signatures). Coordinate with the T8 task for the exact signatures of `WorkspaceManager.didRequestInsightDeepDive(sectionId:topicIndex:)`, `didRequestInsightBreadcrumb(nodeId:)`, `didRequestInsightUp()`, `exportInsightArchive()`, `didRequestInsightIframeReady(nodeId:)`.

- **Section buffer shrink mid-stream.** Edge case: T6's `appendSectionDelta` may, on retry, replace a section's `buffer` with a shorter retry value. The per-section delta computation must detect `state.buffer.count < lastLen` and reset to 0 + forward the whole new buffer. Document this in code comment.
- **Empty `currentNodeSections` emission.** Possible during state reset before new sections are populated. Subscription must no-op on empty dict (no forwarding, no log spam).
- **Skeleton goes from non-nil → nil.** If T6 ever resets `$skeleton` to nil mid-session (e.g. retry path that re-runs Phase 1), the `compactMap { $0 }` filter drops the nil emission, and the subsequent non-nil emission resets `lastForwardedSectionLength` and repaints. Confirm this is the desired behavior with T6.
- **iframe-load timeout fires.** Per T5, parent JS sets a 10s timer; if `insightIframeReady` not received, parent shows "iframe load failed". The bridge handler `insightIframeReady` does NOT need to manage the timer — that's parent JS responsibility. The handler just forwards the event so WorkspaceManager / session can record readiness if needed for analytics.
- **Frame guard rejection log spam.** Pathological case: a malicious iframe (or future WebKit semantic surprise) repeatedly sends messages — the guard rejects all of them, but each may NSLog. Throttle log to once-per-type-per-second to avoid log flood. Or rely on `os_log` with a private subsystem and let log throttling happen at the OS layer.
- **Tab close during in-flight Combine emission.** EditorView Coordinator's `insightCancellables.removeAll()` cancels all 4 sinks. Any emission already in flight on main thread completes (closure captures `[weak self, weak session, weak webView]` so will no-op if any of them deallocated by the time the closure runs). Same v1 invariant.
- **`setInsightStatus` `phase` parameter.** If T6 surfaces only `statusMessage: String` and not a separate phase enum, the `phase` parameter of the bridge method is awkward. Two options: (a) drop `phase` from the bridge signature, derive in JS from `message`; (b) add `statusPhase: StatusPhase` to T6 and pass through. Pre-coordinate with T6 implementer; this task description allows either, with preference for (a) to minimize T6 surface area. If chosen, update tech-spec Implementation Tasks Task 7 description (`setInsightStatus(message:phase:into:)` → `setInsightStatus(message:into:)`).

**Implementation hints:**

- The existing `encodeStringForJS(_:)` helper at lines 232-239 of `WebViewBridge.swift` is exactly the right tool — use it for every string field. Bools must be `"true"` / `"false"` literals — never `1`/`0` (v1 round-2 fix lesson; would break JS truthiness if string `"0"` ever leaked).
- The existing `sanitizeForLog(_:)` in `WorkspaceManager.swift` (lines 1440-1452) is the canonical sanitizer; T8 uses it heavily. Coordinate with T8 to either (a) move it to a shared `MarkView/Utilities/LogSanitizer.swift` file with `internal` visibility, or (b) duplicate (acceptable for now, document the coupling). The DRY-er option (a) is preferred.
- For the 4 EditorView Combine subscriptions, use the v1 idiom: `.receive(on: DispatchQueue.main)` BEFORE `.sink`, `[weak self, weak session, weak webView]` capture, three guard-let early returns, then the work. This keeps ordering deterministic against the multi-publisher stream from T6.
- The `dropFirst()` decision per subscription: `$skeleton` should NOT use `dropFirst` because we DO want the initial nil-or-skeleton emission to drive the iframe paint. `$currentNodeSections` SHOULD use `dropFirst` because the initial empty dict shouldn't trigger any forwarding work. `$lastError` uses `compactMap { $0 }` (drops nil — same as v1). `$statusMessage` SHOULD use `dropFirst` because the initial empty string shouldn't update the status bar.
- Check `session.skeleton == nil` initial value before deciding compactMap vs dropFirst on `$skeleton` — match T6's actual initialization.
- For NSLog format string safety (CWE-134): always use `%@` format specifier with the sanitized string as argument (`NSLog("[Insight] Malformed payload for %@", sanitizeForLog(type))`) — never inline a user-controlled string into the format string itself.
