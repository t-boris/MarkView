# Task 3: InsightCache module (disk CRUD + manifest)

## Required Skills

Before starting, load:
- `/skill:code-writing` — [skills/code-writing/SKILL.md](~/.claude/skills/code-writing/SKILL.md)

## Description

Create a new `InsightCache` Swift struct that owns the per-session disk cache for the v2 Recursive Insight feature. Each `InsightSession` will hold one `InsightCache` instance rooted at `<workspace>/.insight-cache/<sessionUUID>/`. The cache stores per-node HTML files, a session manifest, and a `_assets/` directory containing copies of vendored libs (Mermaid, Chart.js, KaTeX, Prism) needed for the offline ZIP export.

The cache must:
- Provide atomic writes (temp file + rename) for both per-node HTML and `manifest.json` so an app crash never leaves half-written files in place.
- Build the staging directory consumed by `InsightArchiveExporter` (T8) — `archiveStagingDirectory()` returns a URL that `/usr/bin/zip -r` can be pointed at directly with no further prep.
- Cleanly remove the entire session directory on tab close (`cleanup()`), tolerating concurrent removal races and missing-file errors.
- Apply defense-in-depth path validation on every URL it touches even though `nodeId` is a UUID and not user-controlled — the same `resolvingSymlinksInPath().standardizedFileURL` containment check WorkspaceManager.swift uses (with the path-separator boundary fix from commit bb828a9 that closed the sibling-prefix bypass).

This task is foundational: T6 (InsightSession.swift v2 rewrite) and T8 (WorkspaceManager v2 wiring + ZIP export) both depend on this module.

## What to do

1. Add a new file `MarkView/Models/InsightCache.swift` containing the `InsightCache` struct and the `InsightManifest` struct (plus its nested `NodeManifestEntry`) per the Data Models section of the tech-spec.
2. Implement `init(workspaceURL: URL, sessionId: UUID) throws`:
   - Compute and store `rootDirectory = workspaceURL/.insight-cache/<sessionId.uuidString>/`, `assetsDirectory = root/_assets/`, `nodesDirectory = root/nodes/`, `manifestURL = root/manifest.json`.
   - Create `rootDirectory`, `assetsDirectory`, `nodesDirectory` with `FileManager.createDirectory(at:withIntermediateDirectories: true)`.
   - Locate vendored libs in the running app bundle (`Bundle.main.url(forResource:withExtension:subdirectory:)` against `Resources/Editor/vendor/js` and `Resources/Editor/vendor/css`) and copy them into `_assets/` via `FileManager.copyItem`. Skip files that are already present (idempotent re-init within a session must not throw on `.fileWriteFileExists`).
   - The set of libs to copy is the same set referenced by Decision 5: Mermaid, Chart.js (added in T2), KaTeX (CSS + JS), Prism core + the language plugins already vendored. Iterate the bundle subdirectories rather than hard-coding individual filenames so the list stays in sync with whatever is committed under `Resources/Editor/vendor/`.
3. Implement `writeNode(nodeId: UUID, html: String) throws`:
   - Validate the destination path is contained inside `nodesDirectory` (path-separator-aware `hasPrefix` after `resolvingSymlinksInPath().standardizedFileURL`).
   - Write to `<nodesDirectory>/<nodeId.uuidString>.html.tmp` first, then rename to `.html` via `FileManager.moveItem` (POSIX rename is atomic on the same volume).
   - On any failure, attempt to remove the orphan `.tmp` file (best-effort; ignore `removeItem` errors).
4. Implement `readNode(nodeId: UUID) throws -> String`:
   - Validate the path is contained inside `nodesDirectory`.
   - Return `try String(contentsOf: url, encoding: .utf8)`.
5. Implement `updateManifest(_ manifest: InsightManifest) throws`:
   - Encode via `JSONEncoder` with `outputFormatting = [.prettyPrinted, .sortedKeys]` and ISO8601 date strategy for stable diffs.
   - Atomic temp+rename to `manifest.json` (same pattern as `writeNode`).
6. Implement `loadManifest() throws -> InsightManifest`:
   - Decode the file with the matching `JSONDecoder` configuration.
7. Implement `cleanup() throws`:
   - Call `FileManager.removeItem(at: rootDirectory)`.
   - Treat `NSFileNoSuchFileError` (POSIX `ENOENT`) as success — concurrent removal or already-gone is the success state, not an error. Re-throw any other error.
8. Implement `archiveStagingDirectory() throws -> URL`:
   - Return a directory URL that `/usr/bin/zip -r <dest> .` can be pointed at to produce the export.
   - Per Decision 4 ("`_assets/` directory inside session dir means the export staging dir is just a manifest tweak + zip — no separate copy step"), the simplest correct implementation is to return `rootDirectory` itself once `_assets/`, `nodes/`, and `manifest.json` are already in their final layout. The HTML rewriting required by Decision 5 (rewriting `<script src="blob:...">` to `<script src="../_assets/<lib>.js">`) is performed by T8's `WorkspaceManager.exportInsightArchive(sessionId:)` BEFORE calling this method — InsightCache itself does no HTML rewriting. Document this contract in a comment at the top of the method.
   - Validate the returned URL resolves inside `rootDirectory` (defense-in-depth — the caller will spawn an external process against it).
9. Add a private path-validation helper `assertContained(_ url: URL, in root: URL) throws` used by every method that touches a file URL. Throw a typed error (`InsightCacheError.pathEscape`) on failure.
10. Define `InsightCacheError: Error` as the module's error type covering: `bundleResourceMissing(name: String)`, `pathEscape(url: URL)`, `manifestDecode(underlying: Error)`. Wrap `JSONDecoder` failures via `manifestDecode` so the caller sees a typed error rather than a raw `DecodingError`.
11. Mark the struct `@MainActor`-free — it must be safe to call from background tasks (T6's `withThrowingTaskGroup` Phase 2 writes from off-main). All state is captured in `let` properties; no shared mutable state. Document the threading contract in a doc comment on the struct.

## Details

**Files:**
- `MarkView/Models/InsightCache.swift` (NEW) — create the struct, the `InsightManifest` model, the `InsightCacheError` enum, the private `assertContained` helper. ~150-200 lines including doc comments.

**Dependencies:**
- Foundation only (`URL`, `FileManager`, `JSONEncoder`/`JSONDecoder`, `Bundle`).
- No new SwiftPM packages.
- No dependency on T1 / T2 source files; T2 vendors `chart-4.4.x.min.js` but this task only iterates whatever is in `Resources/Editor/vendor/` at runtime, so the Chart.js file does not need to exist for this task to compile (it will be picked up automatically once T2 lands).

**Edge cases:**
- Workspace path contains spaces / Unicode / symlinks → `resolvingSymlinksInPath().standardizedFileURL` handles all three.
- Sibling folder name prefix attack — `/x/foo` vs `/x/foobar` — the bb828a9 fix (path-separator boundary) is the mitigation; mirror it exactly.
- Session re-init within the same app session (e.g. unlikely retry path) — `init` must not throw on `.fileWriteFileExists` from `createDirectory` or `copyItem`.
- Disk full mid-write — `writeNode` cleans up the `.tmp` orphan, rethrows the error.
- App killed mid-write — `.tmp` orphan persists; next session uses a fresh sessionUUID (Decision 4 / risk table: stale cache from previous app crash → directories named with session UUIDs; old dirs are not reused or read).
- `cleanup()` called while a write is in flight from another task — `removeItem` removes the directory; the in-flight write either fails on rename (target dir gone) or completes the `.tmp` file then fails on rename. Either way the error is the writer's problem; cleanup itself succeeds.
- Bundle resource missing (e.g. running unit tests without bundle resources) — throw `bundleResourceMissing(name:)` with the missing filename so the caller sees a precise diagnostic.

**Implementation hints:**
- For atomic write, prefer `Data.write(to: tmpURL, options: .atomic)` followed by `FileManager.default.moveItem(at: tmpURL, to: finalURL)` — `Data.write` with `.atomic` writes to its own temp internally then renames, but combining with our own `.tmp` + explicit move gives a single observable rename and lets us clean the orphan deterministically. Pick one pattern and stay consistent across `writeNode` and `updateManifest`.
- `FileManager.replaceItem(at:withItemAt:backupItemName:options:resultingItemURL:)` is an alternative that handles the rename-over-existing case atomically; consider it but be aware it can leave backup orphans in some failure modes — the simpler temp+`moveItem` (after best-effort `removeItem` on the destination) is fine because writes are write-once-per-node.
- For the iterating-bundle-subdirectory copy at init, use `FileManager.contentsOfDirectory(at:includingPropertiesForKeys:options:)` against `Bundle.main.url(forResource: "vendor/js", withExtension: nil)` and similar for `vendor/css`.
- Use `JSONEncoder.dateEncodingStrategy = .iso8601` and `JSONDecoder.dateDecodingStrategy = .iso8601` for `InsightManifest` Date fields — keeps the on-disk representation human-readable and stable.
- The path-validation helper in `WorkspaceManager.swift` lines 582-589 and 605-612 is the canonical reference; copy its structure (resolve symlinks → standardize → append path separator → hasPrefix). Do NOT re-export `WorkspaceManager`'s helper — duplicate it locally so `InsightCache` has no dependency on `WorkspaceManager`.
- Document the cross-volume caveat for `moveItem`: if `<workspace>` and the temp file are on different volumes, `moveItem` falls back to copy+delete which is non-atomic. The fix is to keep the `.tmp` file inside the same parent directory as the final file (which we already do — `<nodesDirectory>/<id>.html.tmp` and `<nodesDirectory>/<id>.html` are siblings).
