# Task 5: index.html v2 insight-mode (iframe + postMessage + skeleton + libs delivery + sanitization + escape)

## Required Skills

Перед выполнением задачи загрузи:
- `/skill:code-writing` — [skills/code-writing/SKILL.md](~/.claude/skills/code-writing/SKILL.md)

## Description

Replace v1 insight-mode JavaScript inside `MarkView/Resources/Editor/index.html` with the v2 architecture: a single `<iframe sandbox="allow-scripts">` rendered inside the existing `.insight-container` hosts all LLM-generated content; the parent page owns chrome (breadcrumbs at the top, status bar at the bottom, 🤿 deep-dive buttons rendered inline as part of section templates), bridge plumbing, blob-URL lifecycle for vendored libs, and message validation.

This task is the JS counterpart of the new Swift bridge protocol (T7) and v2 InsightSession (T6). It establishes the iframe trust boundary on which Decisions 2 (sandbox), 3 (defense-in-depth), 5 (lazy lib materialization via blob URLs), 10 (escape utility + CDN strip), and 11 (blob URL lifecycle) all rest. The five new `window.*` setters (`loadInsightSkeleton`, `updateInsightSection`, `setInsightError`, `setInsightStatus`, `releaseInsightBlobs`) are the only Swift→JS surface; the five JS→Swift `postMessage` types form a strict allowlist enforced both inside the iframe (sender side) and in the parent listener (validator side).

The v1 insight machinery being removed: marker parser `\n\n---DEEP-DIVES---\n` (`parseInsightMarker`), the v1 `insightMd` markdown-it instance + link sanitizer, per-block Mermaid pipeline (`processInsightMermaidBlocks`), `renderInsight` + `scheduleInsightRender` debounce, deep-dive list rendering in the right pane, `insight-error-banner` DOM, the 5 v1 `window.*` setters (`loadInsightView`, `appendInsightDelta`, `setInsightDeepDives`, `showInsightLoading`, v1's `setInsightError` signature), and the 3 v1 button bindings (`insightSaveRequested`, `insightUpClicked`, `insightRetryRequested`). The split-pane HTML (right pane for deep-dives) is replaced by a full-width iframe; deep-dive buttons live inline inside the iframe per section.

## What to do

1. **Strip v1 insight code.** Inside the `// RECURSIVE INSIGHT MODE` block (currently roughly lines 2783-3226 of `MarkView/Resources/Editor/index.html`), delete: `insightMd` init + link sanitizer, `setText` chrome helper (will be replaced by escape utility + textContent), marker parser (`INSIGHT_MARKER`, `parseInsightMarker`), per-block mermaid (`processInsightMermaidBlocks`), `renderInsight`, `renderInsightDeepDivesFromArray`, `renderInsightBreadcrumbs` (will be rewritten), `setInsightErrorBanner`, `scheduleInsightRender`, `switchToInsightView` (will be rewritten), `leaveInsightView`, all 5 v1 `window.*` setters, `initInsightButtons`, the v1 timer in `state` (`insightRenderTimer`, `insightBufferText`, `insightDeepDives`, `insightIsStreaming`, `insightLastError`).

2. **Restructure `.insight-container` DOM.** Inside the existing `<div class="insight-container" id="insight-container">` (around line 1114), replace the current split-pane (`insight-body` → `insight-center` + `insight-right` deep-dives panel + `insight-button-row`) with three children: a top breadcrumbs bar (`<div id="insight-breadcrumbs">` — kept), a single full-width `<iframe id="insight-iframe">` host (will get `sandbox="allow-scripts"` + `srcdoc` set by JS, no static `src`), and a bottom status bar (`<div id="insight-status-bar">`). Remove `insight-error-banner`, `insight-deep-dives-list`, `insight-button-row`, `insight-btn-save`, `insight-btn-up`, `insight-error-retry` DOM and their CSS classes — Save/Up are now iframe-side buttons that post `insightRequestSave` / `insightRequestUp` messages. Keep `insight-breadcrumbs` CSS; add minimal CSS for `insight-iframe` (full width/height, no border) and `insight-status-bar` (bottom bar style; small font; muted color).

3. **Add the escape utilities.** Implement `escapeForHTMLAttribute(s)` and `escapeForHTMLText(s)` as parent-JS functions, both performing `& → &amp;`, `< → &lt;`, `> → &gt;`, `" → &quot;`, `' → &#39;` per Decision 10. Both functions must accept any value (coerce `null`/`undefined` to empty string). These are the SOLE permitted path for any LLM-controlled string entering an HTML/attribute context anywhere in parent JS (chrome, srcdoc construction, error banner text). For non-HTML chrome interpolation (status bar, breadcrumb labels rendered as DOM text nodes), `textContent =` is preferred; the escape utilities exist for cases where strings are interpolated into HTML/srcdoc construction (e.g. building the iframe srcdoc string).

4. **Add module-scoped state for the v2 session.** Replace the v1 `state.insight*` fields with: `state.insightIframe` (DOM node), `state.insightSessionId`, `state.insightCurrentNodeId`, `state.insightSkeleton` (last skeleton received), `state.insightSectionLibsNeeded` (Set of lib names derived from skeleton), `state.insightBlobURLs` (Map: libName → blob URL), `state.insightLibBytes` (Map: libName → cached fetched lib source string, populated lazily on first need), `state.insightLoadTimer` (10s timeout handle), `state.insightIframeReady` (Boolean — set true on receipt of `insightIframeReady`).

5. **Build the iframe srcdoc template.** Implement `buildInsightSrcdoc(skeleton)` that composes a self-contained HTML document string. Components in order: HTML5 doctype; `<head>` with the CSP meta (`<meta http-equiv="Content-Security-Policy" content="default-src 'none'; script-src 'unsafe-inline' blob:; style-src 'unsafe-inline'; connect-src 'none'; img-src data: blob:; object-src 'none'; base-uri 'none'; frame-ancestors 'none'">`), `<title>` (escaped skeleton.title via `escapeForHTMLText`), inline `<style>` (skeleton-loader pulse animation + section layout + 🤿 button + Save/Up buttons + a top header showing skeleton title); `<body>` with: a header showing escaped `skeleton.title`, then for each `skeleton.sections[i]` a `<section data-section-id="...">` whose content is a placeholder element (id `placeholder-<sectionId>`) styled with the skeleton-loader animation, plus inside the section: for each `deepDiveTopics[j]` a `<button class="dd-btn" data-section-id="..." data-topic-index="j">🤿 <escaped label></button>`; iframe-side Save and Up buttons in a footer bar; an iframe-side `<script>` block that wires postMessage senders (Save/Up/deep-dive click handlers post `insightRequestSave` / `insightRequestUp` / `insightDeepDiveClicked`), defines `window.__appendSection(sectionId, html)` and `window.__initSectionLib(sectionId, libName)` for Swift-driven updates routed via parent's `iframe.contentWindow.postMessage`, plus a top-level `window.addEventListener('message', ...)` that dispatches `updateInsightSection` / `initSectionLib` / `setStatus` / `setError` messages received from parent. Iframe sends `insightIframeReady` once DOMContentLoaded. The iframe-side button click → `window.parent.postMessage({type, payload}, '*')`. Lib `<script src="<blob URL>">` tags inserted in `<head>` — only for libs `state.insightSectionLibsNeeded` actually needs (Decision 5 lazy materialization).

6. **Lazy lib materialization (Decision 5).** Implement `ensureLibBlob(libName)` (async) that: returns existing blob URL from `state.insightBlobURLs` if present; otherwise fetches lib source from `vendor/js/<libName>.min.js` (using `fetch()` against parent origin — same origin — works because parent is loaded from app bundle), caches the source text in `state.insightLibBytes`, creates a `Blob([src], {type: 'application/javascript'})`, calls `URL.createObjectURL`, stores in `state.insightBlobURLs`, returns it. Mapping: skeleton.sections[*].type drives the set: `mermaidDiagram` → mermaid; `chartJsChart` → chart-4.4.x; any section whose metadata declares math content → katex (read skeleton.metadata flag, e.g. `{hasMath: true}`); always include `prism` (code highlighting universal). Compute `requiredLibs` from skeleton, await `Promise.all(requiredLibs.map(ensureLibBlob))`, then build srcdoc with the resolved blob URLs in `<script src="blob:...">` tags. KaTeX webfonts caveat (per tech-spec Decision 5 caveats and Risks): if KaTeX is in the required set, also fetch `vendor/css/katex.min.css` and inline the CSS plus base64-encode the `vendor/css/fonts/*.woff2` files as `data:` URLs substituted into the inline CSS (verify one webfont round-trip works).

7. **Implement `window.loadInsightSkeleton(skeletonOrJSON, sessionId, nodeId)`.** Coerce input (parse JSON if string; reject silently with NSLog-equivalent `console.warn` if not a valid object with `sections` array). Diff `requiredLibs` against `state.insightSectionLibsNeeded`: revoke any blob URLs in `state.insightBlobURLs` that are no longer needed (`URL.revokeObjectURL` + remove from map), then await `ensureLibBlob` for newly required ones. Update state (`insightSessionId`, `insightCurrentNodeId`, `insightSkeleton`, `insightSectionLibsNeeded`). Build srcdoc via `buildInsightSrcdoc(skeleton)`. Switch to insight view (display `.insight-container`). Reset `state.insightIframeReady = false`. Set `iframe.srcdoc = html`. Start the 10s load timer; on expiry call `handleIframeLoadTimeout` (see step 11). Render breadcrumbs from `skeleton` (or skeleton.breadcrumbs if present) into `#insight-breadcrumbs` using `textContent` (chrome → main frame → no innerHTML).

8. **Implement `window.updateInsightSection(sessionId, sectionId, htmlChunk)`.** Validate `sessionId === state.insightSessionId` (drop stale). Validate `state.insightSkeleton.sections.find(s => s.id === sectionId)` exists (drop unknown section). **CDN strip BEFORE forwarding (Decision 10):** apply a regex pass that removes any `<script\s+[^>]*src\s*=\s*["']?(?:https?:|//)[^"'>\s]*["']?[^>]*>(?:\s*</script>)?` and any `<link\s+[^>]*rel\s*=\s*["'](?:prefetch|preconnect|dns-prefetch)["'][^>]*>` from the chunk; replace each removed tag with `<!-- script src stripped: <originalURL> -->` for visibility. **Do NOT modify any other tag** — sandboxed iframe isolates the content, parent only enforces network-egress hygiene. Then forward to iframe via `state.insightIframe.contentWindow.postMessage({type: 'updateInsightSection', payload: {sectionId, htmlChunk: stripped, sessionId}}, '*')`. Iframe-side handler appends chunk to `placeholder-<sectionId>` element via `el.insertAdjacentHTML('beforeend', html)`. On a chunk containing a `[SECTION_DONE]` sentinel (or as a separate explicit `initSectionLib` message — design choice: prefer explicit init message issued by parent when section completes since the sentinel is an LLM-controlled string and may not arrive cleanly), iframe initializes the matching lib (Mermaid run on `.mermaid` nodes inside that section with `securityLevel: 'strict'`; `new Chart(canvas, config)` for chart sections; KaTeX `renderMathInElement` for math sections; Prism `highlightAllUnder(section)` for code).

9. **Implement `window.setInsightError(sessionId, message, retryable)` and `window.setInsightStatus(sessionId, message, phase)`.** Both are chrome-only (main frame). `setInsightError`: drop stale sessionId; render escaped message into a small banner div (or reuse status bar with error styling) using `textContent`; if `retryable`, render a Retry button that posts `insightRequestRetry` (or expose retry as separate message — current spec lists only 5 types, so error retry is initiated by user via re-clicking the originating action; the Retry button posts `insightRequestUp` semantically — verify with T6/T7 designer; **leave a TODO comment if uncertain**). `setInsightStatus`: drop stale sessionId; set `#insight-status-bar` textContent to escaped message (e.g. "Phase 2: 3/7 sections"); update visual phase indicator (CSS class `phase-1` / `phase-2` / `ready` for color tinting).

10. **Implement `window.releaseInsightBlobs()`.** Iterate `state.insightBlobURLs`, call `URL.revokeObjectURL(url)` for each, clear the map and `state.insightLibBytes`. Clear `state.insightSectionLibsNeeded`. This is invoked by Swift bridge `releaseInsightBlobs(into:)` (T7) BEFORE `session.cancel()` per Decision 11.

11. **Iframe load timeout (10s).** After setting `iframe.srcdoc`, `state.insightLoadTimer = setTimeout(handleIframeLoadTimeout, 10000)`. `handleIframeLoadTimeout`: if `state.insightIframeReady` is still false → call `setInsightError(sessionId, 'iframe failed to load within 10s', true)`; tear down iframe (`iframe.removeAttribute('srcdoc')`; consider replacing the node entirely for clean state). Cancel the timer in the `insightIframeReady` listener (step 12) on success.

12. **Parent-side `message` listener (the SOLE inbound channel from iframe).** `window.addEventListener('message', handler)`. Validation chain (reject silently with `console.warn` on any failure): `event.source === state.insightIframe.contentWindow`; `event.origin === 'null'` (sandbox iframe is null-origin); `event.data` is an object with `type` (string) and `payload` (object); `type` is in the 5-type allowlist (`insightIframeReady`, `insightDeepDiveClicked`, `insightBreadcrumbClicked`, `insightRequestSave`, `insightRequestUp`); per-type payload schema validation:
   - `insightIframeReady`: payload `{nodeId: string}` — clear load timer, set `state.insightIframeReady = true`, forward to Swift via `sendToSwift('insightIframeReady', {sessionId, nodeId})`.
   - `insightDeepDiveClicked`: payload `{sectionId: string, topicIndex: integer}` — validate sectionId is in `state.insightSkeleton.sections[*].id`; validate `topicIndex` is integer in bounds of that section's `deepDiveTopics`; forward `sendToSwift('insightDeepDiveClicked', {sessionId, sectionId, topicIndex})`.
   - `insightBreadcrumbClicked`: payload `{nodeId: string}` — validate `nodeId` matches UUID regex (`/^[0-9A-F-]{36}$/i`); forward `sendToSwift('insightBreadcrumbClicked', {sessionId, nodeId})`.
   - `insightRequestSave`: payload `{}` — forward `sendToSwift('insightRequestSave', {sessionId})`.
   - `insightRequestUp`: payload `{}` — forward `sendToSwift('insightRequestUp', {sessionId})`.

13. **Wire mode entry/exit.** Replace v1 `switchToInsightView` with a slimmer version that only flips display state and toggles the breadcrumbs bar visibility (no Mermaid theme re-init at the parent — Mermaid lives inside iframe and re-inits on each srcdoc reload). Keep `state.mode === 'insight'` semantics. On mode exit (existing `switchTo*` helpers), do NOT revoke blob URLs (release is owned by Swift `closeTab` flow per Decision 11) — only hide the container.

14. **Sample fixture sanity check.** Before declaring done, paste the contents of `Tests/Fixtures/insight-skeleton-sample.json` (T1's deliverable) into Web Inspector via `window.loadInsightSkeleton(<paste>, 'test-session', 'test-node')` and verify visual rendering matches expectations described in Verification Steps below.

- [ ] Iframe srcdoc contains CSP meta `default-src 'none'; script-src 'unsafe-inline' blob:; style-src 'unsafe-inline'; connect-src 'none'; img-src data: blob:; object-src 'none'; base-uri 'none'; frame-ancestors 'none'` (verbatim).
- [ ] Five `window.*` setters defined and reachable from Web Inspector: `loadInsightSkeleton`, `updateInsightSection`, `setInsightError`, `setInsightStatus`, `releaseInsightBlobs`.
- [ ] Five postMessage types form an allowlist enforced parent-side: `insightIframeReady`, `insightDeepDiveClicked`, `insightBreadcrumbClicked`, `insightRequestSave`, `insightRequestUp`. No other types accepted.
- [ ] Parent-side listener validates `event.source === iframe.contentWindow` AND `event.origin === 'null'` AND per-type payload schema (deepDive validates sectionId membership + topicIndex bounds; breadcrumb validates UUID regex).
- [ ] `escapeForHTMLAttribute` and `escapeForHTMLText` defined; used at every interpolation of LLM-controlled strings into srcdoc construction or chrome HTML; chrome that uses textContent does not require escape but never uses innerHTML.
- [ ] `updateInsightSection` strips `<script src="https://...">` / `src="http://"` / `src="//"` and `<link rel="prefetch|preconnect|dns-prefetch">` from htmlChunk BEFORE forwarding to iframe; replaces with HTML comment `<!-- script src stripped: <url> -->`.
- [ ] Lazy lib loading: blob URL created only when skeleton requires the lib (Mermaid only if any section.type === 'mermaidDiagram', Chart only if 'chartJsChart', KaTeX only if a section flags math, Prism always).
- [ ] On node navigation (new `loadInsightSkeleton` call): unused libs revoked, new libs created BEFORE setting iframe.srcdoc.
- [ ] `releaseInsightBlobs` revokes ALL blob URLs and clears the map; intended to be called by Swift before `session.cancel()`.
- [ ] 10s iframe load timeout triggers `setInsightError` if `insightIframeReady` not received; iframe is torn down for retry.
- [ ] Manual paste of `Tests/Fixtures/insight-skeleton-sample.json` into `loadInsightSkeleton` renders skeleton placeholders + lib script tags via blob URLs.
- [ ] Manual injection of `</script><script>alert(1)</script>` as a skeleton title field does NOT execute in main frame (escape utility blocks); if pasted as a section content chunk via `updateInsightSection`, executes only inside iframe sandbox (no parent compromise).

- Skeleton arrives twice in quick succession (debounced re-render): second call must revoke obsolete libs from first call before creating new blobs; race-safe via async `await Promise.all` ordering.
- `updateInsightSection` arrives BEFORE iframe is ready (`insightIframeReady` not yet received): queue the chunk in a per-section pending buffer; flush on `insightIframeReady` receipt.
- `updateInsightSection` arrives for a sectionId not in current skeleton (stale or wrong session): drop with `console.warn`.
- LLM emits a chunk straddling a `<script src="https://...">` boundary (split across two chunks): CDN strip operates on each chunk independently, so a partial tag will not match the regex and pass through; mitigation — the iframe-side `appendChild` builds DOM, but the iframe sandbox + CSP `connect-src 'none'` blocks the actual fetch even if the stripped-tag heuristic misses the boundary case. Document this in code comment as a known accepted-risk corner.
- Iframe sandboxed fetch attempts (e.g. KaTeX webfonts via relative URL): blocked by `default-src 'none'` + `connect-src 'none'`; mitigation — base64-inline webfonts into srcdoc (per Decision 5 caveats).
- Multiple insight tabs open simultaneously (deferred — current spec is single-session, but design state to be tab-scoped via session UUID checks on every setter).
- User closes tab during 10s timeout: Swift bridge should call `releaseInsightBlobs` first (Decision 11 §2 + tech-spec "Tab close" step 1), but the timer may still fire after teardown — guard `handleIframeLoadTimeout` against `state.insightIframe == null`.

**Implementation hints:**
- Reuse the existing `sendToSwift(type, payload)` helper at line 2471 — do not duplicate `webkit.messageHandlers.bridge.postMessage` plumbing.
- Use template literals for srcdoc construction; remember every `${var}` interpolating an LLM string MUST go through `escapeForHTMLAttribute` (for attribute values like `data-section-id="${escapeForHTMLAttribute(s.id)}"`) or `escapeForHTMLText` (for text content like `<h1>${escapeForHTMLText(skeleton.title)}</h1>`).
- For chrome breadcrumb DOM construction (parent main frame), prefer `el.textContent = title` over interpolating into innerHTML — simplest defense.
- Iframe-side script block inside srcdoc is itself a string in parent JS — the script body should NOT be escaped (it's meant to be code), but any LLM strings interpolated INTO the script body (e.g. embedded skeleton id) must be escaped to JS-string-safe form (use `JSON.stringify(value)` to embed strings inside iframe-side JS source).
- For the lazy-lib fetch, use `await fetch('vendor/js/' + libName + '.min.js').then(r => r.text())` — parent page is loaded from app bundle (file:// or wkwebview://), same-origin to vendor folder. If `fetch` fails (sandbox quirks), fall back to embedding lib content via XHR on the parent — verify which works during implementation.
- Don't forget to set `state.insightIframe = document.getElementById('insight-iframe')` once after DOMContentLoaded.
- `console.warn` for all rejected messages (validation failures) — NSLog-equivalent for visibility during QA without leaking to user UI.
