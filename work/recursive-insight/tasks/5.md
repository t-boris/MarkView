# Task 5: Insight mode in WebView (HTML/JS)

## Required Skills

Перед выполнением задачи загрузи:
- `/skill:code-writing` — [skills/code-writing/SKILL.md](~/.claude/skills/code-writing/SKILL.md)

## Description

Add a new `state.mode === 'insight'` branch to the WebView's `index.html` that renders the Recursive Insight tab as a split-pane LLM-driven UI: center markdown body, right-side deep-dive topic list, top breadcrumbs, bottom Save/Up buttons, and an error banner above the deep-dive list.

This is the entire client-side surface of the feature. Swift owns the streaming buffer and forwards chunks via `appendInsightDelta`; JS coalesces those chunks into a debounced (~150 ms) `md.render()` re-render of the center pane and a `---DEEP-DIVES---` marker parser that splits markdown body from the topic list. Button clicks (Save, Up, deep-dive item, breadcrumb item, Retry) become postMessage events on the existing bridge with new message types.

Because the rendered markdown is entirely LLM-generated and may transitively contain content from untrusted `.md` files in the user's folder, this task also lands the **full Decision 10 sanitization layer**: `markdown-it` with `html: false`, link target sanitization (only `http(s)://` and relative paths; reject `javascript:`, `data:`, `file:`), CSP `<meta>` tag, Mermaid `securityLevel: 'strict'` per-render, per-block `try/catch` around `mermaid.run` (Decision 7), and a single `setText(el, str)` utility that uses `textContent` for every LLM-derived string (deep-dive labels, hints, breadcrumb titles, error messages — never `innerHTML`).

Existing modes (`source`, `preview`, `structured`, `structured-source`) and their pipelines are not modified. The insight branch is fully additive.

Five small marker fixture files are committed under `Tests/Fixtures/marker-cases/`. Per Decision 9, these serve as documented inputs for the code-reviewer hand-trace and as golden inputs for the deferred follow-up tests.

## What to do

1. **Extend `state` and DOM references:** add `'insight'` as a permitted value of `state.mode`, plus insight-specific buffers (`insightSessionId`, `insightBufferText`, `insightDeepDives`, `insightBreadcrumbs`, `insightIsStreaming`, `insightLastError`, `insightRenderTimer`). Add new DOM container references for the split-pane layout.
2. **Build the split-pane DOM template:** add a hidden insight container to `index.html` body markup with the four regions (top breadcrumbs bar, center markdown pane, right deep-dive list, bottom button row with Save/Up + retry banner above the list). Style it with existing theme variables so light/dark theme works out of the box.
3. **Add the CSP meta tag** to the document head exactly as specified in Decision 10 §3.
4. **Add `setText(el, str)` utility** — single source of truth that always uses `textContent`. Use it for every LLM-derived string in this mode.
5. **Reconfigure markdown-it for insight mode:** create a second `markdown-it` instance (or reconfigure the renderer used in the insight branch) with `html: false`, `linkify: true`, and a link-target validator that rewrites or strips any `href` not matching `http(s)://` or a relative path (reject `javascript:`, `data:`, `file:`). Apply defense in depth to the existing modes too where it doesn't change behavior (per Decision 10 §1).
6. **Implement the marker parser:** a function that, given the raw stream buffer, finds the **last** occurrence of `\n\n---DEEP-DIVES---\n` and splits into `(markdownBody, topicsBlock)`. If no marker found, treat entire buffer as markdown body and topics as empty. Tolerate 0 or >7 topics (no enforcement). Topics block parsed line-by-line in form `- <Label> :: <hint> :: <scope_hint>`; tolerate missing `::` segments by leaving them empty.
7. **Implement debounced re-render:** `appendInsightDelta` appends to the buffer immediately, then schedules `renderInsight()` on a ~150 ms debounce timer (clearTimeout / setTimeout pattern). `renderInsight()` runs the marker parser, calls `md.render(markdownBody)` into the center pane, updates the right pane via `setText` for each topic, and post-processes Mermaid blocks.
8. **Per-block Mermaid pipeline (Decision 7):** find each `pre code.language-mermaid`, replace with a `.mermaid` div, then call `mermaid.run({ nodes: [singleNode] })` on each block individually inside its own `try/catch`. On failure, replace the failed block with the original raw fenced code plus a small "diagram error" label. Pass `{ securityLevel: 'strict' }` per-render. (Use `mermaid.run` only — NOT `mermaid.render`. The codebase already uses `mermaid.run({ nodes })` at index.html L1247; the per-block pattern is the same call with a single-element nodes array.)
9. **Wire button clicks to bridge messages:** attach click handlers that post the five new message types via `window.webkit.messageHandlers.bridge.postMessage(...)`:
   - Save button → `insightSaveRequested` `{sessionId}`
   - Up button → `insightUpClicked` `{sessionId}`
   - Deep-dive list item → `insightDeepDiveClicked` `{sessionId, topicIndex}`
   - Breadcrumb item → `insightBreadcrumbClicked` `{sessionId, nodeId}`
   - Retry button (in error banner) → `insightRetryRequested` `{sessionId}`
10. **Implement Swift→JS window functions** with the exact signatures the bridge calls (Task 6 produces the Swift side):
    - `window.loadInsightView(snapshotJSON)` — full repaint from a node snapshot (used on initial load and on navigation/back). Resets buffer, breadcrumbs, deep-dives, error banner.
    - `window.appendInsightDelta(sessionId, deltaText)` — append + debounced render.
    - `window.setInsightDeepDives(sessionId, topicsJSON)` — explicit topic list set (in case Swift parsed marker server-side; primary path is JS-side parsing).
    - `window.showInsightLoading(sessionId, message)` — show a small loading indicator before first delta arrives.
    - `window.setInsightError(sessionId, message, retryable)` — display error banner; show Retry button only when `retryable === true`.
11. **Mode switching:** add an `insight` branch alongside the existing `switchToPreview` / `switchToSource` / `switchToStructuredView` / `switchToStructuredSource` paths so showing/hiding the right container is consistent.
12. **Commit five marker fixture files** under `Tests/Fixtures/marker-cases/` (each ~10–30 lines) demonstrating one parser case per Decision 9:
    - `happy.md` — well-formed body + marker + 3 topics
    - `in-code-fence.md` — body contains a fenced code block whose contents include `---DEEP-DIVES---`; real marker still appears at end. Parser must take the **last** occurrence.
    - `as-hr.md` — body contains a bare `---` horizontal rule near the end, but no real marker. Parser must NOT match (boundary newlines + `DEEP-DIVES` text required).
    - `no-marker.md` — body only, no marker. Parser returns empty topics.
    - `multiple-markers.md` — two real markers in the buffer; parser must take the **last** one.

**Dependencies:**
- None on Wave 1 Swift tasks. This task is pure HTML/JS and can run in parallel with Task 4 (`InsightSession`). Bridge wiring (Task 6) and end-to-end integration (Task 7/8) consume the JS surface produced here.

**Edge cases:**
- Marker text appearing inside a fenced code block in body — parser must still pick the real marker (last occurrence rule covers this when real marker exists; when no real marker exists, the in-fence text must NOT be treated as a marker because it lacks the surrounding `\n\n` + `\n` boundary structure when seen in raw stream form. Verify both with fixtures.)
- Bare `---` horizontal rules in markdown — must not match.
- Stream interrupted mid-marker (`\n\n---DEEP-DI` with no closing): no match, render full buffer as markdown until next chunk arrives.
- Topic line with missing `::` segments — accept gracefully (use empty hint, empty scope_hint).
- 0 topics or >7 topics — accept as-is, no enforcement.
- LLM emits a malformed Mermaid block mid-stream — that block shows raw fenced code + error label, the rest of the page renders.
- LLM emits `<script>` or `javascript:` link in markdown — `html: false` strips raw HTML; link validator strips dangerous schemes; CSP and Mermaid `strict` provide defense in depth.
- User switches tabs while stream is running — the JS state for this session keeps accumulating in `insightBufferText`; switching back triggers a fresh `renderInsight()` from current buffer (handled by Task 6 Swift side calling `loadInsightView` with current snapshot).

**Implementation hints:**
- For the link sanitizer in `markdown-it`: override `md.renderer.rules.link_open` and validate the `href` token attribute. Strip the `<a>` if invalid, leaving the link text as plain text.
- Debounce timer: a single module-level `let insightRenderTimer = null;` plus `clearTimeout(insightRenderTimer); insightRenderTimer = setTimeout(renderInsight, 150);`. Always clear before re-setting.
- `setText` utility: `function setText(el, str) { if (el) el.textContent = String(str ?? ''); }` — defensive against null/undefined LLM strings.
- Marker scan: search from the end (`buffer.lastIndexOf('\n\n---DEEP-DIVES---\n')`) — single call covers "last occurrence" semantics.
- Topic line split: `line.replace(/^- /, '').split(' :: ')` — defensive against missing parts; pad with empty strings up to 3 elements.
- Per-block Mermaid: iterate over `.mermaid` nodes, for each `try { await mermaid.run({ nodes: [node], suppressErrors: false }); } catch (e) { /* swap with raw fence + error label */ }`. Note: `mermaid.run` accepts a `nodes` array, so passing `[node]` is the per-block idiom.
- Keep all insight-mode CSS scoped under a parent class like `.insight-container` so it does not leak into other modes.
- The bridge encoding idiom in this project: Swift sends strings via `evaluateJavaScript`; large payloads are escaped JSON. Treat all incoming `loadInsightView` / `setInsightDeepDives` arguments as already-parsed JS objects (Swift parses on its side and emits a JS literal call), but defensively `JSON.parse` if a string is received.
