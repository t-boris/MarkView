## Description

Полный test-quality аудит фичи Recursive Insight. Особенность: **в проекте нет test target — это by design** (Decision 9, тесты deferred в follow-up). Поэтому аудит — не «прогнать pytest и посмотреть coverage», а проверить, что **deferral оформлен корректно и компенсирующие меры (фикстуры + ручной QA + code/security audits) реально закрывают риски, которые автоматические тесты должны были бы поймать**.

Контекст deferral'а — Decision 9:
- Проект MarkView не имеет `MarkViewTests` target, нет `Tests/*.swift`, нет `import XCTest` нигде в кодовой базе.
- Setup test-target — отдельная одноразовая задача (~30-60 мин), которая выгодна всем будущим фичам, но раздула бы scope Recursive Insight.
- User явно выбрал defer.
- Компенсация: коммитим fixture-файлы сейчас (`Tests/Fixtures/sse-anthropic-sample.txt` в Task 1, `Tests/Fixtures/marker-cases/*.md` в Task 5), чтобы ретроактивные тесты получили "golden inputs" с замороженным ожидаемым поведением.
- Дополнительная компенсация: code-reviewer (Task 9) hand-traces SSE parser и marker parser против фикстур; pre-deploy QA (Task 12) делает Instruments leak check для ARC-cycle риска.

Аудит — это **review, а не reviewers**. У этого таска нет ревьюверов: test-master сам и есть финальный testing-голос. Аудитор не пишет код, не модифицирует фичу — только читает артефакты и пишет отчёт.

Отчёт идёт в `logs/audit/test-audit.md`. Формат отчёта: per-check секция (по одной на каждый из 5 пунктов чек-листа ниже) + финальная сводка с verdict.
