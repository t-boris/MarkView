# Task 9: Code Audit

## Required Skills

Перед выполнением задачи загрузи:
- `/skill:code-reviewing` — [skills/code-reviewing/SKILL.md](~/.claude/skills/code-reviewing/SKILL.md)

## Description

Holistic code-quality audit across every file produced or modified by Tasks 1-8 of recursive-insight v2. The auditor reads each v2 source file end-to-end and produces a single structured report at `work/recursive-insight/logs/audit/code-audit.md` summarizing findings, severity, and recommended fixes.

This is the first of three Audit-Wave gates (T9 code, T10 security, T11 tests) and the only quality bar between Wave-5 implementation completion and Final-Wave QA. Because Decision 9 defers XCTest, the audit is the project's primary defense against ARC, concurrency, and bridge-protocol regressions. The v1 audit raised one critical lesson — a strong-self capture inside `activeTask` that leaked the entire `InsightSession` graph — and that lesson MUST drive this audit's `[weak self]` discipline check.

The auditor is the review for this task: no separate code-reviewer / security-auditor / test-reviewer is spawned. The output report IS the verdict.

## What to do

1. Re-read the tech-spec sections relevant to v2 architecture: Solution, Architecture (What we're building/modifying + How it works + Shared resources), all Decisions (1, 2, 2.5, 3, 4, 5, 6, 7, 8, 10, 11), Risks table, Acceptance Criteria. Note the contractual statements that the audit must verify.

2. Read every v2 source file in full (paths in Context Files → Code files). For each Swift file, produce a one-screen mental map of: types declared, public surface, async boundaries, closures, Combine subscriptions, retain edges. For `index.html` insight-mode JS, produce the same map for: parent-side helpers, iframe `srcdoc` template, postMessage handlers, blob URL ledger, escape utilities.

3. Run the audit dimensions enumerated below. For each dimension, walk every relevant file, record findings (file + line range + severity + description + suggested fix). Severity scale: `blocker` (ship-stopper), `major` (correctness or leak risk), `minor` (style/clarity), `nit` (cosmetic).

   **Audit dimensions:**

   a. **`[weak self]` discipline (CRITICAL — v1 audit lesson).** Grep every `Task { ... }`, `Task.detached`, `withThrowingTaskGroup`, `group.addTask`, every closure captured by `@Published` Combine sinks, every `URLSession` callback, every `onDelta:` closure, every `Process.terminationHandler`. ANY closure that outlives the synchronous call site MUST capture `[weak self]` (or be pure / capture nothing). Flag every strong `self` capture as `blocker` with the exact file:line and the fix (`[weak self] in guard let self else { return }`). Pay particular attention to: `InsightSession.generateRoot`, `phase1Skeleton`, `phase2StreamSections`, `appendSectionDelta`, `handleStreamError`, the `withThrowingTaskGroup` body in Phase 2, `EditorView.Coordinator` Combine subscriptions to `$skeleton` / `$currentNodeSections` / `$lastError` / `$statusMessage`, `WorkspaceManager.startRecursiveInsight` Task block, `InsightArchiveExporter.bundle` Process termination handler.

   b. **Async error propagation.** Every `async throws` function: confirm errors are not silently swallowed (`try?` only when intentional and documented; never `try!`). Confirm `phase1Skeleton` errors route to `handleStreamError` with the right `forNodeId`. Confirm `phase2StreamSections` per-section errors mark only that section `.failed` and do not cancel the whole group (per Risk row "Phase 2 N parallel calls hit Anthropic rate limit"). Confirm `InsightCache.writeNode` / `updateManifest` errors propagate to caller. Confirm `InsightArchiveExporter.bundle` exit-code != 0 throws.

   c. **Task cancellation.** Confirm `session.cancel()` cancels `activeTask` AND every child Task spawned by `withThrowingTaskGroup` (group cancellation propagates automatically — verify the body actually checks `Task.isCancelled` between stream chunks or relies on `streamCompletion` to throw `CancellationError`). Confirm `InsightArchiveExporter.bundle` is cancellable mid-Process (the staging-temp + `.zip.tmp` cleanup MUST run on cancellation per Risks "In-flight ZIP Process not cancelled on tab close"). Confirm `WorkspaceManager.closeTab` insight branch awaits `session.cancel()` BEFORE `cache.cleanup()` BEFORE `tabsStore.removeTab` (the ordered 4-step close per Decision 11 §2 + Architecture "Tab close").

   d. **Swift conventions.** `@MainActor` placement on `InsightSession` (UI state). `private(set)` on every `@Published`. `let` over `var` where mutation absent. Identifier conformance proper. Codable conformance compiles. `Sendable` annotations where types cross actor boundaries (`InsightSkeleton`, `InsightSection`, `InsightCache`, `InsightArchiveExporter`, `SectionState`, `InsightNode` if shipped across Tasks). Naming consistency with v1 (`appendSectionDelta` not `appendDelta`).

   e. **Shared-resources compliance** (Architecture → Shared resources table). Confirm `AIProviderClient` is consumed (not re-instantiated) by `InsightSession` and `GraphRAG`. Confirm `GraphRAG` is the singleton injected via `WorkspaceManager`, not constructed ad-hoc. Confirm exactly one `InsightCache` per `InsightSession.init` (no second `InsightCache` constructed mid-flight). Confirm `Process` for `/usr/bin/zip` is spawned only inside `InsightArchiveExporter.bundle`. Confirm vendored libs in `Resources/Editor/vendor/` are loaded ONCE per parent page load (not per iframe / per node) — the lazy blob-URL lifecycle in Decision 11 governs.

   f. **JS code quality (`Resources/Editor/index.html` insight-mode block).** Strict-mode declared. `const`/`let` only (no `var`). No globals beyond the documented bridge surface (`window.loadInsightSkeleton`, `window.updateInsightSection`, `window.setInsightError`, `window.setInsightStatus`, `window.releaseInsightBlobs`). Iframe `srcdoc` constructed via template literal — every LLM-controlled interpolation goes through `escapeForHTMLAttribute` or `escapeForHTMLText` (Decision 10). Parent-side chrome (breadcrumbs + status bar) renders LLM strings via `textContent` (NEVER `innerHTML`). Iframe-side `innerHTML`/`outerHTML`/`document.write`/`eval`/`Function` are ALLOWED (LLM-trusted within sandbox boundary) — but parent-side use of any of these on LLM strings is a `blocker`.

   g. **postMessage allowlist correctness.** Exactly 5 JS→Swift types: `insightIframeReady`, `insightDeepDiveClicked`, `insightBreadcrumbClicked`, `insightRequestSave`, `insightRequestUp`. No 6th type. Every parent `window.addEventListener('message', ...)` handler validates `event.source === iframe.contentWindow && event.origin === 'null'` BEFORE acting on payload. Every type has a payload schema check parent-side; malformed payloads are rejected with sanitized `NSLog`. `insightDeepDiveClicked` bounds-checks `topicIndex` against `skeleton.sections[sectionId].deepDiveTopics`. `insightBreadcrumbClicked` validates `nodeId` UUID regex AND manifest membership.

   h. **frameInfo defense-in-depth (Decision 3).** EVERY v2 `WKScriptMessage` handler in `WebViewBridge.swift` opens with `guard message.frameInfo.isMainFrame else { return }`. Count handlers: must be 5. Flag any v2 handler missing the guard as `blocker`. Confirm v1 handlers (if any remain — they should not) are removed.

   i. **Iframe sandbox correctness (Decision 2).** `Resources/Editor/index.html` insight-mode iframe element has `sandbox="allow-scripts"` exactly. NO `allow-same-origin`, NO `allow-popups`, NO `allow-forms`, NO `allow-modals`, NO `allow-top-navigation`. Iframe srcdoc CSP `<meta>` matches Acceptance Criteria spec: `default-src 'none'; script-src 'unsafe-inline' blob:; style-src 'unsafe-inline'; connect-src 'none'; img-src data: blob:; object-src 'none'; base-uri 'none'; frame-ancestors 'none'`.

   j. **Hand-trace tool_use sample → InsightSkeleton parse.** Open `Tests/Fixtures/insight-skeleton-sample.json`. Trace the bytes through `AIProviderClient.toolCall` (HTTP body composition → response decode → `tool_use` block extraction → `input` dict return) → `GraphRAG` phase-1 helper (dict → `InsightSkeleton` decode) → `InsightSession.phase1Skeleton` storage. Verify: schema validation produces correct `InsightSkeleton` for the happy-path sample, AND fallback (single prose section) triggers cleanly when the dict is malformed. Document any divergence between sample shape and `InsightSkeleton`/`InsightSection`/`DeepDiveTopic` `Codable` definitions.

   k. **Hand-trace ZIP staging dir construction.** Walk `InsightCache.archiveStagingDirectory()` step by step for a 3-node session (root + 2 children). Verify the produced staging dir contains: `index.html` (root, deep-dive `onclick`s rewritten to `window.location.href = "<uuid>.html"`, lib `<script src>` rewritten to `_assets/<lib>.js`); `nodes/<uuid>.html` for each child (deep-dive `onclick` rewritten to sibling `<uuid>.html` — NO `nodes/` prefix; breadcrumb hrefs rewritten to `../<root-uuid>.html` or sibling `<uuid>.html`; lib refs rewritten to `../_assets/<lib>.js`); `_assets/` with all 4 libs unconditionally; `manifest.json`. Every interpolated LLM string in the rewritten HTML goes through the escape utility (Decision 10). Flag any path rewriting that produces an absolute path, leaks a `blob:` URL into the export, or escapes the staging root.

   l. **Vendored libs MANIFEST integrity (T2 output).** Confirm `Resources/Editor/vendor/MANIFEST.txt` exists, has the documented pipe-delimited shape (`lib_name | version | sha256 | source_url | cve_check_date | cve_check_result`), one row per vendored asset including `chart-*.min.js`. Confirm `chart-4.4.x.min.js` is present and SHA-pinned in MANIFEST. (Auditor does not re-run `shasum`; that is QA's job. Auditor only confirms file presence and MANIFEST shape.)

4. Compile findings into the report. Section structure (see Details for full template):
   - Executive summary (1-3 sentences + verdict: PASS / PASS-WITH-FOLLOWUPS / FAIL).
   - Findings table grouped by severity (`blocker`, `major`, `minor`, `nit`).
   - Per-dimension subsection (a-l above) with file:line citations and concrete fix recommendations.
   - Hand-trace appendix (j and k) — show the actual trace step-by-step.
   - Followups list (issues that don't block but should be filed).

5. Write report to `work/recursive-insight/logs/audit/code-audit.md`. Verdict drives downstream T10/T11/T12: `FAIL` blocks the Final Wave; `PASS-WITH-FOLLOWUPS` allows progress with the followups appended to `tasks/todo.md`.

**Edge cases:**
- A file from Tasks 1-8 may legitimately be empty (e.g. if T8 chose to leave `EditorView.swift` delegate stubs as no-op for some hooks). Auditor must distinguish "intentional no-op with comment" from "missing implementation".
- `Resources/Editor/vendor/js/chart-4.4.x.min.js` is minified library code — NOT subject to code-quality review. Only confirm presence + version banner (`/*! Chart.js v4.4 */`).
- `Tests/Fixtures/insight-skeleton-sample.json` may not yet exist if T1 deferred its creation to T4. Note this in the hand-trace section if absent and downgrade dimension (j) verdict to "deferred".
- The auditor must NOT modify any source file. The audit is read-only. Findings are SUGGESTED fixes; implementation belongs to a follow-up task or the original task author.

**Implementation hints:**
- Read files in this order to build mental model: AIProviderClient.swift → InsightCache.swift → GraphRAG.swift → InsightSession.swift → WebViewBridge.swift → EditorView.swift → WorkspaceManager.swift → InsightArchiveExporter.swift → Resources/Editor/index.html. JSON sample + MANIFEST last.
- For the `[weak self]` audit, an effective grep is `rg -n 'Task\s*\{|\.sink\s*\{|withThrowingTaskGroup|addTask|terminationHandler|onDelta:' MarkView/`. Then for each hit, inspect the closure's capture list.
- For the postMessage allowlist audit, grep `Resources/Editor/index.html` for `addEventListener.*message` and `postMessage` and enumerate the type strings.
- For the frameInfo audit, grep `WebViewBridge.swift` for `userContentController.*didReceive` (the WKScriptMessageHandler entry point) — count handlers, verify each opens with the guard.
- Severity calibration: a missing `[weak self]` on a Task that lives for the full session = `blocker`. A missing `[weak self]` on a closure that completes synchronously inside a function body = not a finding. A typo in a log message = `nit`.
- Keep the report under 1500 lines. If the findings list grows beyond that, the audit has gone too deep — re-scope.
