## Description

Этот таск вводит **первый streaming code path в кодовой базе** MarkView. Сейчас весь код общения с Anthropic API в `AIProviderClient.swift` использует `URLSession.shared.data(for:)` — одношаговые запросы, которые ждут полное тело ответа. Для фичи Recursive Insight (а конкретно для прогрессивного отображения LLM-сгенерированных summary в новой вкладке) нужен SSE-стрим.

Что добавляется:
1. Новый метод `streamCompletion(systemPrompt:userMessage:model:maxTokens:onDelta:)` использует `URLSession.shared.bytes(for:)` против Anthropic Messages API c `"stream": true`. Парсит SSE-формат: события `content_block_delta` (текст дельты для `onDelta`-колбэка), `message_stop` (нормальное завершение), `error` (бросает `streamingError`). Игнорирует keepalive-лайны: `event: ping`, `event: message_delta`, и SSE-комментарии (`: ...`).
2. Новый кейс `case streamingError(String)` в `AIProviderError`. Используется для:
   - превышения 64 KB на одну SSE-линию (DoS-кап из Decision 10 §7),
   - событий `event: error` от Anthropic (с очищенным от ключа сообщением),
   - parse-ошибок SSE-фрейма, где `parseError` семантически не подходит (поток, а не один JSON).
3. Fixture `Tests/Fixtures/sse-anthropic-sample.txt` — реальный captured SSE-ответ. Используется в Audit Wave для hand-trace проверки парсера, и в будущем (когда test target появится — см. Decision 9) станет golden input.

Никакая часть строки API-ключа не должна попадать ни в одно бросаемое сообщение об ошибке, ни в `NSLog`, ни в значение, прокидываемое через `onDelta`. Это инвариант для всех веток (HTTP-ошибка, parse-ошибка, line-too-long, error-event).

Изменение **аддитивное** — существующие методы (`extractBlockSemantics`, `extractSingleChunk`, `generateMermaidDiagrams`, `generateArchitecture`) остаются нетронутыми. Реюзим существующие `apiKey`, `baseURL`, `session`, `model` константы и идентичный набор HTTP-заголовков (`Content-Type: application/json`, `x-api-key: <key>`, `anthropic-version: 2023-06-01`).

## What to do

2. **Добавить метод `streamCompletion(...)`** в класс `AIProviderClient` рядом с существующим `extractSingleChunk` (примерно после L177) со следующей сигнатурой:
   - `func streamCompletion(systemPrompt: String, userMessage: String, model: String = "claude-sonnet-4-6", maxTokens: Int = 8192, onDelta: @escaping (String) -> Void) async throws`
   - Реализация:
     - Guard на `apiKey`: если nil/пусто — бросить `AIProviderError.noAPIKey`.
     - Собрать body-словарь: `model`, `max_tokens`, `system`, `messages: [{role:user, content:userMessage}]`, `stream: true`.
     - Сконструировать `URLRequest` с теми же заголовками, что и `extractSingleChunk` (L136-141). `timeoutInterval` = 600 (стримы могут идти долго).
     - `let (bytes, response) = try await session.bytes(for: request)`.
     - HTTP guard: если status != 200 — собрать тело ответа итерацией по `bytes` с лимитом ~16 KB и бросить `AIProviderError.httpError(status, body)`. Тело при этом не должно содержать ключ (Anthropic в ошибках его не возвращает, но на всякий случай sanitize-функция).
     - SSE-парсинг: цикл `for try await line in bytes.lines`. Для каждой линии:
       - Проверить размер: если `line.utf8.count > 65536` (64 KB) — бросить `AIProviderError.streamingError("SSE line exceeds 64 KB cap")`.
       - Cooperative cancellation: проверять `try Task.checkCancellation()` перед обработкой каждой линии, чтобы `cancel()` от `InsightSession` останавливал поток в течение 1 секунды.
       - Игнорировать пустые строки и SSE-комментарии (начинаются с `:` — keepalive `: ping`).
       - Распарсить SSE-структуру: линии вида `event: <name>` запоминают текущее имя события; линии вида `data: <json>` — payload текущего события.
       - На завершении блока (пустая линия после `data:`) — обработать пару (event, data):
         - `content_block_delta`: распарсить JSON, извлечь `delta.text` (если `delta.type == "text_delta"`), вызвать `onDelta(text)`. Никогда не падать на отсутствие поля — пропускать с warning в NSLog.
         - `message_stop`: завершить цикл нормально (return).
         - `error`: распарсить `error.message`, бросить `AIProviderError.streamingError(sanitize(message))`.
         - `ping`, `message_delta`, `message_start`, `content_block_start`, `content_block_stop` — игнорировать молча.
         - Любое другое имя события — игнорировать молча (forward compat).
     - Если поток закончился без `message_stop` — вернуть нормально (cancellation от Task или EOF — оба валидны для caller).

3. **Sanitize-helper** для error messages: гарантировать, что `apiKey` (если установлен) не появляется в строке. Реализовать как небольшую приватную функцию `private func sanitize(_ msg: String) -> String`, которая делает `replacingOccurrences(of: apiKey ?? "", with: "[REDACTED]")` если ключ непустой.

4. **Создать fixture-файл** `Tests/Fixtures/sse-anthropic-sample.txt` — в нём captured реальный SSE-ответ от Anthropic, полученный через verify-smoke `curl`-команду. Файл должен содержать достаточно много `content_block_delta` событий (несколько TCP-чанков, разные length дельт), а также один `message_start`, серия `content_block_start`/`stop`, `message_delta`, и финальный `message_stop`. Это lock golden input для будущих тестов и для hand-trace в Audit Wave.

**Edge cases:**
- **Multi-line `data:` блок** — Anthropic SSE присылает `data:` одной строкой на событие, но SSE-спек допускает многострочный data. Безопасный путь: накапливать `data:` строки между пустыми разделителями, объединять через `\n`. Если накопленный JSON не парсится — логировать через NSLog (без apiKey!) и пропустить (forward compat).
- **Линия ровно 64 KB** — граница inclusive vs exclusive. Использовать `> 65536`, не `>=`, чтобы 64 KB ровно не падало.
- **`event:` без последующего `data:`** — SSE-спек разрешает, у Anthropic может прилетать `: keepalive` или `event: ping\n\n` без data. Реализация: если на пустой строке `data` пуст — просто сбросить state и идти дальше.
- **HTTP 401/403 с body содержащим маскированный ключ** — Anthropic в ответах ключ не возвращает (только маску типа `sk-ant-***`), но всё равно прогонять body через sanitize.
- **Cancellation посреди data-блока** — `Task.checkCancellation()` перед обработкой следующей линии, чтобы не вызывать `onDelta` после отмены.
- **`onDelta` бросает** — `onDelta` сейчас non-throwing, но если caller внутри захочет упасть — пусть упадёт сквозь, наш цикл это пропустит и URLSession bytes-iterator закроет соединение через ARC. Document это поведение комментарием.
- **Длинный keepalive-период** — таймаут 600 секунд достаточен (стрим обычно завершается за < 60s), но если Anthropic держит долгое соединение без данных — будет TimeoutError, нормально пробрасываем как `URLError` через `try await`.

**Implementation hints:**
- `URLSession.shared.bytes(for: request)` возвращает `(URLSession.AsyncBytes, URLResponse)`. У `AsyncBytes` есть `.lines` property — `AsyncSequence<String>` где каждый элемент это line без `\n`. Это и есть SSE line-by-line ровно как нам надо.
- Для проверки размера линии до её обработки: `line.utf8.count > 65536` — `String` индекс не используем, raw byte count.
- Для накопления body при HTTP-ошибке: итерировать `bytes` отдельно (не `bytes.lines`), копить в `Data` до 16 KB, decode как UTF-8, lossy. Альтернатива — drop bytes-iterator и сделать второй `data(for:)` запрос, но это лишний RTT.
- `JSONSerialization.jsonObject(with:)` принимает `Data` — `data: <json>` строку взять `.dropFirst("data: ".count)`, конвертировать `.data(using: .utf8)`.
- API key sanitization: `private func sanitize(_ s: String) -> String { guard let k = apiKey, !k.isEmpty else { return s }; return s.replacingOccurrences(of: k, with: "[REDACTED]") }` — применять ко ВСЕМ местам где строка попадает в throw или NSLog.
- Sample SSE event для документации в комментарии:
  ```
  event: content_block_delta
  data: {"type":"content_block_delta","index":0,"delta":{"type":"text_delta","text":"Hello"}}
  ```
- Per Decision 11 §1: внутри `streamCompletion` сам метод не требует `[weak self]` (это плоская функция, не хранит замыкание). Но caller (`InsightSession`) должен передавать `onDelta` с `[weak self]` — это его забота, не нашего метода. Этого требования здесь не реализуем.
