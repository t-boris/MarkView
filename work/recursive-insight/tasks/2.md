# Task 2: Vendor Chart.js 4.x + libs MANIFEST

## Required Skills

Перед выполнением задачи загрузи:
- `/skill:code-writing` — [skills/code-writing/SKILL.md](~/.claude/skills/code-writing/SKILL.md)

## Description

Recursive-insight v2 renders LLM-generated insight skeletons inside a sandboxed iframe. Section types include `chartJsChart` — for which Chart.js must be available. The project already vendors Mermaid, KaTeX, and Prism under `MarkView/Resources/Editor/vendor/` (see Decision 5 — "Pre-bundled libs via blob URLs"); Chart.js is the one missing piece needed before Wave 2 (T4/T5) can lazy-materialize blob URLs for it.

This task adds Chart.js 4.4.x as a vendored asset and creates a `MANIFEST.txt` that records version + SHA-256 + source URL + CVE-check date/result for every vendored library (Mermaid, Chart.js, KaTeX, Prism). The manifest is the single source of truth for supply-chain integrity — Pre-deploy QA (Task 12) and the runtime smoke check both compare on-disk SHA against the manifest entry.

The Xcode project copies the entire `MarkView/Resources/Editor/vendor/` directory into the app bundle via the existing "Build Web Editor (optional)" Run Script build phase (`MarkView.xcodeproj/project.pbxproj` line 346 — uses `/usr/bin/ditto vendor → ${DEST}/vendor`). New files dropped into `vendor/js/` are therefore picked up automatically; no PBXBuildFile registration is required for the JS file. However, `MANIFEST.txt` is also under `vendor/` and will likewise be copied into the bundle by the same ditto step — this is intentional and harmless (it documents what shipped).

## What to do

1. Download Chart.js 4.4.x UMD minified build from the canonical jsDelivr URL and place it at `MarkView/Resources/Editor/vendor/js/chart-4.4.x.min.js`. Pin a specific patch version (do not use `@4.4` floating tag in the saved filename — name the file with the exact version downloaded, e.g. `chart-4.4.7.min.js`, and use that exact name in MANIFEST.txt and any subsequent loader code).
2. Compute SHA-256 of the downloaded file using `shasum -a 256`.
3. Compute SHA-256 of the existing vendored libs that v2 will deliver via blob URLs: `mermaid.min.js`, `katex.min.js`, `auto-render.min.js`, `prism.min.js` (plus all `prism-*.min.js` language plugins that ship), and the CSS files (`katex.min.css`, `prism-okaidia.min.css`, `prism-line-numbers.css`, `prism-diff-highlight.css`).
4. Identify the upstream version of each existing vendored lib (read first lines of the file — most contain `/*! mermaid v…` / `/*! KaTeX v… */` / `/* PrismJS …` headers).
5. Perform a one-time CVE / security advisory check for each lib version (GitHub Security Advisories or `npm audit` against a temp `package.json` listing the four packages at the pinned versions). Record the date of the check and the result (e.g. `clean` / `<list of CVEs>`).
6. Create `MarkView/Resources/Editor/vendor/MANIFEST.txt` with one row per vendored asset, in the pipe-delimited format declared in the tech-spec.
7. Verify the final manifest entry for Chart.js by running `shasum -a 256 MarkView/Resources/Editor/vendor/js/chart-*.min.js` and confirming the value matches the row for Chart.js in MANIFEST.txt.
8. Confirm the Xcode build script picks up both new files: inspect `MarkView.xcodeproj/project.pbxproj` around line 329 ("Build Web Editor (optional)" PBXShellScriptBuildPhase). If the existing ditto-copy step already covers the whole `vendor/` directory (it does — see line 346), no pbxproj edit is needed; document that in the implementation report. Only edit `project.pbxproj` if a `MANIFEST.txt`-shaped exclusion or a per-file PBXBuildFile is required (it should not be — but verify by performing a clean build and listing `${TARGET_BUILD_DIR}/MarkView.app/Contents/Resources/Editor/vendor/` to confirm both `chart-*.min.js` and `MANIFEST.txt` are present in the built bundle).
9. Do NOT modify `MarkView/Resources/Editor/index.html` — Chart.js is loaded lazily as a blob URL by Wave 2 (Task 5), not via a `<script src="vendor/js/chart-...">` tag.

## Verification Steps

### Smoke

Run from project root after the file is downloaded and MANIFEST is written:

```bash
# 1. Confirm Chart.js file exists and matches MANIFEST
shasum -a 256 MarkView/Resources/Editor/vendor/js/chart-*.min.js
grep '^chart\.js' MarkView/Resources/Editor/vendor/MANIFEST.txt
# → SHA value from shasum must equal the sha256 field in the chart.js manifest row

# 2. Confirm every other vendored lib SHA in MANIFEST matches on-disk file
while IFS='|' read -r name version sha url date result; do
  name_trim=$(echo "$name" | xargs)
  sha_trim=$(echo "$sha" | xargs)
  echo "Verifying $name_trim → expected $sha_trim"
done < MarkView/Resources/Editor/vendor/MANIFEST.txt

# 3. Build clean and confirm artifacts ship inside the bundle
xcodebuild -project MarkView.xcodeproj -scheme MarkView -configuration Debug build
find ~/Library/Developer/Xcode/DerivedData -name "MarkView.app" -path "*/Debug/*" -print -quit \
  | xargs -I {} ls "{}/Contents/Resources/Editor/vendor/js/" \
  | grep chart
find ~/Library/Developer/Xcode/DerivedData -name "MarkView.app" -path "*/Debug/*" -print -quit \
  | xargs -I {} ls "{}/Contents/Resources/Editor/vendor/" \
  | grep MANIFEST
```

Expected: shasum value of `chart-*.min.js` exactly matches the sha256 column in MANIFEST's chart.js row; build succeeds with 0 errors; both `chart-*.min.js` and `MANIFEST.txt` are present in the built `MarkView.app` bundle under `Contents/Resources/Editor/vendor/`.

## Details

**Files:**
- `MarkView/Resources/Editor/vendor/js/chart-4.4.x.min.js` — new file. Download with `curl -L -o MarkView/Resources/Editor/vendor/js/chart-4.4.7.min.js https://cdn.jsdelivr.net/npm/chart.js@4.4.7/dist/chart.umd.min.js` (substitute the actual latest 4.4.x patch). Use `-L` to follow jsDelivr redirects. Verify the downloaded file size is non-zero and the first bytes contain a Chart.js banner comment (`/*! Chart.js v4.4 …`).
- `MarkView/Resources/Editor/vendor/MANIFEST.txt` — new plain-text file, pipe-delimited, one row per vendored asset. Use the format declared in the tech-spec critical context: `lib_name | version | sha256 | source_url | cve_check_date | cve_check_result`. Include a header row commented with `#`. Example shape (real values to be filled by implementer):

  ```
  # MarkView vendored web assets — supply-chain integrity manifest
  # Format: lib_name | version | sha256 | source_url | cve_check_date | cve_check_result
  chart.js          | 4.4.7  | <sha256> | https://cdn.jsdelivr.net/npm/chart.js@4.4.7/dist/chart.umd.min.js | 2026-04-30 | clean
  mermaid           | <ver>  | <sha256> | <upstream url> | 2026-04-30 | <result>
  katex             | <ver>  | <sha256> | <upstream url> | 2026-04-30 | <result>
  katex-auto-render | <ver>  | <sha256> | <upstream url> | 2026-04-30 | <result>
  prism             | <ver>  | <sha256> | <upstream url> | 2026-04-30 | <result>
  ...
  ```
  List every file currently in `vendor/js/` and `vendor/css/` that is part of the four pinned upstreams (mermaid, KaTeX, Prism + plugins, Chart.js). Files not part of these upstreams (markdown-it family, js-yaml) — list them too with their respective upstream + version + SHA, since they are also vendored and the manifest is the inventory.
- `MarkView.xcodeproj/project.pbxproj` — likely no edit required (existing `Build Web Editor (optional)` script at line 329-347 ditto-copies whole `vendor/` directory). Only edit if the build verification step shows `chart-*.min.js` or `MANIFEST.txt` missing from the built bundle.

**Dependencies:**
- None on other tasks (Wave 1 task).
- External: requires `curl`, `shasum` (both default on macOS). CVE check requires either internet access to GitHub Advisory DB or `npm` (system Node.js installation).

**Edge cases:**
- jsDelivr may redirect — must use `curl -L`.
- jsDelivr serves both UMD and ESM builds. Wave 2 (Task 5) will load the file via `<script src="blob:...">` in the iframe — needs UMD build (`chart.umd.min.js`), not ESM (`chart.min.js` in ESM tree).
- Pinning to `@4.4` floating tag in the source URL recorded in MANIFEST is acceptable (documents the channel) but the saved filename and SHA must reflect the actual patch version downloaded — otherwise SHA verification on a re-download could mismatch silently.
- Some Prism language plugins are tiny (a few KB). All of them must be hashed and listed individually in MANIFEST; do not use a wildcard.
- KaTeX ships webfonts under `vendor/css/fonts/`. These are referenced by `katex.min.css` via relative URL. They must also be listed in MANIFEST (each `.woff2` SHA) since they will eventually be base64-inlined or copied per Decision 5 caveat.
- If `npm audit` is unavailable, fall back to manual GitHub Security Advisories search for each `<package>@<version>` — record the URL of the advisory page consulted in cve_check_result column or in a comment block at the top of MANIFEST.

**Implementation hints:**
- Use one curl invocation per file. After download, `shasum -a 256 <file>` once and paste the hash into MANIFEST.
- For existing libs already in `vendor/js/`, just run `shasum -a 256` over the directory and version-detect by reading the first line of each file (`head -1`).
- Format MANIFEST with column padding for readability — but keep `|` as the delimiter for parseability.
- Commit the downloaded `chart-*.min.js` to git (it's a vendored dependency, like the other libs already in `vendor/js/`).
- If the existing ditto build script handles the new files automatically (which it should), call this out explicitly in the `decisions.md` post-completion report — Task 12 (Pre-deploy QA) reviewer needs to know that pbxproj diff is empty by design.
