## Description

Подготовить две структурные основы для feature Recursive Insight:

1. **`TabKind` enum в `DocumentState.swift`** — добавить новый тип `enum TabKind { case file; case insight(InsightSession) }` и поле `var kind: TabKind = .file` в `OpenTab`. Дефолтное значение `.file` сохраняет source-compat для всех ~12 существующих call-sites (`tab.url`, `tab.content`, `tab.isModified`, `tab.headings`, и т.д.) — никаких массовых правок не требуется. Только три места (EditorView, closeTab в WorkspaceManager, TabBarView) позже будут ветвиться по `kind`.

2. **`scanMarkdownFiles(in:)` helper и `hasMarkdownFiles` computed property в `WorkspaceManager.swift`** — извлечь дублирующийся паттерн `FileManager.enumerator(at:options: [.skipsHiddenFiles])` + фильтр по `pathExtension == "md"` + исключение `.dde`, который сейчас встречается в трёх местах: `excludeFolder` (L553), `extractWithOllama` (L930), `analyzeAllFiles` (L1564). Helper дополнительно реализует resource caps и security checks из tech-spec Decision 10 §7.

**Важное замечание про forward dependency:** `TabKind.insight(InsightSession)` ссылается на класс `InsightSession`, который будет создан только в Task 4 (Wave 2). Чтобы Wave 1 проект собирался независимо, эта задача должна включить **placeholder declaration**:

```swift
// Replaced by full implementation in Task 4
@MainActor
final class InsightSession: ObservableObject, Identifiable {
    let id = UUID()
}
```

Placeholder помещается в новый файл `MarkView/Models/InsightSession.swift` (минимальный stub) или в `DocumentState.swift` рядом с enum (выбор за реализующим — главное чтобы компилировалось и Task 4 мог расширить класс без переименования). Предпочтительный вариант — отдельный файл `InsightSession.swift` со stub-классом, чтобы Task 4 заменил его содержимое целиком, не трогая `DocumentState.swift`.

**Контекст feature.** Recursive Insight — новый tab-mode, который анализирует папку `.md` файлов через LLM и показывает дерево summary. Эта задача — структурная подготовка модели данных (поле `kind` в табе) и базовая утилита сканирования папки (которая будет использоваться `startRecursiveInsight()` в Task 7 и для `disabled`-state кнопки меню в Task 8).

## What to do

Класс должен быть `@MainActor`, `final`, наследовать `ObservableObject` и `Identifiable`, содержать `let id = UUID()`. Добавить комментарий `// Full implementation in Task 4 (Wave 2). 2. **`MarkView/Models/DocumentState.swift`** — после существующего `OpenTab` (или перед ним — на усмотрение, но в том же файле) добавить:
   ```swift

       case insight(InsightSession)
   }
   ```
   В `OpenTab` (L42-71) добавить поле `var kind: TabKind = .file` — место добавления: после `var isModified: Bool = false` (L47), чтобы соблюсти логическую группировку базовых meta-полей. **Дефолтное значение обязательно** — сохраняет source-compat для всех существующих инициализаторов `OpenTab(url:content:originalContent:)`.

3. **`MarkView/Models/WorkspaceManager.swift`** — добавить новый private/internal метод-хелпер и computed property. Расположение: рядом с другими file-scanning utilities; разумное место — перед `excludeFolder` (L547) или сразу после блока MARK: - Folder Exclusion. Сигнатуры:
   ```swift
   /// Scan a folder for .md files with security and resource caps.
   /// Returns Result with error if folder exceeds 500-file cap.
   /// Skips: hidden files, .dde paths, symlinks resolving outside folderURL.
   /// Truncation happens at read-time by callers, not here — this only enumerates URLs.
   func scanMarkdownFiles(in folderURL: URL) -> Result<[URL], ScanError>

   /// Quick check for menu disabled-state. Returns true if rootNode contains any .md file.
   /// Bounded scan — short-circuits on first match, does not enforce 500-cap.
   var hasMarkdownFiles: Bool
   ```
   Также добавить error type:
   ```swift
   enum ScanError: Error, LocalizedError {
       case folderTooLarge(count: Int, limit: Int)  // > 500 files
       var errorDescription: String? { ... }
   }
   ```

4. **Реализовать в `scanMarkdownFiles(in:)` все правила tech-spec Decision 10 §7 и Decision 5:**
   - Использовать `FileManager.enumerator(at:includingPropertiesForKeys:[.isSymbolicLinkKey], options:[.skipsHiddenFiles, .skipsPackageDescendants])`. **NB:** `.skipsPackageDescendants` — новая опция по сравнению с тремя существующими call-sites; добавляется специально для insight feature, чтобы не заглядывать внутрь `.app`/`.bundle`/`.docset`.
   - Фильтр: `pathExtension.lowercased() == "md"` AND `!url.path.contains(".dde")`.
   - **Symlink containment check:** для каждого URL (даже не-symlink) проверить, что `url.resolvingSymlinksInPath().standardizedFileURL.path` начинается с `folderURL.resolvingSymlinksInPath().standardizedFileURL.path`. Если нет — пропустить файл (логировать через `NSLog("[Insight] Skipped symlink escape: \(url.path)")`). Порядок: `resolvingSymlinksInPath()` СНАЧАЛА, затем `standardizedFileURL` — потому что `standardizedFileURL` сам по себе не следует символическим ссылкам (явно прописано в Decision 10 §6).
   - **500-file cap:** считать matched files в цикле; если счётчик превысил 500, прервать enumeration и вернуть `.failure(.folderTooLarge(count: <found-so-far>, limit: 500))`. Можно либо продолжить считать до конца для точного `count`, либо остановиться сразу — выбор за реализующим (важна сама ошибка). Предпочтительно — остановиться сразу для DoS-устойчивости.

5. **`hasMarkdownFiles` computed property:**
   - Возвращает `false` если `rootNode == nil`.
   - Иначе делает bounded scan: тот же enumerator с теми же фильтрами и symlink-check, но **возвращает `true` на первом найденном `.md`-файле** (без прохода по всей иерархии). Это критично для отзывчивости меню.
   - 500-cap здесь НЕ применяется (т.к. мы выходим на первом match).

6. **Вызывающие сайты НЕ менять в этой задаче.** Существующие три enumerator-блока (excludeFolder, extractWithOllama, analyzeAllFiles) специально оставляются как есть — их рефакторинг под новый helper выходит за scope этой задачи (другие call-sites имеют свои локальные различия: extractWithOllama читает content > 50, analyzeAllFiles собирает в `[URL]` без cap'ов, excludeFolder параллельно делает DB clear). Helper создаётся для нового кода (Task 7 `startRecursiveInsight`, Task 8 menu disabled-state).

**Edge cases:**
- Пустая папка → `.success([])` (валидно, не ошибка).
- Папка с ровно 500 `.md` файлами → `.success` (cap exclusive: > 500 fails, == 500 passes).
- Folder URL — symlink сам по себе → разрешается, потому что мы делаем `folderURL.resolvingSymlinksInPath()` для baseline containment check.
- `.dde` подпапка содержит `.md` файлы → пропускаются через `!url.path.contains(".dde")` фильтр (matches существующее поведение в L934).
- Hidden `.md` файл (например `.notes.md`) → пропускается через `.skipsHiddenFiles` enumerator option.
- Symlink на файл ВНЕ folderURL → пропускается (containment check fails).
- Symlink на файл ВНУТРИ folderURL (валидная reference) → принимается (containment check passes).
- `.app` bundle с `.md` внутри → пропускается через `.skipsPackageDescendants`.
- Файл размером 100 KB → попадает в результат как URL; truncation до 50 KB происходит у потребителей (Task 4 InsightSession.generateRoot читает body и обрезает) — НЕ в этом helper'е.
- `rootNode == nil` для `hasMarkdownFiles` → `false`, без обращения к FileManager.

**Implementation hints:**

- **Symlink containment** — точная проверка из Decision 10 §6:
  ```
  let resolvedFolder = folderURL.resolvingSymlinksInPath().standardizedFileURL.path
  let resolvedFile = url.resolvingSymlinksInPath().standardizedFileURL.path
  guard resolvedFile.hasPrefix(resolvedFolder) else { /* skip + log */ continue }
  ```
  Порядок `resolvingSymlinksInPath()` → `.standardizedFileURL` ОБЯЗАТЕЛЕН. Inverted порядок не следует symlinks — symlink внутри папки, указывающий наружу, прошёл бы containment check ошибочно.

- **`hasMarkdownFiles` early exit** — простой паттерн:
  ```
  while let url = enumerator.nextObject() as? URL {
      // same filters + symlink check
      return true   // first match
  }
  return false
  ```

- **ScanError errorDescription** — должен быть user-friendly для будущей передачи через UI (Task 7 startRecursiveInsight покажет alert при ошибке):
  ```
  case .folderTooLarge(let count, let limit):
      return "Folder too large for Recursive Insight: found \(count)+ markdown files (limit \(limit)). Try a subfolder instead."
  ```
  (Текст dovетает рекомендации tech-spec из Decision 5: "folder too large for Recursive Insight; use a subfolder".)

- **Не использовать `try?` для `String(contentsOf:)`** — этот helper ТОЛЬКО enumerates URLs, не читает контент. Чтение и truncation файлов — ответственность вызывающей стороны (Task 4 InsightSession).

- **Логирование** — стиль `NSLog("[Insight] Skipped symlink escape: \(url.path)")` следует существующему паттерну `NSLog("[DDE] Excluded folder: ...")` в этом же файле (L572).

- **Stub `InsightSession`** — `@MainActor` нужен потому что в Task 4 класс будет иметь `@Published` properties и методы, вызываемые из UI; если не пометить сейчас, Task 4 либо изменит сигнатуру (что заставит другие места перепроверять), либо столкнётся с actor-isolation warnings. Лучше зафиксировать `@MainActor` сразу.
