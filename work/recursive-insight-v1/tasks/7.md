## Description

Wire the Recursive Insight feature into `WorkspaceManager` — the central state holder that owns the tab store, the AI provider singleton, and the `GraphRAG` instance. This task connects the foundations from earlier waves (folder scan helper from Task 2, `InsightSession` from Task 4, `WebViewBridgeDelegate` extensions from Task 6) into a usable end-to-end flow:

1. A new `startRecursiveInsight()` entry point that the AI Tools menu (Task 8) will call.
2. A close-tab branch that cleanly tears down an in-flight stream before the tab disappears, satisfying the cancellation race prescription in Decision 11 §4.
3. Implementations of the five new `WebViewBridgeDelegate` insight callbacks (deep-dive click, save, breadcrumb, up, retry) that route bridge messages by `sessionId` to the right `InsightSession` instance and forward the appropriate method call.
4. A Save handler that produces a clean standalone `.md` file via `NSSavePanel` — sanitized filename derived from the current node title, forced `.md` extension, body content stripped of the `---DEEP-DIVES---` marker section and breadcrumb chrome (per Decision 10 §7).

The implementation must mirror the existing `translateDocument(...)` pattern (L1105-1191) for tab creation + progressive content updates, reuse the `incrementalCompiler.orchestrator.providerClient` singleton (L504, L684) rather than instantiating a fresh `AIProviderClient`, and pass the existing `self.graphRAG` instance into the new `InsightSession` so the >30-file map-reduce path can use it.

## What to do

1. Add a public `startRecursiveInsight()` method on `WorkspaceManager`:
   - Read `rootNode?.url`. If nil, present an `NSAlert` saying a folder must be open and return.
   - Resolve the `AIProviderClient` via `incrementalCompiler?.orchestrator.providerClient`. If nil (no API key / engines not initialized), present `NSAlert` and return.
   - Call `scanMarkdownFiles(in: folderURL)` (helper from Task 2). If the array is empty, present `NSAlert("No markdown files in this folder")` and return.
   - If `mdFiles.count > 500`, present `NSAlert("Folder too large for Recursive Insight (\(count) files, max 500). Use a subfolder.")` and return — do not create a session.
   - Construct `InsightSession(folderURL:, mdFiles:, providerClient:, graphRAG: self.graphRAG)`.
   - Build a placeholder URL: `folderURL.appendingPathComponent(".insight-\(session.id.uuidString)")`. This URL is never written to disk; it exists so `OpenTab.url` and `displayName` keep working for non-insight code paths.
   - Construct an `OpenTab(url: placeholderURL, content: "", originalContent: "", kind: .insight(session))`.
   - Append via `tabsStore.appendTab(tab)`.
   - Resolve sessions by scanning `openTabs` for `case .insight(let s) where s.id == sessionId`. Do **not** add a separate `@Published var activeInsightSession` field — the scan is O(N≤20) and avoids a duplicate-state invariant (which session is "active" if user closes the active tab?).
   - Spawn `Task { await session.generateRoot() }`. Do not `await` it from `startRecursiveInsight` — return immediately so the UI stays responsive.

2. Modify `closeTab(at index: Int)` (L984-1005):
   - Before any other branch (and before the `isModified` save-prompt), check if `openTabs[index].kind` is `.insight(let session)`.
   - If yes: call `session.cancel()` **synchronously** first (per Decision 11 §4 — the in-flight `Task` running the SSE stream must observe `Task.isCancelled` before the `OpenTab` is removed and the session would otherwise drop its strong reference). Then call `tabsStore.removeTab(at: index)` and `return`. Skip the dirty-save prompt entirely (insight tabs are ephemeral, never have `isModified == true` in the file-save sense).
   - The existing file-tab branch (`if openTabs[index].isModified { ... NSAlert ... }`) is left untouched for `.file` tabs.

3. Implement the five new `WebViewBridgeDelegate` insight methods (added by Task 6) on whichever object conforms to `WebViewBridgeDelegate` (existing conformance lives on `EditorView.Coordinator` per code-research §6 — verify after Task 6 lands). Each method receives a `sessionId: String` and resolves the session by:
   - Iterating `workspaceManager.openTabs`, matching `if case .insight(let s) = tab.kind, s.id.uuidString == sessionId { return s }`.
   - If no session found, `NSLog` a warning and return (the tab may have been closed mid-message).
   - Otherwise, dispatch:
     - `didRequestInsightDeepDive(sessionId:topicIndex:)` → `Task { await session.expand(deepDiveIndex: topicIndex) }`
     - `didRequestInsightSave(sessionId:)` → call a new `WorkspaceManager.saveInsightNode(session:)` helper (see step 4 below)
     - `didRequestInsightBreadcrumb(sessionId:nodeId:)` → `session.navigateTo(nodeId: nodeId)` (synchronous, no LLM call — repaints from in-memory cached node)
     - `didRequestInsightUp(sessionId:)` → `session.up()`
     - `didRequestInsightRetry(sessionId:)` → `Task { await session.retryCurrent() }`
   - Forwarding from `Coordinator` to `WorkspaceManager`: pass through the existing `workspaceManager` property already held by the Coordinator.

4. Implement `WorkspaceManager.saveInsightNode(session: InsightSession)`:
   - Resolve `session.currentNode()`. If nil, return silently.
   - Compute default filename: take `currentNode.title`, sanitize per Decision 10 §7 — replace any character that is NOT `[A-Za-z0-9_]` with `_`, collapse runs of `_`, trim leading/trailing `_`, and if the result is empty fall back to `"insight"`. Append `.md` extension always (force).
   - Open `NSSavePanel`:
     - `nameFieldStringValue = sanitizedName`
     - `allowedContentTypes = [UTType.text]` or equivalent for `.md` files (mirror what other save panels in the project use — check `saveFile(at:)` in `WorkspaceManager` for current convention).
     - `canCreateDirectories = true`
   - On `runModal() == .OK` and `panel.url != nil`:
     - Take `panel.url`. If its `pathExtension.lowercased() != "md"`, force `.md` by `panel.url!.deletingPathExtension().appendingPathExtension("md")`.
     - Read `currentNode.markdownBody` — this is the parsed body BEFORE the `---DEEP-DIVES---` marker (per `InsightNode` data model in tech-spec §"Data Models", `markdownBody` is already the body without the marker section).
     - The saved file MUST NOT include: the `---DEEP-DIVES---` marker, the deep-dives list, breadcrumbs, or any UI chrome. It IS the standalone summary text the user wants to keep.
     - Write to disk: `try markdownBody.write(to: finalURL, atomically: true, encoding: .utf8)`.
     - On error: `NSAlert` with the error message. Do not throw to the bridge.

5. Verify build cleanness: `xcodebuild -project MarkView.xcodeproj -scheme MarkView -configuration Debug build` must succeed with 0 errors. No new warnings in `WorkspaceManager.swift`.

**Edge cases:**

- User triggers Recursive Insight while no folder is open → graceful `NSAlert`, no crash.
- User triggers Recursive Insight on a folder with 0 `.md` files → `NSAlert`, no tab created.
- User triggers Recursive Insight on a folder with exactly 500 `.md` files → succeeds (boundary condition: `> 500` rejects, `<= 500` accepts).
- User triggers Recursive Insight on a folder with 501 `.md` files → rejected.
- API key not set in UserDefaults → `incrementalCompiler.orchestrator.providerClient.hasAPIKey == false`; the eventual stream call inside `InsightSession.generateRoot()` will fail and route through its own error handling (Decision 11 §3). `startRecursiveInsight` itself does not need to pre-check the key (defer to session error handling) UNLESS `incrementalCompiler` itself is nil (no folder initialized for AI features) — that case shows the alert.
- User closes insight tab while stream is still streaming first chunk → `cancel()` runs before `removeTab`; ARC frees session after both calls return.
- User clicks Save before the root summary finishes streaming → `currentNode.markdownBody` will be the partial body parsed so far. Save still works; the user gets whatever is currently rendered. Acceptable (matches user-spec ephemeral-tree philosophy).
- Bridge message arrives with `sessionId` not matching any open tab (race: tab closed mid-flight) → `NSLog` warning, return without throwing.
- User picks save filename containing path separators (`/`, `\\`) → `NSSavePanel` itself prevents this; no extra handling needed.
- User picks save filename with non-`.md` extension (`.txt`, no extension, `.markdown`) → forced `.md` via `deletingPathExtension().appendingPathExtension("md")`.
- Two insight tabs open simultaneously, user clicks deep-dive in tab 2 → bridge delegate routes by `sessionId`; tab 1's session is unaffected.

**Implementation hints:**

- Filename sanitization regex: `String(title.map { $0.isLetter || $0.isNumber ? $0 : "_" })` then collapse runs of `_` via a small loop or by splitting on `_` and joining filtered non-empty components, then trim leading/trailing `_`. Empty result → `"insight"`.
- For session lookup by `sessionId`, prefer iterating `openTabs` over a side `@Published` lookup map — fewer moving parts, only N tabs to scan.
- Mirror the call style of `translateDocument` for tab append + Task spawn; do NOT reuse its async/await loop body — `InsightSession.generateRoot()` is the equivalent driver here.
- `session.cancel()` must be `@MainActor`-callable synchronously (per `InsightSession` design in tech-spec). The `closeTab` call site is already on the main actor (UI), so direct call is fine.
- Do NOT add `@Published var activeInsightSession` if it is not strictly needed — the openTabs scan is O(N) where N <= ~20 in practice, and adding extra published state adds another invariant to maintain (which session is "active" if user closes the active tab?). Prefer the scan unless code review identifies a concrete need.
