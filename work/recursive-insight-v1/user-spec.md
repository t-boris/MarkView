# User Spec: Recursive Insight

## Что делаем

Интерактивный анализ папки с `.md`-документацией. MarkView читает все markdown-файлы в открытой папке, генерирует одностраничный summary с inline Mermaid-диаграммами, а справа показывает список «deep dive» подтем. Клик по подтеме рекурсивно генерирует следующий, более глубокий summary с собственным списком подтем — и так далее по запросу пользователя.

## Зачем

Пользователю нужен инструмент для изучения и анализа документации (в первую очередь софтверной, но в принципе любой). Подход — «сверху вниз»: общий обзор всей папки, затем углубление в интересующие части по требованию. Это ускоряет онбординг в незнакомую кодовую базу и помогает учиться на больших корпусах документации.

## Как должно работать

1. Пользователь открывает папку с `.md`-файлами в MarkView (стандартный flow).
2. Пользователь выбирает в меню `AI Tools → Analysis → 🧭 Recursive Insight`.
3. Открывается новая вкладка, в центральной панели начинает стримиться markdown-summary всей папки. По мере появления `mermaid`-блоков они рендерятся inline как обычные SVG-диаграммы.
4. После завершения streaming в правой панели появляется кликабельный список deep-dive подтем (3–7 штук), предложенных LLM на основе содержимого summary.
5. Пользователь кликает на подтему. Появляется новая «страница» того же типа: streaming summary этой подтемы + свой список deep-dive подтем справа.
6. Сверху каждой страницы — breadcrumbs: `Root > Auth > JWT`. Клик по любому breadcrumb-сегменту возвращает к уже сгенерированной странице того уровня (без повторного LLM-вызова, узел берётся из памяти сессии).
7. Снизу каждого узла — кнопки `[💾 Save as .md]` (открывает NSSavePanel, сохраняет текущий узел как обычный markdown-файл) и `[↑ Up]` (возврат на уровень вверх).
8. Закрытие вкладки уничтожает дерево insight-узлов. Сохранённые `.md`-файлы остаются на диске.

## Критерии приёмки

- [ ] В меню `AI Tools → Analysis` появился пункт `🧭 Recursive Insight`, активный когда открыта папка с хотя бы одним `.md`-файлом
- [ ] При нажатии открывается новая вкладка, в которой стримится summary всей папки, токен за токеном видный пользователю
- [ ] Inline `mermaid`-блоки в summary рендерятся как SVG-диаграммы (стандартный `mermaid.render`, без `%%INTERACTIVE`)
- [ ] После завершения streaming в правой панели отображается список из 3–7 кликабельных deep-dive топиков
- [ ] Клик по топику инициирует streaming нового узла со своим summary и своим списком топиков
- [ ] Breadcrumbs корректно отображают путь от root до текущего узла; клик возвращает к уже сгенерированному узлу из памяти без повторного LLM-вызова
- [ ] Кнопка `💾 Save as .md` открывает NSSavePanel и сохраняет markdown текущего узла (без deep-dive списка) в выбранный файл
- [ ] Кнопка `↑ Up` возвращает к родительскому узлу
- [ ] Если папка содержит >30 `.md`-файлов, для root-узла используется map-reduce: новый метод в `GraphRAG` кластеризует файлы и читает их тела; иначе — one-shot вызов со всем содержимым
- [ ] Для deep-dive узлов используется только подмножество файлов из `scope_hint` родителя плюс краткий контекст родительского summary
- [ ] При закрытии вкладки дерево insight-узлов полностью освобождается из памяти

## Ограничения

- **Источник данных:** только `.md`-файлы. PDF, JSON, XML, исходный код — не поддерживаются.
- **Хранение:** дерево insight-узлов живёт только в JS-памяти WKWebView, не сохраняется в SQLite, не восстанавливается между сессиями.
- **API:** только Anthropic Messages API (через существующий `AIProviderClient`). Ollama / Codex / Claude Code CLI не используются для этой фичи.
- **Триггер:** только ручной (пункт меню). Никакой автоматической генерации при открытии папки.
- **Глубина рекурсии:** не ограничена жёстким лимитом — определяется действиями пользователя. Каждый уровень требует отдельного клика.
- **Совместимость:** существующая функциональность (editor, AI Console, Git, Modules) не должна быть затронута.
- **Sandbox:** не должно требовать новых entitlements; работа в текущем режиме (sandbox off).

## Риски

- **Риск 1:** Streaming markdown с inline Mermaid требует частой re-renderизации, что может тормозить WebView. **Митигация:** дебаунс перерисовки markdown (раз в ~150ms), Mermaid-блоки рендерятся только после получения закрывающего `` ``` ``.
- **Риск 2:** LLM может вернуть невалидный Mermaid-код, ломая рендер. **Митигация:** обернуть `mermaid.render()` в try/catch, при ошибке показывать сырой код блока с пометкой об ошибке (как уже делается в существующем editor).
- **Риск 3:** Маркер `---DEEP-DIVES---` может случайно появиться в самом markdown-контенте. **Митигация:** использовать редкий маркер с явными границами (`\n\n---DEEP-DIVES---\n` с переводами строки), и парсить только последнее вхождение в потоке.
- **Риск 4:** Папка с очень большим количеством `.md` может превысить контекст модели даже при map-reduce. **Митигация:** GraphRAG уже фильтрует по communities; если суммарный размер > порога — сообщать пользователю и предлагать сузить scope.
- **Риск 5:** Anthropic SSE-streaming парсер раньше в проекте не использовался, можно неправильно обработать частичный JSON / разрывы соединения. **Митигация:** строго следовать формату Anthropic SSE (event: content_block_delta), unit-тесты на парсер с мок-потоками.

## Технические решения

- Мы решили использовать **только `.md`-файлы**, потому что это основной формат MarkView и не требует новых парсеров.
- Мы решили **lazy on-demand рекурсию** (никакой предгенерации), потому что глубина и направление анализа определяются пользователем; экономия токенов вторична, главное — управляемость.
- Мы решили **не персистить дерево** в SemanticDatabase, потому что каждый сеанс анализа уникален; для долговременного хранения есть `Save as .md`.
- Мы решили использовать **single streaming-вызов с разделителем `---DEEP-DIVES---`** вместо двух раздельных вызовов (markdown + topics), потому что это даёт live-feedback пользователю и экономит latency.
- Мы решили **рендерить Mermaid обычным SVG** (через существующий `mermaid.render`), без `%%INTERACTIVE` D3-canvas, потому что для insight-страницы важна скорость и компактность, а не интерактивность графа.
- Мы решили **расширить `GraphRAG`** новым методом `mapReduceForFolder(folderURL:question:onDelta:)`, который читает тела `.md`-файлов (а не только имена модулей, как существующий `deepResearch()`), и используем его для root-узла больших папок (>30 файлов). Существующая `detectCommunities()` переиспользуется как кластеризатор.
- Мы решили **не делать mini-map дерева**, потому что breadcrumbs дают достаточную навигацию, а mini-map усложнит UI без существенной пользы.
- Мы решили **новый tab kind `.insight`** в `WorkspaceManager`, потому что layout сильно отличается от editor (split-panel, breadcrumbs, deep-dive list) и не должен мешать обычному markdown-редактированию.

## Тестирование

**Unit-тесты:** не делаем в рамках этой фичи — в проекте нет `MarkViewTests` таргета (папка `Tests/` пустая, в `project.yml` нет тест-таргета). Создание тест-инфраструктуры выделено в отдельную follow-up задачу (см. `tasks/todo.md`).

**Интеграционные тесты:** не делаем — по той же причине.

**E2E тесты:** не делаем — по той же причине.

**Verification:** в этой фиче полагаемся на сборку (`xcodebuild build`) и ручную проверку пользователем. Когда после Recursive Insight будет добавлен `MarkViewTests` таргет, ретроспективно покроем тестами SSE-парсер, парсер маркера `---DEEP-DIVES---` и `InsightSession` lifecycle.

## Как проверить

### Агент проверяет

| Шаг | Инструмент | Ожидаемый результат |
|-----|-----------|-------------------|
| 1. Сборка проекта без ошибок и предупреждений | `xcodebuild -project MarkView.xcodeproj -scheme MarkView -configuration Debug build` | Build succeeded, 0 errors |
| 2. Smoke-вызов streaming endpoint Anthropic с тестовым промптом | `curl -N` с заголовками x-api-key и stream:true | SSE-поток приходит, есть события `content_block_delta` |

### Пользователь проверяет

- Открыть папку `TestFiles/` (или другую с `.md`) — запустить `AI Tools → Analysis → Recursive Insight` — убедиться, что summary стримится плавно, Mermaid-диаграммы появляются inline, deep-dive список рендерится справа
- Кликнуть на топик — убедиться, что новый узел открывается, breadcrumbs обновляются, всё streaming
- Кликнуть на breadcrumb root — убедиться, что возврат мгновенный (без LLM-вызова)
- Нажать `Save as .md`, выбрать путь — убедиться, что файл сохранён, открыт в обычном editor-режиме MarkView
- Закрыть вкладку, открыть Recursive Insight снова на той же папке — убедиться, что начинается с нуля (новое дерево)
- Проверить, что обычные `.md`-файлы продолжают открываться нормально (нет регрессий в editor)
