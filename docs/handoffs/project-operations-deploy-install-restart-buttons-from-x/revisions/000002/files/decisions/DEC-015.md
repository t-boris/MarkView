## Context

REQ-004 allows reading 'local folders outside the project root' without a prompt (DEC-003) but does not bound the scope. Project facts: existing agents are restricted to one readableFolder; everything read is sent to the AI provider without redaction (S14); ACP reads do not resolve symlinks (S10). An unbounded scope can include ~/.ssh, ~/.aws or .env files of other projects.

## Alternatives

1. A: Only paths explicitly referenced from the project's own files are followed
2. B: The parent folder of the project root and its direct children
3. C: Any path the agent chooses, with an exclusion list for credential locations
4. D: Any path with no restriction

## Decision

Option A with a deny list and limits. (1) A folder outside the project root may be read only if a file inside the project root references it by an absolute, home-relative (~) or relative (../) path; the application, not the AI, resolves the path, resolves symlinks, and grants read access to that folder. One level of transitive reference is allowed: a path referenced from a file in an already granted external folder. (2) Never readable, even when referenced: ~/.ssh, ~/.aws, ~/.gnupg, ~/.kube, ~/.docker, ~/.config/gcloud, ~/Library, keychain files, and files named .env, .env.*, *.pem, *.key, id_rsa*, id_ed25519*, .netrc, .npmrc; a referenced path that is the home directory itself or a filesystem root is rejected. The same file-name deny list applies inside the project root during discovery. (3) Limits per discovery run: at most 5 external folders, at most 200 files and 2 MB read in total from external folders. (4) Every granted folder and every rejected reference, with the reason, is listed in the provenance report (REQ-005). (5) Web search follows only after the referenced folders were examined. No permission prompt is shown, in line with DEC-003.

## Reason

The motivating case is an install procedure that lives in another project, which the project's own files point to; a referenced-path rule covers it and is testable ('given a Makefile referencing ../infra, discovery reads ../infra'). Sibling scanning and free choice send unrelated private data to the AI provider without the user being asked, which DEC-003 did not approve. Resolving and granting paths in the application keeps enforcement out of the prompt.

## Consequences

REQ-004 must be amended with the rule, the deny list and the limits. Procedures in unreferenced folders are not found automatically; the user adds such an operation by hand (REQ-006) or adds a reference to the project's files. The assistant integration must support several readable folders or several sequential runs, because the current request accepts a single readableFolder; this is implementation work to be estimated. Whether ACP and Codex assistants can enforce the deny list was not verified and must be checked; an assistant that cannot enforce it runs discovery without external folders.
