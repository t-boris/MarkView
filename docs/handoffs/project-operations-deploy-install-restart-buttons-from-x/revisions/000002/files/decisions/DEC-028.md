## Context

F-017: five overview acceptance criteria are not covered by REQ-001..REQ-013. Project fact: the existing non-interactive runner has a 60 s default timeout. Three of the criteria are already settled by proposed decisions but have no requirement: manual re-discover (DEC-016), low-confidence marking (DEC-023), empty-state explanation (DEC-024). One criterion, refresh of operations when source files change, conflicts with DEC-016, which states that discovery never starts automatically.

## Alternatives

1. A. Add requirements for all five criteria as written in the overview, including automatic re-discovery when source files change.
2. B. Add requirements for no timeout, UI responsiveness, low-confidence marking, empty-state explanation and manual re-discover; replace automatic refresh with a staleness hint that leads to the manual action.
3. C. Add requirements for the four non-conflicting criteria and drop the refresh criterion entirely.
4. D. Leave the criteria in the overview only and rely on DEC-012 to rewrite the overview.

## Decision

Option B. New requirements are added: (1) No default timeout: an operation subprocess is never terminated by the system because of elapsed time; it ends only by its own exit, by user cancel (DEC-020) or by quit/close termination (DEC-021). The 60 s default of the existing non-interactive runner must not apply to operations. (2) Responsiveness: while one or more operations run, the UI stays responsive and the user can switch tabs, edit documents, use X-Ray and the terminal tabs; output streaming must not block the main thread. (3) Low-confidence marking: operations with confidence 'low' (DEC-023) carry a visible marker in the operations list, in the Deploy picker and in the run confirmation. (4) Empty state: requirement derived from DEC-024. (5) Manual re-discover: requirement derived from DEC-016. (6) Staleness hint: discovery never runs automatically; when a source file recorded for a discovered operation has changed or no longer exists since the last discovery, the Deployment details panel shows a non-blocking hint 'sources changed' next to the Re-discover action. The hint does not change, disable or remove any operation.

## Reason

Criteria without a requirement are not tested and are likely to be lost. Automatic re-discovery would contradict DEC-016 and would trigger out-of-root reads and web searches (DEC-003) without a user action, and it costs AI calls. A hint keeps the user goal of the overview criterion (operations do not silently go stale) at no such cost. The no-timeout requirement is needed explicitly because the existing runner's default would otherwise kill real deploys.

## Consequences

Six requirements are added and the overview is rewritten accordingly (DEC-012). Open assumption: staleness detection needs a content fingerprint of each source file taken at discovery time; whether it is stored in the operations file (DEC-017) or in machine-local state must be fixed when the requirement is written; machine-local storage avoids diff noise in the shared file. Responsiveness needs a measurable acceptance criterion (for example a high-volume output test) to be verifiable. User-added operations have no source file and never trigger the hint.
