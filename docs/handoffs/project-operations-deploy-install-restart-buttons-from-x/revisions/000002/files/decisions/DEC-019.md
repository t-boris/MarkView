## Context

DEC-007 requires the subprocess to look like a terminal session and leaves the mechanism to the implementer, but user-visible behaviour is undefined: escape sequences, resize, full-screen programs, control keys, no-echo input, retention and persistence. Project fact: an embedded terminal exists as a login shell on a PTY owned by Swift and drawn by xterm.js. F-002 already runs operations on a PTY.

## Alternatives

1. A: Full terminal emulator reusing the existing terminal view component, bound to the operation's process
2. B: Line-oriented log with a single input field; escape sequences stripped, full-screen programs unsupported

## Decision

Option A. (1) The panel renders the operation's PTY with the existing terminal view component; the operation remains a separate execution path and does not appear among the terminal tabs (DEC-001). (2) ANSI colour, cursor movement and carriage-return progress output are rendered as in the embedded terminal; TERM is set to the same value the embedded terminal uses. (3) The terminal size follows the panel size and the process is notified on resize; while no panel view is attached the size is 120 columns by 30 rows. (4) Input is sent per key, including control keys (Ctrl-C, Ctrl-D, Ctrl-Z, arrows); Ctrl-C sends the interrupt character to the process and is distinct from the Cancel control. (5) Full-screen programs work to the extent the embedded terminal supports them; they are not a tested target. (6) No-echo input needs no detection: the panel never echoes typed characters itself and displays only what the process writes, and typed input is never stored separately, so REQ-002's no-echo criterion is met by construction. (7) Retention: a scrollback of 10,000 lines per operation; when exceeded, the oldest lines are discarded and the panel shows a visible marker that earlier output was dropped; output delivery to the view must be chunked so that no data is lost silently within the retained range. (8) Persistence: output is kept in memory only, is not written to disk, logs or the database, is not sent to any AI assistant, and is discarded when the user dismisses the panel, restarts the operation, closes the project or quits the application. (9) After the process ends the view is read-only; text selection and copy remain available.

## Reason

Deploy tools emit colours, progress bars and prompts that a line log renders as noise; reusing a component the project already maintains gives correct behaviour at the lowest cost and makes the no-echo requirement trivially true. Memory-only retention follows security.md's rule against logging credentials, since deploy output can contain secrets.

## Consequences

REQ-002 must be amended with these points. The terminal component needs to support instances not tied to a terminal tab, and the known risk of silent truncation on large writes must be fixed or bounded for this use. Output of a finished operation is lost on application quit or crash; there is no run history or log export in the first version. Memory use grows with the number of retained panels, bounded by the scrollback limit. Behaviour on quit while operations run stays open in F-010 and cancel semantics in F-009.
