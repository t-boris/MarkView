## Context

Operations are long-running and can be started from several entry points (two Deploy buttons and the operations list in the X-Ray details panel). It was undefined what happens when the user starts an operation while another operation of the same project is still running. The answer determines the number of output panels, the running indicator on the Deploy buttons and the scope of cancel.

## Alternatives

1. A: One operation per project; while it runs, starting any other operation is unavailable, with an explanation of which operation is running.
2. B: Several operations at the same time, but the same operation cannot be started twice; each operation has its own output panel.
3. C: One operation per environment; operations of different environments run in parallel, operations of the same environment and operations without an environment run one at a time.

## Decision

Option B: different operations of the same project may run at the same time, each as its own subprocess with its own output panel. An operation that is already running cannot be started again until it ends.

## Reason

User decision (answer to Q-008). Stated advantages of the option: parallel deployment to different environments is possible, and a long operation does not block the others.

## Consequences

The system does not prevent conflicting operations from running together (for example deploy and clean, or two different operations against the same environment); the only guard is the confirmation before every run (DEC-002). The user needs a way to switch between the output panels of several operations. The Deploy buttons must indicate running state per environment rather than a single project-wide state. Cancel applies to one operation only. The overview acceptance criterion 'starting a second one while one is running requires an explicit choice' is satisfied only through the per-run confirmation; no additional prompt is introduced.
