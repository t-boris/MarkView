## Context

Discovery derives commands from project files, from folders outside the project root and from the web (DEC-003), so some commands will be inaccurate or missing. Q-004 asked whether the operations list is only AI output or data the user owns, and what happens to user changes when discovery runs again.

## Alternatives

1. A: Read-only. Operations cannot be edited; a wrong command can only be re-discovered or run manually in a terminal.
2. B: The user can edit the command and working directory of a discovered operation; edits are kept and not overwritten by re-discovery.
3. C: As B, plus the user can add their own operations and delete discovered ones.

## Decision

Option C: the user can edit the command and working directory of a discovered operation, add their own operations and delete discovered ones. User changes are kept and are not overwritten by re-discovery.

## Reason

User answer to Q-004. Commands taken from outside the project and from the web will sometimes be wrong; the user must be able to correct them once and to cover procedures that discovery did not find.

## Consequences

The operations list becomes persistent user data, not a disposable AI result. Re-discovery must merge with user changes instead of replacing the list. Provenance (REQ-005) must distinguish discovered, user-edited and user-added operations. Confirmation (REQ-003) already shows the exact command that will run, so it covers edited and user-added commands without change. Open assumption (AI inference, not decided by the user): when re-discovery proposes a different command for a user-edited operation, the user's version stays active and the difference is only shown. Where the list is stored and whether it is shared with the team is not decided.
