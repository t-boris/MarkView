## Finding

Not defined: which signal is sent first, whether the process gets a grace period to clean up (important for tools like terraform that hold state locks) and when it is force-killed; what state is shown while termination is in progress; what happens with child processes that detached into their own session; what state is shown if the process exits with code 0 or with its own error after cancel was requested. There is also no warning that cancelling a deploy may leave the target environment partially changed.

> using it terminates the process and its child processes and the operation is shown as cancelled, distinct from failed

## Possible interpretations

- Send an interrupt, wait a fixed grace period, then force-kill the process group; the state is 'cancelled' regardless of the exit code.
- Force-kill immediately.
- State follows the real outcome: 'succeeded' if the process finished before the signal took effect.

## Resolution

AI: Отмена идёт по ступеням: SIGINT группе процессов, состояние «cancelling», 30 секунд на завершение, затем SIGTERM и через 5 секунд SIGKILL; кнопка «Force stop» доступна сразу. Если отмена запрошена до выхода процесса, итог всегда «cancelled» (код выхода показывается отдельно); перед отменой показывается подтверждение с предупреждением о возможном частичном изменении окружения. — see DEC-020.
