## Finding

The overview records this fact but no decision or requirement says whether discovery should propose workflow-dispatch deploys as operations (`.github/workflows/*` is among the scanned config files), whether they respect the opt-in GitHub setting, or how state is reported: such a command exits as soon as the workflow is queued, so 'succeeded' would mean 'dispatched', not 'deployed'. The overview puts remote monitoring out of scope, which makes the state misleading for this class of deploys.

> GitHub Actions workflow dispatch already exists (gh workflow run with parsed inputs), behind the opt-in GitHub setting. Projects that deploy through a workflow_dispatch workflow already have a partial path.

## Possible interpretations

- Workflow-dispatch deploys are discovered as ordinary operations; 'succeeded' means the command exited with code 0.
- Workflow-dispatch deploys are excluded from discovery in the first version.

## Resolution

AI: Деплой через workflow_dispatch обнаруживается как обычная операция с командой `gh workflow run …`, но помечается как «удалённый запуск»: при коде выхода 0 состояние и уведомление показывают «dispatched — удалённое выполнение не отслеживается», а не «succeeded». От opt-in настройки GitHub операция не зависит, так как выполняется как явная команда после подтверждения пользователя. — see DEC-030.
