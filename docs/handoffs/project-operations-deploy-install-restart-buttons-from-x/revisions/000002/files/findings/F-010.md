## Finding

No requirement covers what happens to running operations when the user quits MarkView, closes the project window, or the app crashes: whether the user is warned, whether processes are terminated or left running as orphans, and what state is shown after restart. It is also undefined whether the final state and output of the last run survive an app restart (REQ-002 says they remain 'until the user dismisses them or starts the operation again'; REQ-012 shows the final state in the list with no time limit), and how the no-duplicate rule (REQ-009) applies when the same project is open in more than one window or when the same operations file is used by two MarkView instances.

> The operation state is shown as running while the process is alive

## Possible interpretations

- Quit or close asks for confirmation and terminates all running operations.
- Operations keep running detached; after restart their state is unknown.
- Last-run state is in memory only and is lost on restart.

## Resolution

AI: Выход из приложения, закрытие окна или проекта при работающих операциях требует подтверждения со списком операций и затем отменяет их по правилам F-009; осиротевших процессов не оставляем. Итог последнего запуска (состояние, код, время) хранится локально на машине и переживает перезапуск, вывод — нет; после сбоя незавершённый запуск показывается как «interrupted». — see DEC-021.
