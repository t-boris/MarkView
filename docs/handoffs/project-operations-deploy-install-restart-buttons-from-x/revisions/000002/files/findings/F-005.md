## Finding

No requirement states when discovery runs: together with X-Ray deployment mapping, on first open of the Deployment view, only on a manual action, or automatically when source files change. The overview criterion 'refreshed when the relevant source files change; a manual re-discover action is available' is not carried into any requirement. Because results are written to a file under version control (DEC-005), automatic re-discovery would modify the working tree without a user action. Also missing: progress indication and cancel for a discovery that may take many minutes (existing agents run up to 900 s), behaviour when the AI CLI is missing, not logged in, times out or returns invalid output, whether discovery runs when an operations file already exists in a fresh clone, which input files are used (the overview notes package.json scripts, shell scripts, Justfile, Taskfile, Fastlane and README are not detected today), and which AI tools support web access (documentation confirms `WebSearch,WebFetch` for Claude with `allowWeb`; support for Codex and ACP assistants was not verified).

> When operation discovery runs, the system shall propose every operational command it finds for the project

## Possible interpretations

- Discovery runs only on an explicit user action (Discover / Re-discover).
- Discovery runs automatically after deployment mapping when no operations file exists, and manually afterwards.
- Discovery re-runs automatically when the signature of relevant source files changes.

## Resolution

AI: Discovery запускается только по явному действию пользователя (Discover / Re-discover); автоматически файл операций не создаётся и не изменяется. Если источники изменились, показывается ненавязчивая подсказка «список мог устареть», а при любой ошибке или отмене discovery файл остаётся нетронутым. — see DEC-016.
