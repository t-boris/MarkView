## Finding

The feature is marked `status: ready`, but the overview was not reconciled with DEC-001..DEC-011. Contradictions found: (1) production-specific extra confirmation vs DEC-002 (uniform confirmation, no environment classification); (2) 'selecting a deployment node narrows the list' vs DEC-009/REQ-010 (nothing is hidden); (3) 'Before an operation runs for the first time ... If the discovered command later changes, confirmation is required again' vs REQ-003 (every run); (4) 'Any read outside the project root and any web lookup happens only in the way the user has approved (exact policy is an open decision)' vs DEC-003; (5) 'starting a second one while one is running requires an explicit choice' vs DEC-008; (6) the section 'OPEN DECISIONS (not decided by the user; need discussion)' lists seven items that are all decided; (7) 'OUT OF SCOPE (proposed, not yet decided)' was never confirmed by the user. An implementer or tester reading the overview gets a different product than the requirements describe.

> Operations targeting an environment identified as production require an explicit additional confirmation on every run.

## Possible interpretations

- The requirements and decisions supersede the overview; the overview must be rewritten to match them.
- The overview criteria are still binding where no requirement contradicts them explicitly (e.g. low-confidence marking, no 60 s timeout, refresh on source change).
