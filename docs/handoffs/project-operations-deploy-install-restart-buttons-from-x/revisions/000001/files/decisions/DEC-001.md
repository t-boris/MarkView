## Context

Discovered operations (deploy, install, restart, etc.) must run as long-running, observable, cancellable processes. The execution mechanism determines how output, state, cancellation and safeguards are specified. The project already has an embedded PTY terminal and an AI agent terminal.

## Alternatives

1. A: Paste the command into an embedded terminal tab (PTY) and run it there
2. B: Run a dedicated subprocess with its own output panel, status and cancel button
3. C: Hand the task to the AI agent terminal, which executes the command itself

## Decision

Option B: each operation runs as a dedicated subprocess with its own output panel, explicit state (running / succeeded / failed with exit code / cancelled) and a cancel control.

## Reason

Chosen by the user. Considered advantages recorded with the option: exact exit code and unambiguous states, output and cancel located next to the operation button, predictable behaviour for production deploys.

## Consequences

New work is required: an output panel and process management, instead of reusing the embedded terminal. Commands that prompt for interactive input (passwords, y/n confirmations) are not handled by this mechanism without additional work; whether they are unsupported or handled is still an open assumption. The AI agent is not involved in execution, so the executed command is always the reviewed one.
