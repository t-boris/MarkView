## Context

After DEC-004 the operations list became user-owned data (edits, user-added operations, deletions). It had to be decided whether this list belongs to one user on one machine or to the whole team through the repository (open decision 6 in the overview).

## Alternatives

1. A: Local only - operations and edits are kept in the project's local state on this machine and never reach the repository
2. B: Shared project file - operations are stored in a file inside the project that can be committed and edited by hand
3. C: Shared file plus local overrides - a shared list in the repository with personal edits stored locally on top of it

## Decision

Option B: the operations list, including user edits, user-added operations and deletions, is stored in a single file inside the project. The file can be committed to the repository and edited by hand. There is no per-user local override layer.

## Reason

The user chose B. Stated benefits of this option: a correction is made once for the whole team, and command changes are visible in version history and code review.

## Consequences

A command written by one person will run on another person's machine; the confirmation before every run (DEC-002, REQ-003) is the safeguard, as it shows the exact command and working directory. Working directories outside the project root may not exist on other machines. Hand edits and changes arriving through version control must be picked up by the application. Re-discovery writes to a file under version control, so its changes appear as a diff. Machine-specific adjustments cannot be kept private; they change the shared file.
