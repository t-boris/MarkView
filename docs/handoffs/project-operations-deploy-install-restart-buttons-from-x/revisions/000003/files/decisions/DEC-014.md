## Context

DEC-005 makes commands arrive through version control, and DEC-002/REQ-003 show the same confirmation on every run, so a changed command is not signalled. Project fact (security.md S1, S3): a crafted document can post any bridge message, so a confirmation rendered in the web page, or a command carried in the bridge payload, could be bypassed or forged.

## Alternatives

1. A: Accept the risk: uniform confirmation only, no change detection
2. B: Highlight in the confirmation that the command or working directory differs from the last version confirmed on this machine
3. C: Native confirmation dialog, bridge payload carries only the operation id
4. D: B and C together

## Decision

Option D. (1) A run request from any web view carries only the operation id; the native side validates the id against the operations file, reads the command and working directory from that file at that moment, and ignores any other payload fields. (2) The confirmation of REQ-003 is a native dialog owned by the application; no web content can display, pre-answer or dismiss it, and no subprocess starts without it. (3) For each operation the application keeps, in machine-local state (.dde/state.db), a fingerprint of the command and working directory last confirmed and started on this machine. When the current values differ, or no fingerprint exists, the dialog shows a distinct 'new or changed since your last run on this machine' warning, shows the previous command when there is one, and does not have the confirm button as the default action. This run history is not part of the operations list, so REQ-006 ('no part of the operations list is stored only in machine-local state') is not violated. DEC-002 stays in force: confirmation is required on every run and is not environment-specific.

## Reason

With a shared file, the confirmation is the only safeguard, and a uniform dialog trains habitual confirmation. Marking changes restores the signal the dropped overview criterion provided, at low cost. Native enforcement closes a concrete bypass path documented in the project's own security notes.

## Consequences

REQ-003 must be amended with the native dialog, the id-only payload and the change warning. A new machine-local table is needed for run fingerprints; it is lost with .dde/ (gitignored), in which case every operation is shown once as new. On a fresh clone every operation shows the warning on first run. The toolbar button in the native window and the X-Ray web view both use the same native path.
