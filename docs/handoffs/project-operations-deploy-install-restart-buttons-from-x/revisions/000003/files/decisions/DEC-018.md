## Context

REQ-008 and REQ-011 assume exactly one deploy operation per environment. Projects may have a deploy command with no named environment, several deployable units per environment, and user-added deploy operations with missing or duplicate environment names. DEC-009 already relates operations to deployment nodes.

## Alternatives

1. A: The picker lists deploy operations (label plus environment), not environments
2. B: One deploy operation per environment is enforced; additional ones are classified as 'other'
3. C: Two-level picker: environment, then target

## Decision

Option A with grouping. (1) The picker lists every non-deleted operation of kind deploy. Entries are grouped under environment headings when at least one deploy operation has an environment; operations without an environment appear in a group without heading, placed first, shown by label only. (2) `environment` is optional and not unique; discovery produces one deploy operation per combination of environment and deployable unit (`target`) it finds. The REQ-011 criterion becomes: 'for each environment found there is at least one deploy operation, and no two discovered deploy operations share the same environment and target'. (3) Environment names are stored and shown exactly as found in the project or typed by the user; they are not normalised or translated (prod and production stay distinct); grouping compares names case-insensitively after trimming whitespace. (4) Order: groups in the order of first appearance in the operations file, operations inside a group by label; no environment is treated specially, consistent with DEC-002. (5) User-added or hand-edited deploy operations with no environment or with an environment name already in use are valid. (6) With exactly one deploy operation the button starts it directly, without a picker step, through the REQ-003 confirmation. (7) Running state and the 'cannot be started again' rule apply per operation (DEC-008); a group heading shows a running mark when any of its operations is running.

## Reason

Enforcing one operation per environment (B) would hide real deploy commands under 'other' and contradict DEC-010. A two-level picker (C) adds a step for the common single-unit project. A grouped flat list handles all three cases with one rule and degrades to the simple case automatically.

## Consequences

REQ-008 and REQ-011 must be reworded from 'environments' to 'deploy operations grouped by environment'. Because names are not normalised, inconsistent naming in a project produces separate groups; the user fixes this by editing the operation. Order depends on file order, and since the file is sorted by id (F-006), an explicit `order` field may be needed later if users want custom ordering. Projects with many units and environments get a long picker; no search or collapse is planned for the first version.
