## Context

The Scope lists the operation kinds deploy, install, build, clean, restart and other, but the original request named "clean", "refresh" and "restart" only as examples. The set of kinds determines what discovery looks for, how the operations list is grouped and how many low-confidence commands the user may see.

## Alternatives

1. A: Only deploy (per environment), install and restart.
2. B: Fixed set deploy, install, build, clean, restart; commands that fit no kind are not discovered and can only be added by the user.
3. C: All kinds from the Scope including "other"; discovery proposes any operational command it finds in the project.

## Decision

Option C: the first version supports the kinds deploy, install, build, clean, restart and other. Discovery proposes every operational command it finds in the project and assigns the kind "other" to commands that fit none of the named kinds.

## Reason

The user chose C. Nothing the project supports is lost, and projects with non-standard procedures (migrations, seeding, etc.) are covered without manual entry.

## Consequences

The operations list can become long and contain more low-confidence commands; the user relies on per-operation confidence, provenance (REQ-005), confirmation before every run (REQ-003) and deletion (REQ-006) to manage it. The Deploy button still depends only on operations of kind deploy (REQ-008).
