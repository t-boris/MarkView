## Context

Operations are long-running and may run concurrently (DEC-008). Their state was visible only in the output panel (REQ-002), so a finished or failed operation could go unnoticed when the panel is hidden or MarkView is not the frontmost application.

## Alternatives

1. A: In-app only - state in the output panel and an indicator on the Deploy button and in the operations list; no system notifications.
2. B: In-app indicators plus a macOS system notification for every completion (success, failure, cancellation) when MarkView is not frontmost.
3. C: In-app indicators plus a macOS system notification only on failure.

## Decision

Option B: the system shows in-app state indicators on the Deploy buttons and in the operations list, and posts a macOS system notification for every operation completion (succeeded, failed, cancelled) when MarkView is not the frontmost application.

## Reason

The user chose B: the user does not have to wait at the screen, and all outcomes are reported in the same way.

## Consequences

MarkView must request macOS notification permission. Frequent short operations (build, clean) produce a notification each time MarkView is in the background. If notification permission is denied, only the in-app indicators remain. No notification is posted while MarkView is frontmost.
