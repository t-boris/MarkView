## Context

Whether the feature applies to folder X-Rays was listed as unknown and never decided. It defines the meaning of 'project root' in REQ-004 and REQ-006 and what the window toolbar button shows. Project fact: deployment node ids are AI-generated and the Deployment view is remapped when the config-file signature changes, so stored node relations can become dangling. Open assumption, not verified in code: a project window has exactly one workspace root.

## Alternatives

1. Only the project X-Ray (workspace root) is supported; folder X-Rays show no operations.
2. Each X-Ray root has its own operations file; the window toolbar uses the workspace root's file.
3. Folder X-Rays show the workspace root's operations filtered by working directory.

## Decision

(1) 'Project' and 'project root' in all requirements of this feature mean the workspace root of the project window. There is one operations file per workspace root (path per DEC-017). (2) The operations list, the discovery actions and the X-Ray toolbar Deploy button are shown only in the project X-Ray, whose root is the workspace root. A folder X-Ray shows none of them. (3) The project window toolbar Deploy button always uses the workspace root's operations, whatever X-Ray is open. (4) A relation between an operation and a deployment node is optional. It is stored as the node id together with the node name. (5) At display time a relation is resolved by node id, and if no node has that id, by exact node name. A relation that resolves to no node is ignored: the operation is listed as unrelated, no error is shown and the file is not changed. (6) Re-discovery may update the relations of operations that are exactly as discovered; it does not change relations set by the user (REQ-007). (7) The edit and add forms let the user set or clear the related node by choosing from the nodes of the current Deployment view.

## Reason

One root and one file keep discovery scope, storage, the toolbar button and the security boundary unambiguous for the first version. Tolerant resolution makes node relations a display hint, so remapping can never hide or break an operation (REQ-010).

## Consequences

Monorepo sub-projects opened as folder X-Rays get no operations of their own; their commands can be added as operations of the workspace root with a sub-folder working directory. REQ-008 must be narrowed from 'every X-Ray view' to every view of the project X-Ray. REQ-010 needs criteria for dangling relations and the schema of DEC-017 (proposed) needs the relation fields. If a window can hold several workspace roots, this decision must be revisited.
