## Context

No requirement states when discovery runs. Results are written to a file under version control (DEC-005), so automatic runs would modify the working tree without a user action. Discovery reads external folders and searches the web without a prompt (DEC-003) and may take many minutes. Project facts: deployment mapping does not read files and detects a limited set of config files; web tools are documented only for Claude with allowWeb.

## Alternatives

1. A: Discovery runs only on an explicit user action (Discover / Re-discover)
2. B: Discovery runs automatically after deployment mapping when no operations file exists, manually afterwards
3. C: Discovery re-runs automatically when the signature of relevant source files changes

## Decision

Option A. (1) Trigger: a 'Discover operations' action is shown in the Deployment view details panel when no operations file exists, and 'Re-discover' when it exists. Discovery never starts automatically, including on a fresh clone that already has an operations file. (2) Staleness: the application stores a machine-local signature of the discovery input files; when it changes, the operations list shows a 'sources changed since last discovery' hint; nothing is run or written. (3) Inputs: the files detected by ArchitectureScanner.isDeploymentHint plus package.json, shell scripts in the project root and in scripts/, bin/, deploy/ folders, Justfile, Taskfile.yml, fastlane/Fastfile, README* and docs runbooks; discovery is a separate AI pass with file read access and does not change the deployment mapping prompt. (4) Lifecycle: while discovery runs, a progress state with the current phase (project files / external folders / web) and a cancel control are shown; the time limit is 900 s; only one discovery per project runs at a time. (5) Failure: if the AI CLI is missing, not signed in, times out, is cancelled or returns output that fails schema validation, the operations file is not modified and an error naming the cause and the remedy is shown. (6) Web: when the selected assistant does not support web access, discovery runs without the web phase and the provenance report states that the web was not searched. (7) The file is written once, at the end of a successful run, under the merge rules of REQ-007.

## Reason

An explicit trigger is the only option consistent with a version-controlled file and with unprompted external reads: the user's click is the consent moment. It also avoids AI cost and surprise diffs on every config change. The staleness hint keeps the benefit of change detection without side effects.

## Consequences

A new requirement for discovery trigger, lifecycle and failure handling must be written; the overview criterion 'refreshed when the relevant source files change' is replaced by the staleness hint. Users must click once before any button appears in a project without an operations file. The scanner input list has to be extended for discovery. Web support for Codex and ACP assistants remains unverified and must be checked before implementation.
