## Finding

The requirement does not say which folders discovery may read or how it chooses them: sibling folders, paths referenced in project files, the whole home directory, or any readable path. Project fact: existing read-only agents are restricted to one `readableFolder`; Codex runs with `--sandbox read-only`, and ACP reads do not resolve symlinks (S10). Everything the agent reads is sent to the AI provider without redaction (S14), so an unbounded scope can include `~/.ssh`, `~/.aws`, `.env` files of other projects. There is also no time, size or file-count limit, and the acceptance criterion 'discovery reads that folder' is not testable without a rule for how the folder is found. DEC-003 accepted reading without a prompt, but not an unlimited scope.

> first in local folders outside the project root and then on the web, without asking the user for permission

## Possible interpretations

- Only paths explicitly referenced from the project's own files (scripts, Makefile, README) are followed.
- The parent folder of the project root and its direct children (sibling projects).
- Any path the agent decides to read, with an exclusion list for credential locations.
- Any path with no restriction.

## Resolution

AI: Discovery читает вне корня проекта только папки, на которые явно ссылаются собственные файлы проекта (скрипты, Makefile, README и т.п.), с жёстким списком исключений для мест хранения учётных данных и с лимитами по количеству папок, объёму и времени. Соседние проекты и домашний каталог «на всякий случай» не просматриваются. — see DEC-015.
