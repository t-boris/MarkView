## Context

DEC-006 and DEC-009 made the hand-off a text brief given to an agent. Boris expected a feature or bug with instructions and screenshots instead, to be executed afterwards (REQ-012 gave the brief only).

## Alternatives

1. Keep only the text brief for an agent (DEC-009).
2. Create a bug per changed unit instead of one feature.
3. Create the feature and start the implementation in one click without a review stop.

## Decision

"Hand off to code" builds a feature draft from the prototype changes since the sync baseline: one requirement per changed screen or component (what changes, how to verify), the before and after screenshots of each as sources of the feature, and the review requests that led to the changes. The person reads and edits the draft, then "Create feature" writes it into the project (status ready, requirements approved by that click). Implementation then goes through the app's own flow (Implement with AI: branch, pull request). Sending the brief straight to a new agent session and copying it stay as the quick paths for small changes. Studio still writes nothing outside the prototype folder and the feature it was asked to create.

## Reason

Chosen by Boris on 2026-11-03 ("Так и сделай") after the proposal: the hand-off should produce a feature with all instructions and screenshots that he then executes, and a sync afterwards redraws the prototype from the code. A feature gives requirements with acceptance criteria, a tracked status and the existing implementation flow; a bare text brief gave none of that.

## Consequences

The feature panel becomes the place where hand-off work is tracked and implemented. The screenshots need an offscreen renderer for a screen of any saved version of a prototype. DEC-009 stays for the quick paths. A prototype without a baseline cannot hand off, as before.
