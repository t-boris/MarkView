## Context

Boris wants to change a prototype and then have the application code updated to match. Studio today only writes inside the prototype folder (REQ-006 of previews-from-existing-code: sync does not modify application source). The prototype is a plain HTML/JS reconstruction with simulated data, not the real React/Vue code, so a change in it is an intent to translate, not a patch to apply.

## Alternatives

- Variant B: Studio runs a write-enabled assistant on the application source and applies the result itself (a new write path into the user's code, with its own review UI).
- Do nothing: the person tells an agent in words that the prototype changed (the agent cannot know what changed).

## Decision

Variant A. A "Hand off to code" action builds a brief (what changed in the prototype since the sync baseline, the source components involved by their markers, the instructions that led to the changes, the prototype reference) and gives it to an agent in the window's AI panel. The agent changes the code on its own branch and opens a pull request under the repository's normal workflow. Studio itself writes nothing outside the prototype folder.

## Reason

Chosen by Boris on 2026-11-03. It fits the existing architecture (agents change code, Studio edits prototypes), keeps every code change reviewable as a pull request and adds no new write path into application source. The cost is that the translation quality depends on the agent.

## Consequences

The prototype needs a record of what changed since the last sync with the code (the baseline, REQ-009). The brief is shown to the person before it is sent (REQ-012). Variant B stays possible later as a separate decision. After the agent's change, an incremental sync (REQ-010) closes the loop and moves the baseline.
