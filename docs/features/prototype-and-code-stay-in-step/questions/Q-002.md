## Question

How should a changed source file be detected: by content fingerprint or by Git?

## Why it matters

The projects Boris uses are not all Git repositories, and a working tree is often dirty when a sync is started.

## Options

- **A**: A content hash of each source file stored in the baseline; works without Git and with uncommitted changes.
- **B**: Git diff against the commit recorded at the last sync; cheaper to store but needs a clean Git history.

## Recommended

A. It is independent of Git and of the state of the working tree.
