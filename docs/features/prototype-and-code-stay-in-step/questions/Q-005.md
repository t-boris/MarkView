## Question

An incremental sync rebuilds only the changed screens and components and keeps the shell, the styles and the sample data (data.js) from the last full build. When the changed code needs data or fields that data.js lacks, should the sync also refresh data.js?

## Why it matters

Found by a real run on a two-screen app: a new order added in the source did not reach the rebuilt Orders screen, because the sample rows live in data.js, which an incremental sync does not touch. Rewriting data.js can break the screens that were not rebuilt, since they were written against its old shape.

## Options

- **A**: Keep data.js; tell the screen writer to define any missing data inside the rebuilt screen, and say in the sync reply that Rebuild everything refreshes the sample data (what is implemented now).
- **B**: Add a small data writer that may only add rows and fields to data.js and never changes the existing ones, run when a changed unit needs data.
- **C**: Treat data.js as a unit with sources, so a change to the files that feed it makes the sync a full rebuild.

## Recommended

A
