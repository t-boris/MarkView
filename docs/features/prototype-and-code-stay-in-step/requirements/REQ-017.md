## Statement

The hand-off shall take a screenshot of each changed screen as it was at the sync baseline and as it is now, in the same size and theme, without a visible window, and attach both to the feature.

## Acceptance Criteria

- [ ] Before is rendered from the baseline version of the prototype (versions/v<N>) and after from the live site, through the prototype scheme handler, with a non-persistent data store so the sample data is the seed on both sides.
- [ ] Both use the same viewport, the theme the person chose and the same first role; the shot is taken when the page has settled.
- [ ] A screen unit is opened at its route (an embedded widget at its widgets route), a component at its isolated page, and a change of the shell is shown by the first screen.
- [ ] A screen that is new or was removed has only one of the two shots; a shot that fails (no route, the page throws) is reported in the sheet and never blocks creating the feature.
- [ ] The images are stored as sources of the feature (references/SRC-nnn) and linked from the requirement of their unit; no assistant run takes part in taking them.
- [ ] The renderer works on any saved version of any prototype from code and leaves the visible preview and its state alone.
