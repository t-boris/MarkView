## Statement

Prototype Studio shall let the reviewer pick what a change request is about (the whole prototype, one screen, one source component, or one element) by selecting it in the Studio, and shall give that target to the assistant with the request.

## Acceptance Criteria

- [ ] Studio lists the prototype's screens and, for a prototype built from code, its source components; selecting one makes it the target of the next request.
- [ ] The target is shown next to the message field (kind and name, with the source component path when known) and the reviewer can clear it; without a target the request is about the whole prototype.
- [ ] Pointing at an element in the preview (Point) sets an element target and keeps today's data: selector, text, HTML, screen, source component and the optional screenshot.
- [ ] The request sent to the assistant states the target, the files that implement it, and that the change is limited to it unless the request says otherwise.
- [ ] For a prototype built from requirements, the whole prototype, screen and element targets are offered; component targets are offered only when the prototype records components.
- [ ] A target is cleared after the request is sent, and a retry or an edit of a failed request keeps the target it had.
