## Statement

For each changed unit the hand-off shall describe, as a short list, what changed in the prototype and what the application's code must do to match it, from the file differences, the review requests and the screenshots.

## Acceptance Criteria

- [ ] One assistant call per changed unit, bounded in number; its input is the unit's before and after files, the review requests since the baseline and the two screenshots; it reads no application source and writes nothing.
- [ ] The answer is a list of changes, each with where it is (the control, the section), what changes and how to check it; it becomes the acceptance criteria of the unit's requirement.
- [ ] When the call fails or is stopped, the requirement falls back to the review requests and their results, and the sheet says the description is the fallback.
- [ ] The person can edit every description before creating the feature; the calls are counted in the workspace's usage like other prototype runs.
