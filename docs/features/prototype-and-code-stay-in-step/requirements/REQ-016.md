## Statement

The hand-off sheet shall offer "Create feature", which writes a MarkView feature from the prototype changes since the sync baseline: one requirement for each changed screen or component, the before and after screenshots attached, and the review requests that led to the changes.

## Acceptance Criteria

- [ ] The sheet shows the draft (feature title, idea, one requirement per changed unit with its statement and acceptance criteria) and the person can edit it; nothing is written to the project before 'Create feature' is pressed.
- [ ] Creating writes docs/features/<slug>/ with the idea naming the prototype and its versions (baseline and current), status ready, requirements approved, and provenance 'Created from prototype <slug> v<n>'.
- [ ] A change of the shell (index.html, app.js, styles.css, data.js) becomes one requirement of its own; a unit changed in the code since the baseline is named in its requirement as a conflict to reconcile.
- [ ] After creation the app opens the feature at its Build stage, one click from 'Implement with AI'; no application source is written and no agent starts by itself.
- [ ] A prototype without a baseline, or without changes, cannot create a feature and the sheet says why.
- [ ] 'Send to agent' and 'Copy brief' remain available and use the same text, with the screenshots listed.
