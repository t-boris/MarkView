## Context

REQ-001 reuses the source-selection convention "no selection means the whole project". In code mode the planner asked whether that should mean the detected web applications only, and what to do when the selected scope contains nothing that looks like a web interface (Q-002 A limits the first version to web interfaces and Electron renderers).

## Alternatives

1. Scope = detected web-application folders only, whole project as fallback.
2. Allow creation with a warning and let the agent disclose the gap.

## Decision

With no files or folders selected, the whole project is the reconstruction scope, literally: the agent is pointed at the project root and finds the interface itself; detected web applications are listed in the prompt as hints, not as the scope. A web interface counts as detected when the Preview Web App discovery finds a web application or Electron renderer in the scope, OR when the scope contains web-interface files (html, jsx, tsx, vue, svelte and the like, as listed by the code-mode inventory), so static sites and Electron apps without a dev-server script qualify (clarified by Boris on 2026-11-03 after review). When neither holds, creation is refused: the Create button stays disabled and the sheet says that no web interface was detected and which folder to select.

## Reason

Boris chose both on 2026-11-03: the whole-project convention stays literal, and generating a "reconstruction" of code that has no web interface would only produce a made-up design, which DEC-001 forbids presenting as a reproduction.

## Consequences

Detection runs off the main thread when the sheet opens and when the selection changes. Native-only projects cannot start a code-mode prototype in the first version.
