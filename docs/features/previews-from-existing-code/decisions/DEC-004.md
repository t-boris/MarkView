## Context

The existing New Prototype sheet creates prototypes from requirement sources. Code mode needs an entry point, and the list of reconstruction gaps (REQ-001) needs a lifetime: fixed when the prototype is generated, or extended by later Studio edits.

## Alternatives

1. A mode switch inside the single New Prototype sheet.
2. Each accepted edit may add new gaps.

## Decision

Code mode is started from its own menu item, "New Prototype from Code…", next to "New Prototype…". It opens the same sheet with the mode preselected and the texts adapted (sources are existing code, not requirements). Assumptions and gaps are captured once, at generation, and persisted with the prototype; accepted Studio edits never change them. The edit (revise) schema stays as it is.

## Reason

Boris chose a separate menu item and generation-time gaps on 2026-11-03. Gaps describe the difference between the original code and the reconstruction; later edits are intentional changes, not reconstruction errors.

## Consequences

Two menu items share one sheet and one creation path with a `mode` parameter. The gaps block in Studio, SPEC.md and the agent tools always reflects the first generation.
