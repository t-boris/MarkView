## Context

Prototypes were stored in .dde/prototypes/<slug>/, and .dde/ is gitignored, so a preview could not be committed or shared through the repository. Boris asked on 2026-11-03 that previews be stored where they can be committed.

## Alternatives

1. docs/features/<feature>/prototypes/<slug>/ (requires a feature per prototype).
2. Keep .dde/prototypes and un-ignore it in .gitignore.
3. Read legacy prototypes from .dde and create new ones in docs without moving.

## Decision

Prototypes are stored in docs/prototypes/<slug>/ with the same folder layout as before (prototype.json, site/, versions/, SPEC.md, review history). Existing prototypes in .dde/prototypes/ are moved to docs/prototypes/ once, automatically, when the project opens; a folder whose slug already exists at the new place is left where it is and reported. The prototype reference stays markview://prototype/<slug>; path forms of the reference accept both docs/prototypes/<slug> and the legacy .dde/prototypes/<slug>.

## Reason

Boris chose docs/prototypes with automatic migration on 2026-11-03. docs/ is where the project's committed product knowledge lives (features, bugs), and a preview is review material of the same kind.

## Consequences

A stored-data layout change: the version bump is major (5.0.0). The migration runs off the main thread and only moves folders; nothing is deleted or rewritten. Documentation and the agent tools name the new location. Prototype snapshots, screenshots and review history are now part of the repository and count toward its size. Derived artifacts that are not review material, the implementation ZIP produced by approval, are written outside the repository tree, under `.dde/exports/prototypes/`, so binary archives are not committed.
