## Context

On 2026-11-03 Boris extended the feature: a code-derived preview must be re-synchronizable from the code (code → preview), and preview parts must be linked to the components they come from, so a component can be opened and viewed on its own. Open points were what sync does with Studio edits, what "open a component" means, and the component granularity.

## Alternatives

1. Sync re-applies the accepted edits on top of the new reconstruction (agent merge).
2. Component = whole screen/route only (evidence per screen).
3. Only one of: open source file / isolated view / components list.

## Decision

1. Sync from code reconstructs the preview from the current sources and saves it as a new version; earlier versions with the user's edits stay in the history and remain restorable. The agent does not try to re-apply edits on top of the new reconstruction. 2. A component is a component file in the sources (React/Vue/Svelte/Angular component files; a template or HTML file for plain pages). 3. Opening a component means all three: open its source file in a MarkView editor tab; show the component alone in an isolated prototype view with simulated data; and a Components list in Studio that navigates in both directions (component → its instances in the preview, pointed element → its component).

## Reason

Boris chose these on 2026-11-03. A new version is simple and predictable and reuses the existing version history; a file is the component boundary every web framework shares; the three ways of opening together give the component ↔ preview link he asked for.

## Consequences

The reconstruction prompts must mark elements with their component file (a data attribute); the prototype carries a components manifest; Studio gains a Components list, an \"Open source\" action and isolated component pages; the prototype tools expose the components. Produces REQ-004 and REQ-005.
