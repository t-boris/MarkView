## Finding

The criterion requires an actionable explanation for a foreground-only popup but leaves its recovery behavior open. MarkView currently creates a separate popup WebView linked to the originating page. Deferring that popup lets the user continue the original flow, while cancelling it requires the user to repeat the triggering action. Those outcomes differ when the page has already advanced to the next step. [Source: MarkView/Models/Browser/BrowserSession.swift, line 472]

> If an operation requires foreground interaction, such as an unsupported background screenshot, sign-in popup, or trusted input, the tool explains what the user needs to do without bringing the tab or window forward.

## Possible interpretations

- Cancel the popup and tell the user to select the originating tab and repeat the triggering action manually.
- Keep the popup pending without showing it and tell the user how to explicitly open it and continue the original flow.

## Resolution

MarkView сохраняет окно входа скрытым и предлагает открыть его явным действием из исходной вкладки. — see DEC-002.
