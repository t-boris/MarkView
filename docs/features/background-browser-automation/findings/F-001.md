## Finding

An automated action can schedule a new-tab request that arrives after the tool has returned. The specification does not say whether that request still counts as automation, including when the user has since selected the originating tab. The current new-tab callback opens the destination in the foreground and carries no indication of whether the request came from a tool call or a user gesture. The choice determines whether a delayed page action can still interrupt the user. [Source: MarkView/Models/Browser/BrowserSession.swift, line 480] [Source: MarkView/Models/Workspace/BrowserHost.swift, line 191]

> Applies to MarkView's browser tools across assistants, including new tabs, operations on existing tabs, and tabs or popups opened by automated page actions. Manual browsing, terminal URL forwarding, and the explicit `markview_focus_window` command retain their current behavior.

## Possible interpretations

- Keep delayed new-tab requests caused by automation in the background even after the tool returns. Preserve foreground behavior for later manual actions on the same tab.
- Apply the background rule only while the initiating tool call is pending. Handle requests that arrive after it returns using ordinary browsing behavior.

## Resolution

Запрос, вызванный автоматизацией, открывает вкладку в фоне даже после возврата инструмента. Последующий ручной клик сохраняет обычное поведение. — see DEC-001.
