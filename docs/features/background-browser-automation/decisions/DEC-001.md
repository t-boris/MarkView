## Context

F-001 identified an ambiguity in Background Browser Automation. A page action initiated by a browser tool can request a new tab after the tool returns, by which time the user may have selected the originating tab.

## Alternatives

1. Apply background behavior only while the initiating tool call is pending. Requests that arrive after it returns follow ordinary browsing behavior.
2. Apply background behavior to new-tab requests from the originating page until the first manual interaction within that page. Selecting the tab alone does not end this behavior.

## Decision

Open new tabs caused by automated page actions in the background, including when the request arrives after the initiating tool returns or after the user selects the originating tab. A subsequent manual click that opens a new tab follows ordinary browsing behavior.

## Reason

An automated request can interrupt the user's work whenever it arrives. Using the cause of the request preserves focus independently of tool timing and preserves ordinary behavior for manual browsing.

## Consequences

New-tab handling must distinguish delayed requests caused by automation from requests caused by manual interaction on the same page. Acceptance tests must verify that a delayed automated request opens in the background after the tool returns, even if the user has since selected the originating tab, and that it preserves the user's selection and keyboard focus. A separate test must verify that a subsequent manual click that opens a new tab follows ordinary browsing behavior.
