## Context

F-002. Background browser automation must preserve the user's focus when a sign-in popup requires manual interaction. The acceptance criterion calls for actionable guidance but leaves popup recovery unspecified.

## Alternatives

1. Cancel the popup and instruct the user to select the originating tab and repeat the sign-in action manually.
2. Keep the popup hidden and let the user open it explicitly from the originating tab.

## Decision

When an automated action triggers a sign-in popup that requires user interaction, MarkView keeps it hidden and preserves its connection to the originating page. MarkView displays the popup only when the user explicitly opens it from the originating tab.

## Reason

This preserves the user's focus and lets them continue the original sign-in attempt even if the originating page has already advanced.

## Consequences

The tool identifies the originating tab by name and explains how to open the pending popup. The interface provides an explicit action in that tab to show the popup. If the popup is no longer available, MarkView explains how to retry sign-in manually.
