## Context

To explain where a project part came from, the answer needs provenance sources. Current documents and code may not record when or why something appeared.

## Alternatives

1. A: Only current documents (features, REQ, DEC, architecture) and code
2. B: Current documents and code plus git history (log/blame) and pull requests

## Decision

B: the answer draws on current documents and code plus git history (git log/blame) and pull requests.

## Reason

Current documentation alone cannot say when or why a part appeared if it was never documented. Git history and PRs fill that gap.

## Consequences

The answering agent needs read-only access to git history and PR data, so answers are slower and more expensive. It must degrade gracefully when there is no git repository or PR access is unavailable.
