## Context

Boris asked on 2026-11-14 to show Antigravity usage in the top bar beside Claude and Codex. DEC-010 of flexible-files-views-and-visible-agent-usage (2026-11-08) left Antigravity out because it then had no numbers, no API and only binary protobuf conversation files. Research on 2026-11-14 with agy 1.5.9 found a slash command, `/usage`, that works in print mode: `agy --output-format json -p "/usage"` takes about 2 s, spends no model tokens and creates no conversation (num_turns 0). It starts a throwaway language server, signs in as the CLI's Google account and asks `retrieveUserQuotaSummary`. The JSON lists groups of buckets (`command.data.groups[].buckets[]`) with `window` (5h or weekly), `remaining_fraction` and `reset_time`. The quota is account-wide: it dropped from 93.0 to 91.9 percent between two reads while another session worked. Boris approved the proposal as written on 2026-11-14.

## Alternatives

1. Call the endpoint (daily-cloudcode-pa.googleapis.com/v1internal:retrieveUserQuotaSummary) ourselves with the stored OAuth token: an undocumented internal host (the CLI itself uses a 'daily' channel), and MarkView would have to find and read a token it has no stable location for. Rejected.
2. Query the language server of the running Antigravity IDE (local port plus CSRF token read from the process list): works only while the IDE runs and relies on undocumented RPCs. Rejected.
3. Estimate from local conversation files: they are binary protobuf with no token counts and no plan limit. Rejected (still DEC-010's reason).
4. Keep Antigravity out, as DEC-010 did: no longer justified, a reliable source exists.

## Decision

Add Antigravity as a third agent whose only source is the CLI's own command. MarkView runs `agy --print-timeout 20s --log-file /dev/null --output-format json -p "/usage"` off the main thread with its own 25 s timeout and parses `command.data.groups[].buckets[]` into quota windows (percent used = 1 - remaining_fraction, the group is the window's scope, the label carries the group, e.g. "Gemini 4 Argon wk"). MarkView reads no Antigravity credential. The sign-in prompt the CLI prints when signed out (it carries a login link) is classified as 'signed out' and dropped, never stored or logged. There is no local-log fallback and no user-limit form for Antigravity. The headline window is the most used one, like Claude and Codex (DEC-009; Boris confirmed it on 2026-11-14). A bucket nobody has used reports a reset time of now + window that moves on every call, so it is shown without a reset time or pace. Refresh every 5 minutes while an indicator is visible, the same as Claude and Codex (6.24.0 used 10 minutes; Boris asked for the faster rhythm on 2026-11-14, 6.24.1), and every 30 minutes while signed out; the manual refresh keeps its 60 s cooldown.

## Reason

It is the CLI's own documented surface (`--output-format json`, print-mode slash commands), costs no tokens and survives changes of the internal endpoint, token storage and sign-in refresh, which the CLI handles itself. It matches DEC-005's alternative B (use what the agent itself outputs, never read credentials) and needs no new consent. The output shape of `command.data` is not documented, so the parser is tolerant and an unrecognised answer shows 'unavailable', never zero (the same rule as for Claude and Codex). `--log-file /dev/null` avoids one log file per read (462 had piled up in ~/.gemini/antigravity-cli/log).

## Consequences

Supersedes DEC-010 of flexible-files-views-and-visible-agent-usage for Antigravity only; Cline, Copilot CLI and Gemini CLI stay out. Each read starts a 223 MB process for about 2 s every 5 minutes while an indicator is visible, with about five requests to Google per read. If agy is not installed or not signed in, the chip says so; a signed-out CLI hangs at its prompt until MarkView's timeout. Not verified: whether the Antigravity IDE (its own app data, possibly another Google account) draws from the same quota as the CLI. If the `/usage` JSON changes shape, Antigravity shows 'usage unavailable' until the parser is updated.
