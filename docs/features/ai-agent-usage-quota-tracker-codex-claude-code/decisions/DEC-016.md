## Context

Q-002 (where to show progress) was answered 'B. Panel in the MarkView app' but produced no decision. Q-008 later asked where in MarkView to place the indicator, and its text says Q-002 had no answer. DEC-006 then chose a compact indicator in the AI terminal panel with a detail popover. F-009 flags this gap as a traceability issue.

## Alternatives

1. Treat Q-002 as superseded by Q-008 and link both to DEC-006, noting that DEC-006 refines Q-002's answer
2. Create a separate decision for Q-002 ('inside MarkView, not CLI status line or menu bar') in addition to DEC-006
3. Reopen placement and ask the user whether a dedicated MarkView panel was meant instead of the AI terminal panel

## Decision

Q-002's answer (inside the MarkView app, not a CLI status line or a macOS menu bar item) is the parent choice. DEC-006 refines it: a compact per-agent indicator in the MarkView AI terminal panel with a detail popover. Q-002.produces and Q-008.produces both reference DEC-006. DEC-006's context records that CLI status line and menu bar placements were rejected in Q-002. The statement in Q-008 that Q-002 was unanswered is corrected.

## Reason

The two answers agree: the AI terminal panel is a panel within MarkView, and it is where the user works with agents, which partly addresses Q-002's con 'not visible while working in the terminal'. A separate decision would duplicate DEC-006, and reopening the question would add churn without new information.

## Consequences

Traceability from Q-002 to DEC-006 is restored and F-009 can be resolved. CLI status line and menu bar integrations are explicitly out of scope for v1. REQ-004 remains valid. If a standalone MarkView panel is wanted later, that would be a new decision.
