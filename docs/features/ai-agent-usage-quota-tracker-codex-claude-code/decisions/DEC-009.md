## Context

Claude Code and Codex subscriptions may enforce several concurrent limits (e.g. a 5-hour session window and a weekly limit; AI inference, not verified). REQ-002/REQ-003/REQ-004 assume a single window per agent, so the headline percentage, reset time and colour are ambiguous.

## Alternatives

1. Show the most constrained window in the compact indicator, all windows in the popover
2. Show all windows in the compact indicator
3. Always show the short (session) window in the indicator, others in the popover

## Decision

An agent may have one or more quota windows. The compact indicator shows the most constrained window: the one with the highest percent used. If two windows have the same percent, it shows the one whose reset is later. The indicator's percent, time until reset and colour (DEC-008 thresholds) all come from that window, and the window is labelled briefly (e.g. '5h', 'week'). The popover lists every window with its percent used, time until reset and official/estimated marker. The user-configured fallback (REQ-005) defines a single window per agent in v1.

## Reason

Pacing is about which limit will block the user first. A fixed short window hides a nearly exhausted weekly limit. Showing all windows in the indicator clutters the terminal panel. When percents are equal, the later reset blocks the user for longer, so that window matters more.

## Consequences

The data model changes from one window per agent to a list of windows, each with an id/label, percent used, reset time and source. REQ-002, REQ-003 and REQ-004 must say 'most constrained window' and add acceptance criteria for selecting it and labelling it. The popover must render a list. The headline window can switch while in use, e.g. when the weekly limit overtakes the session limit, and the label keeps that switch understandable.
