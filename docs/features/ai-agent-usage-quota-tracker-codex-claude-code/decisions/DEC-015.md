## Context

SRC-001 states the display must show tokens remaining until the next reset. Official agent limit data (DEC-002, DEC-005) provides only percent used and reset time, with no absolute token limit. Local CLI logs (DEC-007) give absolute consumed tokens/money. REQ-004 says absolute values appear 'where available', which conflicts with the unconditional accepted fact (F-007).

## Alternatives

1. Show absolute remaining tokens only on the fallback path (user-entered limit); on the official path show remaining as percent
2. Derive absolute remaining on the official path by extrapolating the implied limit from local consumed tokens and official percent
3. Hide the official percent and always use local counts against a user-entered limit

## Decision

Remaining quota is always shown in the unit in which the limit is known. On the official path: remaining = 100% − percent used, shown as a percentage; locally counted consumed tokens/money for the same window may be shown in the popover as informational, clearly labelled 'from local logs', and are never combined with the official percent to compute a remaining or total limit. On the fallback path (user-entered limit): consumed and remaining are shown in absolute units (tokens or money) plus percent. The SRC-001 fact 'tokens remaining' is reinterpreted as 'remaining quota in the limit's unit (percent on the official path, tokens/money on the fallback path)'.

## Reason

Vendor limits are not published in tokens and may weight models or cache usage differently from raw local token counts, so an extrapolated absolute limit would be unreliable and could contradict the official percent. This conflicts with DEC-001, which treats percent as the headline metric. Showing remaining as a percent still meets the user's pacing goal, and the output stays honest and consistent.

## Consequences

REQ-002/REQ-004 acceptance criteria must state remaining as a percent on the official path and in absolute units only on the fallback path. The popover must label local-log figures as local estimates. The accepted SRC-001 fact about 'tokens remaining' needs rewording or a note linking it to this decision. Users on official plans will not see an absolute tokens-left number. If a vendor later exposes absolute limits, they can be shown without changing the model.
