## Context

REQ-001 says 'each configured agent' and 'agents with no data are shown as unavailable', but 'configured' is undefined and overlaps with DEC-003 (no limit: absolute usage plus hint) and REQ-005 (usage unavailable). MarkView already requires Claude Code and/or Codex to be installed for AI features.

## Alternatives

1. Auto-detect installed CLIs only
2. User-enabled list in settings only
3. Auto-detect built-in agents, with a per-agent hide toggle in settings, plus explicit state precedence

## Decision

Supported agents are a built-in list (v1: Claude Code, Codex). An agent is shown when it is detected: its CLI is on PATH or its data directory (~/.claude, ~/.codex) exists. The user can hide any detected agent in settings. Undetected agents are not shown. Each shown agent is in exactly one state, evaluated in this order: (1) Official: official limit data is available, so show percent, reset time and colour. (2) User limit: no official data but a user-configured limit exists, so show a local estimate against that limit. (3) No limit: local usage exists but no limit is set, so show absolute usage and a 'set a limit' hint with no progress bar (DEC-003). (4) Unavailable: neither official nor local data can be read, so show 'usage unavailable', never zero. A stale official value (DEC-010) keeps state 1 with a staleness mark.

## Reason

Auto-detection needs no setup and matches how MarkView already finds agents. The hide toggle covers users who have an agent installed but do not use it. A single precedence list removes the overlap between REQ-001, REQ-005 and DEC-003 and gives testable states.

## Consequences

REQ-001 acceptance criteria must be rewritten around detection, the hide toggle and the four states. REQ-005's 'unavailable' wording must align with state 4. Settings must list detected agents with visibility toggles. Other agents need a code change to be added to the built-in list; user-defined custom agents are out of scope for v1.
