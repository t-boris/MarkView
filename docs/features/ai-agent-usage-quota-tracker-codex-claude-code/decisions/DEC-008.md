## Context

REQ-004 requires the per-agent indicator to be coloured normal/warning/critical, but no thresholds are defined, so the criterion is untestable (F-001). SRC-001 states pacing as the purpose, which raises the question of whether colour should follow absolute percent or pace relative to elapsed window time.

## Alternatives

1. Fixed absolute thresholds on percent used (e.g. 80% / 95%)
2. Pace-relative colour: compare percent used with the share of the window elapsed
3. Hybrid: colour escalates on either absolute threshold or being ahead of pace
4. User-configurable thresholds

## Decision

Colour is driven by absolute percent of limit used: normal < 80%, warning >= 80% and < 95%, critical >= 95% (including exhausted). Thresholds are fixed constants in v1 and are not user-configurable. Pacing is shown as secondary information in the popover (percent used vs percent of window elapsed, e.g. 'ahead of pace' / 'on pace'), not in the colour. For agents in the no-limit state (DEC-003) no colour state applies.

## Reason

Absolute thresholds are simple, predictable and directly testable, and match what the official data provides (percent used). Pace-based colouring gives misleading results early in a window (small absolute usage showing red) and depends on reliable window start times, which are not always known for fallback limits (see F-006). Showing pace in the popover still serves the pacing goal without making the headline signal noisy.

## Consequences

REQ-004 acceptance criteria must state the 80% and 95% boundaries, including exact boundary values. A popover requirement or criterion for the pace line must be added. It depends on knowing the window start/length, both official and user-configured (F-006). Making the thresholds configurable can be revisited later without breaking the model.
