## Context

Q-001 asked where usage data comes from. DEC-002 already makes official limit data primary with a local-estimate fallback; this answer fixes the local source.

## Alternatives

1. A. Read local CLI logs/sessions (~/.claude, ~/.codex)
2. B. Official provider usage/billing APIs with API keys
3. C. User-entered limit and reset date, consumption from logs

## Decision

Absolute usage (tokens and, where recorded, money) is computed from the agents' local CLI logs and session files (~/.claude, ~/.codex). No provider API keys are required. This is the source for the fallback estimate (DEC-002) and for the no-limit state (DEC-003); official limit data, when available, still takes precedence for percent and reset time.

## Reason

Works with subscription plans without API keys; limits/reset times missing from logs are covered by official limit data or the user-configured fallback.

## Consequences

Log formats may change between CLI versions; unparseable logs must degrade to an 'usage unavailable' state rather than wrong numbers. Codex logs carry tokens but no cost, so money may be shown only for Claude Code.
