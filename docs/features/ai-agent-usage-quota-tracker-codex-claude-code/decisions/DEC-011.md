## Context

REQ-006 forbids modifying or refreshing-and-overwriting the agent's stored credentials. Access tokens expire, and the behaviour on 401 was undefined. An in-memory refresh may rotate the refresh token (refresh-token rotation), which would silently invalidate the CLI's stored refresh token and log the user out of the agent. On macOS, Claude Code credentials may be stored in the Keychain, so reading them can trigger a system access prompt that the user may deny.

## Alternatives

1. Fall back to the local estimate on 401 (no refresh at all)
2. Refresh in memory only, never persisting the new token
3. Show an error state with no data until the user re-authenticates

## Decision

The app never uses the refresh token, not even in memory. Credentials are re-read from the agent's store (file or Keychain, read-only) on each poll. On 401/403, a missing token, or a denied Keychain access, the agent's official data is marked unavailable. The indicator falls back to the local-log estimate (DEC-007 / REQ-005), or to the no-limit state (DEC-003) if no user limit is set, and the popover shows the hint 'Official limit data unavailable — open <agent> to refresh sign-in'. Official data resumes automatically once the agent CLI refreshes its own token. A denied Keychain prompt is not re-requested automatically in the same app session; the popover offers a manual retry.

## Reason

An in-memory refresh can rotate and invalidate the CLI's refresh token and break the user's agent session, which is worse than briefly showing stale or estimated data. The agent CLI refreshes its token on normal use, so official data recovers without the app taking on credential-management risk. The fallback path already exists under DEC-002.

## Consequences

REQ-006 gains acceptance criteria: the refresh token is never used; 401/403, a missing token, or a denied Keychain access leads to the fallback plus a hint; tokens are re-read on each poll. REQ-006 must mention read-only Keychain access and the possible system prompt. If the agent is idle for a long time, official data may stay unavailable until the user runs the agent. The polling frequency (F-003) affects how quickly recovery happens.
