## Context

Boris asked on 2026-11-18 to add Copilot's `/usage` quota data to the usage bars beside Claude, Codex, and Antigravity. In Copilot CLI 1.x (`copilot`), `/usage` shows "Active account/provider usage": the monthly `Plan` budget (`% used`, `used / limit AIC` or premium requests, and time until reset) plus `Session` (5-hour) and `Weekly` rate-limit bars when reported. Calling `copilot -p "/usage"` sends `/usage` as a prompt to the model instead of running the built-in slash command, whereas `copilot --headless --no-auto-update --log-level none --log-dir /dev/null --stdio` exposes the CLI's own JSON-RPC 2.0 server (`account.getQuota` for live quota snapshots from GitHub's `/copilot_internal/user` and `account.getCurrentAuth` for credential-free `copilotUser` metadata including `quota_reset_date_utc`). It completes in about 2 s, spends zero model tokens or AI credits, creates no session, writes no process log, and works with any sign-in method the CLI supports (`copilot login`, `gh auth login`, Keychain, environment variables).

## Alternatives

1. Run `copilot -p "/usage"`: `-p` treats `/usage` as a model prompt, spending tokens and failing if the default model is unavailable. Rejected.
2. Drive an interactive PTY session and scrape ANSI output of `/usage`: brittle TUI layout parsing, slower startup, and creates a foreground session in `~/.copilot/session-state`. Rejected.
3. Read a GitHub token directly and call `https://api.github.com/copilot_internal/user` ourselves: Copilot resolves credentials from multiple sources (its own Keychain entry, `gh` CLI, environment variables, enterprise hosts), so duplicating its auth resolution is fragile and unnecessary. Rejected.
4. Query `copilot --headless --no-auto-update --log-level none --log-dir /dev/null --stdio` with a one-shot JSON-RPC pipeline (`connect`, `account.getQuota`, `account.getCurrentAuth`). Chosen.

## Decision

Add Copilot (`CopilotUsage`) to the usage bars through `CopilotProvider.usage`. MarkView runs `copilot --headless --no-auto-update --log-level none --log-dir /dev/null --stdio` with a one-shot JSON-RPC input containing `connect`, `account.getQuota`, and `account.getCurrentAuth` and a 25 s timeout, reading no GitHub credential itself. The parser turns the finite quota buckets into `QuotaWindow` values: the monthly `Plan` window (`id: "plan"`, `label: "plan"`, `title: "Plan (used / limit AIC)"` or premium/chat requests, `resetsAt` from `quota_reset_date_utc` / `quota_reset_date` / `limited_user_reset_date`, duration of the UTC calendar month ending at `resetsAt`), plus `5-hour session` (`5h`) and `Weekly` (`week`) windows when `5hour-session-ratelimits` / `session` or `weekly-session-ratelimits` / `weekly` are present. There is no local-log fallback and no user-limit form for Copilot (its plan budget is account-wide in AI credits or premium requests, not local tokens). Refresh follows the standard 5-minute visible polling rhythm and 60 s manual refresh cooldown.

## Reason

Uses the CLI's own headless JSON-RPC interface without spending tokens or reading credentials, handles every authentication source Copilot supports, leaves no session or log file behind, and surfaces the same Plan, Session, and Weekly figures that `/usage` renders.

## Consequences

Supersedes DEC-010 of flexible-files-views-and-visible-agent-usage for Copilot CLI; Cline and Gemini CLI stay out. `CLITool.usageTracked` is now `["claude", "codex", "copilot", "antigravity"]`.
