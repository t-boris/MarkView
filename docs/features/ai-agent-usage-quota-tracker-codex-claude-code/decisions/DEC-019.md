## Context

Claude Code keeps its sign-in in the macOS Keychain item "Claude Code-credentials", created with /usr/bin/security. Reading it with the Security framework makes macOS ask the user for access; DEC-011 allowed for that prompt.

## Alternatives

1. Read it silently with /usr/bin/security find-generic-password -w (the tool Claude Code uses)
2. Read it with the Security framework and let macOS prompt

## Decision

The app reads the item read-only with /usr/bin/security on each poll. Exit code 44 (not found) counts as signed out; any other failure is handled as a denied Keychain access (DEC-011). A ~/.claude/.credentials.json file, when present, is read first.

## Reason

No prompt, and the item is still only read. The token is used in memory for one request and is never stored or logged.

## Consequences

If Claude Code changes where it stores credentials, official data becomes unavailable and the local estimate is shown (DEC-002).
