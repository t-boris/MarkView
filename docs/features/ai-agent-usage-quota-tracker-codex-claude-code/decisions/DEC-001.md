## Context

Agents express limits in different units (tokens, messages, dollars); the tracker needs one headline metric that works across agents.

## Alternatives

1. Percent of limit plus time until reset
2. Absolute tokens or dollars used/remaining

## Decision

The headline metric for each agent is the percentage of the current window's limit used, shown together with the time until reset. Absolute tokens/dollars are secondary details where available.

## Reason

Percent is comparable across agents with different limit units and directly supports pacing; absolute numbers make it hard to judge pace.

## Consequences

The limit (or the already-computed percentage) must be obtainable for each agent; agents whose limit is unknown need a fallback display (to be settled with the data-source question).
