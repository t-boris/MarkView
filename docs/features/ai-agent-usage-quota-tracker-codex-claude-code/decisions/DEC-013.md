## Context

REQ-005 acceptance criterion 'Usage is read only from local files; no API keys are requested' can be read as feature-wide, contradicting DEC-005/REQ-006, where the official path reads stored Claude Code/Codex OAuth credentials and makes network requests for limit data (F-008).

## Alternatives

1. Scope the criterion to the fallback path only
2. Apply it to the whole feature (would require dropping DEC-005 official data path)
3. Delete the criterion from REQ-005

## Decision

The criterion applies to the fallback path only. Reword it to: 'In fallback mode, usage is computed only from local agent CLI logs/session files; the fallback path makes no network requests and never asks the user to enter API keys or credentials.' Credential use for official limit data is governed solely by DEC-005 and REQ-006.

## Reason

DEC-002 and DEC-005 are accepted and define the official path using stored credentials; a feature-wide ban would reverse them. Keeping the criterion but scoping it preserves a testable guarantee for the fallback (offline, no key entry) and removes ambiguity for QA and security review.

## Consequences

REQ-005 criterion text is updated; F-008 is resolved. QA tests fallback with network disabled and verifies no key/credential prompt. Feature-wide statement 'the user is never asked to enter API keys' remains true across both paths, since the official path reuses existing stored credentials.
