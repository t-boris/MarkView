## Context

REQ-005 lets the user enter a limit and reset window for agents without official limit data, but does not say where this is configured or how the window is expressed. The REQ-003 countdown needs a deterministic reset time, which a bare duration does not provide.

## Alternatives

1. Rolling duration starting from first usage in the window (anchor inferred from logs)
2. Fixed anchor date/time plus a period (chosen)
3. Calendar-only presets (daily at midnight, monthly on day 1) without custom anchor

## Decision

The fallback window is defined by an anchor date/time (local timezone) plus a period chosen from presets (5 hours, 1 day, 7 days, 1 month) or a custom number of hours/days. The current window is [anchor + n*period, anchor + (n+1)*period) for the n containing now; the next reset is its end. Monthly periods add calendar months, clamping to the last day of the month. Limit (value plus unit: tokens or USD; USD allowed only if the local logs record cost) and window are edited per agent in a settings form opened from the agent's detail popover (including the 'set a limit' hint of DEC-003) and persisted in MarkView app settings. The limit can be cleared, returning the agent to the no-limit state. The anchor defaults to the current time when the form is first opened.

## Reason

A fixed anchor gives a deterministic, explainable countdown that the user can align with their plan's real billing/reset time; a rolling-from-first-use window depends on inferring session starts from logs, which is fragile and would disagree with vendor behaviour. Placing the entry point in the popover keeps it next to the indicator (DEC-006) and the no-limit hint.

## Consequences

REQ-005 and REQ-003 must be updated with the anchor+period model and acceptance criteria (window computation, month clamping, timezone, clearing the limit). A settings form in the popover must be designed. Estimates can drift from vendor windows if the user sets the wrong anchor; that is acceptable since the fallback is labelled an estimate (DEC-002). Rolling windows are out of scope for v1.
