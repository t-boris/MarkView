## Context

REQ-002 fetches official limit data from undocumented vendor endpoints using locally stored agent credentials (DEC-005) and falls back to parsing local CLI logs (DEC-007). No refresh interval, rate limiting, caching or staleness indication is defined (F-003). Aggressive polling risks throttling or account flags; silent stale values mislead pacing.

## Alternatives

1. Fixed short polling (e.g. every 30-60 s) for official data
2. On-demand only: fetch when the popover is opened or the user clicks refresh
3. Moderate polling (5 min) plus on-demand refresh with cooldown, backoff on errors, file-watch for local logs, and visible staleness (chosen)
4. User-configurable refresh interval

## Decision

Official limit data: fetched per agent at most once every 5 minutes while the AI terminal panel is visible, plus immediately on panel open if the cached value is older than 5 minutes; manual refresh from the popover is allowed with a 60 s per-agent cooldown. On HTTP 429 or errors, exponential backoff starting at 5 min, capped at 30 min, honoring Retry-After when present. No polling while the panel is hidden or the app is in background. Local log estimates: recomputed on file-system change events in ~/.claude and ~/.codex, debounced to at most once every 30 s. The last successful value per agent is cached in memory only (no credential or response persistence) and the popover shows 'updated N min ago'; values older than 15 minutes are shown as stale (dimmed with a stale marker) while still displayed. If the official fetch fails and no fresh cached value exists, the display falls back to the local estimate per REQ-002.

## Reason

5-minute cadence is ample for pacing (quota windows are hours/days) and keeps request volume against undocumented endpoints low; the cooldown and backoff protect the user's account from throttling; file-watching gives near-real-time local estimates cheaply; explicit staleness keeps DEC-002's honesty about data provenance. Configurability adds settings UI with little value in v1.

## Consequences

REQ-002 gains acceptance criteria for refresh interval, cooldown, backoff and stale marking; the popover must show last-updated time and a refresh action; a new requirement or AC under REQ-004 covers the stale visual state. Usage shown may lag by up to 5 minutes for official data. Constants (5 min, 60 s, 30 s, 15 min, 30 min cap) are fixed in v1. Resolves F-003.
