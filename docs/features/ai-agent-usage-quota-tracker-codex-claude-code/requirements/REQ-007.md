## Statement

The system shall show the Antigravity quota windows (per model group: 5-hour and weekly, percent used and reset time) in the top bar and its popover beside Claude Code and Codex, read from the Antigravity CLI's own /usage command, without reading any Antigravity credential and without spending model tokens.

## Acceptance Criteria

- [ ] With agy signed in, a chip 'Antigravity' appears beside Claude and Codex showing the most used window (percent used, group and window in the label, countdown to its reset); the popover lists every window of every group with a meter and the Official badge.
- [ ] A window nobody has used shows 0% used and 'Not used yet in this window', without a countdown or pace (agy reports now + window for it).
- [ ] Signed out: the chip says usage is unavailable and the popover says to open Antigravity to refresh the sign-in; the login link the CLI prints is never shown, stored or logged, the CLI is cut at 25 s, and the next automatic try is 30 minutes later.
- [ ] agy missing, not answering in time, or answering in a shape the parser does not know: 'usage unavailable' with the reason, never zero; automatic retries back off (5 to 30 minutes).
- [ ] Antigravity is read every 5 minutes while an indicator is visible (the same as Claude and Codex), not while the app is in the background; the manual refresh keeps its 60 s cooldown; each read leaves no log file behind (--log-file /dev/null) and starts no conversation.
- [ ] Settings has a 'Show Antigravity usage' switch (disabled when agy is not detected); the popover has no 'Set a limit' form and no local-log figures for Antigravity.
- [x] The parser turns the real `agy --output-format json -p "/usage"` output (seen 2026-11-14) into windows, clamps fractions to 0-100% used, skips buckets without a fraction and is covered by tools/tests/agent-usage-tests.sh, including checks that fail when the rules are turned off.
