## Context

The first release needs an explicit execution trust boundary.

## Alternatives

1. Run trusted local projects with explicit access boundaries.
2. Support untrusted projects with enforced process isolation.

## Decision

Support trusted local projects only, with separate controls for secrets, simulated requests and permitted connections.

## Reason

The owner selected the trusted-project model.

## Consequences

Application code runs with the user's permissions. Network interception must not be described as protection against malicious project code.
