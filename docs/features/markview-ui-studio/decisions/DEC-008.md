## Context

Boris (2026-11-04): changes made in UI Studio are not tracked anywhere, neither as features nor as bugs, and that is very bad. Today only the manual Export feature (CAP-05) in History records them.

## Alternatives

1. One record per change: many tiny features
2. Ask where each change goes: an extra step every time
3. Keep the manual export only: changes stay untracked unless someone remembers

## Decision

Every applied change is recorded automatically. A conversation that changes code becomes one feature, titled from its first request. Each applied change is a requirement of it, with the element, scope, files, before and after pictures and checks, and status implemented; Undo marks it reverted. Clear starts the next feature. The assistant classifies each change: a fix of something broken (overlap, wrong text, an error) is filed as a bug marked fixed and linked to the feature; a new or different look or behaviour is a requirement. The classification is shown on the change and can be switched.

## Reason

Boris chose "Feature per conversation" and "AI decides" (2026-11-04). A conversation is the natural unit of one piece of UI work, and the tracker should show what the interface gained and what was repaired without extra steps.

## Consequences

The existing feature writer (StudioFeatureWriter, CAP-05) is reused for the conversation's feature; bugs go through the bug store. The feature is written through the same stores as the markview tools, so ids and links stay consistent. The manual export stays for combining changes across conversations.
