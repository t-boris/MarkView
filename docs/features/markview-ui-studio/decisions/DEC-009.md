## Context

Boris (2026-11-04) wants to tell the assistant things like "show me some component", "fill it with random numbers" or "fill it as you see fit". These change what the view shows, not the code. Today a scenario's data, role, overrides and restoration steps can only be changed by hand, and the composer offers Ask (read-only) and Change (edits source files).

## Alternatives

1. Temporary until Reset: the view could not be reproduced later
2. A third Show button: explicit, but one more choice per request

## Decision

A context request makes a new saved scenario derived from the current one.
- It may change the simulated records, the role and user, the clock and locale, per-rule overrides (error, empty, loading, latency), the route, and restoration steps that open a dialog or fill a form.
- The new scenario becomes active, appears in the Scenario menu, and Undo returns to the previous scenario.
- The request goes through the same composer. The assistant classifies it as a question, a context change or a code change, and the turn says which it did. Ask stays read-only: an Ask request never changes the context or the code.
- Source files are never touched by a context change.

## Reason

Boris chose "New saved scenario" and "AI decides" (2026-11-04). A saved scenario keeps before and after captures reproducible and gives change tracking (DEC-008) something to refer to.

## Consequences

- The edit-plan schema gets a context branch: scenario patch, records, overrides, route and steps. It is validated against the environment's entities before it is applied.
- A context change restores the page in the new scenario and verifies that the page loads.
- Scenario naming and the Scenario menu grow with use, so derived scenarios carry the request as their description.
- Built right after BUG-076, before REQ-012 and REQ-010.
