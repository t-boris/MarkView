## Context

DEC-004 kept SSR and server adapters out of the first release, so UI Studio simulated only requests made in the browser. On vivaa-platform (Next.js 16) the server components call marketplace-core themselves: exchange rates and served cities fail, the page shows "Couldn't load the cities", and "Try again" repeats the server call. The page's test clock also differs from the server's real clock, so server-rendered text does not match and React reports hydration errors on every load.

## Alternatives

1. Keep the exclusion and only list the server requests that were not simulated
2. Use the real clock for server-rendered apps instead of the scenario's test time

## Decision

UI Studio simulates the HTTP requests the development server makes itself: it starts the server with the project's backend URL variables pointed at MarkView's loopback gateway, answers them with the same simulator and rule preparation as page requests, and replaces the project's secrets with test values. The server also runs on the scenario's test clock, time zone and locale. Database, message-queue and native adapters, hard-coded hosts and servers MarkView did not start stay outside and are disclosed.

## Reason

Boris chose to simulate server requests (2026-11-04) after seeing a server-rendered app fail in UI Studio, and chose the same test clock on the server so scenarios stay reproducible.

## Consequences

The DEC-004 exclusion of server-side requests is reversed; REQ-001's SSR criterion is reworded. Server connections and kept-real secrets become part of the environment configuration.
