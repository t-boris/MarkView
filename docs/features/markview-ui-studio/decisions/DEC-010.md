## Context

Boris (2026-11-04): "Зачем там две кнопки Ask и Change? Какой-то бред." He asked the assistant to add test packages to vivaa's home page. It did not understand that this is a data request and told him to press Ask or Change. DEC-009 kept Ask as a separate read-only button.

## Alternatives

1. Keep Ask and Change: rejected by Boris
2. Three buttons: more choices, still the person's job

## Decision

The composer has one Send action. For each request the assistant chooses one of three kinds:
- **answer** (a question; nothing changes);
- **context** (data, role, clock, states, route and page steps; a new saved scenario, as in DEC-009);
- **code** (source edits, verified and undoable).

The turn states which kind it chose and what changed. A request to see, add, fill or show data is a context change, never a refusal or a pointer to another button. A selection is optional: without one, the request is about the current page. This supersedes DEC-009's point that Ask stays a separate button.

## Reason

Boris rejected the two buttons outright. Every outcome stays reversible: context changes through scenario Undo, code changes through operation Undo. Choosing the kind is the assistant's job, not the person's.

## Consequences

- The edit-plan schema gains `kind: answer | context | code`.
- The question path is folded into the same call.
- The thread shows the kind per turn.
- Change tracking (DEC-008) records code and context turns.
