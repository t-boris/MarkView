## Statement

The system shall let the person sign in, sign up, verify, reset a password and submit any form in a UI Studio session with any input, signing in the scenario's test user, including OAuth sign-in and pages outside the application, without contacting a real service.

## Acceptance Criteria

- [ ] In a project that uses Supabase Auth, signing in with any email and password lands signed in, and the app's server-side session check (getUser) sees the scenario's test user
- [ ] Sign-up, OTP and magic-link verification, password reset and sign-out answer success with any input
- [ ] The access token is a JWT with three non-empty segments whose expiry lies after the scenario's test time, and its subject and email are the scenario user's
- [ ] "Continue with Google" (or any OAuth button) returns to the application signed in: a navigation to a simulated service is answered by the simulation, and a navigation to an external site shows a local simulated page with Continue that returns to the app's redirect address with a code and the original state
- [ ] AI-prepared rules for other providers and forms follow the same policy: they never reject input unless the scenario asks for an error, and `{{studio.token}}`, `{{studio.user.*}}` and `{{studio.expiresAt}}` in a fixed response are replaced with the scenario's consistent test values
- [ ] No real credential, token or typed password is sent to a real service or written to a log, prompt or environment.json
