## Statement

The system shall keep the application's screens in the project, find them without being asked, and prepare the main ones ahead with the assistant so that each is a ready scenario with sign-in, role, filled simulated data and the steps to reach it.

## Acceptance Criteria

- [ ] The list of screens is saved in .markview/studio/screens.json and is still there at the next launch; files without the new optional fields still open
- [ ] The list is found automatically once, after the environment map has finished, and Refresh still works; a re-discovery keeps the link of a screen that has the same route and selector
- [ ] At most 8 main screens are prepared ahead, one at a time, with a deadline for each, a banner Preparing screens n of 8 with Cancel, and the session stays usable meanwhile
- [ ] Preparation runs only the assistant phase and the static validator: it does not load a page, does not track a requirement and always derives from the Populated preset, never from the active scenario
- [ ] Each prepared screen is an ordinary scenario saved with a stable id, listed under Saved, with data kept small
- [ ] Choosing a ready screen activates its scenario without an assistant call; the first activation verifies the destination and the visible element, a miss falls back to the correction request, a pass marks the screen verified
- [ ] The Screens menu shows the status of each screen: ready, needs refresh, preparing, failed with a retry, not prepared; a change of the files the screen's source names marks it needs refresh
- [ ] A screen that is not prepared is prepared at its first click and the result is saved
