## Statement

When the page reports an error (an uncaught error, a logged Error, or the framework's error screen) while it shows simulated data, UI Studio shall offer **Fix data**. The assistant then reads the error, its stack, the records involved and the code, and corrects the environment's data so that the page works.

## Acceptance Criteria

- [x] A page error in the session shows a Fix data action, both in the banner and on the error's row in the Log
- [x] Fix data sends the assistant the error message and stack (redacted), the route, the entities and records the page's recent requests answered with, and the rules that answered them. The assistant reads the code (read-only) to find the values and shapes the code expects
- [x] The answer either corrects records of the environment's seed (and of the active scenario when it has its own data), with a one-line reason per change, or says the error is not caused by data and points at the code
- [x] The corrections are validated like a preparation's records, saved in .markview/studio/environment.json, logged ("Fixed data: customBundle.status draft → editable in 6 records"), and the page reloads
- [x] ~~Nothing happens without the click (Boris, 2026-11-04). The same error is not offered or repaired again unless the last fix left it, within the limits of REQ-020
