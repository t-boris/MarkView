## Statement

The system shall place any web application in a simulated environment, without knowing its backend in advance: it finds the APIs the application calls from the page and from its server, simulates all of them, and fills them with coherent data, so every screen shows content and every action succeeds.

## Acceptance Criteria

- [ ] On the first open, the assistant maps the APIs the application's code calls (browser and server, every service variable and route it can find), not only the requests of the first page. It prepares rules, entities and seed for them in the background, with visible progress, and saves them in the environment
- [x] The seed is coherent: related records reference each other, and every group, filter value, tab and carousel the screens show has records. A page is never empty because of the simulation unless the scenario asks for empty
- [x] Any request the application makes is answered: an unknown one is prepared, and a write, sign-in or submission succeeds with the expected answer (DEC-007). Only protocols MarkView cannot serve (GraphQL, WebSocket, streaming) are reported as unsupported
- [ ] Paging, sorting and search parameters behave like a real API over the simulated records
- [x] The environment can be extended or refilled from the conversation ("add test packages to every category") as a context change (REQ-013, DEC-010)
