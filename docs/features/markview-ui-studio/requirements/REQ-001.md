## Statement

Launch actual client-rendered project interfaces across web frameworks, including Electron renderers, in managed test sessions within native MarkView. Exclude SSR execution and server or native dependency adapters from the first release, disclose scenario compatibility limitations, and replace existing-code reconstruction while retaining requirements-based prototyping.

## Acceptance Criteria

- [ ] A project is not rejected solely because it uses a client framework other than React or a bundler other than Vite.
- [ ] Electron support runs the actual renderer as a web interface without requiring Electron main-process execution, preload execution, IPC or native dependency adapters.
- [ ] SSR execution and server/database or native dependency adapters remain outside the first release. A framework name alone does not exclude a browser-executable client-rendered target.
- [ ] Each session reports prepared dependencies, unsupported dependencies and scenario readiness limitations. No-op Electron stand-ins do not establish that a dependent scenario is ready or reproducibly simulated.
- [ ] Each session runs the actual project UI; no permanent HTML reconstruction substitutes for the application.
- [ ] Creating a visual session from existing code opens UI Studio instead of generating a reconstruction. Prototyping from requirements remains available.
- [ ] Previously saved reconstructions remain accessible and are identified as historical prototypes rather than current application sessions.
