## Statement

Launch actual project interfaces across web frameworks, including Electron renderers and server-rendered apps, in managed test sessions within native MarkView. The development server's own HTTP requests and its clock, time zone and locale are simulated (DEC-006); database, message-queue and native dependency adapters stay outside. Disclose scenario compatibility limitations, and replace existing-code reconstruction while retaining requirements-based prototyping.

## Acceptance Criteria

- [x] A project is not rejected solely because it uses a client framework other than React or a bundler other than Vite.
- [x] Electron support runs the actual renderer as a web interface without requiring Electron main-process execution, preload execution, IPC or native dependency adapters.
- [x] Server/database or native dependency adapters remain outside UI Studio; the development server's own HTTP requests and environment are simulated as REQ-007 describes. A framework name alone does not exclude a target.
- [x] Each session reports prepared dependencies, unsupported dependencies and scenario readiness limitations. No-op Electron stand-ins do not establish that a dependent scenario is ready or reproducibly simulated.
- [x] Each session runs the actual project UI; no permanent HTML reconstruction substitutes for the application.
- [x] Creating a visual session from existing code opens UI Studio instead of generating a reconstruction. Prototyping from requirements remains available.
- [x] Previously saved reconstructions remain accessible and are identified as historical prototypes rather than current application sessions.
