## Statement

The system shall simulate the application's WebSocket and server-sent event connections and its GraphQL requests, from the page and from its development server, over the same scenario state as its REST requests, instead of reporting them as unsupported.

## Acceptance Criteria

- [ ] A WebSocket the page opens to a simulated service (including Supabase Realtime and Socket.IO-style endpoints) connects to MarkView. It receives the messages its channel rules define on connect, in answer to a message it sends, and as scenario events, with no real network
- [ ] A WebSocket or server-sent event stream the development server opens through a simulated connection is served by the gateway the same way
- [ ] Messages change and read the same entities as REST: a chat message sent over a socket appears in the REST list, and a record created through REST can be pushed to subscribers
- [ ] GraphQL queries and mutations are answered per operation over the simulated entities, and subscriptions are served over the simulated socket
- [ ] The assistant prepares channel and operation rules from the code, as it does for REST, under the mock-up policy (DEC-007). The log shows each connection and message, redacted
- [ ] Unknown messages are prepared like unknown requests. A protocol MarkView truly cannot serve is named in the turn and the log, never silently dropped
