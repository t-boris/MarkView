## Statement

The system shall repair the page errors it can repair by itself when an application is opened in UI Studio and when a page reports a later error, without a click, and shall never loop, never hide what it did and let the person undo it.

## Acceptance Criteria

- [ ] After the first restore of the page in launch has settled, Studio looks at the problems of that page and repairs the fixable ones; a later page error starts a repair after a debounce of about 2 seconds
- [ ] A repair never starts while the session is busy, mapping, preparing, trying a scenario or closed, nor inside a restore, and never overlaps the initial restore
- [ ] A page data error goes through the existing Fix data contract (records only, validated on a copy, saved only when every correction is valid) and the page reloads on the corrected data
- [ ] A request without a rule gets one more preparation with the longer deadline, and the page reloads by itself afterwards unless something was typed on it
- [ ] A redirect to a sign-in page, when the scenario did not ask for the sign-in screen, is answered by one assistant-made signed-in scenario (the REQ-010 path), verified, saved, and replayed at the next open
- [ ] A ledger per scenario and error keeps the outcome: an error judged not caused by data, or refused, is not repeated; at most 2 attempts per error and 3 automatic repairs per open
- [ ] Each repair writes a Log notice with its reason and shows a banner Fixed automatically with Undo; Undo writes the old values back and reloads, for the running session
- [ ] The Environment panel has a switch, Repair errors automatically, on by default, kept in the environment file as an optional field so older files still open
- [ ] Errors that are code errors or blocked third-party services are only reported, never retried
