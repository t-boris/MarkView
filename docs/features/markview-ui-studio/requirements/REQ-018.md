## Statement

The system shall let a page that loads a known third-party SDK (Stripe.js, reCAPTCHA, Google Maps, analytics) open and work in a UI Studio session without reaching the SDK's servers, and shall show every payment stand-in as simulated.

## Acceptance Criteria

- [ ] A page that loads https://js.stripe.com/v3 through @stripe/stripe-js and renders a Payment Element shows an enabled Pay button, no framework error overlay and no 'Failed to load Stripe.js' error, with no request leaving the Mac.
- [ ] Every payment stand-in is labelled 'Simulated payment — no card is charged', and the session dependencies list the SDK as simulated, not as unsupported or degraded.
- [ ] In a normal scenario confirmPayment succeeds with a paymentIntent of status 'succeeded' and stays on the page; in an error scenario a card payment returns the card_declined error and a bank-redirect method returns to return_url with redirect_status=failed.
- [ ] A reCAPTCHA widget shows a labelled placeholder that is solved and answers a token; a Google Maps script with a callback= parameter or the inline importLibrary loader gives a labelled placeholder map and calls the page's callback; Google Analytics, Tag Manager, Segment, Mixpanel, PostHog and Plausible load as no-ops and call their callbacks.
- [ ] A script address the person allowed in the environment settings is never replaced, and an SDK address that is not registered, or a look-alike host, stays blocked and is reported as before.
