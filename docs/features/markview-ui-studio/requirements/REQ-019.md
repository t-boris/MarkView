## Statement

The system shall let the person act on every problem UI Studio shows, where the problem is shown: each problem row of the Log offers the action that fits its kind, the Log has a Fix problems action for all of them, and an expected consequence of a page reload is not shown as a problem.

## Acceptance Criteria

- [ ] Each Log row that is a problem is classified by fixed rules into a page data error (Fix), a request or channel without a rule (Prepare), a redirect to a sign-in page (Sign in), a blocked third-party service, an error the assistant judged not caused by data, or noise
- [ ] A page data error keeps its Fix action after the page was reloaded by a scenario switch: the action works on the error, not on the page generation
- [ ] The Log drawer header has Fix problems, which runs every fixable problem in turn, one at a time, with the busy banner and Cancel
- [ ] The toolbar Log button opens the Log on Problems when fixable problems exist, and the banner offers Open Log
- [ ] A message of an earlier page generation is answered silently, is not written as a warning and is not counted as a problem
- [ ] A problem that cannot be repaired by data (code error, blocked service) shows why, and is not offered a Fix that will not help
