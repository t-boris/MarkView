## Statement

The system shall let a UI Studio request change what the view shows (simulated data, role, clock, error and empty states, route and page state) without editing source files, and keep the result as a reproducible scenario.

## Acceptance Criteria

- [x] A request such as "fill it with random numbers" or "fill it as you see fit" replaces or generates the simulated records of the entities the page shows. The records are valid against the environment's entities, and the page reloads showing them
- [x] A request such as "show me the booking dialog" or "show the error state" finds the route, the restoration steps (clicks, typing) or the override that brings the view there, and the page ends in that state
- [x] A context change becomes a new saved scenario derived from the current one, with the request as its description. It is selectable in the Scenario menu, and Undo returns to the previous scenario
- [x] The assistant tells a context change apart from a question and a code change. The turn states which it did and what changed (records, overrides, route, steps). Ask never changes anything, and a context change never touches source files
- [x] Unsupported parts (an entity with no rules, a state no step can reach) are reported in the turn instead of being faked silently
