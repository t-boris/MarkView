## Statement

The system shall record every change applied in UI Studio without extra steps: the conversation as one feature, each change as a requirement of it or, when the change repairs something broken, as a fixed bug linked to that feature.

## Acceptance Criteria

- [ ] The first applied change of a conversation creates a feature titled from its request; later changes of the same conversation add to that feature, and Clear makes the next change start a new feature
- [ ] Each applied change is a requirement with the request, element, scope, changed files, before and after pictures and checks, and is marked implemented
- [ ] A change the assistant classifies as a repair is filed as a bug with status fixed, linked to the conversation's feature, with the same evidence
- [ ] The change's turn shows where it was recorded (feature and requirement or bug id) and offers to switch between requirement and bug
- [ ] Undo of a change marks its requirement or bug as reverted; nothing is deleted
- [ ] Records are written through the project's feature and bug stores, with credentials and personal data redacted, and work when the project has no GitHub integration
