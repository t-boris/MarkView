## Statement

When UI Studio runs an Electron renderer as a web page, the globals its preload exposes shall answer from the simulation, over the same scenario state as REST. This covers invoke-style calls, writes and event subscriptions, and replaces the stand-ins that do nothing.

## Acceptance Criteria

- [x] A call such as `window.strikedesk.settings.getDocument()` returns a promise of the simulated answer. The call becomes a simulated request, `<verb> http://electron.ipc/<global>/<path>/<scalar args…>`, with any object argument as its body, so entity operations (list, get, create, update, delete) and fixed answers apply
- [x] An unknown IPC call is prepared like an unknown request: the assistant reads the preload and the main process's `ipcMain.handle` / `on` handlers to learn the answer's shape, under the mock-up policy (DEC-007)
- [x] The application map (REQ-014) lists the preload's IPC methods as endpoints of an `electron-ipc` service and prepares them up front. A map made before this version is extended with them, not redone
- [x] A method that takes a callback (`onDocumentApplied(cb)`) returns an unsubscribe function at once. Channel rules (REQ-015) can push to it
- [x] Each IPC call appears in the session log like a request
