## Context

The app only sends a prompt to the AI terminal and runs no git operations (DEC-002). REQ-004 requires per-bug status updates based on the AI's outcome, but it does not say who writes the status or which statuses are used. The target statuses for fixed and not-fixed bugs are also unnamed.

## Alternatives

1. AI edits each bug file's status field directly, following the prompt
2. App parses a structured report from terminal output
3. User confirms statuses manually after reading the report

## Decision

The batch prompt lists the file path of each bug and tells the AI to update each bug file's frontmatter after it finishes that bug. A fixed bug gets status 'fixed', set only after its per-bug commit exists. A bug the AI could not fix goes back to status 'open', and the AI appends a short 'AI fix attempt' note with the reason to the bug body. The AI does not touch bugs outside the batch. The app does not parse terminal output; it shows the new statuses through its normal file watching. A bug left in 'fixing' after the run means the run was interrupted, and the user can reset it manually.

## Reason

This matches the prompt-only architecture of DEC-002/DEC-003: the AI already edits files in the workspace, and the Markdown files are the source of truth. Parsing terminal output is brittle and requires new infrastructure. Manual confirmation defeats the point of batching. Tying 'fixed' to the existing commit keeps the status consistent with the per-bug commits in DEC-001.

## Consequences

REQ-004 acceptance criteria must name the statuses 'fixed' and 'open' and mention the reason note. The prompt must include the absolute or workspace-relative path of every bug file, which also relates to F-007. If a bug file is edited on the batch branch, its status change lives on that branch until the branch is merged; this must be checked against where bug files are stored. Interrupted runs leave bugs in 'fixing', and the user needs a manual way to reset them. The outcome depends on the AI following the instructions; there is no app-side check.
