## Context

REQ-006 requires AI-suggested similar bugs shown in the Issues panel with an 'Add' control per item. Project fact: the app reaches AI only through the terminal, which cannot return structured results to the UI. Supporting REQ-006 as written would need a new non-terminal AI integration (provider, key, context limits, loading and error states). The feature's core value is the basket plus one batch run on one branch (REQ-001..005), and none of it depends on suggestions. Several core findings are still open (F-002, F-003, F-004, F-006, F-007, F-008).

## Alternatives

1. Send a prompt to the AI terminal and have the user add the listed IDs manually (REQ-006 criteria rewritten, no in-panel results)
2. Make a separate structured AI call with results in the Issues panel (new provider dependency, loading, error and timeout requirements)
3. Use a local text-similarity heuristic (offline, but no longer AI, needs an algorithm and threshold, lower quality)
4. Remove from scope: REQ-006 deferred, item moved to OUT

## Decision

Remove 'Suggest similar' from this feature. Set REQ-006 to deferred and add 'AI suggestions of similar bugs for the basket' to the OUT scope. The basket and the batch Fix with AI are unchanged. Similar-bug suggestion may return as a separate feature once a mechanism for returning AI results to the UI exists.

## Reason

The terminal option breaks REQ-006's core promise of in-panel results. The separate AI call adds a new external dependency and a new integration surface that belong to their own feature. The heuristic changes the requirement's nature and needs an unspecified algorithm. Deferring keeps the feature focused and shippable, and it closes a high-severity gap without blocking the core workflow. Users can still add related bugs to the basket manually.

## Consequences

F-005 is resolved. REQ-006 becomes deferred and DEC-005 no longer implies suggestions. The Scope section must list suggestions under OUT (this can be done together with F-002). There is no new AI or provider dependency. A follow-up feature is needed if the team wants suggestions, and it must first decide how AI results reach the UI.
