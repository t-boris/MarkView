## Context

The Scope section still describes per-feature selection in the Bug panel and lists cross-feature batching as OUT. This contradicts DEC-004 (cross-feature batching is IN) and DEC-005 (shared basket in the Issues panel). The other OUT items are marked 'inferred, to confirm'.

## Alternatives

1. A: Only remove the cross-feature OUT item and leave the rest as is
2. B: Rewrite the Scope section in full from the accepted decisions and confirm the remaining OUT items
3. C: Remove the Scope section and rely on the requirements list

## Decision

B. IN: add bugs from the Issues panel to a shared basket and remove them from it; bugs may come from different features; one 'Fix with AI' action for the basket starts one AI run; the AI creates and checks out one branch for the batch (the app runs no git operations); the AI asks the user when the working tree is dirty or the branch already exists; the prompt lists all selected bugs; every selected bug is set to 'fixing' at start; the AI makes one commit per fixed bug, reports an outcome for each bug, and each bug's status is updated from that outcome. OUT (confirmed): automatic PR creation; running batches in parallel. Bug closing after the fix follows DEC-006 (proposed) and is not listed as OUT until DEC-006 is accepted. 'Suggest similar bugs' stays IN (REQ-006) until DEC-007 is decided. The 'inferred, to confirm' marker is removed.

## Reason

The Scope section is the first thing readers and implementers see, so it must agree with the accepted decisions. A partial fix (A) would keep the Bug-panel wording and the unconfirmed items. Removing the section (C) would lose the explicit OUT boundaries. PR creation and parallel batches stay OUT because they add git and concurrency complexity that the core value does not need.

## Consequences

The Scope section and the requirements agree. When DEC-006 and DEC-007 are resolved, the Scope section must be updated again. F-004 (concurrent runs) is consistent with the parallel-batches OUT item, but it still needs a rule for bugs that are already in 'fixing'. F-002 can be closed after the edit.
