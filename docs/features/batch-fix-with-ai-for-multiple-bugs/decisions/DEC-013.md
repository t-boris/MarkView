## Context

The basket is cleared when a batch starts (REQ-001). If a run is cancelled, its bugs stay in 'fixing'.

## Alternatives

1. Persist a batch record (bugs, branch)
2. Keep the basket until the run finishes
3. No record; manual reset of statuses

## Decision

The app does not store a batch record. The batch prompt stays visible in the AI terminal history, and the AI records the branch in each bug file when it updates the outcome (DEC-006). Bugs left in 'fixing' after a cancelled run are reset manually through the existing status control, and resetting them to 'open' makes them eligible for the basket again.

## Reason

This avoids new persistent state in an in-memory basket design (DEC-008). Cancellation is rare, and the manual recovery is cheap.

## Consequences

Accepted risk: bugs can stay in 'fixing' after a cancelled run. A batch history can be added later if needed.
