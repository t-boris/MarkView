## Context

REQ-001 says the basket 'persists while the user navigates between features'. It does not say whether the basket survives an app restart or a workspace switch, whether each window has its own basket, or what happens to basket items whose bug is closed, deleted or already in 'fixing' status (F-003).

## Alternatives

1. In-memory for the session only, one basket per workspace window
2. Persisted per workspace on disk (e.g. a basket file in the workspace)
3. Single global in-memory basket shared across all windows

## Decision

The basket is in-memory state owned by the workspace window. Each window has its own basket. The basket survives feature navigation inside the window and is discarded when the window closes, the app quits, or the window switches to another workspace. Bugs are referenced by feature ID and bug ID. Stale items are cleaned up each time the basket is shown and again when the batch starts: the app silently removes deleted bugs and bugs that are no longer open. It shows a short notice with the number of removed items. Bugs in 'fixing' status stay in the basket but are marked as 'already being fixed' and are not included in the batch. They also do not count toward the 2-bug minimum.

## Reason

A basket is a short-lived working selection. Saving it to disk would add files to a docs-first workspace that the team reviews in git. It would also need migrations and would lead to stale state after restarts, for little gain. Giving each window its own basket keeps workspaces separate and avoids sync problems between windows. Validating the basket at display time and at batch start protects the batch prompt from closed, deleted or already-fixing bugs no matter how they changed. The 'fixing' part also partly covers F-004.

## Consequences

REQ-001 needs acceptance criteria for: in-memory lifetime per window; clearing the basket on workspace switch or window close; removing closed and deleted bugs with a notice; excluding 'fixing' bugs from the batch count. Users lose their selection on restart; this is accepted. The concurrent-run handling in F-004 still needs its own resolution. If users later ask for a basket that survives restarts, the decision can be revisited and disk persistence added.
