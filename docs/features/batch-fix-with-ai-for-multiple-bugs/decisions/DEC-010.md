## Context

REQ-001 says 'open bug' without defining it relative to 'fixing'. Concurrent runs are OUT of scope, but the busy-terminal case is not specified.

## Alternatives

1. Allow any non-closed bug, including 'fixing'
2. Only 'open' bugs; block start while terminal busy
3. Queue the batch until the terminal is free

## Decision

Only bugs with status 'open' show the 'Add to basket' control. When the user starts the batch, the app re-checks each bug's status. Bugs that are no longer 'open' are shown as unavailable and left out of the run, and the button is disabled if fewer than 2 remain. Batch 'Fix with AI' is disabled, with a tooltip explaining why, while the AI terminal has an active run.

## Reason

This prevents two runs from editing the same bug. It is consistent with parallel batches being OUT of scope, and it avoids a queue.

## Consequences

Add acceptance criteria to REQ-001 and REQ-002. The app needs a way to tell that the AI terminal is busy.
