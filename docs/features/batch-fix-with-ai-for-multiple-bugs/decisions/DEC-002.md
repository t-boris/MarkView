## Context

A batch fix must run on one dedicated git branch. Someone has to create or check out that branch: either the app before it starts the AI, or the AI itself.

## Alternatives

1. A: The app creates the branch from the current one and switches to it; the run is blocked if there are uncommitted changes
2. B: The AI creates the branch itself, following an instruction in the batch prompt

## Decision

B: The batch prompt tells the AI to create and check out a dedicated branch for the batch before making any changes. The app runs no git operations.

## Reason

This is simpler in the app and matches the current Fix with AI flow, which only sends a prompt to the AI terminal.

## Consequences

Nothing guarantees that the branch is created. git errors (dirty tree, existing branch) show up only in the AI terminal. The prompt must say what the AI should do in these cases.
