## Context

REQ-005 says a project without saved settings starts with 'no filter, default sort', but 'default sort' was never defined (F-005). The funnel-highlight rule (DEC-001) and the default direction per sort key depend on it.

## Alternatives

1. Keep the current (unsorted/file) order as the default sort
2. Date descending (most recently updated first) as the default
3. Priority high-to-low as the default

## Decision

Default filter: no toggles selected in any group, so all features and bugs are shown. Default sort: by date (per DEC-003 date key), descending (newest first). When the user switches sort key, the initial direction is descending for date (newest first) and high-to-low for priority; items with empty values stay last in both directions (DEC-003). The filter counts as non-default, and the funnel icon is highlighted, only when at least one filter toggle is selected; the sort state never affects the funnel highlight. Reset restores the default filter only and leaves the sort unchanged.

## Reason

Recently changed items are what users look for most often, and date is available for every item through the fallback, while priority is often empty. The current file order is arbitrary, so it cannot be tested as an explicit default. Keeping sort out of the funnel rule keeps the highlight meaning simple.

## Consequences

REQ-005 and REQ-002 acceptance criteria should reference 'date descending' explicitly. The existing display order changes for users on first launch. F-004 (date fallback conflict) must still be resolved because the default depends on the date key.
