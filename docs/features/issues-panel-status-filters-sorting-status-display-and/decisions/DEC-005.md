## Context

Features use FeatureVocabulary statuses and bugs use a free-form bug.status string, so the Open/Closed filters need one shared mapping.

## Alternatives

1. A: One shared set — Open = anything unfinished; Closed = implemented/done (plus rejected/cancelled, per DEC-002) for features and closed/fixed for bugs
2. B: Separate filters per type — a list of feature statuses for features and open/closed for bugs

## Decision

Option A: Open and Closed filters apply to both types through one mapping. Feature Closed = implemented/done/rejected/cancelled (DEC-002); bug Closed = closed/fixed; every other status (including missing or unknown) counts as Open. The Implemented and Not-implemented filters apply only to features.

## Reason

Keeps the narrow panel UI simple, and one Open/Closed filter works for both types. The user chose it.

## Consequences

Intermediate feature statuses can't be filtered individually. Unknown status values count as Open.
