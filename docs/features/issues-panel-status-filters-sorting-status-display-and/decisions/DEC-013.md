## Context

The user was unsure the panel is not resizable; the shared mechanism, limits and persistence key are not named, so REQ-004 is not verifiable.

## Alternatives

1. Reuse the shared sidebar width (one width for all left panels)
2. Per-panel width stored separately
3. Fixed width, no change

## Decision

The Issues panel uses the same width mechanism as the other left panels and shares the same width value, min/max limits and persistence key. As the first implementation step, the developer verifies current behavior in code and records the mechanism name, limits and key in REQ-004; if the panel is already resizable, REQ-004 reduces to a regression check.

## Reason

Sharing one width avoids layout jumps when switching panels and matches the user's 'like the other panels' request.

## Consequences

REQ-004 acceptance criteria are updated with concrete values after verification; no new persistence key is added.
