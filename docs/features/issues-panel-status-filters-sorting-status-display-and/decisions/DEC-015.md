## Context

REQ-005 adds per-project user-defaults keys without names; handling of unknown persisted values after upgrades is undefined.

## Alternatives

1. Separate filter and sort keys per project
2. One JSON blob key per project
3. Global keys

## Decision

Keys: `features.issues.filter.<12-char hash of root>` (array of selected toggle ids) and `features.issues.sort.<12-char hash of root>` (string 'field:direction', e.g. 'date:desc'). Both are added to docs/architecture/configuration.md. Unknown toggle ids are ignored; an unparseable or unknown sort value falls back to the DEC-008 default; no error is shown.

## Reason

Matches the existing features.active.<hash> convention and keeps upgrades safe.

## Consequences

configuration.md must be updated with the feature; REQ-005 gains a criterion for invalid persisted values.
