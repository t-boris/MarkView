## Context

DEC-003 and REQ-002 disagree on the fallback chain; parsing and tie-breaking are undefined.

## Alternatives

1. updated → created → mtime (REQ-002)
2. updated → mtime (DEC-003)
3. mtime only

## Decision

Date key = `updated`, else `created`, else file modification time. Accepted formats: YYYY-MM-DD and ISO 8601 date-time; date-only values are treated as start of day local time. Unparseable or empty values count as missing and fall through to the next source. Ties are broken by title (case-insensitive, ascending), then by id. DEC-003 is amended accordingly.

## Reason

`created` is present in all spec files and is more meaningful than mtime, which changes on checkout; a deterministic tie-breaker keeps the list stable.

## Consequences

DEC-003 text updated; REQ-002 gains criteria for invalid dates and tie-breaking.

Amended by DEC-016 (BUG-017): equal dates are ordered by id in the direction of the dates; the title tie-breaker is withdrawn.
