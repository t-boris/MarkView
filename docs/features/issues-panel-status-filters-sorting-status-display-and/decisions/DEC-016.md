## Context

DEC-011 breaks equal dates by title, then id. In practice `updated` is rarely written, `created` names a day without a time, and several issues are filed on one day. With Date → Newest First, a day's items were therefore listed alphabetically by title, which does not match the order they were filed in (BUG-017).

## Alternatives

1. Equal dates by id, newest first when the dates are newest first (ids are given in filing order: "BUG-021" after "BUG-020"), oldest first otherwise
2. Equal dates by file modification time, then id
3. Keep the title tie-breaker (DEC-011)

## Decision

Option 1. Items whose effective dates are equal are ordered by id, with the numbers in the ids compared as numbers ("BUG-21" after "BUG-9"). The id order follows the direction of the date order: newest id first under Newest First, oldest id first under Oldest First. Priority ties keep date descending (DEC-007) and then the newest id first. The title no longer takes part in the order. DEC-011 is amended accordingly.

## Reason

A bug id records when it was filed, so a day's bugs keep their filing order. File modification times change on checkout and pull (DEC-003), so they would reorder a day's items for reasons the user cannot see.

## Consequences

Feature slugs carry no filing order; features filed on one day are listed by slug, which is stable but arbitrary. The tie-breaker remains deterministic. REQ-002 gains a criterion for equal dates.
