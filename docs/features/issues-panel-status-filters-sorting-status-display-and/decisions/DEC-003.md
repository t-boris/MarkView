## Context

REQ-002 needs defined sort keys; features and bugs may carry different fields (priority vs severity, created vs updated).

## Alternatives

1. A: date = created from front matter; priority = feature priority / bug severity on a common scale; empty last
2. B: date = updated (fallback: file modification time); priority as in A; empty last
3. C: two date sorts (created and updated) selectable; priority as in A

## Decision

Option B: sort by date uses the `updated` front-matter field, falling back to the file modification time when absent. Sort by priority uses feature `priority` and bug `severity` mapped onto one common scale. Items without a value for the active sort key are placed at the end regardless of direction.

## Reason

User choice: recently changed items should surface on top.

## Consequences

File modification time can change due to git operations (checkout, pull), so fallback ordering may be noisy. A priority/severity mapping must be defined by the implementer. Single date sort keeps the menu simple.
