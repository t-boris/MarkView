## Statement

Verify proposed optimizations against current behavior. For terminal handoffs, mandatory first-release verification applies only when MarkView itself submits the prompt to the agent for execution, as scoped by REQ-005. A PR-review task staged with `submit: false` remains outside mandatory first-release verification even if the user later submits it manually. Require a demonstrated material quality gain for every proposed default with a measured increase in duration or cost, including deep Research. When comparable cost data are unavailable, also require a demonstrated material quality gain unless proxy evidence agreed in advance establishes that cost did not increase. Under DEC-015, verify the first-release evidence-backed deep default against each scenario’s current behavior separately across all four scenarios: creating a research document through Research or Deep Research, Continue / deepen on an existing document, Retry incomplete part on an existing document, and Revise With Comment on an existing document. Each operation uses only the sources and tools permitted by and available to its actual launch profile. If a scenario fails the release gate, refine the deep workflow for that scenario and repeat the comparison. Release the feature only after all four scenarios pass.

## Acceptance Criteria

- [x] First-release verification covers terminal handoff paths where MarkView itself submits the prompt to the agent for execution, as scoped by REQ-005.
- [x] A PR-review task staged with `submit: false` is excluded from mandatory first-release verification even if the user later submits it manually.
- [x] Baseline and candidate runs use the same representative tasks and comparable inputs. Define workflow-specific quality criteria and what constitutes a material gain before comparing results.
- [x] Record end-to-end duration, call counts, available usage or cost, and quality against the predefined workflow criteria. Record unavailable measurements and assess result acceptance separately from process success.
- [x] Representative live checks exercise the launch-profile capabilities the change relies on. Record any capability assumptions that remain unverified.
- [x] If a proposed default increases measured duration or cost, release evidence demonstrates a material quality gain against current behavior under the predefined criteria.
- [x] If comparable cost data are unavailable for a proposed default, record the cost evidence gap, any proxy evidence agreed in advance and what it establishes, and the quality result against the predefined criteria. Release evidence demonstrates a material quality gain unless the agreed proxy evidence establishes that cost did not increase. A measured increase in duration still requires a material quality gain.
- [x] The evidence-backed deep workflow for creating a research document through Research or Deep Research passes the release gate against current behavior for both entry points.
- [x] The evidence-backed deep workflow for Continue / deepen on an existing research document passes the release gate against current behavior for that operation.
- [x] The evidence-backed deep workflow for Retry incomplete part on an existing research document passes the release gate against current behavior for that operation.
- [x] The evidence-backed deep workflow for Revise With Comment on an existing research document passes the release gate against current behavior for that operation.
- [x] For each of the four Research scenarios, verification confirms that the candidate uses only sources and tools permitted by and available to the actual launch profile.
- [x] For each Research scenario that fails the release gate, refine the deep workflow for that scenario and repeat the comparison before release. Release the feature only after all four scenarios pass.
