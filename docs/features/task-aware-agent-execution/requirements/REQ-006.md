## Statement

Match prompts and execution to the actual receiving profile and use its existing capabilities where they serve the task. For terminal handoffs, this requirement applies only when MarkView itself submits the prompt to the agent for execution. Require explicit confirmation before substituting another provider for an explicitly selected provider whose launch profile lacks a needed capability.

## Acceptance Criteria

- [x] Single and batch Fix with AI use instructions valid for the terminal that actually receives the task, including when normal terminal routing chooses a provider different from the configured default.
- [x] Terminal handoffs enter the mandatory audit inventory and first-release verification only when MarkView itself submits the prompt to the agent for execution.
- [x] A PR-review task staged with `submit: false` stays outside the mandatory audit inventory and first-release verification even if the user later submits it manually.
- [x] When an explicitly selected provider's launch profile lacks a needed capability, MarkView identifies the limitation and offers a compatible configured provider when one is available.
- [x] A proposed replacement provider receives task context only after the user explicitly confirms the substitution.
- [x] If confirmation is declined or no compatible provider is available, MarkView stays with the existing provider when the task can proceed within that profile's capabilities and permissions. Otherwise it reports the blocker.
- [x] Representative runs exercise supported provider commands or tools relevant to the task while enforcing repository web settings, approved delegation controls, and existing write and delivery permissions.
