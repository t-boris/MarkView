## Context

The attached static review provides candidates for optimization. It provides no live comparison of quality, latency, or cost.

## Alternatives

1. Favor speed and cost by default and require an explicit request for a more expensive mode.
2. Allow slower or more expensive defaults where a comparison demonstrates a material quality gain.
3. Favor quality for any demonstrated gain even when time or cost increases.

## Decision

Use slower or more expensive execution by default only in workflows where comparison with current behavior demonstrates a material quality gain.

## Reason

The owner chose an evidence-based trade-off that can vary by workflow.

## Consequences

Validation must show the quality gain alongside the latency and cost trade-off for each affected workflow.
