## Context

Two windows can have workspace folders with the same last path component (e.g. two 'docs'), making folder-name-only titles ambiguous.

## Alternatives

1. A: Show folder name only, accept ambiguity
2. B: Prefix parent folder name only on collision across open windows (e.g. 'MarkView/docs')
3. C: Keep title text as folder name and set the full path as the window's representedURL (proxy icon)

## Decision

C: Title text shows only the folder name; the full workspace root path is set as the window's represented URL, so the proxy icon and Cmd+click reveal the path.

## Reason

Standard macOS behavior, no cross-window collision tracking, keeps the title short.

## Consequences

Same-named folders show identical title text in Mission Control and the Window menu; the user tells them apart via Cmd+click on the title. The proxy icon must be cleared when no folder is open and updated when the workspace changes.
