## Context

Behavior for renaming, moving or deleting the open root, and for restoring a non-existent workspace.lastFolder, was undefined.

## Alternatives

1. Keep the name captured when the folder was opened
2. Follow renames live via file-system observation
3. Fall back to 'MarkView <version>' when the folder is missing

## Decision

The title and represented URL are derived solely from WorkspaceManager's current root URL. No dedicated rename/move tracking is added for this feature: if the root is renamed while open, the title keeps the last known name until the workspace is reopened or changed. If workspace.lastFolder no longer exists at launch, no workspace is restored and the REQ-003 fallback applies with no proxy icon.

## Reason

Title-only feature. Live FS tracking is out of proportion, and a stale name is harmless. Launch restore must not show a title for a folder that doesn't exist.

## Consequences

Add an acceptance criterion: when a missing lastFolder is restored at launch, the title is 'MarkView <version>' with no proxy icon. Any future root-tracking in WorkspaceManager automatically updates the title.
