## Context

The title is set at WindowGroup level (MarkViewApp.swift:189), which cannot see the per-window WorkspaceManager owned by ContentView. SwiftUI has no representedURL modifier for folders.

## Alternatives

1. navigationTitle + navigationDocument(url) in ContentView
2. NSWindow accessor setting both title and representedURL imperatively
3. navigationTitle in ContentView plus NSWindow accessor for representedURL only

## Decision

Remove the scene-level navigationTitle. ContentView derives the title from its WorkspaceManager's root URL via .navigationTitle, and sets NSWindow.representedURL (nil when no folder is open) through a small NSViewRepresentable window accessor observing the same root URL. Title formatting lives in a single pure function (version, rootURL?) -> String that can be unit-tested.

## Reason

Keeps the title declarative and per-window, uses AppKit only where SwiftUI has a gap, and gives a testable formatter.

## Consequences

Needs a window-accessor helper. Title and proxy icon both update from one source of truth. The formatter is covered by unit tests; the proxy icon is verified manually or with a UI test.
