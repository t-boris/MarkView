## Finding

MarkViewApp.swift:189 applies navigationTitle on ContentView from the WindowGroup, where the per-window WorkspaceManager (owned inside ContentView) is not visible. To meet REQ-002 and REQ-004, the title and the represented URL must be set inside ContentView (or a view that observes that window's WorkspaceManager). SwiftUI has no representedURL modifier for folders: navigationDocument(_:) works for documents, and otherwise you have to reach NSWindow.representedURL through an NSViewRepresentable window accessor. The spec does not say which mechanism to use or who owns it.

> .navigationTitle("MarkView \(Self.version)")

## Possible interpretations

- Move .navigationTitle into ContentView and bind it to workspace.rootURL; use navigationDocument(url) for the proxy icon
- Use an NSWindow accessor that sets both title and representedURL imperatively

## Resolution

AI: Перенести установку заголовка внутрь ContentView (владельца WorkspaceManager окна): .navigationTitle привязан к workspace.rootURL, а representedURL задаётся через небольшой NSViewRepresentable-аксессор окна. Модификатор на уровне сцены в MarkViewApp удаляется. — see DEC-003.
