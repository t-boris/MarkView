## Context

Lifecycle events need a store that supports duration queries and aggregation without polluting project git history.

## Alternatives

1. Append-only JSONL file in the project repository
2. Local application database/storage
3. External analytics service

## Decision

Lifecycle events are stored in MarkView's local application storage (per machine), not in the project repository and not in an external service.

## Reason

Fast queries for durations/aggregation, no merge conflicts or git noise, no privacy exposure or external dependency.

## Consequences

Events are not shared across team members or machines; analytics reflect only locally recorded events. Team-wide analytics stay out of scope.
