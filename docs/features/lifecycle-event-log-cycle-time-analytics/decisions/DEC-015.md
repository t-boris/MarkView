## Context

The intake says event metadata is open-ended ('and everything else'). REQ-002 defines project, feature, event type, actor, capture source and AI model, but the spec does not say whether extra or free-form metadata is supported. Q-001 duplicates Q-004 and is still listed separately. All SRC-001 facts are still pending.

## Alternatives

1. Fixed field set only, no extensibility
2. Fixed field set plus arbitrary key-value extra metadata
3. Fixed field set plus a single optional free-text note on manual marks

## Decision

Event metadata is limited to the fixed fields in REQ-002 (project, feature id, event type, timestamp, actor, capture source, AI model when applicable). Manual marks can also carry an optional free-text note of up to 500 characters. The note is shown in the feature timeline but is not used in aggregation. Arbitrary key-value metadata is out of scope for now. Q-001 is closed as a duplicate of Q-004. SRC-001 facts are reconciled: facts covered by DEC-001 to DEC-014 are marked accepted, and the quality-measurement fact is marked out of scope.

## Reason

Fixed fields keep the per-project aggregation simple and consistent. A note captures context such as why a step was slow without adding a schema. Events cannot be edited (DEC-005), so the note must be entered at marking time, which fits the confirmation dialog from DEC-010.

## Consequences

REQ-002 gains an optional 'note' field for manual events, and the marking dialog gets a note input. Adding new structured fields later requires a spec change and a storage migration. Q-001 is closed as a duplicate, and SRC-001 facts are no longer pending.
