## Context

Events can repeat (automatic re-triggers, duplicate manual marks) and cannot be corrected; duration pairing was undefined.

## Alternatives

1. First occurrence of each type
2. Latest occurrence of each type
3. First start / last end per step
4. Block duplicates

## Decision

A step is the pair of adjacent stages in the canonical order (DEC-006). Its duration = timestamp of the latest event of the end stage minus timestamp of the earliest event of the start stage. Skipped stages are not bridged: the step shows no duration. If the result is negative or zero-evidence, the step shows 'inconsistent' and no duration. Total idea-to-verified uses earliest 'idea created' and latest 'verified'. Steps without a valid duration are excluded from REQ-004 averages. All raw events, including repeats, remain visible in the timeline.

## Reason

First-start/last-end captures real elapsed effort including rework loops, is deterministic, and never produces negative or guessed values.

## Consequences

REQ-003 and REQ-004 acceptance criteria must state these rules; repeated work cycles inflate step duration by design.
