## Context

Only "CI passed" existed, so the time spent waiting for CI and the number of re-runs were invisible.
DEC-006 fixed the stage list and said no other event types exist.

## Decision

Two automatic event types are added: `ci_requested` and `ci_started`. They are read from GitHub by
the existing poll (no hook): the first request and start of the Actions runs of a pull request's
last commit, and one more `ci_requested` event per re-run (note "… · re-run N of run ID").
They are not part of the chain of adjacent steps (`LifecycleStage.chain`), because CI starts when a
pull request opens, before its review is done; their durations are separate: waiting for a runner
(requested → started), CI time until green (started → passed, failed attempts and re-runs
included) and the re-run count.

## Consequences

The fixed list of DEC-006 grows by two details; the nine-stage chain and its eight steps are
unchanged. GitHub keeps no request time for a re-run, so a re-run has no queue time and is
stamped with the start of its latest attempt. Older MarkView versions cannot read a log that holds
the new event types. Only CI of the last commit of a pull request, or of a commit merged to main,
is measured.
