## Context

Local per-machine storage (DEC-001) needs a stable key for project and feature and defined behaviour for renames, deletion and resets.

## Alternatives

1. Key by path + feature id
2. Key by git remote URL + feature id
3. Stable UUID written into the feature file

## Decision

Events are keyed by project root absolute path and feature id. Moving or renaming the repository or the feature id orphans prior events (they are not shown). Deleting a feature leaves its events in storage but they are not shown. Features created on another machine have no 'idea created' event locally and are treated like pre-existing features (F-007). Resetting app data deletes the log; no backup or export is provided.

## Reason

Simplest keying consistent with the local, per-machine scope; the losses are acceptable for a personal analytics feature.

## Consequences

Documented limitations; a stable feature UUID or remote-based key can be added later if orphaning becomes a real problem.
