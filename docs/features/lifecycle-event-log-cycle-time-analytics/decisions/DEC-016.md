## Context

In real use only "idea created" and "questions resolved" were recorded. Nothing in MarkView sets
the status `ready`; Create issues moves a feature from review straight to `implementing`, so
"spec ready" never fired. "Implement with AI" recorded nothing, so the AI step and its model were
missing. Review, CI and merge were manual only, and this repository commits straight to `main`
without pull requests.

## Decision

The stages after "spec ready" stay manually markable and are also captured automatically
(`source: automatic`) where MarkView can observe them:

- **Spec ready**: status into `ready`, or readiness reaching 100 %. If neither happened, it is
  recorded when the feature is handed to implementation (status into implementation, or
  Implement with AI), so the chain is not broken.
- **Implementation started**: Implement with AI, stamped at the click. The model is the one the
  CLI actually answered with, read from its own session log (Claude Code
  `~/.claude/projects/<cwd>/*.jsonl`, Codex `~/.codex/sessions`), else the model it was started
  with or its configured default. The note names the CLI.
- **Implementation finished**: status into `implemented`, and each pull request opened.
- **Review done / CI passed / merged to main**: pull requests that are or close the feature's
  issues (approved, all checks green, merged into the default branch), with the GitHub
  integration on.
- **Merged to main without a pull request**: a commit on the default branch whose message names
  `docs/features/<slug>` or one of the feature's issues (local git). With the GitHub integration
  on, its green Actions runs give **CI passed**.

GitHub and git events carry GitHub's or the commit's own time, not the time MarkView noticed
(manual marks stay "now", DEC-010). Each stage is recorded once per pull request or commit (the
note names it). Only features with an "implementation started" event are followed, and only
from that moment on (no backfill, DEC-013).

## Reason

Accurate durations need the transitions MarkView can see recorded without the user remembering
to mark them, with the real model of the AI step.

## Consequences

The implementation-started event appears once the CLI first replies (up to 15 minutes); if the
app quits before that, it is not recorded. Several pull requests or commits per feature give
repeated events; durations use the earliest start and latest end (DEC-009).
