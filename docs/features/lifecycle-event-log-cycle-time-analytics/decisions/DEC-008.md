## Context

The MarkView state changes that trigger the automatic 'questions resolved' and 'spec ready' events were not defined, nor was repeat behaviour.

## Alternatives

1. Spec ready = feature status set to ready; fire on every entry
2. Spec ready = all requirements approved
3. Fire only the first time ever

## Decision

'spec ready' is recorded when the feature status transitions into 'ready' from any other status. 'questions resolved' is recorded when the feature's open-question count transitions from ≥1 to 0 (resolving, answering or dropping the last open question). Both fire on every such transition; reopening or adding questions does not record any event itself.

## Reason

Tied to explicit, observable state changes; recording every transition preserves the full truth in an append-only log, while duration rules (F-003) decide which occurrence counts.

## Consequences

Features may carry repeated automatic events; REQ-001 acceptance criteria must name the 'ready' status and the 0-open-questions condition. A feature with no questions records 'questions resolved' only if it ever had one; otherwise that step shows no duration.
