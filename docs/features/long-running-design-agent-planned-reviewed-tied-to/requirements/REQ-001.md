## Statement

The system shall run a big design request, in UI Studio and in Prototype Studio, as a long-running job that splits the request into chunks, does them one after another, and keeps going until every chunk is done, stopped, or waiting for an answer.

## Acceptance Criteria

- [ ] A request that touches many elements or screens (for example a restyle of a whole page) becomes a job with a list of chunks instead of one edit, in both studios
- [ ] Each chunk is applied and checked before the next starts, and the result of the check (for UI Studio the build log, runtime errors and a picture of the result; for Prototype Studio the preview errors and audit) is shown to the agent for the next step; a check that could not run is reported as unavailable, never as clean
- [ ] The job shows its chunks, the current one, the elapsed time of the whole run and a Stop button, and Stop keeps what is already applied and undoable
- [ ] Closing the tab, closing the window or quitting the app pauses the job (it is never lost or marked failed), and the job can be resumed from the chunk it stopped at when the studio is opened again
- [ ] A request that needs one small edit still takes the quick path, without a job
- [ ] While a job is active, actions that would change the same files or state (a second request, Undo of the job's changes, rebuild, sync, revert, clearing the conversation) are refused with the reason, and the request box stays usable for notes and answers
