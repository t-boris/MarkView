## Statement

The system shall open a feature automatically before something is changed, and add to it, as requirements and discussion, the request and everything the person says and decides while the job runs.

## Acceptance Criteria

- [ ] The first request of a job creates a feature, or attaches to the one the person names, before any file is written
- [ ] The request and every later message of the person is appended to the feature's discussion in the person's words, with secrets and credentials redacted
- [ ] Each chunk of the plan is linked to a requirement of the feature
- [ ] A requirement the agent derives for the plan is a draft until the person approves it; the agent has no way to write an approved requirement, an accepted decision or an answer (the quick path keeps recording the person's own small request as it does today)
- [ ] When a requirement of the feature is changed or rejected during a job, the job pauses at the next checkpoint and asks the person whether to replan or continue
- [ ] For a prototype job the feature of the job is linked to the prototype's hand-off feature instead of creating a second competing one
