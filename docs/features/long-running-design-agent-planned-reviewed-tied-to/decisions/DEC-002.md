## Context



## Alternatives

1. A new feature for every request, all through the four gates

## Decision

A feature is opened for a task (a job or a conversation), before any write. A small request is recorded in the current feature as a requirement and takes the quick path as today; a big request becomes a job with four gates: plan, plan review, implementation, implementation review against the requirements.

## Reason

Boris chose one feature per task (Q-003, 2026-11-05). A feature per button change would bury the list and slow small changes.

## Consequences

A deterministic cap on files and changed lines turns an oversized quick answer into a job.
