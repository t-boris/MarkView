## Context



## Alternatives

1. One prototype version per chunk

## Decision

A prototype run keeps the before/after of the touched files per chunk in `.dde/design-runs/<run>/journal/`, undoes the newest chunk or the whole run from it, and writes ONE prototype version at the end with the person's request as its instruction.

## Reason

A version per chunk copies the whole site into the committed `versions/` folder each time, `restore` replaces the whole site (so it cannot undo one chunk), and every history entry becomes a review request in the hand-off brief. Found by the second plan review; part of plan v4 approved by Boris on 2026-11-05.

## Consequences

The journal is git-ignored; Undo of one chunk exists only while the journal does.
