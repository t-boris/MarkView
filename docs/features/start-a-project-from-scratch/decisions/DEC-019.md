## Context

Folder creation, file writes, Git initialization, GitHub creation, remote setup, and push can fail independently.

## Alternatives

1. Roll back every partial result automatically.
2. Leave partial results and require the user to restart.
3. Record completed stages and resume safely from the failed stage.

## Decision

Make each operation resumable and idempotent, preserving completed resources and clear recovery actions.

## Reason

This avoids duplicate repositories and protects user data while giving the user a practical retry path.

## Consequences

Implementation must persist operation state, check existing local and remote resources before retrying, and never silently report partial success as completion.
