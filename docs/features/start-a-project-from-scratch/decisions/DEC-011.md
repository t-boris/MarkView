## Context

F-002 identifies two meanings of “usable local project.” Accepted DEC-006 and DEC-008 define the bootstrap contents as a specification foundation and local Git; the feature scope leaves the technology stack and generated file templates undecided.

## Alternatives

1. A MarkView workspace containing the confirmed brief, decisions, requirements, and local Git is sufficient.
2. Bootstrap also generates application source files that can be built or run.

## Decision

For the first version, bootstrap is complete when MarkView creates a local folder it can open as a workspace, preserves the confirmed brief, decisions, and requirements there, and initializes local Git. The workspace does not need generated application source files or a runnable build.

## Reason

This boundary follows the accepted decisions and gives “usable” an outcome that can be checked without choosing a technology stack or templates.

## Consequences

Clarify DEC-002 and REQ-004 so acceptance checks require an openable MarkView workspace, preserved specification content, and initialized local Git. Application source generation and build or run checks are outside the first-version bootstrap.
