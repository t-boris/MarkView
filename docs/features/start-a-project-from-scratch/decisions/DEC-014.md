## Context

REQ-004 requires initial files to preserve the brief, decisions, and requirements. MarkView already loads structured feature objects from docs/features/<slug>/.

## Alternatives

1. Store everything in one root Markdown file.
2. Use MarkView’s existing feature object layout for the specification foundation.
3. Introduce a new project specification format.

## Decision

Use the existing feature object layout for decisions and requirements, plus a root README.md for the project brief.

## Reason

The existing format makes the foundation discoverable and editable in MarkView without creating a second specification model.

## Consequences

Bootstrap must produce valid feature files with stable IDs and links. The root README must point users to the feature workspace.
