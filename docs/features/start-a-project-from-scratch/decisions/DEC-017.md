## Context

REQ-003 promises repository creation, which requires an owner, name, and visibility. F-006 identifies an inconsistency between that promise and the stated scope exclusion.

## Alternatives

1. Choose owner, name, and visibility automatically.
2. Ask for owner, name, and visibility before creation and handle collisions explicitly.
3. Defer all GitHub repository creation to a later version.

## Decision

Make owner, name, and visibility explicit inputs to optional GitHub creation, and handle an existing repository without overwriting it.

## Reason

A repository cannot be created safely or predictably without these choices.

## Consequences

Repository visibility becomes an explicit connection input despite being omitted from the initial scope. Creation needs authentication, availability checks, and collision handling.
