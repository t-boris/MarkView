## Context

REQ-004 requires the new workspace to preserve the confirmed brief, decisions, and requirements. Existing feature objects use separate Markdown files with structured front matter under `docs/features/<slug>/`, but the clarified idea may describe the entire project rather than a feature.

## Alternatives

1. Store everything in a single project brief.
2. Create a synthetic feature under `docs/features/<slug>/`.
3. Use project-level files under `docs/project/` with the existing Markdown object format.

## Decision

Store the confirmed project brief in `docs/project/overview.md` and each clarification decision and requirement in its own file under `docs/project/decisions/` or `docs/project/requirements/`. Reuse the existing Markdown front matter conventions and object IDs while treating these as project-level records.

## Reason

This preserves the structure needed for later review and editing without misclassifying the whole project as its first feature.

## Consequences

Bootstrap creates `docs/project/overview.md`, `docs/project/decisions/DEC-*.md`, and `docs/project/requirements/REQ-*.md`. MarkView must make these project-level documents discoverable and editable. Actual features can later use `docs/features/<slug>/`.
