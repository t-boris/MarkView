## Context

REQ-003 promises optional GitHub repository creation and connection. The current specification leaves owner, name, visibility, and existing-repository behavior unresolved. MarkView's documented GitHub integration is opt-in.

## Alternatives

1. Create the repository under the signed-in account with an inferred name and default visibility.
2. Ask for owner, name, and visibility, but stop when the repository already exists.
3. Ask for owner, name, and visibility; offer a checked connection path for an existing repository.

## Decision

Before creating a GitHub repository, show the authenticated account and available owners; require the user to select an owner, enter or confirm a repository name, and explicitly choose private or public visibility. Show the target and visibility for confirmation before creation. If the target already exists, offer a different name or connection to the existing repository only after checking access and the local Git remote state; never overwrite a repository or remote automatically. Offer the same choices when connecting later.

## Reason

Owner and visibility affect where project content is published, so they require an explicit user choice. Handling an existing repository lets users recover from name collisions without risking unintended writes.

## Consequences

The flow needs owner and visibility selection, an explicit confirmation before the GitHub write, and checks for repository existence, access, and local remote conflicts. Repository creation remains optional, and the local project stays usable if connection is skipped or fails.
