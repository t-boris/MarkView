## Context

The documented integration is disabled by default and discovers repositories through Git remotes. A remote alone may leave MarkView’s GitHub features unavailable.

## Alternatives

1. Treat a GitHub remote alone as a connection.
2. Require remote setup, authentication, and enabled MarkView GitHub integration.

## Decision

Define connection as a published Git remote plus active, authenticated MarkView GitHub integration for that repository.

## Reason

This aligns the promised connection with the behavior users can observe inside MarkView.

## Consequences

The connection flow must handle the global GitHub setting, authentication, repository detection, and a clear failure state if MarkView cannot activate its GitHub features.
