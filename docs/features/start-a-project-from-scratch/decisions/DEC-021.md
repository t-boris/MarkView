## Context

New Feature intake assumes an open workspace and may create a GitHub issue when integration is enabled.

## Alternatives

1. Reuse New Feature intake without changes
2. Build a separate project clarification flow
3. Reuse the clarification logic while separating workspace storage and GitHub publication

## Decision

Reuse the adaptive clarification logic for project discovery, but keep pre-bootstrap drafts outside the feature workspace. Do not create a GitHub issue during clarification or bootstrap; offer issue creation only as an explicit later action.

## Reason

This preserves a consistent discovery experience without requiring a repository or unexpectedly publishing the project idea.

## Consequences

Pre-bootstrap clarification needs draft storage independent of a workspace. GitHub issue creation remains a separate, explicit action after connection.
