## Summary

Голосовая заметка задаёт желаемую последовательность работы: сначала диалог для определения типа проекта, затем предложение начальной архитектуры, поиск типовых элементов в интернете и только после этого создание проекта. Это входные пожелания для спецификации; порядок шагов выражен прямо, а необходимость подтверждения архитектуры пользователем остаётся открытой.

## Origin

voice

## Content

Я думаю, что нам нужно иметь возможность также перед стартом, бутстрапом этого проекта, мы должны первое определить, какого рода этот проект. Это долгие переговоры получается с клиентом, отвечая на вопросы. Потом он предлагает конкретный тип, какую-то начальную архитектуру, все остальное. Потом он, в зависимости от архитектуры, ищет в интернете, какие классические или стандартные бутстраповые элементы этой архитектуры. И только после этого он создает бутстрапы проекта.
