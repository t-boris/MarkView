## Context

Boris asked for several backgrounds to choose from. The first version kept one app-wide choice. Boris then reported (2026-11-10, BUG-120): changing the background in one window changes it in every window, and every window should have its own welcome screen.

## Alternatives

1. One app-wide preference (the first version, rejected by Boris)
2. Per project in .dde/
3. Only in DDE Settings
4. Per window, like the theme and the panel tabs (chosen)

## Decision

The choice is part of the window's own panel state (`PanelLayout.welcomeBackdrop`), changed from the small menu on the welcome screen. It is saved with the window's session, so each window keeps its own choice after a relaunch. The UserDefaults key `welcomeBackdrop` stays only as the starting choice of the next new window; the default is Matrix rain. No per-project setting and no entry in DDE Settings for now.

## Reason

A window is the unit the person looks at, and the theme and the panel tabs already work this way (BUG-004, per-window themes). A shared @AppStorage value is observed by every welcome screen at once.

## Consequences

Changing the backdrop in one window leaves the other windows alone. A new window starts with the last choice made anywhere. Sessions saved before 5.55.1 have no per-window value: their windows start with the stored choice.
