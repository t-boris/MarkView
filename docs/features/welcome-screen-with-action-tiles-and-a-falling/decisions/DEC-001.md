## Context

BUG-117 was a CPU spin; the welcome screen is shown in every empty window and Boris keeps several windows open. A Canvas inside a TimelineView redraws every glyph on the main thread each frame, for each window.

## Alternatives

1. SwiftUI Canvas + TimelineView: simple, but main-thread CPU per frame per window
2. CAEmitterLayer for the rain: cheap, but no trails and no changing symbols in a column
3. A WKWebView with canvas/WebGL: heavy, another process per window

## Decision

Each backdrop is a tree of CALayers with CABasicAnimation / CAKeyframeAnimation (position, opacity, contents), built once by an NSViewRepresentable. The scenes (columns, blobs, paths, graph) are pure, seeded values in a model file, checked by a standalone swiftc test.

## Reason

The render server does the movement, so the cost does not grow with the number of windows or glyphs; the model stays testable without a window.

## Consequences

The still picture under test and under Reduce Motion is the model's start position of every layer. A moving frame cannot be photographed by an off-screen test; the motion itself is only seen in the running app.
