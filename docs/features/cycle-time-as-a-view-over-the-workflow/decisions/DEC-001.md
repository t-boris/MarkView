## Context

DEC-005 forbade any correction, so a bad period or item could never be neutralised. DEC-009 measured earliest start to latest end, which turns repeated work (a PR per fix, a reopen) into one long interval.

## Alternatives

1. Keep DEC-005 and DEC-009 unchanged
2. Void records appended to the journal

## Decision

The journal stays append-only. Corrections are settings stored in the project (.dde/lifecycle/cycle-time.json): Measure since (a date, default all time), Exclude from statistics (per item, with a reason, reversible) and Recompute (free, because numbers are a projection). An item has rounds: a reopen or rollback ends the round and starts a new one; earlier rounds stay on its timeline. A duration is measured from the first entry into the start role to the first entry into the completed role within the same round; reopens are counted as rework instead of lengthening the step. Deleting a project's data is a separate, confirmed action.

## Reason

Keeps immutability where it matters (the journal) and gives the owner a way out of a polluted period. In the real data the earliest-to-latest rule alone makes the all-projects implementation median 3.5 h against 1.25 h.

## Consequences

Settings live next to the journal in .dde and are therefore per clone, like the journal itself.
