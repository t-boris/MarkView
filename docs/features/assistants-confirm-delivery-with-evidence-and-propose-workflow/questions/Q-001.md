## Question

Should a rule be able to say that MarkView itself moves an item to a status when an event happens (the work is taken into development, an investigation finishes)? Today a rule says who may make a step and with what evidence; MarkView moves an item by itself only when delivery evidence completes it.

## Why it matters

Boris asked for a workflow where taking an item into development or finishing an investigation moves it to review automatically. An assistant can only allow the step by rule and then request it; MarkView cannot make it happen by itself.

## Options

- **A**: No. Rules only say who may make a step; assistants are told by the guide to make it (cheap, nothing new in the format)
- **B**: Yes. A rule can name an event (work attached, investigation done) and MarkView makes the step itself (a new kind of rule, a new part of the format and of the history)

## Recommended

A

## Answer

B. Yes, include it in this feature: a transition rule can name an event (for example work taken into development, investigation finished) and MarkView makes the step itself. Boris, 2026-11-09, in answer to the question in the terminal session.
