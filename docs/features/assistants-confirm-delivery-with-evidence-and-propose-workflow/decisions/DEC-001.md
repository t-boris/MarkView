## Context

The workflow holds the rules that bind the assistants (who may start, complete, accept). Boris wants to tell any assistant in words what to change and then only save it.

## Alternatives

1. A tool that writes the file directly (the assistant could loosen the rules that bind it, and bypass the replacement questions)
2. A tool that writes the file only when the call carries by_user: true (the flag is only a claim by the assistant)

## Decision

An assistant changes the workflow only by proposing it. The proposal is held by the window and shown in the Workflow tab; the person reviews it in the draft and presses Save, which keeps the existing checks, the replacement of statuses in use and the stale-revision guard. No tool writes the workflow file.

## Reason

Boris asked for exactly this: the assistant changes the workflow as he says and offers it to him to save. The person's Save is the single place where a workflow becomes the project's, so the rules cannot be changed by the party they bind.

## Consequences

A proposal that nobody opens does nothing. The window keeps one proposal in memory; it does not survive a restart (DEC-005).
