## Statement

The system shall let a transition rule of the workflow name an event, and shall make the step itself, as MarkView, for every work item in the rule's from-statuses when that event happens for the item, so that a person can ask an assistant for a workflow in which, for example, taking an item into development or finishing an investigation moves it to review by itself.

## Acceptance Criteria

- [ ] A rule has an optional event: work-started (a hand-off was accepted or a session attached), investigation-finished (the bug investigation of the app produced its result), pull-request-opened, pull-request-merged; a rule without an event behaves as today, and a file without events reads as before (the field is optional, schema stays 1)
- [ ] When the event happens for an item whose stored status is one of the rule's from-statuses, and the rule lets MarkView make the step (it has a system entry), the item moves to the rule's target at once; the history shows the actor MarkView, the event and the rule, and the work item that caused it
- [ ] The conditions that the rule asks of MarkView still apply: a step whose conditions are not met is not made and is not retried by the same event; a step is made at most once per item and event, so a person who moved the item back is not overridden by the same event again
- [ ] An event only moves items that were already in the from-statuses when it happened; saving a rule moves no item whose event is in the past
- [ ] An event name that this app does not know is kept in the file, never fires, and Save reports it as a problem to correct, so a workflow written by a newer app never makes an older app move items wrongly
- [ ] The Workflow tab shows the event on the rule (the diagram card and the process page) and lets the person choose it; the source view accepts it; the proposal differences name it in plain words ('when an investigation finishes, a bug moves from In progress to In review')
- [ ] markview_get_workflow and the guide list the events and what each means, so an assistant can write such a rule and an assistant is told that MarkView, not the assistant, makes the step
