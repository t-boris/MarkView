## Statement

The system shall let an assistant propose a changed workflow through MCP when the person asked for it in words, check it with the rules that Save uses, show it to the person in the Workflow tab with the differences in plain words, and change nothing until the person presses Save.

## Acceptance Criteria

- [ ] markview_propose_workflow(workflow, summary) parses and validates the workflow with the same checks as Save and, when it is not valid, returns each problem so that the assistant can correct it
- [ ] A valid proposal is held by the window, the file and every work item stay as they are, and the reply lists the differences in plain words and the work items whose status or process would need a replacement
- [ ] The Workflow tab shows the proposal (who proposed it, when, the summary, the differences) with 'Review in the draft' and 'Dismiss'; Review loads it into the draft like a template does, and Save, its replacement questions and the stale-revision check work unchanged
- [ ] A proposal made on an older revision than the file now has is shown as outdated and cannot be loaded; a newer proposal replaces an older one of the window
- [ ] The reply tells the assistant that the person must open the Workflow tab of this window and press Save, and that the assistant does not save
- [ ] There is no MCP tool that writes the workflow file
