## Context

Files deleted since the baseline have no nodes in the current architecture, but both comparison maps must represent changes.

## Alternatives

1. Show deleted files on the focused map and in a separate changes list for the full map.
2. Show deleted files only in a separate changes list.

## Decision

Show deleted files as clearly marked nodes on both comparison maps, with access to their diffs. Include necessary context on the focused map.

## Reason

This keeps deleted files discoverable alongside other changes in both views and preserves a complete comparison on the maps.

## Consequences

Both maps include representations of files absent from the current architecture, and users can inspect their diffs.
