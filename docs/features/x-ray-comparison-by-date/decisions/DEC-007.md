## Context

Q-003 was answered "all locally available branches" and DEC-003 repeats it. A repository also holds remote-tracking branches (refs/remotes) and tags, which are available locally after a fetch but are not branches of this checkout. The Git tab's own compare menu separates "other branches" (local) from "Remote Branches".

## Alternatives

1. Also include remote-tracking branches (git log --all without tags)
2. Include every reference, tags and stash too

## Decision

The picker offers the commits reachable from the local branches (refs/heads: git log --branches). A commit reachable only from a remote-tracking branch or a tag is not offered.

## Reason

It is the literal reading of the answer and of the plan ("reachable from locally available branches"), and it matches what the Git tab calls local branches. Switching to remote-tracking branches too is a one-word change of the git arguments.

## Consequences

A commit that exists only on origin/<branch> (never checked out locally) does not appear until the branch is created locally. Proposed by the implementing session and applied by default; the owner can accept it or ask for remote-tracking branches.
