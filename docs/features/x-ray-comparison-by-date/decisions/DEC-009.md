## Context

The specification does not say where the date picker lives, how the chosen commit becomes a PR X-Ray source, or how a rename is shown. A branch comparison starts at the merge base with HEAD, which is wrong for a commit that is not an ancestor of HEAD.

## Alternatives

1. A native sheet opened from the Git tab's branch menu
2. Reuse the branch comparison source (cmp:<sha>) with its merge base
3. Let git detect renames

## Decision

The picker is a button in the PR X-Ray toolbar (Compare with a date...): a date field that starts on today, then the commits of that day. Choosing one opens a new source at:<full sha> whose baseline is that commit itself, compared with the working copy; no AI run starts until Analyze or Review is pressed. Renames are shown as a removed and an added file.

## Reason

The X-Ray's source picker and the PR number box are already in that toolbar, so the date-first flow starts where the PR review starts. The commit itself is the baseline the person chose (REQ-002), also when it sits on another branch. A pure rename has no content lines, so it would otherwise not appear at all.

## Consequences

The Git tab's branch menu has no date entry. A moved file appears twice (removed at the old path, added at the new one). Untracked new files are included as for local changes: text files up to 512 KB, at most 200.
