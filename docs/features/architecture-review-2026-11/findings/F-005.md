## Finding

The 6.30.144 full GUI run's general host suite executed 213 tests with three optional skips and one failure. `TerminalLinkHostTests.testEditorLineLinks` failed the check that a code-line navigation queued while the viewer loads scrolls to the requested line. The diagnostic reported a 456-pixel scroller with 2,984 pixels of content and scroll position zero. The earlier focused check passed, so the reason for the difference is not established. The remaining GUI run was stopped after the failure so the cause can be fixed before repeating it.

## Resolution

Open. Five isolated repeats of the editor-line check passed after five terminal-layout repeats. A run placing all 159 editor-host tests before the terminal tests also passed; the diagnostic on success showed the pending request cleared and the code scroller at the target. Five repeats of a hidden-view geometry case passed. The test now also checks the selected line and reports CodeMirror viewport state; a repeat of the complete general host suite with that instrumentation passed 213 tests with 3 optional skips and no failures. This repeat did not reproduce the original failure. A code inspection found a plausible failure mode: CodeMirror can return from `scrollIntoView` when target coordinates are unavailable, while its measurement loop then clears the target. This has not been shown to be the cause of the observed failure. Investigate the real editor navigation path and fixture readiness; reproduce and fix the cause before claiming GUI or CI verification.
