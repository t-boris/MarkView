## Finding

The 6.30.144 full GUI run's general host suite executed 213 tests with three optional skips and one failure. `TerminalLinkHostTests.testEditorLineLinks` failed the check that a code-line navigation queued while the viewer loads scrolls to the requested line. The diagnostic reported a 456-pixel scroller with 2,984 pixels of content and scroll position zero. The earlier focused check passed, so the reason for the difference is not established. The remaining GUI run was stopped after the failure so the cause can be fixed before repeating it.

## Resolution

After the guarded navigation retry and further test migrations, a complete general app-hosted run passed 224 tests with 3 optional skips and 0 failures, including the editor line-navigation test (2026-11-17, `/tmp/markview-gui-nov17-current.log`). This is additional regression evidence, but the original failure was not reproduced and its cause remains unproven; the subsequent complete GUI tier passed 19/19 suites; final CI remains pending.

Open. Five isolated repeats of the editor-line check passed after five terminal-layout repeats. A run placing all 159 editor-host tests before the terminal tests also passed; the diagnostic on success showed the pending request cleared and the code scroller at the target. Five repeats of a hidden-view geometry case passed. The test now also checks the selected line and reports CodeMirror viewport state; a repeat of the complete general host suite with that instrumentation passed 213 tests with 3 optional skips and no failures. This repeat did not reproduce the original failure. A code inspection found a plausible failure mode: CodeMirror can return from `scrollIntoView` when target coordinates are unavailable, while its measurement loop then clears the target. This has not been shown to be the cause of the observed failure. An isolated test forced the first CodeMirror scroll attempt to receive no coordinates; the attempt was observed and the target line remained out of view, reproducing this failure mode. The first attempt now has a guarded retry on the next animation frame only when the document, navigation, selection and scroll position remain unchanged and the target is still outside the viewport. The injected-coordinate-loss test failed before the change and passed five times afterward; a later user selection was preserved in five repeats. Three further repeats passed all 17 editor-line checks, including preservation of later selection and scrolling. Both terminal link tests passed together at the preceding checkpoint (15 editor-line and 93 terminal-link checks). The web bundle rebuilt reproducibly, the editor type check and both lint ratchets passed, and the 6.30.145 Debug build passed with 0 warnings. This fixes the demonstrated failure mode but does not establish that it caused the original intermittent full-suite failure. A fresh full GUI run and final CI remain open. Investigate the real editor navigation path and fixture readiness; reproduce and fix the cause before claiming GUI or CI verification.
