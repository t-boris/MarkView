## Finding

[CI run 44046110367](https://github.com/t-boris/MarkView/actions/runs/44046110367) stopped the app-hosted suite after the GUI runner's default 600-second limit. The log shows the Workflow layout test still running; it does not show an assertion failure before termination. The other CI jobs passed.

## Resolution

The manifest gives this full app-hosted suite a 900-second limit, leaving other suite limits unchanged. [CI run 44047894716](https://github.com/t-boris/MarkView/actions/runs/44047894716) passed all jobs, including the hosted suite. A later three-way split in [CI run 44050803050](https://github.com/t-boris/MarkView/actions/runs/44050803050) passed the workflow job, but the UI Studio session job exceeded its 1,200-second suite limit. The UI Studio scenarios now form three independently runnable groups. All 51 stages passed locally in three tests (182, 42 and 139 seconds). The network group also passed when selected separately by the CI wrapper; final CI verification remains open. Boris requested no further intermediate CI runs.

Separately, the local GUI run spent more than three minutes at full CPU sweeping thousands of mouse coordinates in the welcome-screen test; a sample showed SwiftUI/AppKit hit testing. The stopped test was replaced with native clicks on each tile's accessibility frame and passed on its own in 309 seconds. No completed before/after timing exists, and this local test is not identified as the cause of the CI timeout.
