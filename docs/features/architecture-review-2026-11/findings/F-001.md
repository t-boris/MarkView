## Finding

Installed version 6.28.0 crashed twice in SwiftUI accessibility scroll handling. Before the second crash an agent was active in `vivaa-platform`, and the End-to-End QA live run and its event feed were visible. The reports do not identify the sender or the specific scroll region.

An isolated nested-lazy-list probe reproduced the first 13 stack frames and failed on an advertised accessibility scroll action. Removing the inner lazy list alone did not prevent the trap. An eager accessibility representation passed while preserving lazy visual layout.

## Resolution

In progress: the live QA feed, branch results and scenario sidebar use eager accessibility representations. Focused app-hosted tests exercised 100 evolving feed entries, 60 branch results and 80 scenarios, accessible navigation and presses, and page scrolling. The Debug build, seven QA suites, build-warning, architecture, SwiftLint and changed-file unused-import ratchets passed. A subsequent full-host run failed the page-scroll assertions despite their earlier focused pass; a repeat showed that the feed had auto-scrolled to an endpoint before an action. The test now identifies the feed and places it at the midpoint immediately before each action; the repeat passed all 57 hosted tests, including the in-progress prototype migration. The committed fix passed [CI 44041246783](https://github.com/t-boris/MarkView/actions/runs/44041246783) and was published in [6.30.97](https://github.com/t-boris/MarkView/releases/tag/v6.30.97) with a notarized and stapled installer. At Boris’s request, 6.30.97 was installed in the original `/Applications/MarkView.app` package and launched; the original application directory and four project windows were restored. Restarting interrupted the prior agent processes; the original execution state is not claimed restored. This finding stays open: the exact triggering element in the crash is not proven and the fix has not yet been observed under the reported workload.

2026-11-17: After the local QA runner was moved to an actor, the QA, API and native suites and six focused app-host tests for session lifetime and live-feed accessibility passed. These changes have not been released, and the finding remains open for the reported workload.

The app-hosted UI Studio main window and terminal-layout window were moved offscreen or made transparent after Boris reported confusion from a separate test window. The focused terminal layout and link checks passed: 3 hosted tests, 0 failures; the working MarkView process remained running.
