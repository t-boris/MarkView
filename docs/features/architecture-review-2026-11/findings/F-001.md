## Finding

Installed version 6.28.0 crashed twice in SwiftUI accessibility scroll handling. Before the second crash an agent was active in `vivaa-platform`, and the End-to-End QA live run and its event feed were visible. The reports do not identify the sender or the specific scroll region.

An isolated nested-lazy-list probe reproduced the first 13 stack frames and failed on an advertised accessibility scroll action. Removing the inner lazy list alone did not prevent the trap. An eager accessibility representation passed while preserving lazy visual layout.

## Resolution

In progress: the live QA feed, branch results and scenario sidebar use eager accessibility representations. Focused app-hosted tests exercised 100 evolving feed entries, 60 branch results and 80 scenarios, accessible navigation and presses, and page scrolling. The Debug build, seven QA suites, build-warning, architecture, SwiftLint and changed-file unused-import ratchets passed. A subsequent full-host run failed the page-scroll assertions despite their earlier focused pass; a repeat showed that the feed had auto-scrolled to an endpoint before an action. The test now identifies the feed and places it at the midpoint immediately before each action; the repeat passed all 57 hosted tests, including the in-progress prototype migration. The committed fix passed [CI 44041246783](https://github.com/t-boris/MarkView/actions/runs/44041246783) and was published in [6.30.97](https://github.com/t-boris/MarkView/releases/tag/v6.30.97) with a notarized and stapled installer. The previously running 6.28.0 process was left open to preserve the user’s sessions. This finding stays open: the exact triggering element in the installed app is not proven and the new version has not been observed in the user’s running session.
