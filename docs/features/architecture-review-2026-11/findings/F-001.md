## Finding

Installed version 6.28.0 crashed twice in SwiftUI accessibility scroll handling. Before the second crash an agent was active in `vivaa-platform`, and the End-to-End QA live run and its event feed were visible. The reports do not identify the sender or the specific scroll region.

An isolated nested-lazy-list probe reproduced the first 13 stack frames and failed on an advertised accessibility scroll action. Removing the inner lazy list alone did not prevent the trap. An eager accessibility representation passed while preserving lazy visual layout.

## Resolution

In progress: the live QA feed, branch results and scenario sidebar use eager accessibility representations. App-hosted tests exercise 100 evolving feed entries, 60 branch results and 80 scenarios, accessible navigation and presses, and page scrolling. The Debug build, seven QA suites, build-warning, architecture, SwiftLint and changed-file unused-import ratchets passed. The full host suite, CI and release checks remain open. The exact triggering element in the installed app is not proven.
