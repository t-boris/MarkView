## Finding

The backdrop registry job restored the shared hosted build cache but its script built in a different DerivedData directory. Its cold build compiled the MarkViewCore Swift package for both ARM64 and x86_64 despite the app target's ARM-only setting, then hit the 600-second suite timeout before tests started. Other hosted job logs also show the x86_64 package build. The hosted package build uses whole-module Release optimization. See `/tmp/markview-ci-backdrop-failure.log`, `/tmp/markview-ci-session-speed.log` and [CI run 44310136371](https://github.com/t-boris/MarkView/actions/runs/44310136371).

## Resolution

CI now supplies a test-only xcconfig to hosted jobs, constraining dependencies to `arm64` and using incremental, unoptimized Swift compilation; Release keeps its normal settings. A clean local hosted build completed in 59 seconds (`/tmp/markview-hosted-arm-speed-build.log`); its MarkViewCore compiler invocation used `-Onone` for `arm64`, the log had no Intel Swift driver entries, and `lipo` reported an ARM-only app. The backdrop fixture now has its own correctly targeted cache, preserving isolation from its distinct compilation flags. Its isolated runtime suite passed with a clean ARM-only build in 57.2 seconds (`/tmp/markview-backdrop-arm-pilot.log`). CI timing and cache reuse remain unverified.

The first shared hosted build also passed on GitHub: its log contains ARM64 Swift drivers and no x86_64 Swift driver (`/tmp/markview-ci-hosted-arm-build.log`). It took 5 minutes 6 seconds cold before saving the cache. The formerly timing-out backdrop job passed and saved its separate cache (`/tmp/markview-ci-backdrop-arm-passed.log`, [CI run 44317758173](https://github.com/t-boris/MarkView/actions/runs/44317758173)); its cold job took 7 minutes 50 seconds. The separate eight-minute end-to-end CI requirement remains open.
