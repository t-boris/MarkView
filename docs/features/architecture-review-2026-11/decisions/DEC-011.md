## Context

`docs/architecture/architecture-review-2026-11-followup.md` audited v6.26.0 (`85c6ad0`, PR #415) against `architecture-review-2026-11.md` and identified 13 follow-up defects (`FU-01`..`FU-13`), 7 Fixed findings, 17 Partial, 17 Name-only, 5 Not done, and 3 Regressed, alongside 6 proposed architecture rules (Section 6) and open questions for the owner (Section 9).

## Decisions

1. **Follow-up PR Scope (Section 7 Steps A–D & Section 6 Rule 3):**
   - Implement **Steps A–D** from Section 7 in this branch/PR: close all follow-up defects (`FU-01`..`FU-13`), complete remaining Step C security items, apply Step D unused-code/adoption decisions, and restore CI/tests/docs in Steps A–B.
   - Deliver the multi-week **Step E** structural migrations (`AR-14` steps 2–11, `AR-16`, `AR-17`, `AR-18`, `AR-20`, `AR-24`, `AR-25` remaining 15 files, `AR-26` remaining callers, `AR-27`, `AR-28`, `AR-29`, `AR-31` remaining surfaces, `AR-32`, `AR-37`, `AR-38`) in separate, per-finding pull requests following Section 6 Rule 3 ("One finding (or one extraction step) per pull request").

2. **Unused Code & `MarkViewCore` (`FU-01`, Step D, `DEC-006`):**
   - Link `Packages/MarkViewCore` to the `MarkView` app target in `MarkView.xcodeproj` and delete the duplicate `MarkView/Core/` directory.
   - Keep, fix (`FU-04`, `FU-02`), and wire into real production callers: `Subprocess`, `AIOperation`, `SchemaVersionedStore`, and `ToolRegistry` (rebuilt from the app's exact values).
   - Keep active helpers `DocumentScrollSideTable` (with `FU-11` fixed), `TaskBag`, `MarkdownDocumentChunker`, and `AssistantProviderRegistry`.
   - Delete unused scaffolding until their own per-finding PRs: `WorkspaceModalCoordinator`, `WorkspaceSemanticCoordinator`, `WorkspaceChromeCoordinator`, `WindowDependencies`, `WindowTaskScheduler`, `ProjectContextProviding`, `TabsProviding`, `AssistantContextProviding`, `ThemeRegistry`/`ThemeDefinition`/`ThemeWebTokens`, `LayoutPreset` (`FU-08`, `FU-12`), `BackdropRegistry`, `MCPToolRegistry`, `FileTypeRegistry`, and `SemanticDatabaseExecutor`/`SQLiteMigration`.

3. **Architecture Rules & Honest Statuses (`FU-06`, Section 6, Section 9 #1–#2):**
   - Adopt the 6 rules of Section 6 into `CLAUDE.md`.
   - Update `architecture-review-2026-11.md`, `overview.md`, and `REQ-001`..`REQ-008` so statuses accurately match the real verified state of the codebase (`implementing` while Step E remains for future PRs; `verified` reserved for the owner).

4. **Control Socket Authentication (`FU-03`, `DEC-009`):**
   - Keep control socket authentication strictly token-based + kernel peer UID/PID check without a separate socket-level `by_user` confirmation gate.
   - Fix all `FU-03` token handling defects: remove process-wide `setenv`, fail closed on missing/empty token or `nil` peer UID, use constant-time comparison, prefer the per-socket `.token` file in the client, and remove socket/token files on quit.

5. **Domain Folder Reorganization & Section 3 Cleanup (`6.26.2`, `AR-20`, `AR-23`, `AR-29`, `AR-11`, `AR-13`, `AR-22`, `AR-47`, `AR-48`):**
   - Split grab-bag files (`WorkspaceControllers.swift`, `AILayer.swift`, `StorageAndSecurity.swift`) into single-responsibility files (`DocumentScrollSideTable.swift`, `TaskBag.swift`, `MarkdownDocumentChunker.swift`, `AIOperation.swift`, `AssistantProviderRegistry.swift`, `SchemaVersionedStore.swift`).
   - Reorganize all `MarkView/Models/` files into 21 domain folders, `MarkView/Views/` files into 19 domain folders (0 loose `.swift` files at top level), and move all 34 first-party scripts (`mv-kit.js`, `markview-*`) out of `MarkView/Resources/Editor/vendor/js/` into `MarkView/Resources/Editor/js/` with synchronized `project.pbxproj` groups, `Build Web Editor` copy step, HTML script tags, Swift bundle lookups, and `tools/tests/` paths.
   - Remove the `NSAppleScript` fallback (`FileTreeView`), surface non-blocking save errors in `ContentView` with `AtomicFile.write` (`WorkspaceManager`), replace `TOCView.Tab` with `NavigatorTab`, declare all 20 `.go` inputs in `"Build Cockpit runtime"`, and remove the stale `work/` directory.
