## Decision

The window-close delegate forwards messages to SwiftUI's original window delegate on the main thread, where AppKit window-delegate callbacks run. An off-main `responds` or forwarding query does not access the original delegate and does not advertise its forwarded methods. The close decision still consults the original delegate on the main actor before checking running operations.

## Reason

`NSObject` exposes its forwarding overrides as nonisolated, while the original window delegate belongs to the main actor. A guarded weak reference makes the boundary explicit without trapping on an actor assumption or blocking a background thread waiting for the main thread. The reference has a justified unchecked Sendable annotation; the hosted assistant boundary's unchecked wrapper was replaced by an allocated lock, keeping the app/package unchecked-site count at 42, below the original 43. An isolated app-host test passed for forwarded messages, the original close decision and off-main queries. A clean complete-concurrency Debug build reported 0 Swift warnings; final CI and release verification remain open.
