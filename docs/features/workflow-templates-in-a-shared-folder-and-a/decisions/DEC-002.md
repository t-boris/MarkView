## Context

The previous default gave the bug process a pull request and passing checks when the project had no Definition of Done, which cannot complete without GitHub.

## Alternatives

1. Ship Boris's current setup as the built-in default with GitHub requirements on
2. Only one template may be the default and it is fixed in the app

## Decision

New empty projects start on the template the person chose in Settings. Until one is chosen, or when it cannot be used, they start on the built-in Kanban flow whose processes require no pull request, checks or release.

## Reason

Boris chose that any saved template can be assigned. A fixed built-in 'most configured' scheme cannot work where GitHub or CI is not connected, so the safe built-in must ask nothing of GitHub; the person's own richer scheme is one 'Use for new projects' away.
