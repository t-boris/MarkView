## Context

Boris asked for 'some shared folder of MarkView, locally'.

## Alternatives

1. UserDefaults (invisible, awkward to move)
2. A single templates.json (one bad edit loses all)
3. Inside each project's .dde (not shared)

## Decision

One file per template (<id>.json: schema, id, name, note, savedAt, workflow), and a small default.json next to them naming the template new projects use. The folder is the whole store: copying it moves the templates and the choice.

## Reason

App-wide data of MarkView already lives in ~/Library/Application Support/MarkView/. Files are inspectable, can be copied or shared by hand and reuse the project workflow's own encoder, decoder and validation, so a template can never hold something a project could not.

## Consequences

Templates are per Mac user; sharing between machines is by copying the folder. A template is a copy, like a process template: later edits of the project do not change it.
