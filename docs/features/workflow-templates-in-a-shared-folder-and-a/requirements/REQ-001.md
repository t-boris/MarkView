## Statement

The system shall let a person save the workflow they see in the Workflow tab (features, bugs and all processes) as a named template in a folder of MarkView that every project shares, and shall list, reveal and delete those templates.

## Acceptance Criteria

- [ ] The Flow popover has a 'Save as template…' action that asks for a name and an optional note, and stores one JSON file per template in ~/Library/Application Support/MarkView/WorkflowTemplates/
- [ ] A workflow that fails validation cannot be saved as a template and the reason is shown
- [ ] A template keeps the states, transitions and every process with its delivery settings, as the draft has them
- [ ] Saving a second template with the same name does not overwrite the first (the new file gets its own id) unless the person chooses to replace it
- [ ] Settings > Workflow templates lists the saved templates with name, note, saved date, outline and whether any process needs GitHub, and offers Reveal in Finder and Delete for each
- [ ] A file in the folder that cannot be read, or whose workflow is invalid, is listed as unusable with the reason and is never deleted or rewritten by the app
- [ ] All reading and writing of template files happens off the main thread
