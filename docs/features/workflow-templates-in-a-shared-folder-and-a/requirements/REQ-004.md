## Statement

The system shall start a new, empty project on the Kanban flow with every process requiring nothing from GitHub (work reaches the default branch directly, no checks, no release), unless the project itself declares otherwise, and shall tell the person how to switch the requirements on and when a process needs GitHub that is not connected.

## Acceptance Criteria

- [ ] A new empty project without a Definition of Done adopts Kanban with feature and bug processes that are direct-to-main, no checks, no delivery event
- [ ] A new empty project whose own Definition of Done or guide requires a pull request or CI keeps what it declared
- [ ] The Done panel of a process that needs a pull request, checks or a GitHub release shows a warning while GitHub is not enabled in Settings, saying that work cannot complete and how to fix it (connect GitHub, or switch the requirement off)
- [ ] The Done panel of a process that needs nothing explains where to switch the requirements on: Processes, the process, 'Reaches the branch', 'Checks must pass', 'Delivery event', and that they need GitHub connected in Settings
- [ ] Existing projects that already adopted a workflow are not touched, and projects with items keep the delivery rules they adopt today
