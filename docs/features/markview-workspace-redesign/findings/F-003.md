## Finding

The proposed ready-again action assumes a specification can remain ready while a participant marks it ready again. The current feature model has one `ready` status, and lifecycle capture records readiness only on a transition into `ready` or a readiness-score transition to 100%. The specification needs a separate handoff revision or event model and must say how it interacts with existing feature status and lifecycle history.

> When any participant with project access marks the current specification ready again, the changed flag clears.

## Resolution

AI: Повторное действие «Mark ready» создаёт новую ревизию передачи спецификации и очищает отметку об изменениях, даже если статус функции уже `ready`. Статус функции остаётся `ready`; существующее событие `spec_ready` не создаётся повторно. — see DEC-017.
