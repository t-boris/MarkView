## Statement

Organize the existing interface into Files for reading and writing, Project Map for understanding the project, and Work for specification and Git work. In Work, support explicit specification handoff by any project participant. Keep a handed-off specification ready and visibly flag subsequent changes until a participant marks the current specification ready again.

## Acceptance Criteria

- [ ] A participant with project access can mark a specification ready and hand it to a developer.
- [ ] Editing a handed-off ready specification preserves its ready state and visibly marks it as changed since handoff.
- [ ] The developer can distinguish the current specification from the version that was handed off.
- [ ] When any participant with project access marks the current specification ready again, the changed flag clears.
- [ ] Every mapped capability remains reachable in its destination workspace and through listed secondary routes.
- [ ] Each handoff records a revision, actor, time, explicit file links, and an immutable browsable snapshot of the complete feature folder, excluding handoff metadata from comparison.
- [ ] Added, modified, and deleted files, including external changes, set the changed flag while status remains ready; ready-again creates a new revision without adding a lifecycle event.
- [ ] Left navigation, center workspace, and right assistant terminal can each be shown or hidden independently; changing the center workspace leaves the terminal visible and preserves its session.
