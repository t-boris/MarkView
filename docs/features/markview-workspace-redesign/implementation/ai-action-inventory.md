# AI action inventory and lifecycle contract

Status: approved by Boris on 2026-09-28 (DEC-022). Baseline: `v2.27.0`.

## Shared lifecycle

Every managed action shows its concrete input scope, selected assistant/model, and output location before launch. While running, it shows the current stage and elapsed time, with Stop. A stopped or failed action retains any safe partial output, labels it incomplete, and offers retry. A read-only result can be inspected and dismissed. Generated or externally changed files appear in a review surface with paths and diffs before the user treats the task as finished. Any action needing an assistant explains how to configure one when none is available. Assistant terminals are explicitly unrestricted: their commands can read and edit the project, and MarkView displays observed file changes for review after a terminal command or session.

## Verification gates

- Execute or simulate every named action with a configured assistant and with none configured; verify the scope, executor, destination, progress, Stop, partial/failure, and review states.
- Repeat file-changing actions with edits made outside MarkView while the app is open. The review surface must refresh from disk and report added, modified, and deleted files.
- Preserve existing terminal prompts and their `Option`-click type-only behavior. Never imply that stopping a terminal rolls back file changes or remote actions.
