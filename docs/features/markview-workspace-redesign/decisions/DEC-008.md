## Context

A specification may change after an author marks it ready and hands it to a developer.

## Alternatives

1. A. Keep ready: changes do not affect the ready state and receive no additional signal.
2. B. Reset ready: any change returns the specification to draft.
3. C. Flag changed: retain ready and visibly flag changes made after handoff.

## Decision

Keep the specification ready after a post-handoff change and visibly flag that it changed.

## Reason

Boris selected option C so later edits are visible without undoing the handoff.

## Consequences

The developer can see that the current specification differs from the handed-off version while the ready state and handoff history remain intact.
