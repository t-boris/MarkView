## Context

REQ-002 requires an explicit handoff, and DEC-005 says the developer starts in Files and can return to the specification through Work. The current requirement does not define a recipient, delivery channel, or navigable handoff artifact.

## Alternatives

1. Change the feature status to ready only; the developer finds it independently.
2. Require a named developer and deliver the specification to that person.
3. Create a persistent, unassigned handoff record with a resume entry point in Work and Files.

## Decision

Handoff creates a persistent project-level record for the specification, visible to participants in Work. Its resume action opens Files with the specification's explicitly linked project files and a route back to the specification. It does not require a named recipient or send a notification.

## Reason

A durable, discoverable record supports the author-to-developer journey without introducing an identity or notification system that the feature has not otherwise defined. Explicit file links make the resume path predictable; an empty state prevents the app from implying it selected relevant files.

## Consequences

Work needs a visible handoff entry and Files needs a resume action. The handoff must list its linked files; if none are linked, Files opens the specification and shows an explicit empty state. Snapshot identity and post-handoff change detection remain to be specified under F-004.
