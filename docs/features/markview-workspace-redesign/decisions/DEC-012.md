## Context

REQ-002 requires the developer to distinguish the current specification from the handed-off version. The feature folder can contain requirements, decisions, answers, findings, discussion, and supporting material. The current boundary and snapshot storage are unspecified.

## Alternatives

1. Compare only normative requirements and accepted decisions; other handed-off context could change without a flag.
2. Record a Git commit as the handoff revision; this depends on the feature folder being committed and available in Git.
3. Hash the feature folder without retaining its contents; this detects changes but cannot show the handed-off version.

## Decision

At each explicit handoff, capture an immutable, browsable snapshot of the entire feature folder and record its file paths and content hashes. Compare that snapshot with the current folder, excluding snapshot metadata; any added, modified, or deleted file sets the changed-since-handoff flag until a participant marks the current specification ready again.

## Reason

The developer receives the full feature context, so the change flag should cover that same context. Retaining the content supports direct comparison, while path and hash comparison detects deletions and external edits without depending on Git history.

## Consequences

Handoff needs persistent snapshot storage and a comparison covering additions, edits, and deletions, including changes made outside MarkView. The UI must expose the handed-off snapshot alongside the current specification. Handoff metadata must be excluded from its own comparison. Marking the current specification ready again creates a new snapshot and clears the changed flag. The overview should mark Data Model as requiring a decision.
