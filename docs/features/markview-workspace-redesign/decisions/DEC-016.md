## Context

REQ-004 promises that a developer can reach relevant files after handoff, but it does not define how those files are selected or what happens when none are linked. DEC-011 already proposes explicitly linked project files and an empty state.

## Alternatives

1. Infer relevant files from specification text or recent activity; this may open unrelated files.
2. Require at least one linked file before handoff; this blocks valid specifications that have no known file targets.
3. Use explicit file links and allow handoff without them, with an actionable empty state.

## Decision

Use explicit project-relative file links as the sole source for the resume file list. The handoff resume action opens Files with available linked files. If there are no links, show an empty state with actions to browse project files and return to the specification in Work. Show missing links as unavailable with their paths; do not silently substitute other files.

## Reason

Explicit links make the author's intent reviewable and the developer's resume path predictable. Allowing an empty list supports new projects and early specifications without pretending that MarkView has identified relevant files.

## Consequences

REQ-004 needs acceptance criteria for adding and viewing file links, opening available linked files, handling missing files, and resuming with no links. The handoff record must retain the linked paths and provide a route back to the specification in Work.
