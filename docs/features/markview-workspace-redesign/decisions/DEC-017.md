## Context

DEC-009 requires a ready-again action to clear the post-handoff change flag while the specification remains ready. The current feature model has one `ready` status, and automatic `spec_ready` capture depends on a transition into `ready` or readiness reaching 100%.

## Alternatives

1. Toggle the feature out of `ready` and back to `ready` to reuse lifecycle capture.
2. Record another `spec_ready` lifecycle event for every ready-again action.
3. Keep the changed flag until the feature leaves `ready`.

## Decision

Model each explicit handoff, including ready-again, as a persistent handoff revision separate from feature status and lifecycle events. When a participant with project access marks a changed specification ready again, atomically record a new handoff revision using the current specification snapshot and clear the changed flag. Keep feature status `ready` and leave prior lifecycle events intact.

## Reason

A handoff revision represents acceptance of a particular specification version. Separating it from feature status makes repeated handoffs auditable without artificial status transitions or misleading cycle-time events.

## Consequences

The handoff record must store a revision identifier, actor, timestamp, and snapshot reference. Change detection compares the current specification with the latest handed-off revision. Existing feature status and lifecycle analytics retain their current meaning; the handoff history shows repeat handoffs separately.
