## Context

Boris clarified that the assistant terminal is central to MarkView. Hiding it
under Work made its location unclear. The persistent right Contents panel
occupied space without serving the primary workflow. The approved migration
map already calls for an assistant terminal reachable from every workspace.

## Decision

Put a clearly labelled Terminal control in the full-width header. It reveals
the assistant terminal from Files, Project Map, or Work without changing the
selected workspace. At wide widths, the terminal shares the center area in a
resizable lower pane. At constrained widths, it takes the center area until
the user returns to a workspace. Keep its session tabs and Claude Code,
Codex, Cline, Copilot, and shell profiles. Keep `⌘3` as the terminal route.
Keep the prompt shortcuts collapsed initially so terminal output gets the
available height; users can expand them in the terminal.

The right panel is only an optional document Contents column for Markdown
headings. Hide it by default in the redesigned layout; its header control and
`⌘2` reveal or hide a docked column while a Markdown file is active.

## Consequences

The terminal should be an obvious primary action on a project's empty Files
screen. Preserve session state and the selected assistant while switching
workspaces. Verify usable terminal width, Stop and Restart, and row/column
refitting at the minimum window size and 200% interface text.

## Supersession

DEC-025 replaces the lower-pane layout after Boris found its limited height
unusable for the application's primary terminal workflow. The header route,
terminal profiles, and optional document Contents behavior carry forward.
