## Context

The current app sets a 900 × 600 point minimum window. Its center editor has a 400 point minimum, and the right panel has a 200 point minimum. A documented terminal bug involved clipping after panel resizing. REQ-006 requires usability in narrower windows and at 200% interface text scale but does not define the layout behavior.

## Alternatives

1. Keep all panels visible and increase the minimum window size.
2. Keep a fixed three-column layout and allow content to clip or scroll horizontally.
3. Use an adaptive single-content layout at constrained widths, with direct access to hidden panels and actions.

## Decision

Support a minimum window size of 900 × 600 points. At widths where the active content and adjacent panels cannot remain usable, collapse secondary panels into accessible navigation or menus. Give the editor or terminal the available content width, with an explicit way to switch between them; simultaneous display is optional when space permits. Refit terminal rows and columns whenever its visible size changes.

## Reason

This uses the application's existing minimum as a testable boundary and preserves access to workflows without requiring two width-sensitive surfaces to share insufficient space. Testing the running app addresses the documented terminal clipping risk.

## Consequences

REQ-006 should specify the 900 × 600 point minimum and the adaptive states. Acceptance checks should cover each workspace at that size and at 200% interface text scale, access to collapsed panels and actions, and editor and terminal use after switching between them. Verify terminal fitting and absence of clipped rightmost and bottom content in the running app.
