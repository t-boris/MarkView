## Context

Boris wants the coding assistant terminal to use the whole content area when
focused. He also needs to see code or a document at the same time on some
occasions. A short terminal strip below the workspace does not support this.

## Decision

Keep the labelled Terminal control in the full-width header. Opening it uses
the entire content area below the header. At a width that can support two
usable columns, a clearly labelled Side by side control shows the active
Files, Project Map, or Work content on the left and the terminal on the right.
Both surfaces extend to the bottom of the window. Focus returns to the
full-content terminal. Choosing a workspace while the terminal is focused
enters the side-by-side layout at supported widths; at constrained widths it
shows the chosen workspace and keeps the terminal session available through
the header. The Terminal control can hide the terminal altogether.

Preserve the assistant session, transcript, selected profile, process state,
and prompt shortcuts across layout changes. Keep Claude Code, Codex, Cline,
Copilot, and shell profiles, Stop and Restart, `⌘3`, and terminal refitting.
Prompt shortcuts start collapsed to maximize output space. Document Contents
remains an optional Markdown-only docked column, hidden by default and never
drawn over the terminal.

## Consequences

Verify focused and side-by-side modes with an open document, Project Map, and
Work. At 900 × 600 points and 200% interface text, keep the terminal and each
workspace usable by using one full-content surface at a time. Verify session
continuity and terminal row/column refitting after layout changes.

## Supersession

DEC-027 replaces the terminal presentation modes with three independent
columns after Boris clarified the intended window model.
