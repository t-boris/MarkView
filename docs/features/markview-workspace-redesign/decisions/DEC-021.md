## Context

Boris requested more icons, less persistent text, a minimal visual style, and
current desktop design practices. The redesign must still preserve discoverability
and the existing requirement to communicate status without color alone.

## Decision

Use a restrained, icon-forward macOS visual system. Show familiar SF Symbols for
frequent navigation and actions; move lower-frequency actions into contextual or
overflow menus. Keep short visible labels where an icon alone is ambiguous or the
content is a state, destination, or consequential action. Give every icon-only
control a tooltip, accessibility label, and menu or keyboard route. Use native
system surfaces, typography, focus states, and adaptive layout behavior.

## Reason

This implements Boris's visual preference while retaining the clarity required
for specification handoff, AI output, task status, and accessibility. Apple's
current macOS guidance recommends a selective toolbar, familiar sidebar symbols,
menu access to toolbar commands, and a comfortable information density.

## Consequences

Apply the same icon and spacing system to SwiftUI and the bundled editor. Check
light, dark, increased contrast, 900 × 600 points, and 200% interface text in the
running app. Do not use color or an unlabeled icon as the only way to identify a
workspace, task status, handoff revision, or AI state.
