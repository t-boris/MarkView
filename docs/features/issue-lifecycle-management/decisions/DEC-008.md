## Context

REQ-002 requires "separately evidenced acceptance verification" (feature implemented → verified) but no record said whose evidence counts. Answered by Q-007.

## Alternatives

1. Only a human in the UI (Q-007 A).

## Decision

A feature moves from implemented to verified when a human accepts it in the MarkView UI (a note is optional), or when an AI session requests it through project MCP with non-empty verification evidence text and every acceptance criterion of the feature's active requirements is ticked. For a bug, closing after a fix (fixed → closed) follows the same rule; a bug has no criteria to tick, so the evidence text is enough. The feature must already be implemented through evidence (or be reconciled as such); verification never replaces delivery evidence. The AI path never counts as a human override.

## Reason

Boris chose "a human or AI with evidence" (Q-007 B) so that acceptance does not wait for a person when the work is demonstrably proven.

## Consequences

The ticked criteria are written by the same AI, so they are weak independent evidence; the history records the evidence text and who ticked nothing on the AI's behalf. Humans can still correct a wrong acceptance by reopening.
