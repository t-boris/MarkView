## Context

Q-003 chose reopening the original issue for a regression; REQ-002 criterion 5 says "a confirmed regression", which no record defined. Answered by Q-008.

## Alternatives

1. Only a human in the UI (Q-008 B).
2. Also automatically on a failing required check on the default branch (Q-008 C).

## Decision

A regression is confirmed when (1) a human reopens the issue in the UI with a non-empty reason, or (2) a bug report that is not closed as invalid or duplicate names the completed issue in a regression_of front matter field; then an AI session (or the automatic reconciler) may reopen the original issue. A failing check on the default branch is shown as a discrepancy only and reopens nothing. Reopening goes to the applicable unfinished stage: a feature to implementing, a bug to open. New independent work is tracked as a new issue linked to the original with a related field.

## Reason

Boris chose "a human in the UI or AI by a linked bug" (Q-008 A); a red check alone does not prove a regression.

## Consequences

Reopening a completed issue is not a human override: it needs a reason but bypasses no evidence condition. A reopened issue loses its verified completion and so reopens its closed GitHub issue (REQ-006).
