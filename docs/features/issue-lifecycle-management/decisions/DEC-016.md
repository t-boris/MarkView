## Context

DEC-007, DEC-010, DEC-012 and DEC-015 say what counts as completion and as confirmation but not when MarkView looks, nor what happens without GitHub.

## Alternatives

1. Complete only when an agent or a person asks (no observer); the hand-off prompts would then have to say so
2. Read git and GitHub for every item on every load (too many process runs for a project with hundreds of done items)

## Decision

MarkView, as the system actor, moves a feature in implementing to implemented and a bug in fixing to fixed when the delivery evidence (DEC-012) is complete, under the same rules as any request. It looks (1) after a project load, at most once per five minutes per item and only while the GitHub integration is on, (2) in the GitHub sync, for the items linked to an issue that is open on GitHub, (3) when a person presses Check evidence, and (4) when an AI asks with markview_set_status / markview_set_bug_status. Incomplete or unreadable evidence changes and records nothing. A completed status that was set by an override, was already there when MarkView first recorded the issue, or was edited outside MarkView is unverified; evidence confirms it only when the same sources are read on demand (Check evidence, the sync for items linked to an open GitHub issue), never on its own. With the GitHub integration off MarkView starts no gh process: checks and releases are reported unavailable, so the verdict is unknown and a person decides. verified and closed after a fix are never automatic. A status request that wrote the status but could not write its history record counts as reached; the next start closes the operation.

## Reason

REQ-002 criterion 2 and the idea ("it must all happen automatically") need an automatic completion; DEC-007 and DEC-012 fix what evidence it needs; the project rule that optional integrations stay silent when off fixes the GitHub-off behaviour. An independent review found that the hand-off prompts promised automatic completion that no code performed.

## Consequences

Without GitHub nothing completes by itself; a person marks the work done with an override and a reason. A project with many old done items is not scanned on load: only items under way are looked at, and only linked ones during a sync.
