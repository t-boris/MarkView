## Context

REQ-004 and REQ-005 need an inspectable history and recovery from partial failures; overview.md says the formats need no product choice. The lifecycle analytics log lives per Mac and has other semantics (DEC-001, DEC-005 of the cycle-time feature).

## Alternatives

1. Keep the history in the issue's Markdown file.
2. Reuse the analytics event log.

## Decision

One append-only JSON-lines file per project, .dde/lifecycle/transitions.jsonl, holds the transition journal and the history: each operation writes a begin record, then the status change in the Markdown file with a compare-and-set on the stored status, then an applied record; rejected, aborted, recovered, external-edit, baseline and GitHub outcome records use the same file. A command id makes a repeated request return its first outcome. The file is ignored by git like the rest of .dde. The existing lifecycle events (cycle-time analytics) are left unchanged.

## Reason

A journal written before the status change lets the next start recover an operation that stopped between the two writes, and an append-only file needs no migration.

## Consequences

The history is per Mac and project folder and does not travel with git; the Markdown status stays the single stored status.
