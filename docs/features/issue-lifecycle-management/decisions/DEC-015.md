## Context

REQ-005 requires external Markdown status edits to be detected and reconciled without treating them as proof of lifecycle conditions.

## Alternatives

1. Revert external edits automatically.

## Decision

When the stored status differs from the last status the history applied and no operation is pending, MarkView records an external-edit entry, keeps the stored status (the file is what the person sees) and marks it unverified. An unverified completed status never counts as verified completion, unless the delivery evidence for it is confirmed now (then an automatic confirming transition is recorded). Otherwise the discrepancy stays listed until a human accepts it as an override with a reason or restores the previous status.

## Reason

The service cannot prevent edits made outside it (the research says so); keeping the file and recording the difference is the only non-destructive way.

## Consequences

A git pull that brings another clone's status change appears as an external edit once and is confirmed by evidence or listed.
