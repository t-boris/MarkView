## Context

Q-002 B allows a forced human transition with a reason and says AI acts only by rules; REQ-002 requires a successful handoff to be the start evidence. The records do not say how the three kinds of caller are told apart.

## Alternatives

1. Trust by_user: true on MCP calls as today.

## Decision

Every transition request carries an actor: human (a gesture in the MarkView UI), ai (a call through project MCP) or system (MarkView's own workflows and observers). The override (force) exists only for the human actor and only with a non-empty reason; MCP calls, including by_user: true, can never carry it. A transition into implementing or fixing needs start evidence: a recorded successful handoff of the issue to an agent, or an explicit attachment of an AI session to the issue through MCP. Humans and the system start work through the handoff; a manual start without evidence is an override. Statuses a hand-written file uses outside the vocabulary (done, in-progress) are treated as unknown: only a human with a reason may move such an issue.

## Reason

This is the smallest reading of Q-002, REQ-002 criteria 1 and 4 and REQ-003 criterion 3 that closes the impersonation hole of by_user.

## Consequences

An AI agent that works from a terminal MarkView did not start must attach itself first (markview_attach_issue). The person's quick way to force a status is the new Lifecycle section in the issue view, not a tool call.
