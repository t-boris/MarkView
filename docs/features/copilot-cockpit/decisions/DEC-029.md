## Context

BUG-130: a 20-step run in vivaa-platform stopped at step 3, a QA step that was not a prerequisite, and waited a day. The Temporal workflow paused on every failed step, although the planner prompt said only a prerequisite's failure pauses later steps, so the fix steps planned after QA never ran.

## Alternatives

1. 2b: keep pausing on every failure but offer Skip and continue next to Retry
2. Let the planner mark each step as gating or not, independently of isPrerequisite

## Decision

The workflow decides per step: a failed step that is not a prerequisite is recorded with continuedAfterFailure true, a notice tells the person, and the next step starts and sees the failure and the bugs QA filed in priorResults. A failed prerequisite still runs its bounded recovery and then pauses. The workflow sends its decision to the host (StepTask.continuesAfterFailure) and overwrites the host's answer (Result.continuedAfterFailure), so Swift never decides it alone. Runs started before the change keep pausing (workflow.GetVersion "non-prerequisite-failure-continues"). A run that went on past failures finishes as "Finished with failures", never as a success. The planner is told to mark as a prerequisite every step whose failure makes later steps pointless or unsafe.

## Reason

Boris chose this option (2a) on 2026-11-26. It matches what the planner was already told, lets discovery steps (QA, audits) feed the fix steps planned after them, and keeps the safety gate where it belongs: on prerequisites.

## Consequences

A planner that leaves a gating step unmarked lets the run go on past it; the prompt names which steps to mark. Managed runs mark every composed step as a prerequisite, so they keep pausing. The run list and run screen show the failed steps of a finished run.
