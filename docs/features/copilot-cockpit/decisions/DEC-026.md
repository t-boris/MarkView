## Context

DEC-006 made the capability controls advisory instructions to an agent with full user permissions, and the time, budget and fix cycle limits were free text that nothing read. On 2026-11-13 Boris directed that the controls be enforced through the MarkView MCP server (a disabled capability means the matching MCP tools are switched off for the step), that the budget limit be removed because cost cannot be measured per step, that a limit stops the step and pauses the run, and that the Copilot itself act as a supervisor that answers the questions a step agent asks, by its own judgment, without waiting for anyone.

## Alternatives

1. Keep the controls advisory (DEC-006).
2. Restrict step agents to controlled actions or an isolated environment with no shell, editor or network (the alternatives DEC-006 rejected for simplicity).
3. Send an agent's questions to the person and pause the run until they answer.

## Decision

1. While a Cockpit step runs, MarkView refuses the MCP tools a control forbids: filing bugs, moving a bug into fixing, deployment tools (all of them when deployment is disabled, otherwise any environment but the named one), and always starting or driving other agents. Every tool is classified; an unclassified tool is refused. The step terminal is recognised by the process ancestry of the MCP proxy, so Boris's own terminals are not restricted.
2. After each agent step MarkView compares the project before and after: changed source files or a moved HEAD when fixing is off, and new scenarios when creating scenarios is off. A violation fails the step and pauses the run.
3. The time limit (minutes of agent work for the whole run, kept across interruptions) and the fix cycle limit are typed numbers measured by MarkView. Reaching one stops the step through the existing pause, and the run waits with the reason. The budget limit is removed.
4. A supervisor control (on by default) lets a step agent call markview_cockpit_ask. The project's assistant answers at once with read-only access to the project; nobody is waited for. A matter outside the plan and the controls (secrets, production data, deleting data, anything it cannot judge) is answered "do not, record it as a blocker in your step report". At most 25 questions per step; a repeated question gets its first answer; a failure returns a conservative instruction. Every exchange is logged in the run.

## Reason

The person approving a run needs the controls to mean what they say wherever MarkView can make them so, and honest labels where it cannot. A gate at the MCP server plus an after-the-step audit is the strongest enforcement that needs no change to the agent CLIs, and it keeps the existing full-access agent terminal. A supervisor that never waits keeps the run unattended, which is the point of the Cockpit, and the gate keeps a wrong answer from granting a forbidden capability.

## Consequences

REQ-001 and REQ-003 still say the controls are advisory and not enforced; their wording must be revised once this decision is accepted. What is not enforced must still be disclosed: the agent's own shell and editor can change files (detected after the step, not prevented), builds and deployments run from the agent's shell are neither stopped nor detected, Build and Checks remain instructions only, and a process that leaves the step terminal's process tree is not recognised by the gate. The supervisor's answers are model output and can be wrong; only the gate and the audit are hard. Questions an agent prints into the terminal and the agent CLI's own permission prompts are not seen, so such a step stalls until the time limit or Pause. Runs saved before this change read their free-text limits where they are a clear amount of time or a number, and otherwise as no limit.
