## Statement

Propose a concrete, reviewable sequential plan for the user's goal, with an agent and assignment for each step and explicit success criteria. Disclose infeasible outcomes and alternatives, disclose that capability controls are advisory instructions passed to an agent running in the existing full-access agent terminal, and require explicit approval before execution. A single cockpit plan approval also satisfies the production QA data-changing-actions acknowledgement when the user is shown the exact production QA plan and its data-changing actions and explicitly confirms their execution in production. Approval applies only to the specific QA plan presented; a change invalidates it and requires renewed approval. Existing production-step confirmations remain in force.

## Acceptance Criteria

- [x] The proposed plan identifies the selected scenarios where applicable, sequential steps, an assigned agent and assignment for each step, completion conditions, and explicit success criteria.
- [x] The cockpit discloses goal outcomes it understands it cannot perform and offers alternatives where possible before execution.
- [x] Voice or text refinements revise the whole plan and graph together; individual graph blocks are not directly edited.
- [x] Before execution, the user can review the plan, selected capability controls, limits, and success criteria.
- [x] Before execution, the cockpit clearly discloses that capability controls are instructions to the agent, not enforced restrictions.
- [x] Before execution, the cockpit clearly discloses that the agent runs in the existing full-access agent terminal with the user's full permissions and can perform actions disabled in the controls.
- [x] Before execution, the cockpit clearly discloses that disabling fixes or deployment does not guarantee that those actions will not occur.
- [x] Execution cannot start without the user's explicit approval of the proposed plan.
- [x] When the QA plan includes data-changing actions in production, the review shows the exact production QA plan and the exact list of those actions.
- [x] For a QA plan that includes data-changing actions in production, the user explicitly confirms that those actions will run in production as part of cockpit plan approval.
- [x] That cockpit plan approval also satisfies the production QA data-changing-actions acknowledgement for the specific QA plan presented.
- [x] A change to the QA plan invalidates its approval and requires renewed approval before execution.
- [x] Existing production-step confirmations remain in force.
