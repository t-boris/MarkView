## Statement

Propose a concrete, reviewable plan with explicit success criteria for the test–fix–retest template, disclose that capability controls are advisory instructions passed to an agent running in the existing full-access agent terminal, and require the user's explicit approval before execution. A single cockpit plan approval also satisfies the production QA data-changing-actions acknowledgement when the user is shown the exact production QA plan and its data-changing actions and explicitly confirms their execution in production. The approval applies only to the specific QA plan presented; any change to that plan invalidates the approval and requires renewed approval. Existing production-step confirmations remain in force.

## Acceptance Criteria

- [ ] The proposed plan identifies the selected scenarios, stages, completion conditions, and explicit success criteria.
- [ ] Text refinements update the plan and graph together.
- [ ] Before execution, the user can review the plan, selected capability controls, limits, and success criteria.
- [ ] Before execution, the cockpit clearly discloses that capability controls are instructions to the agent, not enforced restrictions.
- [ ] Before execution, the cockpit clearly discloses that the agent runs in the existing full-access agent terminal with the user's full permissions and can perform actions disabled in the controls.
- [ ] Before execution, the cockpit clearly discloses that disabling fixes or deployment does not guarantee that those actions will not occur.
- [ ] Execution cannot start without the user's explicit approval of the proposed plan.
- [ ] When the QA plan includes data-changing actions in production, the review shows the exact production QA plan and the exact list of those actions.
- [ ] For a QA plan that includes data-changing actions in production, the user explicitly confirms that those actions will run in production as part of cockpit plan approval.
- [ ] That cockpit plan approval also satisfies the production QA data-changing-actions acknowledgement for the specific QA plan presented.
- [ ] A change to the QA plan invalidates its approval and requires renewed approval before execution.
- [ ] Existing production-step confirmations remain in force.
