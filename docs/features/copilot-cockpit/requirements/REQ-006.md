## Statement

Provide controls for an active run, require approval of changes to its remaining plan, preserve plan and result history, and pause execution when MarkView closes with user-initiated continuation after reopening or restart.

## Acceptance Criteria

- [ ] The user can pause or stop an active run and request changes to its goal or limits.
- [ ] The user can start execution from any selected step without requiring verification or successful completion of earlier steps.
- [ ] The cockpit previews changes to the remaining plan and applies them only after explicit user approval at a safe stage boundary.
- [ ] Previously obtained results retain their association with the plan and build under which they were produced.
- [ ] When a change alters an approved production QA plan, the previous production QA acknowledgement is invalidated. Renewed approval requires the user to review the specific changed QA plan and the exact list of its data-changing actions and explicitly confirm their execution in production.
- [ ] Existing production-step confirmations remain in force after replanning.
- [ ] When MarkView closes or the person pauses, the active agent terminal and its process group stop; the interface warns that separately detached background processes may continue.
- [ ] After MarkView or the computer restarts, the saved run is presented for the user to continue only after the person confirms; it does not resume automatically.
