## Statement

The system shall show the proposed plan as an ordered list of steps that the person can read, edit and assign to an agent and model before approving it.

## Acceptance Criteria

- [ ] Each step shows its title, kind, assignment, completion condition, and the agent and model that will run it (a model left empty reads as the agent's default and says which model that is).
- [ ] The person can change a step's title, assignment, completion condition, prerequisite flag, QA scenario, agent and model, and can move, duplicate, insert and delete steps; the scenarios the plan lists always match its steps.
- [ ] The planner, the supervisor and each step can use a different agent and model; a model the planner proposes that the agent does not offer is read as the default and does not fail the plan.
- [ ] A step's model reaches its agent terminal as the agent's model option; a step with no model passes none.
- [ ] Every reason approval is blocked is shown on the step it belongs to, or on the screen when it belongs to none; approval is available exactly when nothing blocks it.
- [ ] A change to the goal or the controls after a plan exists does not discard the plan; the screen says its steps were not re-checked.
- [ ] For each QA scenario the screen shows the environment, the selected branches, the preparation, the confirmations and the production data-changing actions drawn from the exact plan that approval covers, and offers that exact text.
