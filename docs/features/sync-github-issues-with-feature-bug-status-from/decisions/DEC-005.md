## Context

REQ-002 listed free-text 'issue #n' mentions as a link source. GitHub pull requests and issues share one number sequence, and the issues API also returns pull requests. So a '#n' mention can resolve to a PR, and the sync could close the wrong item. The spec also did not say how to handle links to other repositories or forks. DEC-001 applies changes immediately without a preview, so a wrong match leads straight to an unintended change on GitHub (F-002).

## Alternatives

1. Match explicit links plus free-text 'issue #n' and bare '#n' mentions resolved against the project's repository, and verify via the API that each target is not a pull request
2. Match explicit links plus only the literal phrase 'issue #n' (case-insensitive) resolved against the project's repository, and ignore bare '#n'
3. Match explicit links including full issue URLs to any repository the user's credentials can access, and report permission errors as 'failed'

## Decision

Sync matches items to GitHub issues only through explicit links: the `github` field, front matter `issue`/`issues`, and full GitHub issue URLs. Free-text '#n' and 'issue #n' mentions are ignored. Any target that the GitHub API reports as a pull request is skipped with reason 'pull request'. Links to any repository other than the project's configured repository are skipped with reason 'other repository'.

## Reason

Sync applies changes immediately and has no preview (DEC-001). A false match would close an unrelated issue or PR with no chance to review it first. Explicit links make the mapping unambiguous. Limiting sync to the project's own repository keeps the scope and permission surface small. Losing coverage for items linked only by text mentions is an acceptable trade-off: they are reported and can be fixed by adding an explicit link.

## Consequences

REQ-002 must drop 'issue links' and 'issue #n' as free-text sources. It needs acceptance criteria for: ignoring text mentions; skipping PR targets with reason 'pull request', detected from the API response (e.g. the pull_request field); and skipping links to other repositories or forks with reason 'other repository'. Items linked only by text mentions will appear as 'unlinked'. DEC-004 (proposed) says links that explicitly name owner/repo are resolved against that repo. This conflicts with the new decision and must be reconciled so that foreign repositories are skipped. REQ-004 reasons should include 'pull request' and 'other repository'.
