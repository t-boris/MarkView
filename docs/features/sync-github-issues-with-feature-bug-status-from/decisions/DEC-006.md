## Context

The Scope section still lists 'updating GitHub issue state or labels' and 'a preview and result report'. DEC-001 removed the preview and applies changes immediately. DEC-002 represents Implemented status only by closing issues as completed, with no label management. DEC-003 makes sync one-way. The Scope text contradicts the accepted decisions and REQ-001/REQ-003.

## Alternatives

1. Rewrite the Scope IN/OUT lists to match DEC-001..DEC-003 (chosen)
2. Leave Scope as is and let decisions override it implicitly
3. Reopen DEC-001/DEC-002 to restore the preview and labels

## Decision

Update Scope. IN: a manual Sync action in the Issues tab that applies changes immediately; matching items to issues through the existing link sources; closing linked open GitHub issues with state_reason 'completed' for items whose status is implemented, verified or archived; a result report after the run. OUT: preview/confirmation step; adding or removing labels; reopening issues or changing already-closed issues; reading GitHub state back into docs or editing Markdown; automatic/background sync; creating issues; comments, assignees, milestones; other trackers; items with no linked issue.

## Reason

The decisions are accepted and the requirements are already approved. Scope is the entry point readers and implementers see first, so leaving it stale would lead them to build a preview or labels. Listing the removed capabilities explicitly as OUT prevents scope creep from coming back.

## Consequences

The Scope text changes; the requirements and decisions stay as they are. F-001 can be resolved. Adding a preview or labels later would need a new decision that supersedes DEC-001 or DEC-002.
