## Context

Behaviour during a run, repeated clicks, cancellation and concurrent runs were undefined.

## Alternatives

1. Allow cancel mid-run
2. Queue repeated clicks
3. Disable button and block concurrent runs

## Decision

While Sync runs, the Sync button is disabled and shows progress (processed n of m issues). Only one run per project may be active; further triggers are ignored until it finishes. Cancellation is out of scope for this version; the run completes and the report (REQ-004) is always shown, including failures.

## Reason

Runs are short and bounded by linked issues; blocking concurrency prevents duplicate API calls, and omitting cancel avoids partial-state reporting complexity.

## Consequences

REQ-001 gains acceptance criteria for disabled button, progress and single-run guard. Cancel may be added later if runs become long.
