## Context

REQ-003 reports each issue separately, REQ-002 counts unlinked items, but REQ-004 does not define report rows, counts, skip reasons or persistence.

## Alternatives

1. One row per item with nested issues
2. One row per item–issue pair
3. Persist report history to disk

## Decision

The report has one row per item–issue pair showing item id/title, issue reference (owner/repo#n), and outcome: updated (with change applied), unchanged, skipped (reason: item status earlier than implemented, pull request, other repository, issue not found, shared issue with non-implemented item) or failed (error message). Items with no resolvable link appear as one row with outcome skipped/unlinked. A summary header shows counts per outcome. The report stays visible in the Issues tab until the next Sync run or until the tab/window is closed; it is not persisted to disk.

## Reason

Pair-level rows match REQ-003's per-issue reporting and make wrong matches visible; in-memory retention is sufficient for a manual action and avoids new storage.

## Consequences

REQ-004 acceptance criteria must be updated with row structure, skip reasons and summary counts. No report history is available after closing.
