## Finding

DEC-001 says matching must be conservative and must exclude PRs, but REQ-002 has no acceptance criterion for this. GitHub PR numbers share the same numbering as issues, and the issues API returns PRs too. The spec also doesn't say how to handle links to other repositories or forks, or which repository a bare '#n' refers to.

> using the existing link sources (github field, front matter issue/issues, issue links, 'issue #n')

## Possible interpretations

- Match only explicit issue URLs and front-matter fields
- Also match free-text '#n' mentions, which can point to pull requests

## Resolution

Match only explicit links: the `github` field, front matter `issue`/`issues`, and full GitHub issue URLs. Free-text '#n' / 'issue #n' mentions are ignored. Any target that the API reports as a pull request is skipped with reason 'pull request'. Links to repositories other than the project's configured repository are skipped with reason 'other repository'. — see DEC-005.
