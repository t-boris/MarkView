## Statement

Enforce the current project workflow and the work item's selected rule variant for transitions requested by a person, AI or the system, including transitions of work already started. For feature and bug rule variants, transition conditions can include whether changes reach the main branch directly or through a PR, PR presence and merge, successful checks, and human acceptance. When the standard workflow is adopted, migrate existing verifiable transition rules into it while preserving existing feature and bug transition behavior. Treat a transition from a completed lifecycle role to a non-completed lifecycle role as a reopening. A lifecycle role alone does not confirm delivery; start and delivery evidence remain explicit transition conditions. The workflow is authoritative for transition conditions; the Definition of Done and project instructions remain guidance for carrying out work, and subsequent changes to them do not change transition conditions. Allow only a person to make a reasoned one-time exception without changing the policy.

## Acceptance Criteria

- [x] A transition requested by a person, AI or the system is evaluated against the current project workflow and the work item's selected rule variant.
- [x] When the standard workflow is adopted, existing verifiable transition rules are migrated into it, preserving existing feature and bug transition behavior.
- [x] After migration, the workflow is authoritative for transition conditions.
- [x] For both feature and bug rule variants, transition conditions can include whether changes reach the main branch directly or through a PR, PR presence and merge, successful checks, and human acceptance.
- [x] The Definition of Done and project instructions remain guidance for carrying out work.
- [x] Subsequent changes to the Definition of Done or project instructions do not change transition conditions.
- [x] Changes to the selected rule variant apply to subsequent transitions of work items already started.
- [x] Changing the workflow does not rewrite previously recorded transitions.
- [x] A transition from a status with a completed lifecycle role to a status with a non-completed lifecycle role is treated as a reopening.
- [x] A status's lifecycle role alone does not confirm delivery.
- [x] Start and delivery evidence remain explicit transition conditions.
- [x] Only a person can make a one-time exception to transition conditions, and the exception requires a reason and does not change the policy.
