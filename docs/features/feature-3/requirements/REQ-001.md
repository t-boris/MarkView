## Statement

Automatically apply a backward-compatible standard workflow to existing projects, migrate existing verifiable transition rules into it, automatically assign each existing work item a standard rule variant that preserves the previous behavior for its work-item type, and allow a user to select and customize a software development workflow independently for each project.

## Acceptance Criteria

- [x] Existing projects automatically receive the standard workflow.
- [x] When the standard workflow is adopted, existing verifiable transition rules are migrated into it, preserving current feature and bug transition behavior, including their different delivery checks.
- [x] When the standard workflow is adopted, every existing work item is automatically assigned a standard rule variant that preserves the previous behavior for its work-item type.
- [ ] A person can subsequently select another configured rule variant for an existing work item.
- [x] Subsequent transitions use the work item's assigned variant under the current workflow.
- [ ] A user can select and customize the workflow independently for each project.
- [x] The workflow is authoritative for transition conditions.
- [x] The Definition of Done and project instructions remain guidance for carrying out work; subsequent changes to either do not change workflow transition conditions.
