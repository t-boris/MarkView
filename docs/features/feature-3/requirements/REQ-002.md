## Statement

Allow each project to configure statuses, lifecycle roles, transitions, and transition conditions for features and bugs, and require a human-selected replacement when deleting a status used by work items. Lifecycle roles determine completion and reopening and inform GitHub synchronization; they do not by themselves confirm delivery.

## Acceptance Criteria

- [ ] A project can configure separate statuses, transitions, and transition conditions for features and bugs.
- [x] Every status has a lifecycle role, such as not started, active, completed, or cancelled.
- [x] Existing statuses have default lifecycle roles.
- [x] A work item in a status with a completed role is treated as completed; a transition from a completed role to a non-completed role is treated as a reopening.
- [x] A completed role alone does not confirm delivery; start and delivery evidence remain explicit transition conditions.
- [x] GitHub synchronization uses lifecycle roles to recognize completion and reopening while retaining the requirement for verified completion before closing a linked GitHub issue.
- [ ] Before deleting a status used by work items, the user must choose a valid replacement for the affected items.
- [ ] After deletion, affected work items use the selected replacement status.
