## Statement

Use available GitHub synchronization with lifecycle roles for custom statuses, while supporting workflows without GitHub and requiring confirmation for new policy-driven GitHub actions.

## Acceptance Criteria

- [x] Workflows can operate without depending on GitHub.
- [x] Existing GitHub issue synchronization remains available.
- [x] GitHub synchronization recognizes a transition from a status with a completed lifecycle role to a status with a non-completed lifecycle role as a reopening, including for custom statuses.
- [x] A completed lifecycle role alone does not confirm delivery for GitHub synchronization; applicable delivery evidence remains an explicit transition condition.
- [x] A new policy-driven GitHub action is executed only after user confirmation.
