## Context

Project workflows need to support different development practices, including direct changes to the main branch and changes delivered through pull requests. Existing requirements specify delivery evidence but do not define the configurable development conditions.

## Alternatives

1. Configure integration into the main branch, PR presence and merge, and successful checks; defer human acceptance.
2. Configure only whether changes reach the main branch directly or through a merged PR; defer configurable checks and human acceptance.

## Decision

In the first version, allow each project rule variant for features and bugs to configure conditions for changes reaching the main branch directly or through a PR, PR presence and merge, successful checks, and human acceptance.

## Reason

This covers the development practices and acceptance conditions identified in the feature scope and allows different work items in the same project to follow different configured rule variants.

## Consequences

REQ-005 must explicitly cover all four groups of conditions for feature and bug rule variants. The specification must define available evidence for each condition and behavior when evidence is unavailable, while preserving the backward-compatible standard workflow.
