## Context

Projects can choose whether delivery is required and which event constitutes delivery.

## Alternatives

1. Support only an automatically verified published GitHub release.

## Decision

Support automatic verification of a published GitHub release and human confirmation of another delivery event.

## Reason

Delivery can be represented without assuming that publication proves installation or deployment.

## Consequences

A workflow can use automatic GitHub release evidence or human confirmation of another delivery event.
