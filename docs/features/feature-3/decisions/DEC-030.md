## Context



## Alternatives

1. Add actions such as labelling or commenting on a status change now, each behind a confirmation dialog.

## Decision

This version adds no policy-driven GitHub action. The existing synchronization (close an issue on verified completion, reopen it when linked work was reopened) keeps working and now reads lifecycle roles. Any other action type is classified as needing a person's confirmation before it runs; the classification is a function of the action type, so a future action cannot run without confirmation by omission.

## Reason

Q-003 allows the existing synchronization and requires confirmation for new policy actions. Adding none keeps the first version small, and making the gate structural keeps the answer binding for later work.

## Consequences

The concrete set of automatic actions stays open for a later feature, as the overview says.
