## Context

The standard workflow must reproduce existing feature and bug behavior, some of which depends on the project Definition of Done and instructions. Their relationship to workflow rules after adoption is undefined.

## Alternatives

1. Existing Definition of Done settings and recognizable project instructions remain active inputs to transition rules alongside workflow settings.
2. The workflow and existing settings remain editable; the workflow takes precedence for transition validation, and conflicts are shown to a person.

## Decision

When the standard workflow is adopted, migrate existing verifiable rules into it. The workflow then becomes authoritative for transition conditions; the Definition of Done and project instructions remain guidance for carrying out work.

## Reason

The team selected a single authoritative source for transition conditions while preserving existing verifiable rules during adoption.

## Consequences

Migration must preserve existing feature and bug transition behavior when the standard workflow is adopted. Subsequent changes to the Definition of Done or project instructions do not change transition conditions. Agent guidance may require separate synchronization with the workflow.
