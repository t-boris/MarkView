## Finding

The problem and scope identify direct-to-main work, PRs, checks, and acceptance as reasons to configure a workflow, but the requirements specify only delivery evidence. Without an agreed set of configurable development conditions, an implementation could satisfy the written requirements while leaving the central direct-to-main versus PR use case unsupported.

> Support project-specific development and delivery rules

## Possible interpretations

- The first version must support configurable branch or merge, PR, checks, and acceptance conditions.
- The first version supports a narrower set of development conditions, with the rest deferred.

## Resolution

Настраивать условия для попадания изменений в основную ветку напрямую или через PR, наличия и слияния PR, успешных проверок и приёмки человеком. — see DEC-025.
