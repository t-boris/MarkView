## Finding

Custom statuses are configurable, but the specification does not say how their meanings are assigned for consumers that distinguish active, completed, and reopened work. Transition validation alone cannot determine issue completion, GitHub issue synchronization, or the appropriate start and delivery evidence for a custom status.

> A project can configure separate statuses, transitions, and transition conditions for features and bugs.

## Possible interpretations

- Each custom status is assigned a lifecycle meaning that other consumers use.
- Custom statuses participate only in transitions, while separate explicit rules define completion, synchronization, and evidence collection.

## Resolution

Для каждого статуса задаётся роль жизненного цикла, например «до начала», «активный», «завершённый» или «отменённый». Возобновление определяется переходом из завершённой роли в незавершённую. Роль сама по себе не подтверждает доставку. — see DEC-023.
