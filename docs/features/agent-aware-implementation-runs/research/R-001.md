## Topic

Как пользователь должен выбирать между прямой передачей задачи и запуском через Cockpit из Build?

## Summary

Option A is recommended for the first release. Offer direct handoff and Cockpit plan preparation in the existing Build launch dialog after the user reviews the Definition of Done. The project sources establish the approval and handoff behavior relevant to this choice. Q-001 remains open.

- `ai-inference` Option A fits the existing launch sheet. Use the same edited Definition of Done for both actions. The direct action submits the terminal goal. The Cockpit action prepares a plan for approval. Record implementation start when the approved run begins executing its first step.
- `ai-inference` Option B needs an explainable recommendation rule. Dependency ordering, independent review, and managed time limits are concrete signals when explicitly requested. The number of required Definition of Done items is a weak proxy for orchestration needs. Option C adds plan approval to every Build launch and makes every launch depend on Cockpit availability.
- `ai-inference` When Cockpit cannot prepare or execute the requested run, explain the specific blocker and let the user explicitly choose direct handoff. Automatic fallback would make a planning action submit work to a terminal.
