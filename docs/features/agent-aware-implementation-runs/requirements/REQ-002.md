## Statement

Match goal handling, delegation, and review to available launch-profile capabilities. Allow Build to prepare and review a separate Cockpit plan draft per feature while preserving other features’ drafts and run associations, even when another feature has an unfinished run in the same project. Require plan approval and an explicit user start for each managed implementation run. Cockpit checks project occupancy on each start request and allows at most one unfinished run per project. If another run is unfinished, Cockpit identifies the blocking run and preserves the pending plan and its approval. After the blocking run ends, the pending plan requires a new explicit user start. When a managed implementation run starts or resumes, Cockpit automatically selects the first step in the approved plan whose completion is unsupported by current evidence and skips steps whose completion is supported by current evidence. Execute remaining Cockpit steps sequentially and permit supported delegation of independent work within a step. Ask me gates scheduled Cockpit delivery actions and leaves agent and delegate launch-profile permissions in effect.

## Acceptance Criteria

- [x] For Claude Code, Codex, GitHub Copilot, and Antigravity, the plan checks capabilities available in the selected launch profile, including the installed CLI and applicable permissions. An unavailable capability results in a viable alternative or a visible blocker before execution.
- [x] Build allows each feature to have a separate Cockpit plan draft that can be prepared and reviewed even when another feature in the same project has a draft or an unfinished run. Preparing or reviewing a draft preserves other features’ drafts and run associations.
- [x] Cockpit starts a managed implementation run only after the user approves its plan and explicitly requests Start.
- [x] On each explicit Start request, Cockpit checks for another unfinished run in the same project. At most one run can be unfinished per project, including when Start requests arrive concurrently.
- [x] If another run in the project is unfinished, Cockpit blocks the requested start, identifies the blocking run, and preserves the requested plan and its approval.
- [x] After the blocking run ends, Cockpit keeps the approved plan ready and starts it only after a new explicit Start request from the user.
- [x] When a managed implementation run starts or resumes, Cockpit automatically selects the first step in the approved plan whose completion is unsupported by current evidence. This rule takes precedence over Cockpit DEC-016 for managed implementation runs.
- [x] Cockpit skips steps whose completion is supported by current evidence in managed implementation runs and executes any remaining approved steps one at a time in dependency order.
- [x] A step may delegate independent work only when the selected profile supports it under the approved controls.
- [x] Delegated work stays within the step's approved scope and permissions. The step accounts for outstanding delegated work before it can succeed. If the profile cannot honor these conditions, the step runs without delegation or is blocked.
- [x] When a scheduled Cockpit delivery action is set to Ask me, Cockpit pauses that action until the user explicitly approves it. Agents and their delegates retain the permissions of their launch profiles, including any ability to perform the same action directly through the terminal.
- [x] When Cockpit verifies that a scheduled delivery action was completed outside Cockpit without its approval, it uses that evidence when evaluating the step's completion condition and applies REQ-004 to record the external completion, skip the duplicate action, and retain the evidence for existing lifecycle checks.
