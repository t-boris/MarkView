## Statement

Give the managed run a configurable active execution time limit, preserve evidence on interruption, and reconcile delivery state before retrying external actions. Keep an interrupted step paused until Cockpit confirms that every delegate capable of writing to the checkout has stopped. Once those stops are confirmed, let the user retry the step in the same checkout with existing changes preserved.

## Acceptance Criteria

- [x] The user can set and review the Cockpit active execution time limit before approving the run.
- [ ] Elapsed active execution time carries over across interruptions.
- [ ] At the limit, Cockpit pauses the run and interrupts the active attempt.
- [ ] When Cockpit pauses the run at the limit, it shows the reason, the latest evidence, and any delegated work whose stop it has yet to confirm.
- [x] Cockpit keeps an interrupted step paused and blocks retries until it confirms that every delegate capable of writing to the checkout has stopped.
- [ ] While a retry is blocked, Cockpit shows which delegate or process is blocking it.
- [x] Once Cockpit confirms that every delegate capable of writing to the checkout has stopped, the user can retry the step in the same checkout with existing changes preserved.
- [x] Before retrying an interrupted external delivery action, Cockpit checks for its recorded or remote result.
- [x] Cockpit reuses confirmed results and keeps uncertain external delivery actions pending until it can establish their state.
