## Statement

From Implement with AI in Build, recommend a launch mode using the feature specification and selected Definition of Done and let the user override it. Allow separate Cockpit plan drafts for each feature, including while another feature in the project has a draft or an unfinished run. Require plan approval and a separate, explicit user start for managed execution, with at most one unfinished Cockpit run per project.

## Acceptance Criteria

- [ ] After the user reviews the Definition of Done in Build, MarkView recommends a mode, gives a reason grounded in the specification and selected checklist, and lets the user choose either mode before launch.
- [ ] Direct handoff submits the feature goal with the selected checklist.
- [ ] Choosing Cockpit prepares a feature-scoped plan draft from the specification, recorded answers, accepted decisions, and the same checklist. If Cockpit cannot prepare the plan, MarkView shows the blocker and requires an explicit choice to use direct handoff.
- [ ] Build lets the user prepare and review a separate Cockpit plan draft for each feature even when another feature in the same project has a draft or an unfinished run. Preparing or reviewing a draft preserves other features’ drafts and run associations.
- [ ] Before approval, the Cockpit plan shows each step’s assignment, proposed agent and model, and observable completion condition.
- [ ] Cockpit requires the user to approve the plan before requesting a separate, explicit start.
- [ ] On each explicit start request, Cockpit checks whether the project has an unfinished run and starts execution only if none exists.
- [ ] If an unfinished run blocks execution, Cockpit identifies the blocking run and preserves the new plan and its approval.
- [ ] After the blocking run ends, the approved plan can start only on a new explicit start request from the user.
- [ ] The feature records implementation as started only after successful terminal handoff or successful start of the first step of the approved Cockpit run.
