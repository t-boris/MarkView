## Statement

Verify implementation against the specification using observable test and independent review evidence. Carry the managed run through all applicable delivery steps, including merge and release where applicable, under the project rules and selected Definition of Done. Require explicit user approval before Cockpit executes a scheduled Ask me delivery action. Agents and their delegates retain their launch-profile permissions, which may allow them to perform the same action directly through the terminal. Warn the user of this possibility before launch. If Cockpit verifies that an action was already completed outside Cockpit without its approval, record it as externally completed without Cockpit approval and skip the duplicate action. Before executing each scheduled merge or release action, Cockpit checks for confirmed independent review findings that identify violations of acceptance criteria or mandatory project rules. Each such finding blocks the action until a fix is verified or the user explicitly accepts the risk for that finding and revision, where project rules permit an exception. For each blocking finding, record the violated criterion or rule, the reviewed revision, and, when the block is lifted, evidence of the verified fix or the user's explicit risk acceptance and rationale. Risk acceptance applies only to the recorded finding and revision. A later revision requires re-verification and, if the finding still blocks delivery and the user chooses to accept the risk, a new acceptance where project rules permit an exception. Track partial delivery, including each action blocked by a review finding, and retain verification and delivery evidence, including evidence of verified external completion, for the project's existing lifecycle checks.

## Acceptance Criteria

- [x] The managed run plan includes all applicable delivery steps under the project rules and selected Definition of Done, including versioning, PR, CI, merge, and release.
- [x] Before execution, the run surfaces conflicts between the selected Definition of Done and mandatory project rules for the user to reconcile.
- [x] Before launch, Cockpit warns the user that agents and their delegates retain their launch-profile permissions and may perform Ask me actions directly through the terminal if those permissions allow it.
- [x] The run records evidence for each Require item.
- [x] Cockpit pauses each scheduled Ask me delivery action until the user explicitly approves it, except when Cockpit verifies that the action was already completed outside Cockpit without its approval.
- [x] When Cockpit verifies that a scheduled delivery action was already completed outside Cockpit without its approval, it records the action as externally completed without Cockpit approval.
- [x] Cockpit skips the duplicate scheduled action after verifying its external completion.
- [x] The run omits Skip items.
- [x] If the user declines an action that is mandatory for delivery and remains incomplete, the run shows which action blocks delivery.
- [x] The run presents test evidence and independent review findings tied to the changes examined.
- [x] Before executing each scheduled merge or release action, Cockpit checks for unresolved confirmed independent review findings that identify violations of acceptance criteria or mandatory project rules.
- [x] Cockpit blocks each scheduled merge or release action while any such finding lacks a verified fix or valid risk acceptance for the revision to be delivered.
- [x] For each blocking finding, the run records the violated acceptance criterion or mandatory project rule and the reviewed revision.
- [x] When a fix resolves a blocking finding, the run records evidence that verifies the fix.
- [x] Cockpit allows risk acceptance only where project rules permit an exception.
- [x] For each accepted risk, the run records the user's explicit acceptance and rationale for the specific finding and revision.
- [x] Cockpit requires re-verification of a blocking finding on a later revision because risk acceptance applies only to the recorded finding and revision.
- [x] If the finding still blocks delivery on the later revision, Cockpit keeps the action blocked until a fix is verified or the user explicitly accepts the risk for that finding and revision, where project rules permit an exception.
- [x] The run records each delivery action blocked by a review finding in its partial delivery status.
- [x] After fixes, the run verifies the updated changes before reporting success.
- [ ] Where required, the run records CI results for the relevant revision, merge evidence, and release evidence tied to the delivered changes.
- [x] If delivery is partial, the run records which delivery steps completed and which are pending or blocked.
- [ ] The run retains verification and delivery evidence, including evidence of verified external completion without Cockpit approval, for the project's existing lifecycle checks.
- [ ] An unmet or unverified mandatory criterion prevents the run from reporting success.
- [ ] The project's existing lifecycle rules govern status transitions and acceptance.
