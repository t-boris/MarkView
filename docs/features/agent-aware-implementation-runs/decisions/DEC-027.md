## Context

F-001 identifies a conflict between Cockpit DEC-016, which allows execution from any selected step without verifying earlier steps, and the managed-run requirements for dependency order, prerequisite evidence, and delivery approvals. A managed run could otherwise start at merge or release with required checks still outstanding.

## Alternatives

1. Let the user select any step. Start that step only after verifying its mandatory prerequisites, and show what evidence is missing if it cannot start.
2. Let the user start any selected step under Cockpit DEC-016. Gate each merge or release action on verified prerequisites and applicable approvals. This option depends on Cockpit being able to enforce the gate before the agent acts.

## Decision

For managed implementation runs, Cockpit starts or resumes at the first step in the approved plan whose completion is not supported by current evidence. Cockpit uses current evidence to skip completed steps. This rule takes precedence over Cockpit DEC-016 for managed implementation runs.

## Reason

Automatic selection preserves the approved dependency order and prevents a selected starting point from bypassing unfinished prerequisites. Reusing current evidence lets the run resume after an interruption without repeating verified work.

## Consequences

REQ-002 must require automatic selection of the starting and resumption step for managed runs. REQ-003 must continue to require reconciliation of interrupted delivery actions before retrying them. Under REQ-004, merge and release still require current evidence for the applicable revision and any approvals required by project rules or the selected Definition of Done.
