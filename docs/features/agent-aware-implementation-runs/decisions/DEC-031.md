## Context

F-004 identifies an ambiguity in REQ-001 when Build opens Cockpit for a feature in a project that already has another feature’s draft or unfinished run. R-001 records that Cockpit reuses the existing session for the same project, so the new plan needs its own feature association.

## Alternatives

1. Defer plan preparation until the existing project draft is closed or the current run ends, preserving the existing work.
2. Allow each feature to prepare and review its own draft while keeping Cockpit execution limited to one run per project.

## Decision

Allow Build to prepare and review a separate Cockpit plan draft for each feature, even when another feature has a draft or unfinished run in the same project. Cockpit requires plan approval and an explicit start. Execution can begin only after any existing run in the project has ended.

## Reason

This lets the user prepare and review the next feature’s plan without disturbing existing work, while keeping execution sequential within the project.

## Consequences

Update REQ-001 to require feature-scoped drafts that preserve other features’ drafts and run associations. Check project occupancy when the user requests execution. If a run is still unfinished, show which run blocks execution and preserve the new plan and its approval. Once the existing run ends, execution requires an explicit start by the user.
