## Context

DEC-027 says a managed run starts or resumes at the first step that current evidence does not support. In the Temporal workflow only a failed prerequisite can be retried in place, and a pause or an interruption waits for stop.

## Alternatives

1. A resume signal in the Go workflow that jumps to a step
2. A new run record for each continuation

## Decision

Every step MarkView adds is a prerequisite, so a gate (Ask me, review findings, an uncertain delivery state, live processes of an earlier attempt) fails the step and Retry runs it again once the gate holds. For "Continue" or "Continue from evidence", MarkView stops the workflow, probes git and GitHub again, and starts a new workflow at the first unsupported step, on the same run record and with the same approval. Steps that passed stay passed, the others are marked skipped, an interrupted attempt's partial result is kept in the run's results, and the changes in the checkout are kept. The Go workflow is unchanged.

## Reason

The run keeps one history, one approval, the time it has used, and the evidence it collected, without a second kind of workflow. The step it continues at follows evidence, never a choice the person makes inside the run.

## Consequences

If evidence moves the start to a step that would change the approved plan, the person approves the plan again before it starts.
