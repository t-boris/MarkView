## Context

REQ-004 requires independent review evidence but leaves its effect on delivery undefined. A run with passing tests could reach merge or release despite a confirmed finding that an acceptance criterion or mandatory project rule was violated.

## Alternatives

1. Block merge and release until a fix is verified, with no risk acceptance option.
2. Retain findings as review evidence and rely on existing mandatory checks to determine whether delivery can proceed.

## Decision

A confirmed independent review finding that identifies a violation of an acceptance criterion or mandatory project rule blocks Cockpit's scheduled merge and release actions. The block is lifted when a fix is verified or when the user explicitly accepts the risk for that finding and revision. Risk acceptance is available only where project rules permit an exception.

## Reason

Passing tests can coexist with a confirmed violation. A delivery gate makes that violation actionable and allows the user to accept a specific, traceable risk where project rules permit it.

## Consequences

Update REQ-004 to check for unresolved blocking findings before Cockpit performs merge or release. For each blocking finding, record the violated criterion or rule, the reviewed revision, and either evidence of a verified fix or the user's explicit risk acceptance and rationale. An acceptance applies only to the recorded finding and revision. A later revision requires re-verification and, if the finding still blocks delivery, a new acceptance. Record any blocked delivery action in the run's partial delivery status.
