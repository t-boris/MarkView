## Context

Cockpit's "Fix bugs" control, when off (its default, and the default of a feature draft), compares the project before and after each step and fails the step for any source change or commit; the step agent also reads the control and declines to change code. A managed implementation run must change code and commit through merge (REQ-002, REQ-004, DEC-012). The first run with a real agent failed its branch step: "Fix bugs is off, but a commit was made".

## Alternatives

1. A feature draft starts with Fix bugs on: every step, review and verification included, may change source and commit, and agents may also move bugs into fixing
2. No source and commit audit in a managed run; Fix bugs governs only moving a bug into fixing

## Decision

In a managed implementation run, the steps that write or deliver the change (branch, work, fix, version, checklist, pull request, merge, release) may change source files and commit on the feature branch whatever Fix bugs says. The verification steps (tests, independent review, re-verification, CI checks, final verification) stay under the audit: a source change or a commit in one of them fails the step. Fix bugs keeps its meaning (an agent may move a bug into fixing) and stays off by default. Plans made outside Build are audited exactly as before.

## Reason

Boris chose this on 2026-11-24 when asked during implementation, after the real-agent run failed. Implementation needs source changes, while a reviewer or verifier that changes the code it checks is no longer independent.

## Consequences

The step prompt tells each managed step whether it may change source and commit. The audit takes the step's kind into account; the scenario check is unchanged.
