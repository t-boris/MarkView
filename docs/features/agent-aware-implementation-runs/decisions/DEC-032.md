## Context

DEC-029 allows the user to lift a blocking review finding by accepting its risk only where project rules permit an exception. No project rule (CLAUDE.md, the project workflow or the Definition of Done) states when an exception is permitted.

## Alternatives

1. A per-project setting "Allow risk acceptance for review findings", off by default, for both kinds of findings.
2. Risk acceptance always allowed for any confirmed finding, with a rationale for that finding and revision.

## Decision

The user may accept the risk of a confirmed finding that violates an acceptance criterion of the feature. A confirmed finding that violates a mandatory project rule (the project guide such as CLAUDE.md, or the project workflow) can be lifted only by a verified fix. No new setting is added.

## Reason

Boris chose this on 2026-11-24 when asked during implementation. Acceptance criteria belong to the feature and its owner, while mandatory project rules apply to every change and have no recorded exception mechanism.

## Consequences

The review step classifies each finding as a criterion or a project-rule violation. Cockpit offers risk acceptance only for criterion findings, always tied to the finding and the reviewed revision with a rationale, and keeps rule findings blocked until a fix is verified.
