## Context

F-005 identifies a gap in REQ-003. Cockpit reports delegated work whose stop could not be confirmed after an interruption. A surviving delegate with write access could modify the checkout during a retry and invalidate the retry's changes or verification evidence.

## Alternatives

1. Allow a retry in a new checkout from a recorded state if Cockpit can verify that surviving delegates cannot modify its files, shared Git refs, or verification results. Preserve unfinished changes in the original checkout.

## Decision

Cockpit keeps the interrupted step paused until it confirms that every delegate capable of writing to the checkout has stopped. After confirmation, the step may be retried in the same checkout with existing changes preserved.

## Reason

Waiting for confirmed stops protects the retry's changes and verification evidence from concurrent writes by delegates from the interrupted attempt while preserving work already in the checkout.

## Consequences

Update REQ-003 to require Cockpit to block retries while any delegate with write access to the checkout has an unconfirmed stop. Cockpit shows which delegate or process is blocking the retry. If Cockpit cannot confirm that a delegate stopped, the step remains paused. Once Cockpit confirms all required stops, the user can retry in the same checkout with existing changes preserved.
