## Context

REQ-001 and REQ-002 allow at most one unfinished run per project, including when Start requests arrive at the same time. A run saved as running or paused may belong to a window that has closed or to an app that has quit, and then nothing will ever finish it.

## Alternatives

1. Only the saved runs, without a reservation (two concurrent Starts could both pass)
2. Ending an orphaned run automatically when its worker is gone

## Decision

A Start first reserves the project root synchronously on the main actor (CockpitAdmission), then reads the saved runs. A run whose status is running or paused blocks the Start, and the blocker names it; a stopped or finished run does not. A saved unfinished run that no longer runs anywhere shows "End run", which stops it ("Ended by you.") and frees the project. Continuing a run does not block itself. The reservation is released when the run finishes or stops, when the start fails, or when the project closes.

## Reason

The main-actor reservation makes two windows that press Start at once deterministic. Reading the saved runs covers runs from earlier sessions. "End run" is an explicit choice by the person, so no run is ever ended or replaced without them.

## Consequences

After a crash, the person ends or continues the orphaned run before another feature's run can start in the project.
