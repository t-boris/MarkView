## Context

REQ-002 lets a step delegate independent work only when the selected launch profile supports it under the approved controls. Cockpit's controls had no delegation switch, so a managed run needs one, and a new feature draft needs a starting value for it.

## Alternatives

1. Off by default; the person switches it on per draft
2. No switch; delegation follows the launch profile alone

## Decision

A new feature draft starts with "Delegation to subagents" switched on. The planner may mark a step for delegation only for agents whose provider names a delegation mechanism (Claude Code, Codex, GitHub Copilot, Antigravity). MarkView removes the mark for any other agent, and the agent is told not to delegate whenever the switch is off or its step is unmarked. Plans made outside Build keep the switch off, and a plan without it saves exactly as before.

## Reason

Staged features gain most from parallel work inside a step. The person sees the switch in the guardrails and in the approval bar, and can turn it off before approving. Delegated work that is left outstanding, or processes that outlive the step, still fail the step, so the default does not loosen what a step must account for.

## Consequences

A person who does not want subagents must switch delegation off before approving. Changing the switch changes the plan's steps, so the plan must be checked again.
