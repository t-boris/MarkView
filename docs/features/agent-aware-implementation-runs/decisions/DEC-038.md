## Context

DEC-033 switched "Delegation to subagents" on only for a new feature draft; a plan made from a goal of the person's own still started with it off, so its steps were told not to delegate. Boris's goal of 2026-11-26 asks that every agent call is optimal, with the agent creating its parallel work itself where it can.

## Alternatives

1. Keep it off outside Build; the person switches it on per plan
2. Change the default of CockpitControls itself

## Decision

Every new Cockpit plan (a feature draft or a goal of the person's own) starts with "Delegation to subagents" on. The planner still marks a step for delegation only for an agent whose provider names a mechanism, and MarkView still removes the mark for any other agent. Controls that cannot be read, and plans saved before the switch existed, keep it off: the restrictive defaults of CockpitControls do not change.

## Reason

The goal covers every agent call, and DEC-033's reasons hold for any plan: the person sees the switch in the guardrails and in the approval bar and can turn it off before approving, and delegated work left outstanding still fails the step. Changing CockpitControls' own default would also loosen the fallback used for unreadable stored controls.

## Consequences

A person who does not want subagents in a plan of their own switches delegation off before approving. Saved plans and runs are unchanged.
