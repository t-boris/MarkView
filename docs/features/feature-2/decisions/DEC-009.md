## Context

Automatic assignment and the picker need a shared, testable color rule.

## Alternatives

1. Choose randomly and persist the result
2. Hash the project key into a fixed palette
3. Generate an unrestricted color from the project key

## Decision

Use one fixed palette of eight visually distinct colors. Select the initial color by a stable hash of the project key, persist it, and offer the same palette for overrides.

## Reason

A fixed palette supports predictable assignment, a compact picker, and consistent icon rendering.

## Consequences

The palette needs defined color values and readable rendering in light and dark appearance. Automatic assignments remain stable across relaunches; distinct projects may share a color.
