## Statement

The system shall let the planner mark adjacent independent steps of a plain plan as one parallel group, and keep a group only when every member may run beside the others.

## Acceptance Criteria

- [ ] The planner's answer may give a step an optional group label; adjacent steps with the same non-empty label form one group.
- [ ] MarkView keeps a group only when it has 2 to 3 members, all adjacent, none a prerequisite, none with a recovery, none with a QA scenario, none the plan's last step, in a plan that is not a managed run; otherwise it removes the label and still accepts the plan.
- [ ] The planner is told to group only steps that inspect (reviews, analyses, reading checks) and never a build, a test run or a step that changes files.
- [ ] A plan or saved run without groups keeps the fingerprint it had before this feature: the label is left out of the JSON when empty.
- [ ] A plan with groups has a different fingerprint from the same plan without them, so the approval covers the grouping.
