## Context

One window has one QA model and one browser (QAModel.reserveForCockpit refuses a second run, which the workflow treats as an interruption of the whole run); before/after audits of steps running together overlap; concurrent builds and git commands collide (DerivedData, index.lock); every delivery step of a managed run is a prerequisite.

## Alternatives

1. Allow writing steps in separate worktrees
2. Allow QA scenario steps with one QA model per step

## Decision

A group may hold 2 to 3 steps (CLICompletion.sideBySide) that only inspect (reviews, analyses, reading checks): no recovery, no QA scenario, no build or test run, never the last step. In a plain plan the planner forms the groups and their members are not prerequisites. In a managed run the only group is the review: two reviews by different agents, both prerequisites (Q-002). Writing steps, QA steps and the other managed delivery steps keep running one at a time.

## Reason

It gives the gain where steps are most often independent (several reviews or analyses) without new isolation for writes, a second QA model or changes to delivery order.

## Consequences

Grouping writing steps (one worktree per step) and QA steps can follow as separate features. A managed run whose project has only one agent besides the implementer keeps a single review.
