## Statement

While an operation runs and after it ends, the system shall show an output panel for that operation with live combined standard output and error, the current state, and a cancel control, shall accept user input in that panel while the operation is running and pass it to the process, shall keep a separate output panel for each operation when several operations run at the same time and let the user switch between them, and shall make these panels reachable from wherever the operation was started, including the project window toolbar when X-Ray is not open.

## Acceptance Criteria

- [ ] Output lines appear in the panel while the process is running, without waiting for it to finish.
- [ ] A prompt written by the process without a trailing line break (e.g. 'Password:' or 'Continue? [y/N]') is visible in the panel while the process waits for the answer.
- [ ] While the operation is running, the user can type into the panel and the typed text is delivered to the process; a y/n confirmation, a password prompt and a 2FA code prompt can each be answered and the operation continues.
- [ ] When the process requests input without echo, the typed characters are not displayed in the panel and do not appear in the output retained after the process ends.
- [ ] Input is accepted only while the operation is running; after the process ends the panel is read-only.
- [ ] The panel shows the operation label, environment (if any) and current state.
- [ ] Cancel is available only while the operation is running, including while the process is waiting for input; using it terminates the process and its child processes and the operation is shown as cancelled, distinct from failed.
- [ ] After the process ends, the output and final state remain visible until the user dismisses them or starts the operation again.
- [ ] An operation started from the project window toolbar shows its output panel without requiring the user to open X-Ray.
- [ ] An operation started from one entry point shows the same output and state, and accepts input, when viewed from the other entry point.
- [ ] A remote trigger that exits zero shows dispatched and states that the remote run is not tracked.
- [ ] With two or more operations running, each has its own output panel showing only its own output, and the user can switch between the panels without stopping any operation.
- [ ] Input typed into a panel is delivered only to that panel's process, and cancel in a panel terminates only that panel's operation; the other operations keep running.
- [ ] When several panels exist, each is identifiable by operation label, environment (if any) and state without opening it.
