## Context

The operations file can change at any time through UI edits, hand edits, version-control updates or re-discovery. REQ-003 requires the executed command to be exactly the one shown in the confirmation. DEC-014 (proposed) makes the native side read the command from the file when the run is requested. Editing cannot be blocked for hand edits or version-control updates.

## Alternatives

1. A run uses a snapshot taken when the confirmation opened; later file changes affect only future runs.
2. Editing and deleting are disabled while the operation runs (cannot be enforced for hand edits).
3. Re-read the file at start and abort the run with a message if the command differs from the confirmed one.

## Decision

(1) When the confirmation opens, the native side takes a snapshot of the operation: id, label, kind, environment, command and working directory. The confirmation shows the snapshot and the run executes the snapshot; the file is not read again between confirmation and start. (2) A running operation is bound to its snapshot for its whole life; its panel, state indicators and notification use the snapshot's label and environment. (3) Editing and deleting an operation are allowed while it runs, in the UI and by any other means, and affect only future runs. (4) If the entry's command or working directory changes or the entry disappears while the run is active or its panel is still shown, the panel displays a notice 'definition changed since this run started' or 'operation removed since this run started'; the run is not stopped. (5) The no-duplicate rule is keyed by the snapshot's operation id. If the id is changed in the file during the run, the entry is treated as a different operation and may be started; this is an accepted limitation. (6) A panel whose operation was removed stays until the run ends and the user dismisses it.

## Reason

The snapshot is the only rule that can be enforced for all sources of change and it makes the REQ-003 criterion verifiable. Blocking edits in the UI alone would give a false guarantee.

## Consequences

REQ-003 and REQ-009 need explicit snapshot criteria. If the file changes while the confirmation is open, the user runs the command they saw, not the newer one; the newer one applies to the next run. The changed-command warning of DEC-014 compares the snapshot with the run history.
