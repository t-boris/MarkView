## Context

Project fact (from the finding): docs/architecture/feature-workflow.md records fetched web pages in prompts as a prompt-injection surface and security.md S14 records that content is sent to AI CLIs without redaction. DEC-003 made investigation automatic and accepted the privacy risk; the injection risk was never decided. Here the AI output is an executable command stored in a team-shared file and offered as a button, so one poisoned source can reach every team member.

## Alternatives

1. Accept the risk; the provenance marking of REQ-005 is sufficient.
2. Commands from web or external sources are shown as proposals and are added to the operations file only after the user accepts them.
3. The confirmation for such commands carries a distinct warning until the user marks the operation as reviewed.
4. Forbid web-derived commands entirely; web research only explains tooling.

## Decision

(1) Investigation stays automatic as decided in DEC-003; no permission prompt is added for reading or searching. (2) Discovery writes to the operations file only operations whose command is derived solely from files inside the project root. (3) An operation whose command is derived wholly or partly from a web source or from a folder outside the project root is shown in the discovery report as a proposal, with the full command, its sources, its confidence and a warning that the command comes from content outside the project. (4) The user accepts or rejects each proposal individually; there is no 'accept all'. Only an accepted proposal is written to the operations file, with its external origin recorded. A rejected proposal is not written and is not proposed again for the same command by later discovery on this machine. (5) An accepted operation keeps its external-origin mark in the list (REQ-005). (6) The run confirmation of an operation with external origin shows a distinct warning with the source, on every machine, until that exact command has been run once on that machine according to the machine-local run history (DEC-014). (7) Editing the command removes the external-origin warning and applies the user-edited rules.

## Reason

Provenance display alone does not stop a harmful command from entering a file that the whole team trusts. Gating the write, not the investigation, keeps the low-friction discovery chosen in DEC-003 and places one deliberate human check exactly where the risk becomes persistent and shared.

## Consequences

Discovery is no longer a single step for externally derived operations: they need one acceptance each. REQ-004 and REQ-005 need added criteria and a new security requirement is needed for proposals. Team members who receive an accepted operation through version control still get the distinct warning on their first run. Residual risk: a poisoned source can still influence commands presented as derived from project files; the uniform confirmation (DEC-002) remains the last control. Proposals pending acceptance are machine-local.
