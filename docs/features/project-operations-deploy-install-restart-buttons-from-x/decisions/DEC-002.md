## Context

Operations become one-click buttons, so an accidental run (including a production deploy) is easier than typing a command in a terminal. The scope already includes reviewing a discovered command before its first run, but repeated runs and the difference between production and other environments were undecided.

## Alternatives

1. A: No extra safeguard; only the command review before the first run, same for all environments
2. B: Confirmation dialog before each run in a production-like environment only
3. C: Typed environment name required for production-like environments
4. D: Confirmation before every run of any operation in any environment

## Decision

Option D: the system asks for explicit confirmation before every run of any operation, regardless of operation kind or environment. The confirmation shows the operation, the environment and the exact command.

## Reason

User decision. A single uniform rule avoids having to classify which environments are production-like, and no run can start from a single click.

## Consequences

No classification of production-like environments is needed. Every run, including harmless ones (build, clean in dev), costs one extra step, with a risk of habitual confirmation. No stronger safeguard (typed environment name) exists for production. Inference, not yet confirmed by the user: the per-run confirmation also serves as the command review before the first run, and no 'do not ask again' option is offered.
