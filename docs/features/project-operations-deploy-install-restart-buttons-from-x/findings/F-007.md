## Finding

The requirement assumes exactly one deploy operation per environment. Not covered: (1) a project with a deploy command but no named environment (the overview lists this as an open assumption: 'single unnamed "Deploy"?'); (2) a project with several deployable units, where discovery finds several deploy operations for the same environment (e.g. deploy API to prod and deploy web to prod); REQ-011 says 'one deploy operation per environment' while DEC-009 introduces per-node operations; (3) a user-added or hand-edited deploy operation with no environment or with a duplicate environment name; (4) ordering of environments in the picker and whether environment names are normalised (prod vs production). The picker cannot be built or tested without these rules.

> each environment whose deploy operation is running is marked as running and cannot be started again

## Possible interpretations

- The picker lists deploy operations (label plus environment), not environments.
- One deploy operation per environment is enforced; additional ones are classified as 'other'.
- The picker is two-level: environment, then target.

## Resolution

AI: Picker показывает сами deploy-операции, сгруппированные по окружению, а не окружения: на одно окружение может приходиться несколько операций (по одной на развёртываемую единицу), а операция без окружения показывается просто по своей метке. Состояние «running» и запрет повторного запуска относятся к операции, а не к окружению. — see DEC-018.
