## Finding

Project fact: docs/architecture/feature-workflow.md records fetched web pages in prompts as 'a prompt-injection surface', and security.md S14 records that content is sent to AI CLIs without redaction. Here the AI output is an executable command that is persisted in a team-shared file and offered as a button. A malicious web page or file can steer discovery to propose a harmful command (e.g. a download-and-execute install line). The mitigations in the spec are provenance display and the uniform confirmation. No requirement demands stronger handling for commands derived from the web or from outside the project (for example a distinct warning in the confirmation, or not writing them to the shared file until the user accepts them). DEC-003 accepted the privacy risk of reads and queries; the injection risk was stated only as an AI inference in the overview and was not decided.

> It may read local folders outside the project root and search the web without a separate permission prompt

## Possible interpretations

- Accept the risk; the provenance marking of REQ-005 is sufficient.
- Commands from web or external sources are shown as proposals and are added to the operations file only after the user accepts them.
- The confirmation for such commands carries a distinct warning until the user marks the operation as reviewed.

## Resolution

AI: Команды, полученные из веба или из папок вне корня проекта, показываются как предложения и записываются в общий файл только после явного принятия пользователем. После принятия они сохраняют пометку внешнего происхождения, а подтверждение запуска показывает отдельное предупреждение, пока операция не была запущена на этой машине. — see DEC-026.
