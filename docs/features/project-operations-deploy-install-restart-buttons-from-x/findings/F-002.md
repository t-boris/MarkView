## Finding

An operation's command is a single free-text string (discovered, hand-edited or user-added). The spec does not say how it becomes a process. Project fact: docs/architecture/security.md §4 requires 'Pass subprocess arguments as arrays ... and never shell-interpolate user or repo strings'. Commands such as `make deploy ENV=prod`, `cd infra && terraform apply` or ones using pipes and variables only work through a shell, which conflicts with that rule unless an explicit exception is recorded. Also undefined: which environment the process gets. The overview says 'operations use whatever the user's shell environment already provides', but (AI inference) a macOS GUI application does not inherit the PATH and variables of the user's login shell, so tools like kubectl, fly, npm or nvm-managed binaries may not be found. Without this, REQ-001 cannot be implemented or tested.

> shall execute exactly the command the user reviewed

## Possible interpretations

- Run through the user's login shell (e.g. `$SHELL -l -c <command>`): full shell syntax and the user's PATH; requires a documented exception to the security rule.
- Split the string into an argument array and exec directly: no pipes, `&&`, variables or globbing; many real deploy commands will not work.
- Store the command as an explicit argument array in the operations file; shell features only when the user writes `sh -c` themselves.

## Resolution

AI: Команда выполняется через login shell пользователя (`$SHELL -l -c <command>`, запасной вариант `/bin/zsh`) на псевдотерминале в рабочем каталоге операции; строка команды передаётся одним аргументом массива без какой-либо подстановки со стороны MarkView. В security.md записывается явное исключение из правила о массивах аргументов именно для операций. — see DEC-013.
