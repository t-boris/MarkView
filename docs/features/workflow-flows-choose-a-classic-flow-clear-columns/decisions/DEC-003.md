## Context



## Alternatives

1. Make the Definition of Done the single source and derive the process from it
2. Synchronise both ways

## Decision

What counts as delivered is decided by the process (integration, checks, delivery event, acceptance), as the Workflow tab already says. The Definition of Done checklist is shown next to it and a disagreement is a warning, never an automatic change. Templates take the delivery settings of both types from the Definition of Done once, when they are chosen.

## Reason

Two sources of Done that disagree (the checklist requires a pull request and CI, the standard feature process allows direct commits without checks) is what Boris could not see. One authority plus a visible warning removes the surprise without silently rewriting a process.

## Consequences

The MarkView flow template keeps its standard feature process (direct, no checks), so the warning shows in projects whose checklist requires more.
