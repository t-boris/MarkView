## Statement

The system shall show, for each process that follows the transitions on the Workflow tab, whether a pull request, passing CI checks, a published release or a confirmed event, and an acceptance by a person or an AI are required, at which step, and what Done therefore means, and shall warn when the project's Definition of Done contradicts the process.

## Acceptance Criteria

- [ ] Under the diagram a block per process names the step where delivery is judged (the completion step) and the step where the result is accepted, and shows pull request, CI checks, release or event and acceptance each as required or not required
- [ ] A one-sentence 'Done here means' line is built from the process settings
- [ ] When the Definition of Done requires a pull request, CI or a deploy and the process does not, a warning names the difference; the process stays the authority and nothing is changed by the warning
- [ ] The Definition of Done is read off the main thread and a missing or unreadable file shows no warning
