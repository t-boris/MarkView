## Context

Acceptance criterion 5 says existing users keep their current light or dark appearance on upgrade until they choose a preset, while criterion 1 and DEC-001 say System follows macOS and the picker lists only System and four presets. In the code the saved "theme" setting is light, dark or system (default system), and every window is forced to a dark appearance (MarkViewApp.swift onAppear, WindowSessionController.swift), so a user on the default sees a dark window today.

## Alternatives

1. Move light to Paper and dark and the default to Graphite on first launch (no legacy mode, look changes slightly).
2. Map every saved value to System (follows macOS; the forced-dark default would change on a light Mac).

## Decision

Saved light and dark values, and the absent value (today's default), map to a legacy Classic appearance that looks exactly as today: Classic Dark for the absent value and for dark, Classic Light for light. Classic is shown in the picker as one extra row only while it is the active appearance; choosing System or any preset replaces it for good and the row disappears. System follows macOS from this release. A saved value that cannot be read falls back to Classic Dark.

## Reason

The owner chose "Classic until chosen" so that upgrading changes nothing visible, and System does what its name says.

## Consequences

The theme model has a sixth, non-selectable-after-leaving value for Classic Dark/Light. The Classic palettes reproduce the existing VS Code Dark+/Light+ colors of the native views and the existing editor, preview and terminal colors. Because the default user sees Classic Dark, the new themes are reached through the picker (toggle button or shortcut) and are not forced on anyone.
