## Context

The idea says voice input should work 'wherever the app asks for text'. Fields are split between native SwiftUI inputs and the WebView/CodeMirror editor, which need different implementations.

## Alternatives

1. Only intake-flow fields (new feature, new bug, intake question answers)
2. All multi-line text inputs including the Markdown editor

## Decision

Add the mic control only to intake-flow free-text fields: new feature description, new bug description, and answers to intake questions.

## Reason

Small, clear scope; avoids CodeMirror conflicts and extra work in the WebView editor.

## Consequences

Other text fields, including the Markdown editor, have no voice input; extending it later is a separate feature.
