## Context

REQ-001 limited the mic to the intake sheet and said other text inputs are out of scope. The audit found nine more AI input fields without it, and five fields with a hand-written copy of the same wiring.

## Alternatives

1. Only New scenario and New Project
2. Also the notes sheet, hand-off brief, Definition of Done instruction and QA step details (not chosen)

## Decision

Every free-text field whose text is sent to the assistant shows the mic: New Feature/Bug/Research/Understand, New Project idea, New scenario, answers to clarifying questions (features and bugs), bug discussion, Deployments "Ask the AI", Research follow-up, Prototype and Diagram creator, the studios' chats, discussions and terminals. One component (DictationInput) owns the recording, the mic and the status line; fields only place them. Not covered: the Markdown editor, GitHub comments, filters, names and paths.

## Reason

Boris (2026-11-10): there was no audio input in the New scenario; he asked to check that it exists everywhere text is typed for the AI. This replaces the narrower scope of Q-002 (intake fields only) and the hide-without-key rule of DEC-002, which 4.64.0 had already superseded with macOS built-in recognition.

## Consequences

New AI text fields use DictationInput; the five hand-written copies were migrated and removed. Material the AI only reads (notes, hand-off brief, step details) has no mic.
