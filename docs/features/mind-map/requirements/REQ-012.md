## Statement

The system shall let a node show a Mermaid diagram or an image instead of its title, shall offer a Draw menu on a node (Sequence, Flowchart, Data flow, Architecture and the other Graph Creator types) that adds the chosen diagram of what the node describes as a child node, and shall open any visual in a full-screen viewer with zoom and move.

## Acceptance Criteria

- [x] A node with `visual: diagram` shows its rendered diagram on its card instead of the title (scaled to the card; the title stays as tooltip, accessible label and outline name); a node with `visual: image` shows its image the same way
- [x] Selecting a visual node shows the diagram or image larger in the properties panel, with an Expand button
- [ ] Expand (the panel button and a double click on the card; in View the existing expand button of the Markdown preview) opens the full-screen viewer of the Markdown preview: the wheel zooms around the pointer, the buttons Fit, 100%, minus and plus and the keys do the same, dragging moves the diagram, Esc closes; a diagram larger than the screen can be reached in full
- [ ] The node actions have Draw with the types of the Graph Creator: Sequence, Flowchart, Data flow, Architecture, Entity-Relationship, Deployment, Pipeline and Custom (with a typed instruction); a choice adds one child node per diagram, titled after the diagram and built from the node's title, description and the project; the selected node is unchanged, the new child is selected and shown; several diagrams on one node give several children
- [x] Sequence is a real Mermaid sequenceDiagram; the other types are drawn the way the Graph Creator draws them; Flowchart carries decisions and condition labels, so that rules found in research can be read as a diagram
- [ ] The result is checked in code, whichever model wrote it, with the Graph Creator's checks (node budget, ids, labels cleaned, no HTML, link or click directive); a node may have no source file when it is about a process rather than code, but a source path that is given must exist; a result that fails adds no node and says why
- [x] A diagram that fails to render shows an error state on the card and the editable source in the panel, never an empty card; the diagram follows the app theme in dark and light
- [ ] The panel lets the person turn a node into a diagram node (type or paste Mermaid) or an image node (choose a project file or enter an address) and back to text; going back keeps the content
- [x] The content is stored as `visual` plus a fenced block or image in the description (DEC-013); maps without it read and write as before; View, Source and the Markdown report show the diagram or image; Expand description and Correct do not rewrite a visual node's diagram
- [ ] The AI actions other than Draw never set `visual`
