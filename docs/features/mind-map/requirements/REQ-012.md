## Statement

The system shall let a node show a Mermaid diagram or an image instead of its title, and shall offer a Draw flow action that adds a child node holding a Mermaid sequence diagram of what the selected node describes.

## Acceptance Criteria

- [ ] A node with `visual: diagram` shows its rendered diagram on its card instead of the title (scaled to the card; the title stays as tooltip, accessible label and outline name); a node with `visual: image` shows its image the same way
- [ ] Selecting a visual node shows the diagram or image larger in the properties panel, with an enlarge button; the button and a double click on the card open a pop-up with zoom (wheel, buttons, fit) and drag, closed by Esc, the same viewer the Markdown preview uses
- [ ] The node actions have Draw flow; it adds a child titled after the flow with a Mermaid sequence diagram built from the node's title, description and the project, leaves the selected node unchanged, and selects and shows the new child
- [ ] The AI result is checked in code, whichever model wrote it: it must start with sequenceDiagram, stay within a size limit and carry no HTML, link or click directive; a result that fails adds no node and says why
- [ ] A diagram that fails to render shows an error state on the card and the editable source in the panel, never an empty card; the diagram follows the app theme in dark and light
- [ ] The panel lets the person turn a node into a diagram node (type or paste Mermaid) or an image node (choose a project file or enter an address) and back to text; going back keeps the content
- [ ] The content is stored as `visual` plus a fenced block or image in the description (DEC-013); maps without it read and write as before; View, Source and the Markdown report show the diagram or image; Expand description and Correct do not rewrite a visual node's diagram
- [ ] The AI actions other than Draw flow never set `visual`
