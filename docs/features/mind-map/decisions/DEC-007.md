## Context

DEC-002 asks for several predefined layouts that apply to any branch; the discussion treats "seven" as a guide, not an exact count. DEC-005 makes a layout apply to the whole subtree and replace nested choices. The prototype places nodes with one fixed scheme (children of the root alternate left and right, deeper nodes continue outward).

## Alternatives

1. Store computed coordinates for every node (rejected: stale as soon as a node is added, noisy in Markdown)
2. Fewer presets in the first version

## Decision

Seven layouts, chosen per branch: balanced (children alternate left and right of the branch node; the default for the root), right (tree growing to the right), left (tree growing to the left), down (top-down tree), up (bottom-up tree), radial (children on a circle around the branch node, deeper levels on wider rings in the same angular sector) and outline (compact indented list below the branch node). A layout arranges all descendants of the branch node; the branch node itself stays where its own parent's layout (or the user) put it. A node without its own layout uses the nearest ancestor's, the root defaults to balanced. Applying a layout to a branch stores it on that node and removes the layout and the manual position of every descendant, so the whole subtree follows the new layout (DEC-005); a layout chosen later on a descendant is a nested layout until a parent is arranged again. The list is stored in the file as "- layout: <id>"; manual moves are stored as "- position: x, y" and are absolute map coordinates. Descendants without a manual position are placed relative to their parent's current position, so moving a node by hand moves the branch layout with it. The preset list is owned by the Swift module and sent to the map view with each snapshot; an unknown id in a file is ignored.

## Reason

Seven covers the usual mind-map arrangements (both sides, one side each way, top-down, bottom-up, radial, list) and the number matches the user's guide. Storing only the choice and manual moves keeps the file small and lets a layout adapt when nodes are added.

## Consequences

The map view computes positions from the tree, the layouts, node sizes and manual positions with a pure layout function that is tested on its own. Applying a layout is a Swift operation so the recursive clearing of nested layouts has one implementation.
