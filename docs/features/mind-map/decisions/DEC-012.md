## Context

Boris wants to change the shape and the size of each node of the research map (2026-11-04). His choices: a base set of 5 shapes; the size changed with handles on the node, with Width/Height fields in the panel and with S/M/L presets; a given size is a minimum, so the text is never cut; shape and size apply to the selected node only (no branch action, no per-map default). The map file (DEC-006) stores a node's properties as `- key: value` lines, and the new keys must not break maps written by 5.29.0 to 5.31.0. The layout engine (DEC-007) already places nodes by their measured boxes.

## Alternatives

1. A fixed size that cuts the text with an ellipsis: the person can lose text on the map
2. One `size: WxH` property: forces a height when only the width is wanted, and a width when only the height is wanted
3. Shape and size kept in the view state like folding (DEC-010): the map would look different after a copy, on another Mac, or in an export
4. An Apply to children action and a per-map default shape: not asked for now; both can be added later without a format change
5. Free polygons and custom paths: far more than five shapes need, and the text would have no defined area

## Decision

A node gets three optional properties in its section: `- shape: <id>` (rectangle, pill, ellipse, diamond; the current rounded rectangle is the default and is not written), `- width: <60..800>` and `- height: <28..600>` in pixels of the map. Width and height are minimums: the node is never smaller than its text, a width makes the text wrap, a height is a floor. A missing width or height means automatic. Swift owns the list of shapes and the limits, validates on every write and on read (a bad value is dropped, the rest of the file is kept), and sends the shapes in the snapshot. The page sends the values through the existing `update` action (`shape` string, `width` and `height` integer or null). The layout engine is unchanged: it uses the measured bounding box of the node. Ellipse and diamond keep their text in the inscribed rectangle, and the page pads the node so that the text fits. The AI never sets a shape or a size, and the Markdown report ignores them.

## Reason

Optional properties keep every existing map valid and need no migration, and they follow the pattern of color, icon and number. Minimum sizes keep the map honest for a documentation tool: nothing the person wrote disappears behind a frame. Reusing the measured box means the layout, the connection lines and the fold toggles work for every shape without a second layout code path.

## Consequences

Maps gain three properties; an older app version that reads a newer map ignores the lines it does not know and loses them on the next write (single user, one version at a time). The shape ids exist in two places (Swift list, page drawings); a web test fails when they differ. A node whose stored height is below the height of its text shows the text height, so the stored value can be larger than what is drawn. A large ellipse or diamond occupies its whole bounding box in the layout, which leaves empty corners.
