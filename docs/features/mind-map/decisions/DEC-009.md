## Context

REQ-001 wants the research map in its own tab; REQ-003 and REQ-005 want the prototype's interactions. The app has one editor web page shared by all Markdown tabs, with overlay views for canvas, code, data and architecture files; the page has a Source/Preview toggle, and there is no autosave. A map changes from three places: the person in the map view, an AI job, and a text editor. SRC-002's SPEC leaves open how sources and findings appear in the final properties panel and what a person can do with an existing logical connection.

## Alternatives

1. A new tab kind with its own web view (rejected: touches about thirteen exhaustive switches and duplicates what the editor tab already provides)
2. The page owns the Markdown and Swift only appends AI nodes (rejected: two implementations of the format, and AI jobs must work while another tab is on screen)

## Decision

A map is an ordinary editor tab of the .md file; no new tab kind. When the page loads a document whose front matter says type: research-map it shows the map view in place of the document, with a Source button to the Markdown text and a way back. The Swift module of DEC-006 is the only implementation of the file format and of every rule (cascade delete, duplicate-connection check, cycle check on moving a branch, recursive layout, limits). The page sends operations over the existing "bridge" message handler as type "researchMap" with an action; Swift applies the operation to the tab's current text (or the file on disk when no tab holds it), writes the file atomically at once, updates the tab so it is not shown as modified, and answers by running window.mvResearchMapSet(documentId, snapshot) on the page. Actions: snapshot, addChild {parent,title}, update {id, title?, tags?, color?, description?}, delete {id}, moveVisual {id,x,y}, reparent {id,parent}, link {from,to}, unlink {from,to}, layout {id,layout}, develop {id,direction}, continue, cancel, open {source}. A snapshot carries the map id, the map (ok or the problem that stops it from being shown), nodes in outline order with their evidence, connections, the layout list, web queries, status, the running job (label, step, start time), a one-line notice or the id of the node the last operation created, and the text of the tab (markdown) for the Source view. While an AI job runs, and when the file changes on disk, the app pushes new snapshots without a page request; the page is not reloaded. The page keeps only view state (selection, pan, zoom, panel width) per map id, in the page's own storage. Moving has two explicit actions: dragging changes the visual position only (moveVisual), and "Move to another branch" in the node menu changes the parent (reparent). The node menu holds add child, develop with AI, add connection, edit, move to another branch, arrange branch (layout) and delete, as small icons like the prototype. The properties panel follows the prototype (title, tags, colour, description with the Markdown toolbar) and adds an Evidence list under the description: each finding with its label as a small chip, its text and its source; a path opens the file, a URL opens the page. Evidence is changed by the AI or in the Markdown source, not in the panel. A web-queries list and the status (researching, incomplete with Continue, Stop) sit in the map toolbar. Images are inserted as Markdown syntax as in the prototype; the description is a source editor and is not rendered.

## Reason

Reusing the editor tab keeps saving, tab restore, recent files, find, Git status and the Source toggle working with no change to the tab model. One Swift implementation of the rules is testable with the repository's standalone Swift test scripts and means the page cannot write an invalid file. The explicit move action satisfies Q-003's wish to tell the two moves apart.

## Consequences

Operations are validated at the bridge boundary in Swift. A new bridge message type is added on both sides. Map tabs start the open-file watcher so edits saved elsewhere appear. The Evidence list and the connection removal control are additions to the prototype that the specification leaves open (see Q-007 and Q-008); they are built as recommended and removed if the answer is B. In the Source view of a map the text follows the file until the person types in it; editing the Markdown source of a map while an AI job is adding nodes to the same map is not merged (the typed text becomes the text the job continues from, and nodes the job added between two keystrokes can be lost).
