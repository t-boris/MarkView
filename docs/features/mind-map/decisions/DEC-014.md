## Context

The report of 5.31.0 maps every node to a numbered heading and every finding to a bullet (DEC-010). Boris wants a document to share: narrative text that accounts for every node, with images and diagrams where they help, for the Markdown file and for the PDF.

## Alternatives

1. The model writes the whole file including diagrams and source lists: it can drop nodes and invent sources and paths
2. Keep the deterministic outline and add an AI summary on top: Boris rejected a one-to-one list in any form
3. One section per branch written by separate calls and stitched by code: more calls, a weaker story across branches

## Decision

Export becomes an AI job (the same job bar and cancel as the other map jobs). The model gets the map as structured data and answers with a JSON object: the narrative as Markdown with placeholders (`{{node:n12}}` for a node's image or diagram, `{{diagram:kind|what it must show}}` for a new diagram, `[1]` style citations) and, per section, the ids of the nodes it covers. Code then checks that every node is covered, that every citation points at a source of the map, that the text is not a node-by-node list (bullet share and heading count), builds the Sources list from the map's evidence, expands the placeholders (the map's own Mermaid blocks and images, new diagrams through `DiagramAI` with its checks), and only then writes the file. A failed check goes back to the model for a repair round (at most two), as `DiagramAI.generate` does. The PDF renders the same final Markdown, with Mermaid drawn before printing.

## Reason

The prose is the model's job; whatever must be exact is done in code, so the result does not depend on which model writes it: no node is dropped, no source or path is invented, diagrams and images are real. The same machinery as the Graph Creator and the node AI actions is reused.

## Consequences

The export takes minutes and costs model usage, so it is a job, not a click. The one-to-one report generator goes out of the menu (its tests change). Diagrams in the report need REQ-012's `visual` property and the Graph Creator reuse (DEC-013); the PDF path must render Mermaid before printing. A guard that is too strict can make the model loop, so the repair rounds are limited to two and the failure is reported.
