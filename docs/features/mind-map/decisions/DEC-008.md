## Context

DEC-004 requires the map tab to open when initial research starts and nodes to appear as they are ready. The prototype SPEC leaves the depth and the stop criterion open ("Глубина и критерий остановки не определены"); the overview leaves most failure handling to the implementation, except that a stopped result is marked incomplete and can be continued (REQ-002). DEC-001 keeps existing Markdown reports as they are.

## Alternatives

1. Ask for one JSON answer with a node array through the structured-output path (rejected: Claude streams it only at the end, so nodes would not appear while the agent works, and Codex returns it whole)
2. Let the model decide depth and size (rejected: results would vary by model)

## Decision

Starting New Research (every existing entry point) creates the map file at once with the question as the root node and status researching, opens it in a tab, then runs one cancellable agent job over the repository, with the same inputs (target documents, attachments, scope listing), web-search setting and timeout as before. The agent writes its answer as lines, one JSON object per line: "NODE {…}" with fields ref (a short label of its own), parent ("root", a ref it used earlier, or an existing node id), title, description (Markdown), tags and evidence (label, text, source). The first line describes the central subject and renames the root. The app parses the stream line by line from all backends, ignores every other line (narration), and applies ready nodes to the file in batches at most every 0.4 s, so the open map grows while the agent works. Deterministic guards, not the model, set the limits: initial research accepts at most 60 nodes, at most 3 levels below the root and at most 12 children per node; developing a branch accepts at most 24 nodes and 2 levels below the chosen node, all inside that node's subtree; a node whose parent is unknown or has been deleted meanwhile is dropped; titles are cut to 120 characters. Evidence keeps the existing verification: a [Project fact] must cite an existing repository file and an [External fact] a URL, otherwise it is relabelled [AI inference] with a note (ResearchDocument.checkedFinding). Web queries the agent ran are added to web_queries as they appear. The file is written after each batch; a failed, cancelled or timed-out run sets status incomplete with the reason and keeps every node received. A run that produced no node at all sets incomplete with that reason and leaves the root. Continue (shown while status is incomplete) starts a run that is given the current map and told to deepen the branches that have no children or little detail. Develop with AI (the sparkle action on a node) asks for a direction in words and runs a job that adds children under that node; when the direction asks for options, each option is its own child. Only one AI job runs per map file; a second request says so. Existing research reports, their Continue/Deepen and Revise With Comment keep working unchanged and are not converted.

## Reason

One line per node streams reliably from every backend (token deltas, whole messages or protocol chunks), survives narration between tool calls, and loses at most one node to a malformed line. Fixed limits enforced in code keep the result the same whichever model the person configured. Writing after every batch means a crash or cancel never loses what was shown.

## Consequences

A pure Swift module holds the prompts, the line parser and the guards and is tested with recorded streams, malformed lines and limit cases. The limits are constants that can be changed in one place. Free-form narration is not kept; the map is the result.
