## Context

Boris wants a node to show an image or a diagram instead of its text, and a Draw menu on a node that adds a child node with a diagram of what the node describes (a sequence diagram, a flowchart of rules found in research, a structured diagram). The map file is Markdown that Swift owns (DEC-009); the same file is also opened in View and Source (REQ-010) and exported as a report. The app already has a diagram generator, the Graph Creator (`DiagramAI`: diagram kinds, prompts, checks against the project), which writes a separate file and is not tied to the map.

## Alternatives

1. A separate `diagram:` property with the source inline: not renderable as Markdown, a second place for the same text
2. Sidecar .mmd/.svg/.png files next to the map: files to move, rename and delete together with the map
3. Infer the kind from the description with no property: a text node that merely quotes a diagram would turn into a visual node

## Decision

A node may have the optional property `- visual: diagram` or `- visual: image`. A diagram node keeps its Mermaid source in a ```mermaid fence in the node's description, an image node keeps a Markdown image in the description. The card shows the first such block instead of the title; the title stays as the outline name, tooltip and accessible label. Bad values are dropped on read and refused on write. The AI writes visual nodes only through the Draw menu, which reuses the Graph Creator's generator and checks (`DiagramAI`) and puts each result into a new child node; a sequence diagram is written as a Mermaid sequenceDiagram. For a map node a diagram node may have no source file, but a source path that is given must exist.

## Reason

The file stays valid Markdown that every other view already renders: View, Source, the Markdown report and other tools show the diagram or image with no extra work. Validation stays in Swift and is the same whichever model drew the diagram. No sidecar files have to be kept in sync with the map.

## Consequences

Backward compatible (minor bump). Expand description and Correct on a visual node must not rewrite the diagram. An image path has to resolve the same way as images in ordinary documents (checked while building). Diagram theme follows the app theme. `DiagramAI.validate` gets a switch that makes the source file optional, and the Sequence kind gets a sequenceDiagram writer next to the flowchart writer; the Graph Creator itself keeps its behaviour.
