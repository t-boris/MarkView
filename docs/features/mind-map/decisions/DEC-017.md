## Context

Before 5.34.0 the root's children alternated right, left, right, left by index, so a side never changed when a branch was folded or unfolded, a node was added or a node was moved under a new parent. Boris (2026-11-05): when a node with the balanced layout is closed and opened, the side it is calculated on should be reconsidered; the layout is not static unless he changed it himself.

## Alternatives

1. Keep alternating by index (static; what 5.33.0 did)
2. Greedy by height with no slack (sides flip whenever a title wraps)
3. Store the chosen side per node in the map file (static again, and a new property)

## Decision

`splitSides` in markview-research-map-layout.js works the sides out on every layout run: children alternate right, left, right, left, but a branch goes to the lighter side when the side it would alternate to is already taller by more than `sideSlack` (90 px). Nothing is stored. Hand-placed x/y and a layout set on a node are untouched.

## Reason

Equal branches give the familiar picture, a heavy branch no longer leaves one side empty, and no new state enters the map file. A pure greedy choice by height would break the alternation for branches whose titles differ by a line, so the slack keeps the alternation unless the imbalance is real.

## Consequences

A branch can change sides when another branch is folded, unfolded, added or moved; this is intended. The first picture comes back when the map is restored. 90 px is a default that can be tuned.
