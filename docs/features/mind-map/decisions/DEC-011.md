## Context

Boris wants icons and numbers (1, 2, 3, 4...) in the node card; before, a number could only be typed into the title and was not marked in any way. The map file (DEC-006) stores each node's properties as `- key: value` lines, and the new keys must not break maps written by 5.29.0 and 5.30.0. Boris chose, on 2026-11-04: built-in icons and free emoji, a hand-set badge plus a Number children action, and one release with the other map changes.

## Alternatives

1. Emoji only: no consistent look, nothing follows the theme
2. Automatic numbering by position with a per-parent switch: numbers change when nodes move, and a number cannot be set by hand
3. A free-form badge text (any short string): harder to validate and to sort, and not what was asked for
4. Storing the icon and number in the title text: the existing way, which is what looked unmarked

## Decision

A node gets two optional properties in its section: `- icon: <id or one emoji>` and `- number: <1..999>`. The icon is a built-in id (a fixed list of 41 drawings, owned by Swift as ResearchMap.iconIDs and drawn by the page by id) or one emoji. Swift validates both on every write and on read (a bad value is dropped, the rest of the file is kept). The page sends them through the existing `update` action (`icon` string, `number` integer or null) and adds one action, `numberChildren` (id, clear). The AI may write `number` on a NODE line when the order of siblings matters. The report writes a built-in icon as [name] and an emoji as it is. The change is backward compatible: no `major` bump.

## Reason

Optional properties keep every existing map valid and need no migration. A fixed built-in list keeps the look consistent with the application and themeable; free emoji covers what the list lacks without a file-format change. The badge stays a hand-set value (with a bulk action) because the person, not the position, decides what step a node is; automatic renumbering on every drag would change numbers the person set on purpose.

## Consequences

Maps gain two properties; an older app version that reads a newer map would ignore the lines it does not know and lose them on the next write (single-user app, one version at a time). The icon list is in two places (Swift ids, page drawings); a web test fails when they differ.
