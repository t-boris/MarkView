## Context

Today a node changes parent only by editing the `## Map` outline in the Source view. Dragging a node moves it on the canvas only. Logical connections are created through a two-list dialog and removed with the cross of the properties panel (Q-008, built as option A). The file format does not change: the outline already carries the parent.

## Alternatives

1. Dragging draws a logical (dashed) connection and the parent changes elsewhere
2. Plain drag draws a logical connection, a modifier key re-parents
3. A "Move under…" item in the node menu with a search field
4. Drag the node itself onto another node

## Decision

Every node has a small arrow on its outer side (the right edge, the left edge for a node in a branch that grows to the left), shown on hover and on the selected node. Dragging from the arrow of node A to node B makes B a child of A: B moves with its whole subtree and becomes the last child of A. The page sends one `move` action with the node id and the new parent id; Swift refuses a move that would put a node under itself or one of its descendants, the root, and a target that is already the parent, and the page says why in a toast. The moved nodes lose their hand-placed positions so that the layout of the new branch places them. A logical connection (dashed line) is deleted by clicking the line, which selects it and shows a small cross in its middle; the cross and Delete or Backspace remove it. The cross in the properties panel stays. Creating a logical connection through the dialog stays as it is.

## Reason

Boris, 2026-11-05: he asked how to move a node to another parent and wants a small arrow on each node, dragged to any other node, with connections that can be deleted; his answers: dragging makes the target a child of the origin, and deleting is a click on the line, then a cross. The earlier "move to another branch" (a dropdown dialog behind an unlabelled icon) was removed because of its form (DEC-010, BUG-093), not because moving is unwanted.

## Consequences

Supersedes the "no move-to-branch" half of DEC-010 in form only: moving is back, as an arrow drag. No change to the file format. Open: what clicking a hierarchy (parent-child) line does; the default is that it is not deletable, because every node needs a parent, and the arrow is the way to change it. New Swift operation `ResearchMap.move(id:to:)` with the cycle and root checks, `researchMap` message `move`, page drag state with a rubber-band line and drop target highlight, hit areas on the lines, tests in the document and WebKit suites.
