## Context

New research must open as a persistent mind map, while existing Markdown research reports remain accessible. The prototype treats Markdown storage as a working assumption, but the approved requirements did not settle the artifact format or access outside the map interface.

## Alternatives

1. Store each research map in a dedicated structured file without requiring a human-readable Markdown representation.
2. Store each research map in a structured file and provide a separate Markdown export; edits to the export would not have to update the map.

## Decision

Store each new research map as a human-readable Markdown file that users can open and edit as a document.

## Reason

The team selected Markdown storage so that research content remains accessible and editable outside the map interface.

## Consequences

REQ-001 must require each map to be saved and reopened from Markdown with its hierarchy, properties, logical connections, evidence, and layout settings intact. The specification must define how these elements are represented in Markdown and how the map handles edits made in an ordinary text editor.
