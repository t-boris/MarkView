## Context

The requirements call for separate outcomes for selected branches and automatic bug creation, but do not specify how failed, blocked, and interrupted checks relate to bug reports.

## Alternatives

1. Create bug reports only for completed checks that fail to meet their expected results; report blocked and interrupted checks separately.
2. Create bug reports only for defects identified by AI analysis; report failed checks as run results.

## Decision

Automatically create a MarkView bug report when a check fails, is blocked, or is interrupted, identifying which outcome occurred.

## Reason

Record every check that encounters a problem, including checks that could not complete.

## Consequences

REQ-003 must report failed, blocked, and interrupted checks as distinct outcomes. REQ-005 must automatically create a MarkView bug report for each such outcome and identify its outcome type. This will also create reports for issues that may not be product defects.
