## Context

The requirements call for separate outcomes for selected branches and automatic bug creation, but do not specify how failed, blocked, and interrupted checks relate to bug reports.

## Alternatives

1. Create bug reports only for completed checks that fail to meet their expected results; report blocked and interrupted checks separately.
2. Create bug reports only for defects identified by AI analysis; report failed checks as run results.

## Decision

Automatically create a MarkView bug report when a check fails or is blocked, identifying which outcome occurred. Checks interrupted by one Stop get one report for the run, naming every interrupted branch (Boris, 2026-11-27: web and API branches run side by side since 7.21.0, so one Stop can interrupt up to three at once).

## Reason

Record every check that encounters a problem, including checks that could not complete.

## Consequences

REQ-003 must report failed, blocked, and interrupted checks as distinct outcomes. REQ-005 must automatically create a MarkView bug report for each failed or blocked check, and one per Stop for the checks it interrupted, and identify the outcome type. This will also create reports for issues that may not be product defects.
