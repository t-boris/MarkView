## Context

DEC-007 supports several actors in a native macOS check but leaves the isolation and execution model open. The Mac has one mouse and keyboard, and synthetic clicks sent to a SwiftUI app in the background are often ignored, so actors cannot act at the same moment.

## Alternatives

1. One app instance for the whole check; actors are accounts that sign out and in between turns.
2. Actors act at the same time through Accessibility actions without focus.

## Decision

MarkView launches a separate instance of the selected installed application for each actor, each under that actor's own account, and the actors take their turns one after another. MarkView brings the acting instance's window to the front before its turn and addresses it by process id. An application that does not allow a second instance makes the check blocked, with the reason stated.

## Reason

Boris chose this model. Actors can be signed in at the same time, so live exchange between users (one sends, another receives) can be checked, and per-process addressing avoids hitting the user's own copy.

## Consequences

Native checks run actors in turns, not in parallel. Single-instance applications cannot be used for multi-actor checks. The run needs the Accessibility and Screen Recording grants.
