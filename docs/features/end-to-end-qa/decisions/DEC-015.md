## Context

All browser tabs share one cookie store, so two users cannot be signed in to one host at once. Only the active tab is mounted in a window, and a page snapshot needs a mounted web view.

## Alternatives

1. Use a data store identified per actor (needs macOS 14, above the macOS 13 target).
2. Switch the visible tab between actors.

## Decision

Each web player gets its own non-persistent website data store. Its web view sits in a window kept off every screen (the page still gets real mouse and keyboard input, which needs a window), and the run view shows each player's pictures side by side. The run owns an approval record, the production data-changing confirmation and Stop.

## Reason

It is the isolation pattern UI Studio already uses and it works on macOS 13; nothing switches tabs, so snapshots stay reliable, and the person sees every player at once.

## Consequences

The browser session gets an optional data store with the current default unchanged. The tab-level stop and tool toggles of the agent server do not apply to in-process calls, so the run enforces its own gate.
