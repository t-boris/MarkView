## Context

The plan drew the editor with Cytoscape and ELK in a new JavaScript file, with the scenario owned by Swift and every edit sent over the bridge. The scenario, its edits and its branches are Swift types that are checked on their own.

## Alternatives

1. Cytoscape and ELK in a new web page with a bridge for each edit (the first plan).
2. A table of steps with no picture of the graph.

## Decision

The editor is native SwiftUI. A pure layout (QAGraphLayout, checked with 400 random graphs) places the steps; steps are buttons, connections are drawn on a canvas, and dragging from one step to another connects them. The tab adapts to the width of the centre area.

## Reason

No bridge messages, no change to the shipping web editor, no new bundled library; steps are reachable from the keyboard and by assistive technology, and the edit rules have one implementation in Swift.

## Consequences

The graph is not shared with the architecture view's Cytoscape code. Large graphs scroll or are scaled down to 60 percent at the least; there is no automatic re-layout by hand-dragged positions, because positions are always computed.
