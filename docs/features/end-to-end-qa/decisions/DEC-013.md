## Context

A scenario generated from a goal in words has no selectors, so it cannot be replayed as fixed recorded steps. The request is a manual QA test performed automatically, like a human.

## Alternatives

1. Replay only recorded steps like UI Studio scenarios.
2. Start one long-lived interactive AI agent for the whole run through the browser MCP tools.

## Decision

For each step an observe-act loop runs. Every turn the assistant is shown the application's current page or screen as text, the step and its expected check, and answers with one move (an action, done, not met, or blocked) and one sentence of narration. A check is judged by the assistant from what the page or screen shows; the screenshot goes to the separate review. A step has no cap on its actions. It is given up as blocked only when the same action is chosen four times on a page that did not change (going in circles), after three failed actions in a row, or after two unusable answers in a row.

## Reason

It works from a scenario written in words, with no recorded selectors, and keeps every step under the run's gate (approval, production confirmations, Stop) while recording a structured outcome per step. One long-lived agent could not be gated per action.

## Consequences

Each turn costs one call of the project's AI command line tool at low effort, so a run is slow and costs tokens. Steps are not cached: a re-run asks the assistant again (replaying resolved steps without the AI is a possible later optimisation, not built). With no ceiling on actions, a run that wanders over new pages forever ends only when the person presses Stop (BUG-123).
