## Finding

The requirements call for an outcome for each branch and automatic bug creation, but do not distinguish a failed expected check from an execution that could not complete, or say whether either creates a bug. Those cases carry different meanings for the user.

> A run can execute multiple user-selected branches as separate checks and reports the outcome of each selected branch separately.

## Possible interpretations

- Failed checks create bugs, while blocked or interrupted checks are reported separately without asserting a product defect.
- Both failed and incomplete checks create bug reports.
- Only AI-detected problems create bugs; failed checks are reported as run results.

## Resolution

Создавать баг как при провале проверки, так и при её блокировке или прерывании. Это обеспечит учёт всех проблем, но увеличит число отчётов, не связанных с дефектами продукта. — see DEC-010.
