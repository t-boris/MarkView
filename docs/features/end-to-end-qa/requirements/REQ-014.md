## Statement

A baseline or a condition that the application's own pages cannot bring about (restoring a snapshot, seeding a database, an operator tool) shall be marked as the person's own: the plan lists it as theirs, the run asks for their word before the check and does not hand it to the page assistant, and the generator shall not write such a step unless it has to.

## Acceptance Criteria

- [ ] A baseline or a state/data condition has the switch 'I restore it myself' / 'I set it up myself'; a manual step needs no way to verify it
- [ ] The plan lists a manual step as 'you do this' and the run shows 'This is for you to do' with 'It is done, go on' and 'No, skip this check' on every target, local and development too
- [ ] The page assistant is never given a manual step to do; when the person says no, the check is blocked before any step
- [ ] A baseline that the page assistant could not establish says in the result how to get past it (switch on 'I restore it myself' or switch the baseline off)
- [ ] The generator is told what the pages can and cannot do, sets baselineManual / conditionManual only when it must, and never describes existing accounts for a player with a test account
- [ ] Scenarios written before the switch existed still load; the switch is part of what an approval covers
- [ ] Verified end to end with the real assistant on a local site: manual baseline card, test account through sign-up, three steps, Passed
