## Statement

The system shall review the user experience of the application at every step of a running scenario: it measures how much effort the step cost (clicks, typed fields, scrolls, page loads, time), has the AI look at the screen of each new screen state against the application's review requirements, and shows the findings as they appear in a feed beneath the playing scenario, each with its screenshot and a concrete suggestion for improvement.

## Acceptance Criteria

- [x] The run counts, per step and per branch, the interactions a person would need: clicks, fields filled, scrolls, page loads and screen changes, and the elapsed time. The counts are measured by the runner, never estimated by the AI.
- [x] After each step that reaches a new screen state, the screenshot and the measurements go to the AI together with the application's review requirements. The AI returns findings with a kind (layout, typography, missing control, superfluous control, extra step, inconsistency, confusing wording, other), a severity, the step, a description and a concrete proposed improvement.
- [x] For web applications the run also measures in the page and gives the AI the evidence: text below a readable size, low contrast, clipped or overlapping elements, small click targets, horizontal scrolling and controls without labels.
- [x] For native macOS applications the run measures from the accessibility tree and gives the AI the evidence: controls smaller than a comfortable target, controls without a name, and elements reaching past the window edge.
- [x] While the scenario plays, the run view shows the players with the current step highlighted and, beneath them, a feed with one entry per step; a new finding appears in the feed as soon as it exists, with its screenshot and text, and selecting an entry shows the recorded frame of that moment.
- [x] Each branch ends with a summary of its effort (for example, 7 clicks and 3 scrolls to approve a request) and names the steps that cost the most.
- [x] The person chooses how deep the review goes (every step, every new screen state, or off) and sees what it costs; the review runs beside the scenario and never slows or blocks it.
- [x] A finding that is a defect becomes a bug as in the analysis requirement; an improvement suggestion stays in the run report and can be turned into a bug on request.
