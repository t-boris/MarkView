## Statement

The system shall let one scenario cover several applications of the same product and several players (actors), each player belonging to an application, with the place where each application runs stated for each environment.

## Acceptance Criteria

- [ ] The user can define several applications in one scenario (for example a user application, an administration application and a partner application), each with a name.
- [ ] For each environment (local, development, production) the user can state where each application runs: an address for a web application, an installed application for a native macOS one.
- [ ] The user can define several players; each player belongs to an application, and a step can name its own application when a player uses more than one.
- [ ] A scenario with three applications and five players can be created, edited and run, and the graph shows which player and which application each step belongs to.
- [ ] The generated scenario uses the applications and players the user named, not one default application.
- [ ] All applications of one scenario are of the same type (web or native macOS), as DEC-007 requires, unless Q-009 is answered otherwise.
