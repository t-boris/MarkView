## Statement

The system shall review each application of a scenario against the requirements set for that application, so that a user-facing application is judged as a product and an administration application as a working tool, and shall name the application and the requirement in every finding.

## Acceptance Criteria

- [x] Each application has a review profile (user-facing, administration or custom) and requirement text that starts from the profile and that the user can edit.
- [x] A user-facing application is reviewed for attractiveness, production readiness and its ability to hold attention: visual quality, hierarchy, wording, first impression, consistency, and the empty, loading and error states.
- [x] An administration application is reviewed for speed, optimality and readiness for automation.
- [x] The speed of an administration application is measured during the run and reported with the findings, not only judged by the AI: the time of each step, and for a web application the page's own load time and the slowest requests with their times.
- [x] Readiness for automation is assessed partly by measurement and partly by the AI: for a web application the run counts the buttons, links and fields that have no identifier, name, test attribute or label (so automation could only find them by position), and the AI judges predictable addresses and repeatable actions; for a native application the controls without a name come from the accessibility tree.
- [ ] Every finding, and every bug created from the review, names the application and the requirement it concerns.
