## Statement

The system shall review each application of a scenario against the requirements set for that application, so that a user-facing application is judged as a product and an administration application as a working tool, and shall name the application and the requirement in every finding.

## Acceptance Criteria

- [ ] Each application has a review profile (user-facing, administration or custom) and requirement text that starts from the profile and that the user can edit.
- [ ] A user-facing application is reviewed for attractiveness, production readiness and its ability to hold attention: visual quality, hierarchy, wording, first impression, consistency, and the empty, loading and error states.
- [ ] An administration application is reviewed for speed, optimality and readiness for automation.
- [ ] The speed of an administration application is measured during the run (page load and request timings for each step) and reported with the findings, not only judged by the AI.
- [ ] Readiness for automation is assessed from what the page offers to automation (stable identifiers, labelled controls, predictable addresses, repeatable actions) and reported with the findings.
- [ ] Every finding, and every bug created from the review, names the application and the requirement it concerns.
- [ ] The review of an application uses only material the user allowed to be transmitted (DEC-004).
