## Statement

Native QA shall obtain actionable, bounded observations of dense application windows including later panels, preserve secure-field protections and the attached application's lifecycle, and distinguish incomplete observations from missing application UI.

## Acceptance Criteria

- [ ] REQ-018: Read/render diagnostics distinguish count, depth, time and failure omissions with elapsed time and counts, without exposing secure values. Measure the actual StrikeDesk failure before choosing its repair.
- [ ] REQ-018: Dense native/Electron windows with 16 and 96 option-like rows retain access to account, trade, Positions, Activity and menu controls; bounded scope inspection or continuation reaches omitted content without unbounded reads.
- [ ] REQ-018: The assistant can inspect a relevant container and return to the window, with current references after each read; it does not repeatedly reload/zoom the application because a tree is incomplete.
- [ ] REQ-018: Tests cover later siblings, deep layout wrappers, truncation, secure fields, stale references, two sequential attached branches and retries; the existing attach/launch permission and ownership tests remain green.
- [ ] REQ-018: The installed updated app establishes the real StrikeDesk baseline and completes the requested paper entry/close matrix. Fixtures or successful attachment alone do not prove this acceptance.
