## Context

Automatic analysis runs AI work without a user action, so its cost and load need bounds. The planner proposed concrete values.

## Alternatives

1. No limits (analyze on every change).
2. Different values chosen by the user.

## Decision

The automatic run traces 3 scenarios (at most 5). After code changes a refresh waits for 60 seconds of quiet, and AI runs happen at most once per 15 minutes per project; a local rescan may run more often. Projects with more than 5000 source files are not analyzed automatically, only through the manual Refresh.

## Reason

Boris accepted these values on 2026-11-02. They keep the background cost predictable and are plain constants that can be changed later.

## Consequences

A pure scheduler decides debounce and interval and is covered by a standalone test. The size cap is reported in the "What was understood" section so the user knows why nothing ran.
