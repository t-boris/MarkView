## Context

AC-3 offers the categories All, Folders and Openable files. F-001 and DEC-003 assumed that the current browser hides files MarkView cannot open. The code says otherwise: FileType.isOpenable (MarkView/Models/DocumentState.swift) returns true for every regular file, so the current list already shows all files and "openable" would be identical to "All". Boris answered how to define "openable" on 2026-11-08.

## Alternatives

1. Text files by content: read the first bytes of every file to tell text from binary (accurate, but I/O for every file on every listing).
2. Drop the category: keep only All and Folders and change AC-3 and plan I-2.

## Decision

A file is openable when MarkView has a viewer for it, decided by extension or file name without reading the content: Markdown, source code with a known language or known plain-text name, JSON, XML, YAML, canvas, PDF, images, tables, Parquet, SQLite, logs and archives. Every other regular file (unknown extension, binary) is unsupported. FileType.isOpenable keeps its meaning (the editor may still try any file as text); a new FileType.hasViewer(_:) answers the category question.

## Reason

Boris chose the viewer-based definition: fast (no file reads), stable, and it makes the Openable files category different from All.

## Consequences

The classification is a heuristic by name: a text file with an unknown extension is unsupported although the editor can show it. It stays reachable through All and through Open with Default App.
