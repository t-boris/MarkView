## Context

I-6 asks for indicators of other agents only where a reliable usage source exists. A read-only survey on 2026-11-08 compared Cline, GitHub Copilot CLI, Gemini CLI and Antigravity with the Claude Code and Codex sources. Reliable means a documented or demonstrably stable local format with counts, or a documented API for plan limits and remaining quota reachable with the credentials the tool stores.

## Alternatives

- Add Copilot CLI and Gemini CLI now as estimated windows from their OpenTelemetry export: needs launch-time environment injection and a privacy filter, so it is a feature of its own, not part of a relocation.
- Add Cline as a log-based USD estimate: both log formats are unstable.
- Use the undocumented quota endpoints of Gemini or Copilot: the request excludes undocumented sources.

## Decision

Add no indicator for another agent now. Claude Code and Codex stay as they are. Copilot CLI and Gemini CLI could later become user-limit (estimated) windows fed by their documented OpenTelemetry export, but only for sessions MarkView starts with the export enabled, and Gemini telemetry logs prompts by default so it would have to be reduced to counts. That is a separate feature.

## Reason

Cline: no quota API, two log formats that already changed once, USD only with a user budget. Copilot CLI: the documented REST billing endpoints return usage but no limit, remaining or reset; session-state files and session-store.db are undocumented. Gemini CLI: per-tier daily request limits are documented but no API for remaining quota or reset time, and chat files changed format between versions. Antigravity: only a refresh cadence is published, no numbers, no API, binary protobuf conversation databases. None gives a limit and a reset time the way a quota window needs.

## Consequences

AC-8 is met by its clause 'otherwise the existing supported agents continue to work'. Copilot CLI and Gemini CLI estimates are the follow-up candidates.
