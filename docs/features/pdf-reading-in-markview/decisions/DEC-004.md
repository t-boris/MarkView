## Context

Q-001 through Q-003, DEC-001 through DEC-003, F-001's Resolution and discussion.md
settle the product scope. They leave native implementation and explicit failure
handling to the implementer, not to another product questionnaire.

## Decision

Use the system PDFKit renderer, thumbnail navigation, hierarchical outlines and
embedded-text search. Keep reader state outside the text editor, saving and
indexing paths. Load files and prepare read-only forms off the main thread.

Show explicit errors for missing, unreadable, invalid and empty PDFs. For locked
PDFs, offer a password field and retry without storing or logging the password.
Respect document copying permissions. Do not write PDFs, edit annotations or forms,
offer OCR, or change existing PDF feature-source ingestion or export.

Allow only absolute HTTP/HTTPS and mailto external links, matching the scheme
conventions in GitHubViews.swift. Require valid web hosts, reject credentials and
control characters, and block file URLs, executable/custom schemes and remote
PDF actions. Internal links and outline destinations stay in the current document.

## Verification

Exercise the shipping reader with generated multipage text, scan, mixed, outlined,
linked, form and encrypted fixtures in standalone native tests. Verify byte-for-byte
source preservation, routing/session state, permissions, search and safe links.
Run relevant existing regression suites and the app build. No MarkView browser-tab
inspection or stakeholder manual-test checklist is part of delivery.
