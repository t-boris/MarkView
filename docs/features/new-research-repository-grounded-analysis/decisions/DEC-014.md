## Context

REQ-003 says that earlier sections stay unchanged, but it does not cover user edits between follow-ups, unsaved editor changes, or what context the AI receives.

## Alternatives

1. Snapshot the document at creation and ignore user edits
2. Block follow-ups while the document has been modified by the user
3. Save pending edits, use the current file as context and append only at the end

## Decision

Before a follow-up starts, unsaved editor changes to the research document must be saved; the user is prompted to save or cancel. The current on-disk content, including user edits, is sent to the AI as context. The result is appended as a new section at the end of the file as it exists when the job finishes; the job re-reads the file instead of writing back a stale copy. The AI never rewrites existing sections. 'Unchanged' means unchanged by the follow-up, and user edits are preserved.

## Reason

User edits are respected and no data is lost. Appending only is a simple and safe way to handle concurrent changes.

## Consequences

REQ-003 gains criteria for these cases: unsaved edits trigger a save prompt, user edits survive a follow-up, and the whole current document is used as context. Very large documents may need truncation of the context.
