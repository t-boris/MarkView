## Context

Нужно выбрать единое состояние проекта, относительно которого определяется исправление.

## Alternatives

1. Проверять текущее рабочее состояние проекта.
2. Проверять основную ветку main.
3. Проверять последнюю выпущенную версию.

## Decision

Use an identifiable revision of the project's main branch as the verification baseline. Uncommitted changes and fixes present only on another branch must not establish resolution. If main cannot be identified or inspected, the validity outcome is inconclusive.

## Reason

Выбрана main: исправление уже входит в основную линию проекта, а временные локальные изменения не влияют на закрытие.

## Consequences

Исправление только в рабочей ветке не закроет баг автоматически; ожидать выпуска версии не потребуется.
