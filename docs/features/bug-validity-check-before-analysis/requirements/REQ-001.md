## Statement

Perform a mandatory validity check against an identifiable revision of the project's main branch before every analysis of an existing bug report, including analysis triggered by answers and discussion messages. Uncommitted changes and fixes present only on another branch must not establish resolution. If main cannot be identified or inspected, the validity outcome is inconclusive. Verification of a fix on main does not require waiting for a released version.

## Acceptance Criteria

- [ ] Explicit investigation, question-answer submission, and discussion submission each pass through the validity check before starting bug analysis.
- [ ] Selecting a bug alone does not start analysis.
- [ ] The check distinguishes still-present, already-fixed, and inconclusive outcomes.
- [ ] Each validity check uses an identifiable revision of the project's main branch as its verification baseline.
- [ ] Uncommitted changes must not establish that the bug is already fixed.
- [ ] Fixes present only on another branch must not establish that the bug is already fixed.
- [ ] If main cannot be identified or inspected, the validity outcome is inconclusive.
- [ ] A fix verified on main does not require a released version to establish that the bug is already fixed.
