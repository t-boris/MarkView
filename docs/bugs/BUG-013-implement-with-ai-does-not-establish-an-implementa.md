# Implement with AI does not establish an implementation `/goal`

## Summary

The main implementation handoff does not establish an implementation `/goal` in the reported runs. The current source explains the missing `/goal` for non-Claude prompts and exposes a possible configured-backend versus receiving-terminal mismatch. It does not yet explain the reported Claude Code prompt without `/goal`.

## Steps to reproduce

1. Open a workspace with a feature specification.
2. Select each available assistant backend in turn. Include a run with an existing terminal for a different backend selected.
3. Click “Implement with AI” in the Feature panel, file tree, or content view.
4. Inspect the prompt displayed in the receiving terminal and whether an implementation `/goal` is established.

## Expected

Clicking “Implement with AI” should establish an implementation `/goal` in the receiving assistant when it supports `/goal`. The intended behavior for assistants without `/goal` support is an open product decision.

## Actual

The reporter saw an implementation prompt in the receiving terminal without `/goal`, including across assistant configurations and a case involving a terminal for a different backend. Source inspection confirms that non-Claude prompts omit `/goal`. The reported Claude Code result conflicts with the Claude prompt generated by the current source and needs a specific runtime example.

## Environment

MarkView native macOS app (macOS 13+, Swift 5.9). The report covers all configured assistant backends and an existing terminal for a different backend. The tested app version is unknown.

## Suspected code

- `MarkView/Models/HandoffPrompt.swift` — `feature(_:claude:)` emits `/goal implement …` only for Claude Code and a plain instruction otherwise.
- `MarkView/Models/WorkspaceManager.swift` — `implementWithAI` selects prompt format from preferences before `sendToAssistant` chooses the receiving terminal, which may use another backend.
- `MarkView/Models/TerminalSession.swift` — `pasteWhenReady` and `paste` are relevant to the unresolved Claude Code case if a generated `/goal` is altered or lost during delivery.
- `tools/tests/HandoffPromptTests.swift` — Tests expect a plain non-Claude prompt and check only the generated Claude prompt, leaving terminal selection and delivery unverified.

## Likely causes

- Confirmed: `HandoffPrompt.feature` generates a plain instruction when `claude` is false.
- Possible: `implementWithAI` chooses the prompt format from the configured backend, while `sendToAssistant` can use an existing terminal running another backend.
- Unresolved: the reported Claude Code prompt without `/goal` is not explained by the inspected prompt generator.

## Missing information

- The app version used for the reported behavior.
- A specific Claude Code run showing the configured backend, receiving terminal, and exact prompt text. This is needed to locate the discrepancy between the report and current source.
- Which non-Claude assistants support `/goal`, and the intended behavior for those that do not; this is a product decision, not a missing reproduction observation.
